# 델타포스 참고 미니맵·전체 지도 레이아웃 적용

- 대상: `C:/UnityProject/escape`
- 상태: 구현 완료. 실제 A맵 실행 검증 53항목 PASS, 전후 화면 및 시설 선택 화면 확인.

## 사용자 지시와 기획 의도

사용자 요청: “구현 부탁. 레이아웃 디자인은 델타포스 참조 부탁함.”

기존에 구현한 M키 전체 지도, 내 위치, 주요 파밍 시설, 탈출 지점, 발견한 보관함 표시를 유지하며 화면 디자인을 현대 Delta Force Operations의 실제 화면을 참고해 개편했다. 서브에이전트는 이전 사용자 지정대로 GPT-6.1 Sol / Extra High를 사용했다. 메인이 설계·구현·Unity 실행·통합 검증을 담당했고, 에이전트는 레퍼런스 조사와 독립 소스·화면 검토를 각각 읽기 전용으로 수행했다.

## 확인한 레퍼런스와 적용 범위

- [GameWith 작전 모드 미니맵 실제 화면](https://img.gamewith.jp/img/original_4587b6b2d4fbbb5bc4216d0da6d1dd77.jpg): 원형 미니맵, 얇은 경계, 중심 플레이어, 아래 타이머 배치를 직접 확인했다. [출처 페이지](https://gamewith.jp/deltaforce/471096).
- [Delta Force 입장대기 지도 실제 화면](https://truth.bahamut.com.tw/s01/202412/forum/78342/e3ea203db5f065fe52b27e919b0a0920.JPG): 중앙 지형도, 왼쪽 임무 목록, 오른쪽 아이콘 범례를 확인했다. [출처 글](https://forum.gamer.com.tw/C.php?bsn=78342&snA=305).
- 레퍼런스 에이전트는 [알파 테스트 플레이 중 전체 지도](https://steamuserimages-a.akamaihd.net/ugc/2494516750425655681/2816EA00DC52E415A307287EEED5A92F6E3B55EA/)와 [Space City 미니맵](https://img.gamewith.jp/img/original_40be1e08f7e27a9433365f814780cc53.png)도 직접 확인했다.

참고 이미지에는 알파 테스트 및 입장대기 화면이 포함된다. 이를 최신 버전의 모든 상황에 공통인 UI라고 주장하지 않는다. 웹 보조 지도 사이트를 게임 UI로 취급하지 않았다. 다른 게임의 임무·보스·파밍·탈출 규칙은 도입하지 않았고, 그래픽 자산이나 로고를 복사하지 않았다. 픽토그램은 프로젝트 코드에서 직접 그린다. 왼쪽 임무 목록의 자리는 현재 게임에 존재하는 파밍 시설 목록으로 구성했다.

## 변경 전 상태와 문제

- 사각 미니맵을 제목과 반경 설명이 둘러싸고 별도의 둥근 타이머 카드가 놓여 있었다.
- 전체 지도에는 오른쪽 한 패널에 필터·이동 버튼·상세 설명이 모여 있었다.
- 시설 아이콘은 한글 한 글자를 넣은 채운 사각형이며 시설마다 서로 다른 색을 사용했다.
- 지도에서 시설 종류와 전체 시설 목록을 빠르게 함께 읽기 어려웠다.

## 실제 변경과 방식

- 미니맵을 북쪽 고정 원형으로 변경했다. 실제 반경 70m와 내 위치·방향을 유지하고 얇은 테두리, 작은 M키 안내, 아래 타이머를 배치했다.
- 전체 지도는 중앙 지도, 왼쪽 파밍 시설 5곳 목록, 오른쪽 범례·필터·선택 지점 상세의 세 영역으로 구성했다. 모든 영역은 입력 사각형과 일치하며 서로 겹치지 않는다.
- 작전 시간과 닫기는 상단, 조작 안내는 하단 한 줄에 배치했다. 전체 지도를 열면 전 맵을 맞추는 동작을 유지했다.
- 지형은 회색 계열로 정리하고 탈출은 초록색, 파밍 시설은 황색, 발견 보관함은 밝은 중성색으로 구분했다.
- 의료 가방·공구·전자칩·부품·산업 시설·탈출 문·보관함 픽토그램 7종을 추가했다. 원형 미니맵 밖의 아이콘은 숨기며 목적지 표시는 원 둘레 안에 둔다. 선택 테두리의 대각선 돌출까지 여유를 확보했다.
- 시설 목록에서 시설을 선택할 수 있고, 오른쪽에 실제 시설 이름·종류·직선거리·목적지 지정 버튼이 표시된다.
- 실제 지형·시설·탈출·발견 보관함 데이터는 기존 데이터 연결을 사용한다. 새 파밍 아이템이나 보관함, 적, 스폰 위치를 배치하지 않았다.
- 원형 지도는 기존에 만든 지도 픽셀을 재사용한다. 256×256 버퍼와 텍스처를 재사용하고 이동 시 최대 초당 10회 갱신한다. 추가 카메라나 씬 복제, GPU 읽기는 사용하지 않는다. 지도 원본 픽셀 보관으로 A맵에서 약 3.2MiB의 CPU 메모리를 추가로 유지하며 작전 데이터 정리 시 해제된다. 별도의 이동 중 프레임 성능 측정은 수행하지 않았다.

## 검증과 독립 검토

- Unity 6.1 실제 A맵 분리 미리보기에서 컴파일·실행했다. `LIVE_CHECKS.txt` 최종 결과는 53개 PASS / ALL CHECKS PASSED다.
- 기존 좌표 왕복, 전 맵 맞춤, 시설·탈출 데이터, 층 구분, 확대·이동·선택, 지도 사용 중 이동·사격·재장전·의료·수색 차단, 타이머 진행, 닫은 뒤 마우스 해제와 입력 복구 검사를 통과했다.
- 새 검사: 좌우 패널과 지도 입력 영역 비중첩, 원형 미니맵의 같은 가로·세로 축척과 입력 범위, 투명 모서리와 불투명 중심, 지도 밖 샘플의 안전한 표시.
- 단축키와 제스처 검사는 실제 처리 함수 및 Input System 시험 장치 이벤트를 사용한다. 물리 키보드·마우스부터 화면까지의 전체 입력 전달 검증과 별도 배포 빌드 검증은 포함하지 않는다.
- 소스·화면 검토 에이전트가 `after_gameplay.png`, 전체 지도 이미지를 직접 보고 심각한 겹침·잘림·표시 회귀가 없음을 보고했다. 원형 샘플의 좌표 방향·범위, 버퍼 재사용·해제, 패널 간격도 검토했다. 메인이 그 결과를 읽고 선택 테두리의 원 외곽 돌출 여유를 추가 반영했다.
- 시설 선택 화면은 메인이 추가로 직접 확인했다. 최종 53개 실행 검사는 메인이 수행했다.
- 일반 저장 슬롯을 사용하지 않고 `StageMapPreview/<임의 ID>` 임시 저장 환경을 사용했다. 검증 후 Play를 종료했다.
- 동시에 다른 맵 도구의 D08 명령이 실행 중 미리보기를 보존하도록 거절된 편집기 기록이 있었다. 이번 작업은 그 도구·맵 배치 파일을 수정하지 않았다.

## 전후 증빙

| 변경 전 | 변경 후 | 확인 항목 |
|---|---|---|
| `before_gameplay.png` | `after_gameplay.png` | 사각형 → 원형 미니맵, 타이머와 안내 배치 |
| `before_full_map.png` | `after_full_map.png` | 전체 지도 레이아웃, 목록·범례·아이콘 |
| 기존 선택 화면은 별도 촬영하지 않음 | `after_selected_facility.png` | 진료소 선택, 거리·상세·목적지 버튼, 목적지 해제 버튼 |

모든 변경 전 화면은 런타임 디자인 소스를 수정하기 전에 실제 게임에서 촬영했다. `before_gameplay.png`는 첫 기준 위치 기록 후 카메라 안정화를 위해 같은 수정 전 실행에서 다시 촬영한 것이다. 증빙 도구의 after 이름 명령으로 촬영한 파일을 변경 전 파일명으로 보관했으며, 후속 디자인 구현 전에 생성된 실제 변경 전 이미지다. 이전 작업의 완성 화면을 이번 작업의 변경 전 이미지로 대체하지 않았다.

전후 해상도는 1244×700, 플레이어 위치·방향은 `baseline_position.json`을 사용한다. 카메라의 마우스 주시 반응 때문에 화면 중심은 완전히 같지 않으며, 임시 출격별 테스트 보급함 위치·발견 상태와 타이머 값도 다를 수 있다. 비교 대상은 지도 UI다. 기본 전체 지도·미니맵 촬영 뒤 마지막 런타임 수정은 선택 아이콘의 원 가장자리 여유이므로 기본 화면에는 시각적 변화가 없다. 최종 시설 선택 화면은 그 수정 후 촬영했다.
