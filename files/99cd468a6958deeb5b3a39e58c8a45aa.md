# 에델 애니메이션 후속 작업 전달본

## 사용자 지시와 적용 범위

사용자: “지금 애니메이션 모션 좀 애매해서 chat pro로 넘겨서 edel 애니메이션 작업 좀 시켜보려 하거든. 여태 너가 작업한 edel 모델 정리해서 파일로 줘볼래? chat pro에 넣어서 애니메이션 작업 추가로 시켜볼거야”

현재 에델 애니메이션 개선을 다른 환경에서 이어갈 수 있도록 모델·리그·모션·게임 보정·검증 상태를 로컬 파일로 인계하는 작업이다. 기존 에델 모션 작업의 연속이므로 같은 주제 ID를 유지했다. 이번 인계 완료는 새 모션 구현 또는 기존 파지·머리 물리 완료를 뜻하지 않는다.

## 변경 전 상태와 목적

Blender 원본, 게임에 적용한 FBX/재질/프리팹, 현행 C# 보정과 검증 화면이 여러 폴더에 나뉘어 있었다. 특히 최근 손 파지·검지·머리 충돌·피부 명암은 실행 중 코드로 적용되므로 FBX만 전달하면 실제 게임 상태와 차이를 알 수 없다. 원본의 과거 시험 액션과 현재 게임에서 쓰는 모션도 구분해야 한다.

게임 자산·씬·동작은 수정하지 않았다. 별도 Blender 백그라운드 프로세스에서 파일 복사본을 열고 검증·참고 렌더/GLB를 생성했다. 공유 Unity 편집기나 실행 요청 파일은 사용하지 않았다. 원본 blend는 바이트 그대로 복사했고 원본 FBX/텍스처에도 쓰지 않았다.

## 검증과 증빙

`BLENDER_COPY_VERIFICATION.json`: 원본/전달 blend를 각각 다시 열어 같은 리그52본·액션92개·패킹 이미지9개 및 누락 외부 이미지0을 확인했다. 두 blend SHA256은 `d57e7f6c0b1c4d8c67a7a08e05d0353a8a9701889a746e5f4433273d6696e64e`로 동일하다.

before_authoring_copy.png는 원본을 열어 촬영한 실제 Blender 렌더, after_authoring_copy.png는 전달용 복사본을 다시 열어 촬영한 렌더다. 같은 카메라·포즈·조명·프레임61·480×640 조건이다. 복사 작업이므로 시각적 변경은 없으며 EEVEE 표본 노이즈의 차이를 모델 변경으로 해석하지 않는다. 원본 파일을 수정하기 전 화면을 사후 이미지로 위장하지 않았다.

`PACKAGE_VERIFICATION.json`: ZIP CRC 오류0, 전체 포함 파일의 SHA256 재조회 일치. Unity 자산 GUID는 패키지 내에서 연결되며 URP17.1.0의 Lit 셰이더/AssetVersion 두 GUID는 실제 설치 패키지에서 확인했다. 누락된 비패키지 자산 GUID0.

정지 GLB는 새 프로세스에서 다시 열어 25메시/56,828삼각형·이미지 누락0·애니메이션 없음 확인. 모델 방향의 좌우가 원래 Unity 정면과 맞는지 렌더로 확인했다. 이는 정지 참고 파일의 정상 개방 검증이며 애니메이션/관통 성공 검증이 아니다.

현재 Unity 핵심 소스·FBX 해시는 직전 검증본과 일치했다. 과거 C10 들림 반려, C15b 위쪽 형상 복원과 실제 충돌 미완료, 손 파지의 남은 검증 한계를 전달 안내에 유지했다. HIGH READY 폐기 및 LOW READY 요구, 제자리 대기/표정 연동, 기존 체형·머리색 보존을 명시했다. 원본 내부의 다른 프로젝트/옛 지시는 참고 이력으로 구분하고 현재 규칙으로 적용하지 않았다.
