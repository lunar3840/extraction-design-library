# A맵 진입점 간격 검토 기록

## 사용자 지시 요약

이번 대화에서 확인한 A맵 진입점 관련 판단을 기억하고, 이후 건물·자연물·엄폐물·적 등을 배치하거나 맵 동선을 수정할 때 반영한다.

## 기획 의도와 해결하려는 문제

기본 진입점 B4와 위험 진입점 후보 R8이 가까우며 같은 길목으로 합류해, 서로 다른 진입 경험을 제공하지 못할 수 있다. 이후 오브젝트 배치가 이 문제를 악화시키거나 가리지 않도록 거리뿐 아니라 실제 동선·적 노출·엄폐·파밍·탈출 접근성을 비교할 기준을 남긴다.

## 변경 전 상태 및 문제점

- 기존 `AGENTS.md`에는 이 진입점 간격 문제에 관한 지속적 점검 지침이 없었다. 수정 전 원문은 `before_AGENTS.md`에 보관했다.
- 사용자 제공 화면에서 B4와 R8은 근접해 있었다. 해당 화면은 `reference_current_layout.png`에 원본 그대로 보관했다.
- 별도의 지속 설계 메모가 없어 이후 배치 작업에서 이 판단을 누락할 수 있었다.

## 실제로 바꾼 부분과 방법

- `AGENTS.md`에 「A맵 진입점 간격 검토 기록」을 추가해 이후 맵 작업 때 확인할 기준을 명시했다. 수정 후 원문은 `after_AGENTS.md`에 보관했다.
- `outputs/map_design/2026-09-17/a-map-entry-spacing-memory/DESIGN_NOTE.md`에 현재 B4·R8 상태와 향후 배치 점검 항목을 기록했다.
- 메인이 기록을 작성하고 Sol high 보조 에이전트가 기존 맵 정보와 기록 방향을 읽기 전용으로 독립 검토했다.
- Unity 씬·지형·건물·스폰 로직·에셋은 변경하거나 실행하지 않았다.

## 기대 효과와 확인 결과

향후 맵 배치 시 B4·R8의 단순 좌표 간격만이 아니라 초반 이동 경로, 실제 위험, 엄폐, 보상과 탈출 접근을 검토할 수 있다. R8은 현재 활성 스폰이 아닌 위험 진입점 후보이며, 위험 지역의 경계나 적 위치를 나타내지 않는다는 점도 명확히 했다. 기록 파일과 `AGENTS.md` 수정 전후 사본이 저장된 것을 확인했다. 실제 플레이에서 두 진입점의 체감 차이는 아직 검증하지 않았으며, 이후 배치·동선 작업에서 확인해야 한다.

## 화면 자료와 한계

- `reference_current_layout.png`: 사용자가 제공한 기존 맵 화면의 사본. 수정 전후 비교 스크린샷으로 표기하지 않는다.
- 이 작업은 설계 판단을 문서로 보존한 것으로 게임 화면의 시각적 변경이 없다. 변경 대상인 새 설계 메모는 수정 전 존재하지 않았고, 문서 화면의 전후 캡처를 동일한 앱 화면에서 확보하지 못했다. 따라서 존재하지 않는 전후 스크린샷을 재구성하거나 기존 참고 이미지를 사후 화면으로 위장하지 않았다. 대신 `before_AGENTS.md`와 `after_AGENTS.md`를 정확한 문서 전후 원문 증빙으로 보관했다.
