# 드래그 버리기와 다중 전리품 상호작용

## 사용자 요청과 적용 범위

인벤토리 물품, 파밍 중인 전리품, 장착 중인 무기·방어구를 창 밖 게임 화면으로 드래그하면 땅에 버릴 수 있게 한다. 여러 바닥 물품의 상호작용 UX는 로블록스 작업에서 정했던 최종 방식을 확인하여 적용한다.

참고 출처는 로블록스 프로젝트의 `UI (BASECAMP)` 대화(`01a00953-7e1c-7231-82d0-8139f8d61aba`)다. 해당 대화의 사용자 수정 지시 및 완료 보고를 읽기 전용으로 확인했다. 관련 두 턴은 `ROBLOX_UX_REFERENCE.json`에 보존했다. 사용자가 이번에 명시한 다중 전리품 UX만 현재 Unity에 적용하며, 로블록스 게임의 다른 밸런스·스테이지·키 설정은 가져오지 않았다. Roblox Studio 연결은 없었으며 로블록스 프로젝트는 수정하지 않았다.

## 기획 의도와 변경 전 문제

기존에는 가방/전리품 간 격자 이동과 전리품의 직접 장착·맞교환만 연결되어 있었다. 드래그를 창 밖에서 놓아도 월드에 물품이 생성되지 않았다. 월드 상호작용은 가장 가까운 전리품 한 개만 선택하여 여러 물품을 골라 상호작용하기 어려웠다.

수정 전 현재 Runtime 소스로 격리된 검증 씬을 빌드·실행하여 `before_inventory.png`, `before_world_prompts.png`를 촬영했다. 본 편집기 상태도 `before_editor.png`로 저장했으며 기존 수정 파일 5개는 `source_before/`에 보관했다.

## 실제 변경

### 바닥에 버리기

- 가방, 수색 완료된 전리품, 무기 1·2, 헬멧, 방탄복에서 드래그하여 창 밖의 월드 영역에 놓으면 버린다.
- 장착 장비는 가방에 먼저 해제하지 않는다. 가방이 꽉 차 있어도 버릴 수 있다. 일반 클릭의 무기 선택/장비 정보 확인은 유지한다.
- 격자와 장비 패널, 버튼, 헤더, 상세창, 전리품 창 및 인벤토리 내부 여백은 버리기 영역이 아니다. 화면 밖 포인터도 버리기로 처리하지 않는다.
- 드래그 중 실제 버리기 영역에 들어가면 `바닥에 버리기 · ESC 취소`를 표시한다.
- 플레이어 앞의 가까운 지면을 먼저 검사하고, 벽 건너·지면 없음·물리적 장애물 위치는 제외한다. 바닥 위치나 생성 준비에 실패하면 원본 물품을 제거하지 않는다.
- 기존 월드 전리품 상자 외형을 재사용한다. 바닥 아이템의 상호작용 명칭은 상자명이 아닌 실제 아이템 이름·수량이다.
- UID와 실제 무기/방어구/의료품 상태 객체를 이동시켜 탄창·내구도·잔량·보호 상태를 보존한다. 일부 수량만 옮긴 일반 묶음은 새 UID를 부여하고 잔여 수량은 원본에 둔다. 파밍 전리품의 복수 물리 스택도 하나의 바닥 묶음으로 전량 이동할 수 있다.
- 양쪽 소유 상태와 무게를 확정한 뒤 알린다. 관찰자 예외가 확정된 바닥 물품을 비활성 상태에 가두지 않도록 방어했다. 버리는 행위 자체는 전리품 획득으로 계산하지 않는다.
- 바닥 아이템은 기존 F 상호작용으로 직접 줍는다. 가방이 일부만 받을 수 있으면 남은 수량은 바닥에 보존된다. 비게 된 바닥 오브젝트는 정리된다.

### 로블록스 최종 UX 반영

- 별도 화면 우측 목록을 만들지 않고 기존 월드 상호작용 위치에 프롬프트를 세로로 묶는다.
- 동일 X축, 논리 UI 좌표 42 간격으로 정렬한다. 카메라 원근에 따라 행 간격이 겹치지 않는다.
- 휠로 대상을 바꾸면 왼쪽 원과 F 표시가 선택 행으로 이동한다. 선택 행은 더 진하고 크다(높이 40/34, 폭 248/238).
- 기존 항목은 범위에서 빠진 것만 제거한다. 새로 들어온 항목은 더 가까워도 뒤에 추가한다. 선택한 항목이 남아 있으면 선택을 유지한다.
- 최대 8행을 한 번에 보여주고, 전체 후보는 휠로 순환한다. 선택한 행이 보이도록 표시 구간을 이동하며 선택 번호/전체 개수를 안내한다.
- 현재 프로젝트의 F 길게 누르기·기존 거리/시야 조건은 유지했다. 로블록스의 E 키나 다른 상호작용 시간을 복사하지 않았다.

## 검증과 보완

- 복제 프로젝트에서 새 검사 **65 PASS**, 기존 직접 장착·인벤토리 영역 교환·인벤토리·장비·전리품·세션·거점·테트리스·무기·의료 UI·피격 검사 **785 PASS**, 합계 **850 PASS**. 최종 `rules_final.log` 종료 코드 0.
- 새 검사는 장착 칸 4종, 꽉 찬 가방, 활성 무기 제거 후 보조 무기 선택, 실제 객체/UID 보존, 부분 스택, 65발 복수 스택 전량/일부 이동, 의료품 잔량, 수색 미완료/오래된 UID 거절, 관찰자 예외, 지면 없음 취소, 실제 월드 생성·재획득, UI 닫힘/동결, 버리기 영역, 후보 순서와 행 간격을 확인했다.
- 별도 실행 게임에서 실제 마우스로 가방 소총탄, 파밍 의료품, 장착 소총·권총·헬멧·방탄복을 버리는 6회 입력을 수행했다. `native_first_six_drops_state.txt`에서 원본 장비 칸이 비고 여섯 바닥 묶음의 UID·수량·상태가 남은 것을 확인했다. 패널 사이 여백에 의료품을 놓았을 때 원래 칸에 유지되는 것도 실제 입력으로 확인했다.
- 화면 검수 중 목록 글자가 잘리는 문제를 발견했다(`diagnostic_prompt_label_clipping.png`). 월드 목록 전용 글자 스타일과 충분한 행 내부 높이를 적용한 뒤 다시 빌드하여 이름·수량이 보이는 것을 확인했다.
- 최종 실행본에서 실제 정방향/역방향 휠 입력으로 `소총탄 ×25 ↔ 보급 상자 A` 선택 및 원·F·크기·배경 강조 이동을 확인했다. `after_prompt_selection_1.png`, `after_prompt_selection_2.png` 참조.
- 키보드 길게 누르기의 네이티브 자동 입력 검증은 하지 않았다. 검증용 F8 단축키 입력도 실행되지 않아 이를 성공 증빙으로 사용하지 않았다. 선택 대상의 획득 경로는 실제 `LootInteractor.InteractCandidate`를 호출하는 격리 검사로 확인했다. 검증 게임의 F8/F9 코드는 본 프로젝트에 배포하지 않았다.
- 본 프로젝트 최초 통합 검사에서 고정 검증 좌표가 편집기의 렌더 영역을 벗어나는 테스트 문제가 있었다. 제품 코드는 변경하지 않고 검사 좌표를 실제 렌더 표면의 모서리 기준으로 수정했다. 최종 본 편집기 검사 **65 + 77 = 142 PASS**를 확인했다(`validation_reports/MainEditorImport.txt`).
- 본 편집기의 Play를 실행하거나 씬을 열기/저장하지 않았다. 기존 A 씬의 루트 4개, 미저장 상태 false, 씬 선택이 유지됐다. 통합 확인 뒤 편집기 창이 최소화되어 추가 편집기 화면 저장은 하지 않았다. 변경 후 실제 게임 화면은 별도로 확보했다.
- 기존 `LootContainer`의 static `Reset` 명칭 때문에 편집 모드의 임시 AddComponent에서 `Failed to call static function Reset because an object was provided` 진단이 나온다. 기존 메서드는 이번 범위 밖이라 수정하지 않았으며 기능 검사 결과와 구분한다. 기존 맵 검증기의 obsolete 경고도 수정하지 않았다.
