# D06 독립 검증 — 지정 범위 PASS

## 현재 판정

**최종 배치의 지정 정적·접촉·실제 플레이 검사 모두 PASS.** 커플러의 중간 위치 (470,120)에서 기존 `EnclosuresV33_ConnectedFacilities/Equipment/EE2/Unit_00` BoxCollider와 0.0719m 관통한 결과는 `CONTACTS_before_spacing.txt`에 보존했다. 커플러 홀더만 (470.8,121)로 옮긴 뒤 `SPACING_VALIDATION.txt`와 저장·재로드한 `SPACING_RELOAD_VALIDATION.txt`는 각각 **306 PASS / 0 FAIL**이다. 최종 `CONTACTS.txt`는 비지면 실제 관통 0건, 지원하지 않는 비지면 쌍 0건, 지면 지지 하단 높이차 0.0000m, `RESULT NO_CONFIRMED_PENETRATION`이다. 최종 `D06_PLAY_VALIDATION.txt`는 **20 PASS / 0 FAIL / 0 NOT_EXERCISED**다. D06 before 기준자료(13개 시점, 원본 보호서명, 충돌·좌표·스폰 서명 및 백업)는 메인이 확보했다. Unity 컴파일·씬 적용·플레이 실행은 메인 단일 실행권한에 속하며, 이 검토자는 실행하지 않았다.

첫 Apply 시도는 `VALIDATION.txt` 기준 304 PASS / 3 FAIL이다. D03 A/B 우회로 캡슐 샘플 3,765개 중 6개가 신규 D06 고체와 겹쳤고, D04 E05는 유효한 물리적 입구가 0개였다. D04 종합 회귀 실패 행은 이 E05 실패의 상위 집계다. 메인은 미저장 씬을 복원하고 첫 시도의 증빙을 보존했다. 이후 D03 실패에는 cell·A/B·map 좌표·실제 콜라이더 전체 경로를 최대 40행 진단 NOTE로 남기도록 검증기를 보강했다. 통과 기준은 완화하지 않았다.

배치 담당이 E05 도크와 캐노피를 원래 문에서 옆으로 옮긴 재적용에서는 `VALIDATION.txt`와 `RELOAD_VALIDATION.txt`가 모두 **306 PASS / 0 FAIL / RESULT PASS**다. 이후 W02 포털을 실제 열린 B 문으로, PC 커플러를 실외 (470,120)으로 정제한 `REFINEMENT_VALIDATION.txt`와 `REFINEMENT_RELOAD_VALIDATION.txt`도 각각 **306 PASS / 0 FAIL / RESULT PASS**였지만 커플러 접촉 때문에 이 단계는 최종본이 아니다. 최종 간격 교정의 `SPACING_VALIDATION.txt`와 `SPACING_RELOAD_VALIDATION.txt`도 각각 **306 PASS / 0 FAIL / RESULT PASS**다. D03 A/B는 3,765개 캡슐 샘플 중 신규 차단 0개, 28/28 스폰→탈출 경로와 V33 12개 문, D04 68개 건물 실제 출입구 회귀가 PASS다. 원본 좌표·콜라이더·SpawnTiers 서명이 before/after에서 동일 SHA-256이며, 보호서명 62,752행과 허용된 렌더러 비활성화 8건도 재로드 후 모두 일치한다. 최종 저장 작업 명령은 COMPLETE다.

전후 이미지 19개 대응 시점 중 `tank_close`, `power_coupler_close`, `power_yard`는 각 `before_detail_*`와 SHA-256까지 동일하다. 해당 카메라에서는 새 탱크·커플러가 실제로 보이지 않아, 이 사진들을 그 모델의 시각 배치 증거로 인정하지 않는다. 미배치 `clinic`이 동일한 것은 예상 가능하다. 탱크·커플러는 다른 시점 또는 실제 Play 화면으로 별도 확인해야 한다.

반입 초기에는 GLB accessor `sparse` 판정 및 임시 preview scene 처리 오류로 재시도와 전량 롤백이 있었으나, 수정 후 **현재 `IMPORT_AUDIT.md`는 14종 반입 성공 기록**이다. `REFINEMENT_RELOAD_VALIDATION.txt`도 14/14 프리팹 존재, 각 프리팹 콜라이더 0개를 확인했고, 텍스처 상한은 1,024px이다. 과거 실패는 해결된 이력이지 현재 실패가 아니다.

메인이 Unity 컴파일에서 발견한 `PlayerSettings` 이름 충돌은 D06 Play 코드에서 `Escape.Player.PlayerSettings`로 명시해 수정했으며, 이후 실제 플레이 완료로 재컴파일 결과를 확인했다. 배치 초안의 `D06_BoundaryJunctionPier_SC`에는 수입 모델 외에 원본 벽 접합부를 잇는 시각 큐브 2개가 있어, 정확한 두 이름만 예외 허용하고 콜라이더 부재·렌더러 상태를 검사하도록 했다.

실제 플레이는 단계적으로 판정을 강화했다. 첫 16 PASS / 0 FAIL은 탱크·포털에서 D06 콜라이더가 카메라 광선을 실제 막지 않은 사례도 PASS로 센 한계가 있었다. 가림 검사를 강화한 다음 15 PASS / 1 FAIL / 1 NOT_EXERCISED에서 포털의 닫힌 A 문과 실제 가림 미실행을 발견했다. 포털을 B 문으로 옮긴 뒤 W02 holder는 `DOOR_EXTERIOR_B`에 0.00m로 일치하고, 대응 `metadata_1`/`DOOR_INTERIOR_B`만 선택해 실제 `PlayerMotor`로 양방향 통과했다. 간격 교정 직후 첫 Play는 커플러 측면 검사의 사전 NavMesh 스냅 좌표와 실제 시작·끝 좌표가 달라 **19 PASS / 1 FAIL**이었다. 검사 코드가 사전 승인한 스냅 좌표를 그대로 보행에 사용하도록 수정하되 기존 0.8m 실제 샘플 기준은 유지했다. 그 뒤 최종 `D06_PLAY_VALIDATION.txt`는 **20 PASS / 0 FAIL / 0 NOT_EXERCISED / RESULT PASS**다. 커플러 옆 짧은 실제 보행은 28 step으로 통과했다. 캐노피·탱크·포털·커플러 네 모델 모두 실제 탑뷰 광선이 해당 D06 콜라이더에 닿았고, 플레이어 실루엣과 로컬 리빌이 켜진 것이 기록됐다. 이 선택 플레이 검사는 전 구역·장시간 성능 시험이 아니다.

`before_spacing_power_coupler_yard.png` ↔ `after_spacing_power_coupler_yard.png`를 같은 카메라에서 직접 비교했다. 커플러가 기존 변압기 열에서 분리되어 보인다. 최종 `after_play_D06_MachinePowerCoupler_PC_side_walk_end_retry_02.png`, `after_play_D06_MachinePowerCoupler_PC_overhead_visibility_retry_03.png`도 직접 열어 플레이어가 커플러 곁에 있고 가림 상태에서는 실루엣이 나타남을 확인했다. 앞선 W02 포털·탱크·캐노피 플레이 사진도 확인했으며, 최신 보고서에서는 W02 B 문 양방향 및 네 모델 광선·표시 검사가 다시 PASS다.

## 독립 검증 경로

- `StageATripoD06Validation.Run(map)`: D06 before 원본 충돌·좌표·스폰 서명 exact 비교. 원본 렌더러는 배치 담당의 `RENDERER_ALLOWLIST.txt` 경로에서 `enabled=True → False`인 변경만 허용. 14종 원본 프리팹/콜라이더 분리, 배치 ID·중복·새 MeshCollider와 시각 메시 대응, V33 12문 캡슐 폭, D03 A/B 동선, B1–B4→X1–X7 28개 경로, 교량·릴레이·실내·계단, D04 68개 실제 출입구 회귀를 검사한다.
- 기존 V33/D03 `Run()`은 과거 기록 CSV를 다시 쓰므로 호출하지 않는다. D04 `Run()`은 파일 쓰기가 없어 독립 회귀로 호출한다.
- `StageATripoD06Play.Run()`: 선택된 D06 인접 V33 문, D04 실제 문, 도크 우회, W02 포털 B 문 양방향, PC 커플러 옆 짧은 보행, 캐노피/탱크/포털/커플러 탑뷰 가림을 활성 `CharacterController`와 `PlayerMotor.Simulate()`로 검사한다. 가림 검사는 해당 D06 콜라이더에 실제 광선이 닿지 않으면 PASS가 아니라 `NOT_EXERCISED`로 남긴다. 매 사례의 화면은 `after_play_*.png`로 저장한다. 원본 사진을 덮어쓰지 않도록 재시도에는 `_retry_XX` 접미사를 쓴다.
- `StageATripoD06Validation.InspectCouplerContacts(map)`: PC 커플러 exact MeshCollider와 활성 원본 콜라이더의 AABB 겹침을 추린 뒤 지원되는 Box/Sphere/Capsule/convex-Mesh 쌍의 `Physics.ComputePenetration` 방향·깊이를 별도 `CONTACTS.txt`에 쓴다. 비-Convex mesh 쌍은 미판정으로 남기고, 지면 지지 접촉은 별도 분류한다. 첫 실행의 EE2 변압기 0.0719m 관통은 `CONTACTS_before_spacing.txt`에 보존됐다. 최종 재실행은 비지면 관통 0/미판정 0, 지면 지지 높이차 0.0000m다. 정적/플레이 기존 결과 파일을 덮어쓰지 않는다.
- `FAIL` 행이 0이고 `RESULT PASS`인 검증 파일과 실제 플레이 사진을 직접 확인하기 전에는 통과로 보고하지 않는다. bounds 검사는 broadphase라서 문틀·계단·오버행의 시각/충돌 정합성은 사진과 실제 이동을 함께 확인해야 한다.

## 범위 밖·남은 항목

1. B4와 R8의 초반 W5 접근 경험 차이는 이번 구조 장식 배치만으로 해결됐다고 간주하지 않는다. R8은 비활성 위험 진입점이며 적/보스 또는 위험 구역 경계 표시가 아니다. 별도 기획 변경이 없으면 이 항목은 미해결로 유지한다.
2. 28개 스폰→탈출 경로는 NavMesh 계산이며, 실제 PlayerMotor는 D06 인접 선택 사례 16건만 보행했다. 모든 카메라 각도·장시간 전투·AI의 전 구역 이동·최저사양 또는 전 맵 FPS는 검증하지 않았다. 이번 PASS는 지정된 정적·접촉·선택 플레이 범위에 한정한다.
