# 네 캐릭터 · 실물 동료 칩 · 대기모션

작성일: 2026-10-22. 네 캐릭터 모델, 실물 동료 칩, 외형 숨김, 대기모션 및 Liv 인벤토리 크기 수정의 최종 적용·검증 기록이다. Unity 실제 실행과 마우스 조작으로 확인했다. 별도 배포 실행파일은 새로 빌드하지 않았다.

## 사용자 지시와 기획 의도

Downloads의 Serin v21, Liv v28, Edel v24, Yui v61 최신 모델을 적용하고 네 캐릭터 테스트 칩을 실제 인벤토리 물품으로 지급한다. 칩은 전용 장착 슬롯에 연결하며 출격 중 교체·해제·버리기를 막는다. 방어구의 효과·장착 기능은 유지하고 외형만 임시 숨긴다. 캐릭터 직접 조작이 없으면 월드와 인벤토리에서 원본 호흡·표정·스트레칭·총기점검을 보여 주고, 아이템 이용만으로 대기 시간을 초기화하지 않는다. 직접 이동·조준·회전·전투에는 대기모션을 취소한다.

후속 지시인 Liv의 작은 인벤토리 표시도 함께 수정했다. 캐릭터별 임의 확대값으로 맞추지 않고 실제 표시 중인 스킨의 크기로 동일한 카메라 기준을 적용했다. 원형·머리색·재질을 유지하며, 캐릭터 교체를 이유로 무기·탄약·상태를 새로 지급하거나 회복하지 않는다.

## 변경 전 상태

기존 Serin/Edel은 목록에서 선택했고, 정화된 칩은 가방의 실물 물품이 아니었다. Liv/Yui의 이번 모델은 설치되어 있지 않았다. 출격 파밍에는 별도 미정화 화물·파편의 edel/liv/uui 저장 ID가 존재했다. 사용자 확인에 따라 Yui/Uui는 같은 캐릭터로 보고 표시를 ‘유이’로 통일하되 기존 uui 저장 ID와 저확률 회수·5파편 복원 규칙은 보존했다.

기존 인벤토리 초상화는 정지 Idle와 고정 총기 자세를 사용했다. 새 모델 통합 중에는 Edel 팔 보조 뼈의 리타게팅 불일치, 일부 머리·총구 잘림, Liv의 과대 renderer bounds에 의한 축소 표시가 확인되었다. 이 중간 실패 화면을 최종 통과 화면으로 간주하지 않았다.

## 협업·적용 범위

사용자 요청에 따라 메인이 통합·기획·실행 검증을 맡고 GPT-6 Astra medium 서브 에이전트가 모델·칩 코어·대기모션 및 분리된 UI 후보를 staging에서 병렬 준비했다. 각 파일 소유 범위를 나누었으며 메인이 결과와 검증 기록을 읽고 통합했다. 원본 ZIP과 README는 자료로만 사용했고 별도 게임 지침으로 확대하지 않았다.

공유 Unity는 사용자 승인으로 관련 ‘UI 배치 적용 분석’ 및 ‘미니맵 이미지화 및 위치 표시 수정’ 채팅과 직접 조율했다. 19:15경 원래 v08 장면/Edit 상태를 반환받아 변경 전 증빙을 확보했고, 이후 재장전/UI 검증 때도 소유 시간과 반환을 조율했다. 해당 채팅의 InventoryHudView, 더블클릭, 자동 재장전 및 Mapping 변경은 보존했다. 사용자의 ‘이 프로젝트 관련 채팅들과 계속 직접 조율’ 승인을 AGENTS.md에 기록했다.

## 실제 변경 및 방법

### 모델·리깅·원본 유지

- 원본 ZIP은 보존하고 별도 staging에서 Blender 리그·스킨·UV·모프·텍스처를 추출했다. 텍스처 20개는 packed 원본 bytes의 SHA256 일치를 확인했다.
- 네 Humanoid 모델을 CPU 스킨 정점 기준 높이 2m로 정규화했다. 기존 Serin/Edel 프리팹 GUID·루트 참조를 유지하고 Liv/Yui를 추가했다. 각 원본 Idle을 기존 이동·전투 컨트롤러에 연결했다.
- Edel 팔 문제는 weighted twist helper가 주 팔뼈와 형제여서 Humanoid/IK 회전을 따르지 않는 구조에서 발생했다. UpperArmTwist.L과 ForearmTwist.L/R 세 본을 대응 주 팔뼈 자식으로 옮기되 rest 월드 좌표를 유지하고 92개 원본 액션의 local 곡선을 보정했다.
- Edel 13개 메시의 정점·면·UV·가중치·shape 좌표 해시는 보존되었다. 원본 Idle/AimIdle의 변형 차이는 최대 약 0.000000328m였다. Blender 재현 비교와 실제 Unity 재캡처를 구별했고, 메인은 20:02 실제 인벤토리 전/측/후면에서 삼각 돌출·팔꿈치 수축 해소를 확인했다. 따라서 해당 문제는 ‘분석 중’이 아닌 적용·실화면 확인 완료로 기록한다.

### 실물 칩·저장·UI

- 정화 칩 4종과 독립 장착 ItemSnapshot을 추가했다. 이전 선택은 장착 슬롯으로 이관하며 나머지 테스트 칩은 1회만 가방→창고→복구보관함 순으로 지급한다.
- 동일 물품 칸 교환, 정확 좌표 해제, 공간 부족 실패, 저장 실패 원자성, 중복 instance 차단을 적용했다. 출격·사망 중 변경과 정화 칩 드롭은 UI뿐 아니라 하위 데이터 경로에서도 차단한다. 미정화 화물·파편은 기존 규칙을 유지한다.
- 목록 선택 화면을 실물 슬롯·상세 장착/해제·가방/창고 드래그·전용 코드 아이콘으로 바꿨다. UI는 저장 트랜잭션 콜백만 호출하며 소유 아이템을 임의 복제·삭제하지 않는다.
- 새 게임의 큰 starter 장비를 먼저 배치하고 지급 칩의 원래 instance 스냅샷을 뒤에 추가해, 칩 덮어쓰기와 큰 조끼의 연속 공간 부족을 막았다. 저장 후 새 가방은 실제 인벤토리에 재연결하되 PlayerState는 재생성하지 않아 체력·활력 등의 초기화를 막았다.

### 대기모션·방어구 표시

- 제공 Idle에 눈깜박임·미소·목/등 스트레칭·무기점검을 더했다. 팔은 기존 양손 IK가 계속 담당하고 무기점검은 총 위치·회전 입력에만 작은 변화를 준다. 모션 코드에서 발사·장전·탄약 사용을 호출하지 않는다.
- 입력 알림은 프레임 번호 동등 비교 대신 다음 유효 LateUpdate가 소비하는 pending 상태로 유지한다. OnGUI/프레임 종료 뒤의 초상화 회전 알림도 다음 자세 평가에서 빠짐없이 취소된다.
- 생성 순서상 SdIdlePresentation.Awake 당시 RifleController가 아직 없었다. 무기 참조가 null이면 LateUpdate에서 다시 연결하도록 보완하여 무기가 실제로 존재해도 점검을 계속 건너뛰던 원인을 해결했다. 실제 시간 경과로 목·등·무기점검 3종이 순환함을 확인했다.
- HidePlayerArmorAppearance=true는 플레이어 방어구 표시만 숨긴다. 장착·방어·무게는 유지하고 원래 머리와 의복을 복원한다. false로 되돌릴 명시적 설정을 남겼으며 적의 외형에는 적용하지 않았다.

### 인벤토리 표시 크기

- 머리와 측면 총구가 잘리던 구도는 모든 보이는 부위의 가로/세로 범위를 화면비에 맞추고 여백을 확보하도록 수정했다.
- 20:03 Liv가 유독 작던 원인은 실제 자세보다 넓은 imported animation envelope를 카메라 계산에 사용한 것이었다. 현재 preview의 bone.localToWorldMatrix×bindpose로 실제 스킨 정점과 활성 모프를 평가하도록 변경했다. BakeMesh의 스케일 이중 적용을 피했고 정점·가중치·본·행렬·모프 배열은 캐시하여 매 프레임 새 Mesh/정점 배열을 만들지 않는다.
- 20:09 실제 front 기록에서 Liv와 Serin의 FramingHeight는 모두 1.974609m, ortho는 각각 1.110018/1.109853이며 fallback은 0이다. Liv imported visual 범위는 (2.14, 2.35, 1.79), 실제 범위는 (0.91, 1.97, 1.49)였다. 메인 화면 비교에서 두 캐릭터 표시 키는 약 735px로 맞춰졌다. 기존 모델 신장이나 실제 손 IK를 변경한 결과가 아니다.

## 실패 원인·검사 정정과 보존 확인

- 디스크 공간 부족으로 Unity modal 및 staging 저장 실패가 발생했다. 사용자가 약 10GB를 확보한 뒤 손상 가능 파일을 원본에서 복구하고 재컴파일했다. 사용자 원본·게임·Downloads를 삭제하지 않았다.
- 텍스처 지연로드 누락은 packed 원본으로 재추출했다. 초기 Edel export에서 선택 상태로 바디 전체가 지워진 실패 후보는 폐기하고 legacy mouth 445개 정점만 제거하도록 재변환했다. 바디 27,647/전체 29,671정점과 실제 가시성을 확인했다.
- 19:42 소유물 직렬화 실패는 원본 diff로 확인했다. JsonUtility가 null인 nested weapon/armor/resource를 빈 객체로 만드는 표현 차이가 있었다. 장비 정의 ID가 없는 weapon/armor만 장비 없음으로 정규화하고, resource는 정화 칩의 0용량·0charges에 한해 빈 값과 동등하게 처리했다. 실제 소모품의 0 잔량은 정규화하지 않았다. raw before/after와 전체 snapshot, 발사 수 진단을 남겼고 실제 item ID·instance·수량·유효 장비/자원 상태 비교는 유지했다. ownership_failure_* 폴더 이름은 이전 실패 진단의 보존이며 최종 손실의 증거로 단정하지 않는다.
- 상대 채팅의 정상 자동 재장전은 인벤토리를 닫을 때 초기 AR 0발/예비 100발을 30발/예비 70발로 바꾼다. 이를 캐릭터 교체의 물품 손실로 오인하지 않도록 격리 fixture에서 정상 Reload/Update/Tick 완료 후 소유물 기준을 잡았다. fixture_preload_checks.txt는 0/100→30/70, 합계 100, 발사 0을 확인한다. 자동 재장전을 비활성화하거나 시간을 강제로 건너뛰지 않았고 실제 사용자 저장에 접근하지 않았다.
- idle의 프레임당 dt 상한과 8.5/46초 wall-clock timeout이 낮은 FPS에서 다를 수 있어 누적 QuietSeconds 기준으로 검사를 고쳤다. 제스처 상태값만 확인하지 않고 월드·초상화 뼈의 실제 변화도 검사한다. 입력 검사는 UI/잠금 사전조건과 프레임 경계를 명시하고 수평 이동을 확인한다.
