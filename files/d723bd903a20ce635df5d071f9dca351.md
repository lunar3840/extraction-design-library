# Figma 공식 MCP 직접 인증 기록

- 사용자 지시: ChatGPT 앱과 진행 중인 탭을 종료하지 않고 Figma MCP 연결을 직접 처리한다.
- 의도: 플러그인 계정 연결의 404 실패를 대신해 공식 Figma MCP 서버 직접 OAuth 경로를 사용한다.
- 변경 전: 플러그인은 설치되어 있으나 Figma 도구는 현재 대화에 제공되지 않음. 사용자 제공 before_user_mention_list.png를 변경 전 증빙으로 보관.
- 변경 내용: Codex 공식 mcp add로 figma 서버 https://mcp.figma.com/mcp 등록. 기존 config는 C:/Users/ehoji/.codex/tmp/config-before-figma-direct-20261021.toml에 백업.
- 최초 검증: enabled=true 및 streamable_http URL 확인. 최초 OAuth 대기는 시간 초과 종료. 사용자가 허용 후 연결 불가 화면을 보고함.
- 원인 판단: 최초 인증 수신 프로세스가 시간 초과되었음을 확인. 이후 돌아온 localhost 콜백을 받지 못한 것이 연결 불가의 유력 원인이다.
- 후속 처리: OAuth 로그인 재시작. 127.0.0.1의 새 콜백 포트가 LISTEN 상태임을 확인. 인증 완료는 아직 미확인.
- UI 제한: Chrome 자동 조작이 브라우저 URL 검증 오류로 차단됨. 새 인증 창은 기본 브라우저에 열렸으며 사용자 클릭을 기다림.
- 스크린샷 제한: 인증 완료 후 화면은 아직 확보하지 못함. 완료 전 이미지를 완료 증빙으로 사용하지 않는다.
- Unity 프로젝트, 게임 에셋 변경 없음. ChatGPT 앱 재시작·종료 및 기존 탭 종료 없음.

## 최종 확인
- 새 인증 요청에서 사용자가 허용을 누른 뒤 Successfully logged in to MCP server figma 성공 응답을 받음.
- 후속 codex mcp list에서 figma enabled=true, auth_status=o_auth 확인. verified_status.json에 저장.
- before_user_mention_list.png는 사용자가 제공한 설치 후 미노출 화면이며, after_figma_app.png는 인증 후 Figma 앱 확인 화면이다. 서로 동일 시점·동일 UI 비교는 아니며 인증 자체는 verified_status.json 및 성공 응답으로 검증했다.
- 현재 진행 중인 대화의 사용 가능 도구 목록에는 아직 Figma 도구가 없다. 따라서 직접 MCP 등록과 인증 완료를 실제 파일 읽기 또는 @목록 노출 검증 완료로 확대하지 않는다.
- 앱 종료/재시작 없이 완료했다.
