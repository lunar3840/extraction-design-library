## 2026-10-12 Tripo 담장 생성 화면 추가 검토

`after_wall_10k_tripo.jpg`를 직접 열어 이미지 원본의 사선 콘셉트와 대조했다. Tripo 작업 ID `553852e7-21e4-4c53-be55-23d1467e9f8a`의 화면에는 기본 생성 55크레딧과 리토폴로지 5크레딧 소비 후 잔액 3140, 목표 폴리곤 수 10,000, 정점 8,169/8,169이 표시된다. 이는 **서비스 화면의 표시값**으로 기록한다. 생성 GLB를 수령하거나 정점·폴리곤 데이터를 독립 분석한 결과는 아니다.

화면 정면에서 두꺼운 양단 기둥, 골판 패널의 큰 수직 리듬, 하부 콘크리트 받침과 오른쪽 보수판이 남아 있다. 폭 넓은 1개 벽 조각으로 읽히며 기존 V33 단색 직선 벽보다 가까운 거리의 표면 층위가 분명하다. 과도한 SF 장치나 장식은 보이지 않는다. 색은 카툰 환경의 회색·녹색·적갈색 팔레트에 가깝지만 녹·물때의 미세 대비가 작아 실제 게임 카메라 거리에서는 평평해질 수 있다. 같은 모델을 10여 곳 연속 반복하면 보수판 위치와 녹 패턴이 너무 규칙적으로 반복될 위험도 있다.

이 캡처는 **정면 한 시점**이다. 상단 두께, 뒷면, 양 끝 실제 결합면, 바닥 피벗과 지면 접촉을 보여 주지 않는다. 특히 탑다운 게임 카메라에서 윗면이 분명히 보일지, 기존 담장과 수평 이음이 맞을지는 이 화면으로 판정할 수 없다. 따라서 시각적 첫 시범 후보 `SC_W6_1_8`은 유지하되 Unity 반입 성공이나 배치 적합 판정으로 확대하지 않는다. GLB 다운로드가 앱 내 브라우저에서 전달되지 않아 Unity 반입·배치는 미실행이다. 이번 실행의 `before_*.png` 11장과 `BASELINE`/`SOURCE_HASHES`는 확보됐지만 배치 후 `after_*`가 없어 Unity 전후 비교는 미완료다.

후속 확인이 필요한 항목: 실제 폭·높이·두께(기존 조각 3.308m×2.2m×0.28m와 비교), 후면/윗면/끝단 메시, UV·텍스처 해상도와 반복 흔적, 노멀/분리 부품, 원본 V33 콜라이더와의 일치, 12개 열린 게이트 및 보행·시야, 실제 플레이 화면의 프레임 성능. 10,000 폴리곤이 실제 Unity 반복 배치에서 적절한지 이 스크린샷만으로 판단할 수 없다. `after_export_settings_1k.jpg`에서 GLB 형식과 텍스처 해상도 **1K 내보내기 설정**을 확인했다. 이는 사용자의 ‘4K는 과하니 적당히 낮추되 너무 낮추지 말 것’ 지시를 반영한 설정이며, 실제 파일을 수령하지 못했으므로 내보낸 텍스처의 실해상도·화질·UV 품질은 미검증이다.

## 2026-10-12 ServiceFacade 생성 정면 화면 추가 검토

`after_facade_tripo_front.jpg`를 원본 `concepts/ServiceFacade_3m_reference_v01.png`와 직접 비교했다. 작업 ID는 `224e9db7-e95b-4a63-9d7d-eb9d6ed4011c`; 원본 이미지 2K·ultra off로 생성한 화면이며 잔액은 3110으로 표시된다. 생성비 30크레딧, 8,704 faces/7,636 vertices는 Tripo UI 표시·작업 정보이지 다운로드 GLB를 독립 계측한 수치가 아니다.

정면 형태는 좌측의 두 짝 청록색 루버 함체, 그 위 빗물받이형 사선 덮개, 우측의 굵은 쌍관·작은 조절함·전선함, 이를 묶는 외곽 프레임까지 **콘셉트의 비대칭 구조를 대체로 유지**한다. YardWall과 역할이 구별되는 설비 파사드로 읽힌다. 반면 원본의 두 관이 뒤판에 이어지는 깊이감, 덮개의 윗면 경사, 뒤판의 완결성은 정면 한 장에서 판정하기 어렵다. 루버의 잔패턴·벗겨진 페인트는 게임의 높은 카메라에서 뭉개질 수 있지만 두 큰 색면과 배관 실루엣은 중거리에서도 식별될 가능성이 있다. 이는 아직 Unity 카메라 검증이 아닌 시각적 추정이다.

이 모델은 한쪽만 루버이고 다른 쪽만 관·전선인 것이 정체성이므로 같은 벽에 촘촘하게 연속 설치하면 동일한 얼룩·관 위치가 반복되어 오히려 획일적이다. 최초 배치는 E03의 **실측 통과한 1개 무개구 구간**에 한정하고, 후속 반복도 서로 다른 건물·방향에 띄워 두는 쪽이 안전하다. 좌우 반전으로 변주하면 텍스처 문자·배관 논리·노멀 문제가 생길 수 있어 검증 전 사용하지 않는다. 모델 프레임 뒤로 비치는 틈과 하단 가로재가 있어 기존 건물 외벽에서 뜨거나 기존 창을 비칠 위험도 있다. 후면·윗면 회전 화면, 실제 모델 두께/피벗, 벽과 배관의 충돌 간섭, Unity 탑뷰·야간 시야와 프레임 성능을 봐야만 배치 적합성을 판단할 수 있다.

### ServiceFacade 추가 회전 화면으로 확인한 범위

`after_facade_tripo_angle.jpg`에서 루버 상부의 경사진 청록 덮개와 두꺼운 함체 옆면이 실제 입체로 만들어졌음을 확인했다. 탑다운에서 큰 덮개 색면은 보일 가능성이 높다. `after_facade_tripo_back.jpg`에는 루버 뒤판이 막힌 형태로 보이지만, 배관 쪽 후면은 프레임과 관 사이에 열린 틈이 남는다. 따라서 이 모델을 기존 벽에 부착할 때 뒤쪽에 가려지는 창·낡은 외벽 무늬가 틈으로 드러날 수 있고, 평평한 한 장의 뒷면이라고 취급할 수 없다. 위 문단의 ‘후면·윗면 미확인’은 이 **회전 UI 화면으로 시각상 일부 확인**되었으나, 메시의 닫힘·노멀·정확한 깊이·UV·지면/벽 피벗은 GLB 분석 전까지 여전히 미확인이다. 기존 E03 무개구 구간을 실측하고 프레임·함체의 최대 돌출량까지 재어야 한다.

## 2026-10-12 DrainHeadwall 생성 화면 독립 검토

Tripo 작업 ID `da8a1e9c-e9b1-40a2-9fac-75bcff992d89`의 `after_drain_tripo_front.jpg`, `after_drain_tripo_angle.jpg`, `after_drain_tripo_back.jpg`를 원본 `concepts/DrainHeadwall_5m_reference_v01.png`와 직접 대조했다. 생성비 30크레딧 후 화면 잔액은 3080이고 5,060 faces/4,320 vertices가 UI 작업 정보로 제시된다. 이는 다운로드 GLB의 독립 계측이나 성능 검사가 아니다. 세 모델의 이번 Tripo 생성 화면 누적 소비는 담장 60+파사드 30+폐쇄 수문 30=**120크레딧**, 시작 3200 대비 표시 잔액 3080이다. 내보내기·추가 리토폴로지 비용이 이후 생기면 별도 산입해야 한다.

정면의 중앙 녹슨 강철 판문, 상부 황색 조절 핸들, 양옆 단계적으로 낮아지는 콘크리트 날개벽과 아래쪽 물때가 원본의 주요 실루엣을 유지한다. 측면 화면에서 날개벽의 깊이와 상단 부품이 입체임을 확인했다. 뒤쪽은 수로가 뚫린 통로가 아니라 **연속된 콘크리트 막음벽**이다. 이는 닫힌 폐수문을 정적 제방 장식으로 쓰는 현재 해석에는 허용 가능하지만, 실제 흐르는 배수구·개폐 가능한 수문·관통 가능한 수로로 표현하거나 기능을 주장할 근거는 없다. 탑뷰에서는 양 날개벽의 계단형 상단과 황색 핸들이 인식될 가능성이 있으나 실제 Unity 게임뷰 확인 전의 예상이다.

기존 `BankGuard_03_*`와 날개벽 높이·폭·두께가 맞는지는 아직 알 수 없다. 제안한 Map `(400,293)`은 현행 수로 경계에서 두 교량 사이의 **검사점**일 뿐 승인된 배치가 아니다. 모델 뒤가 막혔으므로 제방 바깥으로 불필요한 덩어리가 돌출하거나 물가의 기존 가드와 이중 벽이 되는지 특히 주의한다. GLB 수령 후 실측, 지형 접지, 원래 콜라이더 보존, 캐릭터 보행·시야, 실제 조명/카메라 및 반복 사용 시 프레임 성능을 검증하기 전에는 Unity 적합 판정을 하지 않는다.
