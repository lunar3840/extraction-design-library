# A 구역 v0.3 실제 Unity 블록아웃 배치 기록

## 사용자 지시

부분 침수 정비구역 기획을 Unity의 실제 블록 모델로 배치하고 적용 가능성을 검사합니다. 기존 A 공간은 B에 임시 보존하고, 새 A는 테스트 후 삭제하지 않고 프로젝트에 남깁니다. Astra 메인이 설계·통합·검증하고 Sol high 서브가 병렬로 공간 제작과 독립 검증을 담당합니다.

## 변경 전 상태 및 확보한 증빙

- 원본 프로젝트는 `C:/UnityProject/escape`입니다. A/B 별도 콘텐츠 씬 없이 SystemsTest의 40×40 테스트 공간을 공유하고, StageAArtPass가 기존 비 오는 마당 아트를 덧씌우고 있었습니다.
- `before_editor.png`: 수정 착수 전 원본 Unity SystemsTest 편집 화면.
- `before_editor_install.png`: 원본 설치 직전 같은 Unity 편집 화면. 이 캡처 이후 파일을 설치했습니다.
- `before_legacy_overview.png`: 수정 전 원본 Assets/Packages/ProjectSettings를 복사한 격리 프로젝트에서 기존 CaptureBeforePreviewOrThrow를 실행해 렌더한 실제 옛 A 공간. 원본 데이터에서 얻은 사전 화면이며 사후 이미지를 전 이미지로 사용한 것이 아닙니다.
- 원본 Runtime, Scenes, EditorBuildSettings를 `work/stage-a-v03-backup/`에 복사했습니다. 원본 설치 직전 수정 대상 기존 파일 6개의 해시가 백업과 같은지 확인했습니다.

## 기획 의도와 실제 변경

중앙 중정비동을 식별 가능한 실내 랜드마크로 유지하면서 의료·전기·부품·공구 시설을 외곽에 분산했습니다. 외곽 순환로와 중앙 우회로로 중앙 통과를 강제하지 않습니다. 넓이는 520×400이며 국소 수로와 두 교량을 포함합니다.

새 A에는 12개 진입점, 7개 탈출구, 높이 4m 상부 작업 통로, 깊이 2.4m 정비 피트 두 곳, 실제 벽/바닥/계단 충돌을 저장했습니다. 외곽 네 실내 시설은 테스트에서 발견한 과도한 순찰 우회를 줄이기 위해 양측 출입 구조로 수정했습니다. 지붕은 내부 플레이어를 가리지 않도록 숨기며 비충돌로 처리했습니다. 지붕 위 이동은 이번 범위가 아닙니다.

무장 가치에 따라 진입 후보가 4→8→12곳으로 누적 확대됩니다. 경계값 10,000/30,000은 임시 검증값입니다. 인간형은 세 지역의 순환 경로에 2명씩 기존 AI를 연결했습니다. 인간 철수·탈출 행동은 없습니다. 기계 조우는 배치 슬롯 세 곳까지만 구현했습니다.

기존 A는 StageB_Legacy 프리팹과 씬으로 보존하고 실제 런타임 B도 이 프리팹을 소비하게 했습니다. A/B 전환 시 이전 지형, NPC, 전리품, 내비게이션이 중복 활성화되지 않도록 분리했습니다. 초기 테스트 더미도 B로 이동해 A 내부에 남지 않게 했습니다. A는 별도 밝기/환경 설정을 사용하고 B 복귀 시 기존 환경을 복원합니다.

StageA_Blockout 씬의 Play는 숨긴 프리팹 복제본이 아니라 해당 씬의 실제 편집 가능한 geometry 인스턴스를 사용합니다. 일반 SystemsTest의 출격은 저장된 프리팹을 사용합니다. 미리보기 슬롯은 고유 임시 폴더에 격리했습니다. 일반 세이브와 일반 B 퀘스트 해금 조건, 캐릭터 외형/헤어 재질은 변경하지 않았습니다. 원본 빌드 씬 목록도 보존했습니다.

## 변경 방법

1. 사전 원본 화면 및 기존 맵 렌더 확보, 원본 코드/씬 백업.
2. 메인 통합 코드와 두 Sol high 서브의 지형·검증 코드를 staging에서 병렬 작성.
3. 최신 원본의 격리 복제 프로젝트에만 먼저 반영. Unity 6000.1.0f1에서 실제 씬/프리팹 생성, 재로드, Play 검사와 렌더 수행.
4. 검증 성공 이후 해시로 동시 수정 여부를 확인하고 필요한 파일/새 에셋만 원본에 복사. 원본 기존 프로젝트·세이브를 전체 교체하지 않았습니다.
5. 원본 Unity에서 컴파일 완료 후 Open Retained A 메뉴로 A 씬을 열고, 실제 Play 출격 화면을 확인했습니다. 확인 후 편집 상태로 복귀하여 A 씬을 남깁니다.

## 확인 결과

- Unity 컴파일 및 씬 생성 성공. A 씬 재로드 후 12 진입/7 탈출 참조 유지, Missing Script 0.
- 기존 SessionChecks 저장·원자적 저장·백업·귀환·사망 회귀 검사 통과.
- 최종 통합 Play 검사 PASS: 경로 187건, 실제 PlayerMotor 이동 9건.
- 경로 검사에는 12×6 실내, 12×7 탈출구, 인간 순찰 폐루프 연결, 계단·피트 양방향 경로가 포함됩니다.
- 실제 PlayerMotor로 진입→실내 한 경로와 두 상부 계단·두 피트의 왕복 이동을 통과했습니다. 모든 맵 경로를 사람이 직접 걸었다는 의미는 아닙니다.
- 실전 로직을 통한 루팅 열기, A 4초 탈출, 정상 A 의뢰 보고에 의한 B 해금, B 진입·귀환, A 재진입 시 NPC/전리품 중복 없음 확인.
- 보존 A 씬 직접 Play 검사 PASS: 동일 편집 geometry 인스턴스, 12/7 참조, 고유 임시 세이브, 실제 CharacterController 5.067m 이동 확인.
- 원본 설치 뒤 새 맵/런타임 에셋 81파일 및 주요 기존 코드·씬·도구 12파일을 검증 복제본과 해시 비교해 모두 일치했습니다. 원본 빌드 씬 목록도 변경 전 해시와 일치합니다.
- 원본 Unity에서 StageA_Blockout 편집 화면과 실제 HUD/30분 레이드 출격 화면 확인. `after_editor.png`, `after_original_game.png`에 저장했습니다.
- 검사 산출물: `outputs/map_design/2026-09-11/stage-a-v03/unity/PLAY_VALIDATION.json`, `RETAINED_SCENE_VALIDATION.txt`, `SCENE_VALIDATION.txt`.

## 주요 변경 파일 / 복구

원본 `Assets/Escape/Runtime`의 PlayerTestWorld, Enemy/EnemyTestWorld, Save/ProfileSession, Save/QuestTransactions, Stage/SessionTestWorld, UI/UiTheme를 수정했습니다. 새 `Runtime/Stage/Blockout/`에 StageABlockoutMap, BlockoutSurface, StageMapRouter, StageScenePreview를 추가했습니다.

새 `Resources/StageMaps/`에 A/B 프리팹과 해당 생성 재질을 저장했습니다. 새 Scenes/StageA_Blockout.unity 및 StageB_Legacy.unity, Editor/StageABlockoutBuild.cs, StageABlockoutPlayChecks.cs, StageRetainedSceneChecks.cs, StageMapGizmos.cs를 추가했습니다.

기존 에셋 삭제는 하지 않았습니다. 이전 코드는 `work/stage-a-v03-backup/`에서 복구할 수 있고 옛 A 아트 프리팹도 원래 경로에 그대로 남아 있습니다. 새 생성 재질 재빌드는 격리 프로젝트의 이번 작업 전용 Generated 에셋에만 적용했습니다.

## 한계와 후속 조정

이번 결과는 이동/충돌/출격/귀환을 검증한 블록아웃입니다. 최종 아트, 기계 보스 AI, 인간 파티 협동 전술, 랜드마크 보상표, 조건부 탈출, 시야를 끊는 세부 엄폐, 실제 전투 압박 속 난이도/시간 밸런스는 미완성입니다. 통과한 경로 검사만으로 무장별 체감 난이도나 퀘스트 횡단 여유가 완성됐다고 판단하지 않습니다.
