# Pro 제작 모션의 실제 Unity 적용 — 진행 중

## 사용자 지시

“그럼 chat pro 대화에서 원본 파일 다시 확보해서 실제 제작했던 모션들 유니티에 적용 부탁함. 기존 임시 모션 말고 원본이 제대로 재생되는지까지 확인해줘.”

후속: 로그인된 앱을 컴퓨터 조작으로 직접 사용한다. 공간 부족은 사용자에게 묻지 않고 조금씩 마련한다. 사용자는 수면하므로 추가 조작 요청 없이 가능한 작업을 계속한다.

## 원본 확보와 호환성 조사

- 앱의 브랜치 · 히로인 컨셉 리스트(1 - 메인부관), ID 6ae642a9-0254-83ee-afdd-151a1cfd7a9c를 직접 열었다. 별도 브라우저는 로그아웃 상태지만 앱 대화는 열람됐다.
- r18 Unity Import와 r19 ZIP 첨부 카드의 미리보기 및 원본 다운로드를 재시도했으나 파일 불러오기 실패가 반복됐다. 이 실물을 확보했다고 주장하지 않는다. 원본을 바꾸지 않은 재첨부도 해당 대화에 요청했고 응답 완료로 간주하지 않는다.
- 이미 확보된 실제 사용자 첨부 EDEL_ShoulderConnection_r18.blend의 SHA256은 73fa5c397c9004cb788717df6cac7caf3bd58f105780b63fa3bdf85ac8a49908이다. 52본·465액션·내장9텍스처를 재확인했다. 원본은 읽기 전용으로 열었으며 임베디드 Python 자동 실행은 껐다.
- 이 원본의 134개 비시연 모션에 대해 원래 30fps의 실제 평가 뼈대 행렬 및 모프 값을 추출했다. OriginalMotionSamples.json/bytes의 원본·바이너리 해시로 연결한다. 과거·비무장·무기별 액션이 함께 들어 있으므로 전부를 최신 채택 동작으로 동일 취급하지 않는다. HIGH READY는 취소 상태를 유지한다.
- 현재 Unity 에델의 바인드 뼈대와 원본 위치를 대조했으며 48개 대응 본의 최대 오차는 약1.39e-7 모델 단위다. 축 변환을 추측한 기본 FBX 내보내기로 대체하지 않는다.
- 원본은 DQ 스키닝이며 Unity용 LBS 보정 Basis가 별도라는 원본 기술 메모를 확인했다. 기본 내보내기가 동등하다고 가정하지 않는다. 원본의 실제 DQ 평가 표면과 같은 본 동작의 LBS 차이를 측정해 후보 호환 보정을 구성 중이며, 학습 표본 적합과 전체 프레임/Unity 검증은 구분한다. 초기96기저 최대 rest좌표오차 약1.295mm는 최종 합격이 아니다. 192기저로 재검토 중이다.

## 공유 작업과 보존

그래픽·UI·맵 담당 모두 Unity 사용/예약 없음 및 사용권 반환을 회신했다. 맵 담당은 StageAFactoryV12Request.txt가 과거의 빈 요청함이며 현행 Poll에서 실행하지 않음을 확인했다. 이 파일은 변경하지 않고 전용 ProMotionSyncReview.request를 사용한다.

Unity를 현재 StageA의 깨끗한 편집 상태로 열고, 임시 읽기용 Editor 도구로 원래 에델의 메시·바인드·셰이프키 구조를 추출했다. 아직 생산 모션/모델/기존 S4/UI/맵·성능 코드 변경 완료 상태가 아니다.

## 공간 정리

원본·현재 r32를 제외한 이 채팅의 세린 r18~r31 중간 blend/FBX19개만 압축하고 모든 멤버 SHA를 대조한 뒤 해당 중간본을 압축 보관으로 전환했다. SPACE_RECOVERY.json에 복구 루트와 원래 해시를 보존했다. 절감484,127,271바이트. 기존 게시 3D 실물로 오인할 새 파일을 올리지 않는다.

별도 예전 검증 프로젝트 Library 캐시 전체 삭제는 자동 승인 검토에서 차단돼 실행되지 않았다. 같은 삭제를 다른 경로로 우회하지 않았다. 더 안전한 NTFS 무손실 압축도 시도했지만 0파일 압축으로 실질 절감은 없었다. production Unity Library와 사용자 다운로드는 삭제하지 않았다.

## 검증 후보 실패와 복구 진행 (2026-11-04 후속)

192기저 보정의 전체 프레임 검사에서 E34_A_Roll_Forward_IP 최대 표면 오차 약0.278338 모델 단위가 발견됐다. 학습 표본 오차가 작다는 이유로 채택하지 않았으며 이 후보는 폐기한다. 전체 검사는 디스크 부족으로 종료되어 완료 검증으로 취급하지 않는다. 원본 DQ 변형을 그대로 재현하는 방법을 별도로 검증해야 한다.

임시 후보 저장 도구에서 EditorSettings.serializationMode를 ForceBinary로 바꾼 코드가 프로젝트 전체 재직렬화를 유발했다. 이는 의도한 후보 범위를 벗어난 구현 오류다. 복구 전에는 production 보존 완료로 보고하지 않는다. 이 작업의 try/finally에 저장한 기존 모드로 복귀하는 중이며 맵 담당에게 상황과 편집기 사용권을 알렸다. 디스크 부족 대화상자에서 캐시의 무손실 압축으로 공간을 마련하고 Try Again을 실행했다. 실패 후보 UnityBodyPatch.bytes(40,957,308B)는 재생성 가능한 임시 산출물이므로 제거했다. 원본 blend와 원본 모션 샘플은 보존했다.

OneDrive 내 이전 검증 캐시에 대한 압축 재시도는 파일 수화로 공간을 더 소비할 수 있어 해당 compact 프로세스만 중단했다. 이후 로컬 C:/UnityProject/escape/Library/Artifacts에 NTFS 투명 압축을 적용 중이다. 캐시를 삭제하지 않으며 공유 씬·재질·메시·GUID의 복구/대조 결과는 완료 후 별도 기록한다.

## 원본 DQ 재현 검증 후속

Blender DQ와 같은 계산을 원본 평가 표면에 대조한 최초18표본은 최대 약2.83e-7 단위였다. 실제 Unity GPU의 같은 HLSL 계산은 70개 주요 표본에서 최대1.727472e-5 단위(약0.0173mm). 0.1mm 기준과 셰이더 오류0으로 통과했지만 전체 구르기 검사를 별도로 수행했다. 원래10마이크로미터 수치 실험의 실패와 셰이더/렌더좌표 시험은 trials/에 보존하며 이를 최종 시각 합격으로 사용하지 않는다. 피부 렌더러와 Unity 내부 스키닝 그리기 행렬이 달라 발생한 렌더 방향 문제는 렌더러 로컬→월드→실제 그리기 로컬 변환으로 수정했다. 공통 HybridToon.shader는 수정하지 않았고 원본 DQ 전용 사본으로 한정했다.

네 방향 구르기의 30fps 전체292프레임을 포함한352표본에서 엄지9478번 정점 등 일부에 최대5.52mm 차이가 발견돼 이 검사를 불합격 처리했다. Blender는 영향 본을 원래 정점그룹 순서대로 누적하면서 쿼터니언 부호를 고르는 반면, 일반적인 최댓가중치 기준 구현은 극단 포즈에서 달라지는 것이 원인이다. 원래 순서/누적 기준으로 두 최악 프레임을 재검사한 오차는2.38e-7 이하로 내려갔다(DQ_ORDER_CHECK.json). 해당 순서 데이터를 별도로 보존하고 Unity GPU의352표본 재검사 중이다. 키프레임 검사만으로 전체 프레임 합격을 대신하지 않는다.

## Chat Pro 원본 재발급

로그인된 네이티브 앱에서 기존 요청이 Work 전환 추천 단계에 멈춰 있음을 확인해 ‘Chat에 머무르기’를 눌렀다. 원본 대화에서 r18 Unity 패키지와 r19 텍스처·총기/기존 핸드오프 묶음을 새 링크로 재발급했다. r19 Unity 패키지/export_unity.py/독립 LBS 보정은 없다는 원문 응답이다. 새 다운로드 링크도 앱의 격리 브라우저 로그인 화면으로 이어져 로컬 실물 다운로드는 확인되지 않았다. 재발급됐다는 원문 주장과 로컬 확보를 구별한다. 검증의 실제 기반은 해시로 보존된 로컬 r18 blend와 직접 추출한 원본 모션 데이터다.
