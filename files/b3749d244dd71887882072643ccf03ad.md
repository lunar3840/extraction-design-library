# Edel arm retarget compatibility correction

## Observed problem
The user's right-arm issue was reproduced from the actual Unity transform dump. The old rig placed ForearmTwist.R beside Forearm.R under UpperArm.R, so a Humanoid clip rotated the mapped forearm but could leave the weighted twist helper behind. ForearmTwist.R affects328 body vertices with maximum weight0.858781. In the captured SD Idle, main forearm vs twist world rotation differed85.1409degrees, compared to approximately0degrees at rest. The same structure affects left forearm and upper arm. The supplied authored clips in Blender did not exhibit the severe generic-pose triangle; Unity retargeting did.

## Minimal correction
Reparent only three weighted helper bones while preserving their rest world matrices:
- UpperArmTwist.L: Clavicle.L -> UpperArm.L
- ForearmTwist.L: UpperArm.L -> Forearm.L
- ForearmTwist.R: UpperArm.R -> Forearm.R

Bake the helper bones' local transform curves in92 source actions to compensate for their new parent, preserving original animated world transforms. No model vertices, topology, UVs, weights, shape-key coordinates, textures or material assignments were removed/repainted. The original package remains unchanged. Before artifacts are retained in this folder.
