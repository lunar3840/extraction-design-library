# D06 Tripo 조합 배치안 — 적용·보정 이력과 최종 간격 교정 후보

## 적용 범위와 선행조건

- 현행 `StageA_Relay_Blockout_v08.unity`의 보존된 Stage A 맵에만 `StageATripoD06Placement.Apply(map)`을 한 번 적용한다. 결과는 `TripoD06_Placements/{구역}/{D06_ID}/Visual` 및 필요한 경우 `Collision`에 둔다. 이미 D06 루트 또는 renderer allowlist가 있으면 재실행을 거부한다.
- 이번 실행의 새 `before_*` 13장, `BASELINE.txt`, `BEFORE_PROTECTED.txt`, `BEFORE_COLLISION_TRANSFORMS.txt`는 메인 워크플로가 보관한다. 아래 좌표는 배치 *후보*이며, 가져온 모델의 실제 장면 시각·통행·경사·성능 검증 전에는 승인된 최종 위치가 아니다.
- 코드가 원본 V33 Renderer를 끄는 정확한 경로는 `RENDERER_ALLOWLIST.txt`로 남긴다. 원본 Collider·Transform은 변경하지 않는다. 새 독립 구조물의 충돌은 보이는 수입 Mesh와 같은 sharedMesh의 비볼록 MeshCollider로만 만든다. 12개 열린 게이트, 기존 문·교량·스폰·B4/R8/W5 로직은 건드리지 않는다.

## 이번 코드에서 보류한 3종

- `IndustrialMachinery` / ServiceFacade: 실제 얇은 파사드 단일 슬롯과 출입문·창 위치가 확인되지 않아 기존 외벽 앞에 겹쳐 세우지 않는다.
- `SluiceGate` / DrainHeadwall: 실제 폐쇄 둑 단면 및 수로 통행을 검증하기 전에는 수문처럼 보이는 막힘 구조를 놓지 않는다.
- `RuinedWallSection` / ClinicPlasterCorner: 진료소는 회전 다각형 벽과 D04 단일 파사드 메시를 사용한다. 작은 L모서리를 기존 벽에 임의 삽입하면 이중벽/문 가림이 되므로, 서비스마당의 기능적인 부속실 배치 후보를 이후 실측·별도 전후 증빙으로 판단한다.

## 완료 판정의 경계

수입과 Unity 컴파일은 완료됐다. 첫 장면 적용은 독립 검증 3 FAIL로 원본 씬에 복원했고, E05 수정 후 두 번째 적용은 정적 검증 306 PASS/0 FAIL 및 실제 플레이 16 PASS/0 FAIL로 저장됐다. 이후 PC·W02 두 홀더 보정과 PC 간격 교정을 실행·저장했고, 최종 `SPACING_VALIDATION.txt` 및 `SPACING_RELOAD_VALIDATION.txt`는 각각 **306 PASS/0 FAIL**, `D06_PLAY_VALIDATION.txt`는 **20 PASS/0 FAIL/0 미실행**이다. W02 실제 B 출입구의 양방향 PlayerMotor 통행과 커플러 옆 보행이 플레이에서 통과했다. 가져온 14개 중 보류 3종을 무리하게 설치하지 않았다. 기존 `before_*`는 D06의 새 증빙이며 D05 과거 캡처를 새 before로 재사용하지 않는다.

## 첫 Apply 실패 후 E05 조정 (미재검증)

첫 Apply의 `VALIDATION.txt`는 304 PASS / 3 FAIL이었고, 실패 항목은 D03 A/B 대체 통로에서 새 충돌체 6회 접촉(3765 capsule 샘플 중), D04 E05 물리적으로 열린 출입구가 0개였다. 실패 장면은 메인이 따로 보존하고 원본 씬을 복원했다. E05의 남측 벽은 `(351.28,205.48)`→`(374.06,202.28)`이며 남측 출입 중심은 대략 `(362.67,203.88)`, 외부 문 앵커는 그보다 약 1.4m 남쪽이다. **초안 도크 `(362.7,205.2)`는 외부 문 앵커와 사실상 겹쳤다.**

따라서 도크·차양을 출입 중심에서 약 6.8m 동쪽으로 옮겼다. 도크 길이 5m의 양 끝은 남측 벽을 따라 대략 x=367–372m로, E05 동쪽 모서리 x=374.06m보다 안쪽이다. 첫 검증의 도크 AABB 남측 반폭 1.59m를 그대로 대입하면 새 최남단은 y≈205.77m이다. D03 `SC_SORTING` A 북측 대체길 중심선은 y=207.5m이지만 폭 샘플은 y=206.5m까지 오며 capsule 반경은 0.4m다. 따라서 AABB 기준의 예상 여유는 **약 0.33m**로 좁다. 이는 **코드상의 기하학적 후보 분석**이며 D03의 6개 접촉이 실제로 어느 모델/경로였는지 확정된 뒤 다시 Validate/Play로 판정해야 한다.

## 두 번째 적용 후 시각 검토와 두 홀더 보정안

- 새 `after_*` 19장과 `after_play_*`를 직접 검토했다. E05 도크·차양은 출입구 옆 창 아래 작업공간으로 읽히며, D03 대체 동선과 D04 E05 문 검증은 통과했다. 벽 3곳·산업 무창벽·각도 접합 기둥·터빈 크래들은 현재 촬영 화면에서 눈에 띄는 관통·뜬 배치가 보이지 않았다. 단, 개별 접촉면과 게임 성능까지 사진으로 확정하지는 않는다.
- `after_tank_close.png`는 가까운 지붕에 대상이 가려진 **카메라 문제**다. V33 N06 다각형은 `(55.58,130.31)`부터 시작하므로 `(57,126)`은 그 밖이며, `after_play_D06_RoofWaterTank_Ground_EN2_overhead_visibility.png`에서 지상 탱크가 실제 건물 외부에 보인다. 이동하지 않는다.
- 첫 PC 커플러 `(446,113)`은 V33 E02 다각형 내부이며 `after_power_coupler_close`와 역방향 사진 모두 지붕/벽에 가린다. 새 `(470,120)`은 외부 PC 내부 빈 공간 후보이고, 기존 D03 PC_CABLE 컨테이너 `(446,130)`, `(461.4,115/122)`, 경로 A x≈465, 경로 B y≈136과 떨어진다. 별도의 충돌·탑뷰·출입/게이트 접근 검증 전까지 안전하다고 확정하지 않는다.
- W02 포털은 첫 배치의 `DOOR_EXTERIOR_A` 앞에서 시각적으로 거짓 문틀일 위험이 있었다. D04 `VALIDATION.txt`에는 W02의 실제 열린 통로가 `metadata_1` 하나로 기록되어 있어 `DOOR_EXTERIOR_B`로 이동했다. 최종 플레이에서 `W02_portal_anchorB_in/out` 양방향 PlayerMotor 통과를 확인했다.
- `RefineValidatedSites(map)`은 이미 저장된 D06 루트에서 **두 홀더의 기존 좌표와 소유 자식**을 확인한 뒤 PC 홀더 위치와 W02 홀더 위치만 바꿨다. 실패 시 두 Transform을 복원하고, 중복 실행 또는 수동 변경 상태는 거부한다. 메인 워크플로의 `before_refinement_power_coupler_yard.png`↔`after_refinement_power_coupler_yard.png`, `before_refinement_portal_entry_B.png`↔`after_refinement_portal_entry_B.png`를 직접 비교했다. PC 장치는 이제 E02 지붕 밖에서 기존 전력설비 열의 첫 항목처럼 명확히 보인다. W02 문틀의 사선 화면에서 제기된 오른쪽 기둥의 문 폭 침범 우려는 최종 실제 플레이의 B 출입구 양방향 17단계 통행으로 확인했다. 보정 직후 및 저장 후 재로딩 정적 검증은 모두 306 PASS/0 FAIL이다.
- `ReclamationBasin`은 `after_basin_close.png`에서 수로 옆 잔디에 단독으로 보여 설비 맥락이 약하다. V16 보유 펌프/밸브/파이프를 작은 2–3개 군으로 연계하는 *별도 검토 후보*가 있으나 이번 두 홀더 보정에는 포함하지 않는다. 새 충돌·출입·수로 가장자리 안전 검증 없는 장식 증식은 하지 않는다.

## PC 커플러의 간격 교정 — 적용·저장·재로딩 검증 완료

- 메인의 실제 contact 검사에서 중간 위치 `(470,120)`의 커플러가 보존 대상 `EnclosuresV33_ConnectedFacilities/Equipment/EE2/Unit_00` BoxCollider를 **0.0719m** 관통했다. 정적 배치 검증 306 PASS만으로 이 접촉은 검출되지 않았으므로, 앞선 사진상 '대형 교차 없음'은 정확한 충돌 판정이 아니다.
- `CorrectCouplerSpacing(map)`은 검증된 중간 위치를 확인한 뒤 `PowerYard/D06_MachinePowerCoupler_PC`의 **localPosition 하나만** 지형 표본을 사용해 `(470.8,121)`로 옮겼다. 다른 D06 물체, 원본 V33 설비·Collider·Transform은 수정하지 않는다. `RefineValidatedSites`의 `(470,120)`은 기존 전후 기록 재현을 위해 유지한다.
- 메인이 실제 장면에서 교정을 실행하고 저장·재로딩했다. `SPACING_VALIDATION.txt`와 `SPACING_RELOAD_VALIDATION.txt`는 각각 **306 PASS / 0 FAIL**이다. `CONTACTS.txt`는 새 비지면 관통 0, 비지원 비지면 쌍 0, 지면 바닥 오차 0.0000m 및 `NO_CONFIRMED_PENETRATION`을 기록한다. 이 접촉 검사는 확인된 관통이 없다는 뜻이지 모든 메시 표면의 완전한 물리 증명은 아니다.
- 대응 화면은 `before_spacing_power_coupler_yard.png`↔`after_spacing_power_coupler_yard.png`이며, 가까운 시점은 `before_spacing_power_coupler_close.png`↔`after_spacing_power_coupler_close.png`이다. 야드 화면을 직접 비교하면 커플러가 기존 전력설비 줄의 첫 장치에서 조금 떨어져 독립적으로 보인다. 최종 플레이 재실행은 `D06_PLAY_VALIDATION.txt`에서 **20 PASS/0 FAIL/0 미실행**이며, `D06_MachinePowerCoupler_PC_side_walk`와 머리 위 가림 확인도 통과했다. 이는 접촉 검사와 구분된 실제 PlayerMotor·시야 검증이다.
