# Roblox 반투명 UI 배치 이식 — 2026-09-04

## 반영 범위

대상은 `C:/UnityProject/escape/Assets/Escape`의 UI 표시 계층이다. Roblox 원본·실사용 DataStore·Unity 저장 형식·아이템 ID·사용자가 별도로 적용한 SD 캐릭터/총기 에셋은 수정하지 않았다. 맵이나 몹 구성 이식은 하지 않았다.

Roblox Studio의 Basecamp Edit 상태에서 `SpatialUiStyler`, `ExtractionInventoryController`, `InventoryTabsController`, 성장/메인 메뉴/HUD/전리품/상점/보관함의 실제 구조와 위치·크기를 읽고 사용자의 첨부 스크린샷과 대조했다. Studio Play나 원본 쓰기는 하지 않았다.

- 왼쪽 인벤토리: 500×602 기준. 제목·고철 헤더, 캐릭터 310×202, 오른쪽 장비·퀵슬롯 160×202, 아래 가방 480×326. 4열 스크롤 아이콘 슬롯, 수량·중량·생존 수치. 상세는 항목을 선택할 때 옆에 열린다.
- 캐릭터 영역 H/V 방어구, 무기 카드. 슬롯 간 드래그 교환, 캐릭터로 드롭해 장착, 퀵슬롯으로 드롭해 등록. 기존 상세 버튼 조작도 유지한다.
- 우측 상단 Tab/K/Q 바로가기. 기존 상단 전체 HUD·항상 열린 캠프 탭은 없애고 하단 소형 HUD와 필요할 때 여는 창으로 바꿨다.
- 성장: 생존/기동/숙련 3열 트리와 하단 강화 상세. 의뢰는 별도 창, 전리품은 우측 4열 슬롯.
- 메인 메뉴는 왼쪽, 슬롯 선택은 중앙. 상점/보관함은 가방 옆에서 선택/거래한다. 기존 메인→슬롯→로비→출격과 저장 실패 시 세션 보존 규칙은 유지한다.
- 공통 둥근 청회색 반투명 그라데이션, 얇은 테두리, 금색 강조. 한국어 작은 글자와 30px 닫기 버튼의 잘림을 실제 렌더 확인 후 수정했다. 긴 슬롯 이름은 말줄임, 전체 이름은 상세에서 확인한다.

## 구현과 원작의 차이

전체 Roblox UI를 픽셀 단위로 복제한 것은 아니다. 주요 배치·구획을 참고했고 Unity의 기존 기능과 한국어 문구에 맞춰 일부 창 크기/여백을 조정했다. 상점의 검색·분류·목록과 보관함 거래 내용은 기존 Unity 동작을 유지한다. 원작의 모든 탭·아이콘·애니메이션을 복제하지 않았다.

현재 IMGUI 표시 계층이며 Canvas/UI Toolkit 변환은 하지 않았다. 유리 느낌은 반투명 그라데이션/테두리/화면 어둡힘으로 표현한다. 실제 실시간 배경 블러 셰이더는 없다. 인물 창은 실시간 3D 모델 대신 임시 실루엣, 아이템은 코드로 그린 임시 픽토그램이다.

최종 이미지 교체 경로:

- 아이템: `Assets/Escape/Resources/UI/ItemIcons/<ItemId>.png`
- 인물: `Assets/Escape/Resources/UI/CharacterPortrait.png`

이미지는 다음 Play부터 로드한다. 색/폰트/기준 배치는 `Runtime/UI/UiTheme.cs`, 슬롯/인벤토리는 `InventoryGlassView.cs`, 캠프/성장은 `SessionGlassView.cs`에서 관리한다.

3. K/Q로 전환해 가방이 숨겨져도 이전 지연 명령이 실행되던 경로: 화면 변경 시 취소.
4. GUI.Button이 MouseDrag를 먼저 소비하던 순서: 소유한 드래그 입력을 버튼보다 먼저 처리. 실제 검증 실행 창의 마우스 입력으로 수정 전 실패를 재현했다.
5. 입력 잠금/사망 등으로 모델 명령이 폐기될 때 드래그 상태가 남을 위험: 시각 제스처는 MouseUp에서 즉시 정리, 모델 거래만 지연. 잠금 시 취소 및 자기 마우스 소유권만 해제.

## 검증 환경 및 해석

사용자의 열려 있는 Unity 프로젝트에서 두 번째 Editor를 실행하지 않고 별도 `player-validation` 사본에서 검사했다. 기존 사용자 SD 에셋에 필요한 폴더/메타도 검증 사본에 복사했다. 첫 사본에는 Avatar 의존성이 빠져 있었고, 이를 소스 수정 없이 보충했다.

그래픽 결과는 별도 Windows Player에서 실제 렌더한 10장이다. 이 검증 사본은 Built-in 렌더러여서 검증 실행 중에만 URP 재질을 Standard 임시 재질로 바꾼다. 그러므로 UI 배치/글자 증거이며 사용자의 URP 아트·조명 품질 검증은 아니다. 작은 Game 창에서는 전체 UI가 비례 축소되므로 충분히 확대해 확인해야 한다.

초기 reflection 방식 GUI 합성 이벤트는 GUI.matrix 변경으로 좌표가 (0,0)으로 재설정되어 폐기했다. 후속 검사는 Windows 마우스 메시지를 **검증 실행 파일 자신의 창에만** 보내 Unity의 실제 OnGUI 입력 경로를 거친다. 사용자의 Editor 창/데스크톱 커서를 조작하지 않는다. 모든 입력 방식·해상도·모달 조합을 전수 검사했다는 뜻은 아니다.

독립 검증자는 원본을 수정하지 않고 소스/결과 기록을 검토하고 결함을 전달했다. 검증자의 코드 검토와 구현 담당의 실제 Unity 실행 결과를 구분한다.
