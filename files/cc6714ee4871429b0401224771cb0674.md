## 실제 수정·방법

- C# 토큰 분석에서 `?.` 뒤에 숫자가 오면 null 조건부 접근이 아니라 `?`와 `.75f`를 분리한다. 진짜 `obj?.Member`와 문자열·주석은 기존처럼 처리한다. 숫자 바인딩 시작점에 소수점을 포함해 교체 시 `?.0.8f` 같은 잘못된 원문을 만들지 않는다.
- 기존 게시 카탈로그는 원본 경로·필드·원문 문장·리터럴 순서·잘못된75가 정확히 일치하는1행의 기준값만0.75로 보정한다. 최신 Unity 전체를 새 게시 데이터로 추출하지 않는다. 같은 소수점 형태를 게시본 전체에서 검사한 결과 해당 후보는1행이었다.
- D1의 기존 상태도 해당 원문/값을 대조해 원자적으로 보정한다. 새 revision과 한 번의 보정 이력을 남기며 원본지문·비밀번호·인증·다른 저장 편집값을 유지한다. 해당 행의 별도 사용자 편집은 삭제하거나 일괄100으로 나누지 않고 보존·충돌 표시한다. 진행 중인 Unity 요청·lease가 있으면 건드리지 않고 완료 뒤 보정한다. 오래 열린 화면의 이전 revision 저장은 거부한다.
- 일반 CSV와 전달 CSV의 C# 숫자에는 `numericFormat=csharp-literal-v2`를 기록한다. 이전 오류75/잘못된 기준75가 담긴 미표기 CSV는 가져오기에서 거부하고 최신 파일 재내보내기를 안내한다. 같은 유형의 선행 소수점 누락도 검사한다. 다른 정상 구형 CSV는 계속 허용한다. 새 형식에서 사용자가 명시적으로75를 입력하면75f로 정확히 처리하며,0.75로 멋대로 나누지 않는다.
- 연결 도구의 적용 결과 스냅샷도 알려진 조건식의 원문 숫자와 보고 값이 같아야 한다. 구버전의75 또는 잘못 만들어진 `.0.8f` 같은 결과로 완료를 주장하면 거부한다. 실제 반영은 기존 원본충돌 검사·백업·다시 읽기 증명을 유지한다.
- UI는 경고만 하던 표시를 정상 ‘정찰 필살기 탄퍼짐 배율’/0.75/효과 배율 설명으로 바꾼다. 기존 인증·공개 읽기 전용·White/Black·공통 UI는 유지한다.
