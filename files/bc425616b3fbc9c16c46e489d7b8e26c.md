## 실행 설정 및 입력 확인

실행 전에4방향의 업로드 슬롯을 확인했다.
정면·좌측·우측·후면 전용 슬롯에 동일r3 도면에서 추출한4개 파일을 넣었다. 업로드 후 파일 입력요소가 사라져 순서 기반 선택이 바뀌는 점을 발견하여 방향별 슬롯으로 다시 연결하고4개 미리보기를 최종 확인했다. 이 과정에서 생성은 아직 하지 않았으므로 중복 생성/크레딧 사용은 없다.

실제 생성 선택은 HD H3.1 / Ultra Mesh Quality ON / 목표150000삼각형 / Generate in Parts ON·Detailed / Privacy Private다. 부품 분리 모드를 켜면 텍스처 동시 생성은 자동으로 꺼지는 UI 제한을 확인했다. 따라서 우선 무재질 분리 형상60크레딧 한 건을 실행하고, 생성된 형상의 품질과 부품 구조를 확인한 뒤 같은 형상의 재질 작업을 다룬다. 처음 열었을 때의4K 텍스처 설정을 이번 무재질 생성에 적용했다고 주장하지 않는다.

전 스크린샷: before_tripo_settings.jpg(입력전), before_tripo_inputs.jpg(4개 입력/분리Detailed/60크레딧), before_tripo_generation_settings.jpg(Ultra·15만·TextureOFF). 업로드 원본·크롭·해시는 전달폴더inputs/INPUT_MANIFEST.json에 있다. 생성 버튼은 한 번만 눌렀고 완료/차감/작업ID는 후속 화면에서 확인한다.

## 생성/다운로드 결과

단일 작업ID `6d084c10-8f7d-45f8-88f0-13b050c8dfb4`에서147229삼각형·76581버텍스·44파트가 생성됐다. 잔여크레딧은815→755였다. 분리된 무재질 원본을 먼저GLB로 내려받아 보존했다. 같은 작업의Texture 모듈로 넘어가면4방향 참조가 이어져 있었으며4K·RemoveLightingON으로 재질 생성을 한 번 실행했다. 추가20크레딧으로 잔여735, 이번 작업 총80크레딧이다. 모델4벌 생성이나 두 번째 형상 재생성은 하지 않았다. 기본 생성 설정은 작업전의 GeneratePartsOFF·TextureON·4K/PBR/RemoveLightingON·UltraON·15만으로 복원하고 결과Texture 탭을 사용자용으로 유지했다.

## 실제 형상/부품 검토

다운로드한GLB를 별도 Blender 백그라운드 장면에 불러와 확인했다. 분리형상/텍스처 원본 모두44개 실제 메시이며 삼각형수147229와 경계[-.315182,-.147151,0]~[.315182,.147151,.979296]가 같다. 실제 렌더로 오른쪽 긴소매/긴바지/공구수납, 반대쪽 빈 팔/허벅지와 분리 스트랩·부츠, 목깃/옆구리의 개방부, 등X하네스·원형 연결부를 확인했다. 재질을 숨긴 회색 검사에서도 봉제/구김/버클/보호판의 실제 깊이가 보인다. 다만 일부 면과 모서리는 뭉개지거나 울퉁불퉁하고, 등판·개구부 내부와 파트 경계는 추가 정돈이 필요하다. 각파트의 raw boundary edge 수는 UV/부품 분리 경계를 포함하므로 이를 그대로 관통 구멍 개수로 해석하지 않는다. 실제 시안 충실도와 사용자 미적 승인은 별도이며 완료로 단정하지 않는다.
