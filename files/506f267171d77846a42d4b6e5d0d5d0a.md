# 인게임 우측 상단 조작 안내 버튼 제거

## 사용자 지시와 기획 의도

인게임 우측 상단에 상시 표시되는 `조작 안내 O` 버튼을 제거하여 시야를 정리한다. 입력 기능 자체를 삭제하라는 지시로 확대하지 않는다.

## 변경 전 상태

`SessionGlassView.DrawControlHelp()`가 기본 HUD에서 버튼을 그렸고, 세 곳의 공통 포인터/인벤토리 판정과 바닥 드롭 판정이 해당 사각형을 별도로 제외하고 있었다. 버튼 그림만 없애면 보이지 않는 클릭 차단 영역이 남는다.

## 변경 내용과 방식

- 기본 HUD에서 상시 조작 안내 버튼을 그리는 한 줄을 제거했다.
- 세션·공통 HUD·인벤토리 포인터 판정에서 숨겨진 버튼 영역을 제거했다.
- 인벤토리에서 실제 표시되지 않는 안내 버튼/패널 영역의 바닥 드롭 제외를 제거했다. 실제 인벤토리 헤더·아이템·외부 창·상세 창의 보호는 유지했다.
- O키로 여닫는 안내 패널과 I/K/Q 단축키, 로비 하단의 안내 버튼은 유지했다. 펼쳐진 안내 패널은 기존처럼 클릭을 차단한다.
- 기존 GlassLayoutChecks에 숨겨진 영역은 포인터를 막지 않고 펼쳐진 패널만 막는 검사를 추가했다. 이 추가 검사를 이번에 실행한 결과로 가장하지 않는다.
- 맵·캐릭터·기지·저장 로직 및 별도 동료 칩 작업은 수정하지 않았다.

## 전후 증빙

- `before_gameplay.png`: 소스 수정 전 원본 Unity의 실제 A맵 프리뷰 화면. 우측 상단 버튼이 보인다.
- `after_gameplay.png`: 반영·컴파일 후 원본 Unity의 실제 A맵 프리뷰 재실행 화면. 미니맵·작전 시간·하단 HUD는 남고 우측 상단 버튼은 없다.
- 동일 Editor 창, Game 뷰 배율/종횡비와 HUD 비율을 유지했다. 프리뷰 재시작에 따라 진입 방향/배경과 남은 시간·캐릭터 자세가 달라 완전히 동일한 월드 프레임은 아니다.
- 컴퓨터 조작 스킬로 실제 창을 캡처했다. 반환된 JPEG 원본은 `before_native.jpg` / `after_native.jpg`로 보존하고, 이미지 내용 편집 없이 PNG 형식으로만 변환했다.
- `source_before/`에 수정 전 5개 소스 파일을 보존했다.

## 확인 결과와 한계

- 제품 런타임/Editor assembly가 2026-10-19 11:17경(KST) 갱신되고, 재생을 다시 시작하여 제거된 버튼을 실제 화면에서 확인했다. 관련 소스에 C# 컴파일 오류는 확인되지 않았다.
- 변경 전후 소스 대조에서 런타임 4개 파일의 표시/입력 영역 변경과 Editor 검사 변경만 확인했다. 안내 키와 로비 버튼은 소스상 그대로다.
- 추가 회귀 검사 코드는 컴파일했으나 전체 GlassLayoutChecks 실행은 하지 않았다. O키의 실제 열기/닫기는 동시 UI 사용과 재컴파일로 신뢰할 만한 확인을 끝내지 못했으므로 실행 검증 완료로 표시하지 않는다.
- 같은 시간에 별도 `companion-chip-validation` Unity batch와 실행 창이 사용 중이었고, 공유 컴퓨터 조작 요청 충돌이 한 차례 있었다. 해당 별도 창·프로세스·파일은 종료/수정하지 않았다.
- Play 중 소스 재컴파일 이후 기존 세션 참조 유실에 따른 NullReferenceException/ArgumentNullException과 HUD 소실을 관찰했다. 재실행 직후 정상 HUD와 버튼 제거는 별도 캡처했지만, 전체 실행 무오류라고 주장하지 않는다. 이번 변경은 세션 재직렬화 문제를 함께 고치는 범위가 아니다.
- 원래 열려 있던 씬을 바꾸거나 저장하지 않았다. 검증을 위해 시작한 원본 Unity 재생은 종료해 편집 상태로 돌린다.
