## 원본 LOS의 실제 동작과 겹친 상자 처리 차이

L10986의 `hasLineOfSight`는 대상 또는 전역 `InteractionLineOfSight=false`면 통과한다. 기본값 true에서는 캐릭터 머리 위치(없으면 루트+Y2)에서 대상 기준점으로 Raycast한다. 캐릭터만 제외하고 물을 무시한다. 첫 충돌이 대상 자신/그 자손일 때만 통과한다.

```lua
parameters.FilterDescendantsInstances = character and { character } or {}
local result = workspace:Raycast(origin, targetPosition - origin, parameters)
if not result then return true end
return result.Instance == target or result.Instance:IsDescendantOf(target)
```

따라서 **다른 전리품 상자는 원본 LOS에서 명시적으로 제외되지 않는다.** 당시 “상자 2개+AK-47 드롭” 실기 성공 보고는 있지만, 모든 방향에서 다른 상자 물리 충돌이 통과됐다는 보장은 아니다. 그룹화가 전방 시야각을 제거한다고 해서 벽 LOS까지 없애는 구현도 원본과 다르다.

별도 후속 안정화(L12603)는 **홀드를 시작한 뒤** 순간적으로 흔들린 시야 판정을 거리·높이 조건으로 보완한 것이다. 최초 후보 수집에서 모든 벽·상자 LOS를 없앤다는 요구로 확대하지 않는다.

현재 구현에서 근처 전리품 Collider만 LOS에서 통과시키고 벽은 계속 차단한다면, 이는 **겹친 전리품에 대한 현재 문제를 해결하는 명시적인 보완**으로 기록해야 한다. 원본과 완전히 같은 LOS라고 표현하지 않는다. 검증은 적어도 (a) 겹친 상자 두 개·단일 바닥품 모두 선택/열기, (b) 그 뒤에 벽이 있을 때 반대편 전리품 차단, (c) 다른 층 차단을 구별해서 수행한다. 단순 LOS 재귀를 피하고, 통과 대상은 활성·가용하며 현재 거리/층 조건에 맞는 전리품으로 제한하는 편이 일관적이다.

## 현재 Unity와 비교한 적용 판단

비교 시점: 2026-10-22 기록 작성 중, 메인의 후속 Production 통합 전 읽기 결과.

- `C:\UnityProject\escape\Assets\Escape\Runtime\Loot\LootPromptSelection.cs`는 생존 항목 순서·선택 유지와 신규 뒤 추가, 선택 탈락 시 인덱스 보정, 휠 순환이 이미 같은 방향이다. 재작성할 이유가 없다.
- `LootInteractor.cs`의 `PromptRow`는 이미 42px 간격, 선택 높이 40/일반 34다. 별도 새 목록 패널을 만들면 최종 사용자 지시와 어긋난다.
- `DrawPromptStack`의 첫 상자 앵커는 기존 Roblox의 첫 대상 앵커와 같은 방향이다. 플레이어 앵커로 바꾸는 근거는 없다. Roblox는 목록 전체 중앙 정렬이었고 현재 Unity는 첫 앵커에서 아래로 쌓고 화면 경계로 clamp하며 최대 8행을 표시한다. 화면 안전영역·8행 창은 현재 구현의 보완이며 원본 수치로 주장하지 않는다.
- `CanOpen`의 전방 내적 0.9 제한은 Roblox 그룹 수집에 없다. 주변 그룹화의 핵심 차이이므로 제거를 검토하는 것이 타당하다.
- Unity는 플레이어 Y+1에서 상자 중심으로 `RaycastAll`하고 자신/대상 외 모든 Collider를 차단한다. 원본의 머리→InteractionPoint 단일 Raycast와 다르다. 위의 근처 전리품 예외는 별도 보완으로 검증한다.
- Unity의 목록 선택 왼쪽 원, F 키, 막대형 홀드 표시는 역할을 구별해 다룬다. 후속 22px 홀드 원을 선택 표시 원 전체에 일괄 적용하지 않는다. F 원형 진행 UI로 바꿀 때 과거 E 입력 자체와 혼동하지 않는다.
- 원본의 보간은 부드러운 반응이라는 사용자 의도를 뒷받침한다. 이미 같은 순서·행 크기를 갖춘 Unity 목록 전체를 다시 만들 필요는 없다.

이 문서는 참조 조사 기록이다. 이번 Unity 수정·테스트 완료의 증명은 상위 `CHANGE_RECORD.md`와 실제 전후 화면·검증 결과에서 별도로 확인한다.
