# A맵 경계 통과 시 밝기 급변 수정 — V25

작업일: 2026-09-24

## 사용자 지시와 기획 의도

사용자가 재보고한 특정 경계 통과 시 화면 전체가 갑자기 어두워지는 문제를 수정한다. 주변 조명·색감의 완만한 변화는 유지하되 순간적인 화면 처리 방식 전환은 제거한다. 기존 V24 중정비동 시야·벽 교차부 수정, V23 실내 재질과 사용자 에셋 배치·충돌·동선은 변경하지 않는다.

## 변경 전 상태 및 원인

- 실제 수정 전 Play 화면을 `before_current_unity.png`로 저장했다. 사용자 원본 두 장은 `user_report_bright.png`, `user_report_dark.png`로 보존했다.
- 수정 전 프로필·제작 코드·런타임 분위기 코드·씬·프리팹을 `backup/`에 복사했다. `BASELINE.txt`에는 Play 종료와 씬 미변경 상태를 기록했다.
- A맵 기본 톤매핑은 Neutral인데 공장 분위기 프로필은 ACES를 강제로 덮어썼다. 톤매핑 모드는 연속 보간되지 않는 enum이므로, 프로필 가중치가 0에서 조금만 양수가 되어도 즉시 ACES로 바뀌었다.
- 공장 분위기의 네 외곽 경계(x=±70, z=53/-96)에서 같은 카메라·캐릭터·장면을 고정하고 경계 양쪽 0.12m의 평가 위치를 전달해 증상을 재현했다. 내부 가중치가 겨우 0.00005496인 상태에서 이미 ACES로 바뀌었다.
- `before_VALIDATION.txt`의 `BASELINE_DEFECT` 8개는 의도적으로 기록한 수정 전 결함이다. 이 파일의 `RESULT PASS`는 재현 절차 완료를 뜻하며, 문제가 없었다는 뜻이 아니다.

## 실제 수정

1. `Assets/Escape/Art/LookV16/LookV16Volume.asset`: Tonemapping.mode override를 해제해 A맵 기본 톤매핑을 그대로 사용한다. 기존 숫자 값 2는 비활성 override이므로 렌더링에 적용되지 않는다.
2. `Assets/Escape/Editor/StageALookV16Lighting.cs`: 분위기 제작 기능을 다시 실행해도 ACES override가 켜지지 않도록 변경하고 원인 주석과 결과 설명을 갱신했다. 톤매핑 서브에셋에도 저장 대상 표시를 명시했다.

노출·대비·채도·Bloom 및 기존 28m 조명 보간 폭은 변경하지 않았다. 전체 구역을 ACES로 통일하거나 맵 전체 밝기를 강제로 올린 것은 아니다. 공장 내부도 기존 기본 톤매핑을 따르게 되므로 과거 ACES 적용 화면보다 밝게 보일 수 있다.

## 스크린샷 대응 관계

- 주요 동일 시점 전후 비교 12쌍: `before_{east,west,north,south}_{outside,inside,reverse_outside}.png` ↔ `after_{동일 이름}.png`. 각각 1600×1000, 같은 캐릭터 위치·카메라·회전·조명 조건. inside/outside에서 평가 위치만 달라진다. 게임 UI는 이 카메라 캡처에 포함되지 않는다.
- `walk_{east,west,north,south}_{outside,inside,reverse_outside}.png` 12장은 수정 후 실제 보행 보조 증빙이다. 카메라가 이동하므로 고정 카메라 전후 비교와 동일시하지 않는다.
- `before_current_unity.png`는 수정 전 실제 Unity 창 기록이다. 원본 사용자 화면은 별도 참고 자료이며 동일 시점 비교쌍으로 주장하지 않는다.
