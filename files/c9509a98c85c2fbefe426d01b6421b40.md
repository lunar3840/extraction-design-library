# 썸네일 조명 수정 독립 검토 — 2026-10-21

## 판정

검토한 소스와 Editor 실행 증빙에서 차단할 문제를 발견하지 못했다. 메인이 통합한 `WeaponModelThumbnails.cs`와 `WeaponThumbnailLifecycle.cs`는 검토한 staging 파일과 각각 SHA-256이 일치했다. Unity 컴파일과 실행은 메인이 수행했고, 이 검토에서는 해당 실행이 저장한 로그와 이미지를 독립적으로 읽었다. 검증 helper 제거 및 최종 컴파일 정리는 메인 소유다.

## 소스 검토

- 정리 API는 정적 `owner` 참조가 끊겨도 컴포넌트와 정확히 식별된 컴포넌트 없는 루트를 찾는다. 영구 에셋을 제외하고, 무효 씬 또는 전용 `Weapon thumbnail studio` 씬의 `Weapon thumbnails — render only` 루트만 대상으로 한다. 컴포넌트 없는 루트는 전용 카메라 1개와 이름이 확인된 두 광원까지 검증한다.
- Editor에서는 대상 GameObject를 즉시 비활성화·파괴하고, 전용 씬만 닫거나 언로드한다. 에디터 수명 hook은 Play 진입·종료, 편집 모드 재진입, 어셈블리 재로드 전, Editor 종료 및 재로드 후에 API를 호출한다.
- 두 썸네일 광원은 평소 비활성이고 썸네일 카메라 렌더 중에만 켜진다. 다른 카메라가 중첩 렌더되면 해당 카메라의 시작·끝 사이에는 꺼진다. 예외가 발생해도 `finally`에서 다시 꺼진다.

## 실행 증빙 확인

- `before_validation.txt`: 실제 게임 카메라의 outdoor, hall 1F, hall 2F 각각 네이티브 썸네일 광원 34개. 인벤토리에서 AR_001 라이브 썸네일 768×323, 표시 픽셀 73,366개. `before_returned.txt`: Play 종료 후 34개가 남아 있음.
- `after_validation.txt`, `repeat2_validation.txt`, `repeat3_validation.txt`: 세 실행 모두 세 시점의 네이티브 썸네일 광원 0개, 보유 스튜디오 광원 2개는 렌더 사이 비활성. 인벤토리 열기·닫기 후에도 활성/네이티브 광원 0개. AR_001 썸네일은 세 실행 모두 768×323, 표시 픽셀 73,366개이며 세 PNG의 SHA-256이 서로 일치한다. 각 로그는 `RESULT PASS`다.
- `after_returned.txt`, `repeat2_returned.txt`, `repeat3_returned.txt`: 매번 Play=false, 원래 A맵 씬 dirty=false, 썸네일 광원 0개. 세 실행의 플레이어·카메라 위치, 회전, FOV, 태양 강도와 노출 수치가 대응 시점마다 동일하다.
- `before_outdoor.png`↔`after_outdoor.png`, `before_hall_1f.png`↔`after_hall_1f.png`, `before_hall_2f.png`↔`after_hall_2f.png`를 직접 보았다. 과노출로 사라졌던 건물·바닥·창문 질감이 후 사진에서 보인다. `IMAGE_STATS.csv`는 hall 2F 평균 밝기 170.124→62.048/255, repeat2 62.049/255를 기록한다. `after_weapon_thumbnail.png`는 과노출 전 아이콘보다 어두워졌지만 무기 형태는 식별되며, 세 수정 후 실행에서 동일하다.
- `PROTECTED_BEFORE.csv`의 SHA-256과 현재 파일을 직접 다시 계산해 대조했다. A맵 씬, A맵 프리팹, PlayerDefaults, QualitySettings, GraphicsSettings, LookV16Volume 여섯 대상 모두 일치했다. `PROTECTED_AFTER.json`도 여섯 대상 전부 `Unchanged: true`다.

## 검증 범위

라이브 무기 아이콘은 AR_001 한 종류를 표본으로 확인했다. 다른 무기 전체와 standalone 빌드는 실행하지 않았다. 이 검토는 Editor의 실제 Play 3회 및 저장된 게임 카메라/인벤토리 증빙에 한정한다.
