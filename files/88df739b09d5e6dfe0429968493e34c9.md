## 시계 정책

`fixedFrameReady=false`인 최초 렌더 프레임은 `Animator.Update(0)`을 호출한다. 고정 프레임이 생긴 뒤 실제 인벤토리가 열린 동안, 현재 `Time.unscaledDeltaTime`이 유한·비음수이며 **0.5초 이하**이면 그 값을 그대로 전달하고, 0.5초 초과 단일 공백은 0.1초만 전달한다. 비유한/음수 값은 0으로 닫는다. 따라서 통상 100–180ms 지연 프레임에서도 기본 Idle 클립의 시간이 버려지지 않는다. 로비/타이틀에서 `InventoryOpen=false`이면 원래 `Mathf.Min(rawUiDelta,0.1f)` 규칙을 유지한다. Idle 절차 시계의 visible inventory 경로도 같은 원시 delta/0.5초 기준을 쓴다. 서로 다른 `LateUpdate`의 진단값을 참조하지 않아 실행 순서 의존성을 만들지 않는다.

수동 Animator의 속도는 Update 직전 1로 설정되고 `finally`에 0으로 복원된다. 이후 고정 사격 자세, 발/골반 고정, 표현식, 턴테이블, Hair Step은 기존 순서를 따른다. Editor 전용 `LastPreviewAnimatorUpdateDeltaSeconds`는 실제 전달한 delta를 기록하고 매 LateUpdate 시작, `Show(false)`, `Rebuild`, `OnDisable`에서 0으로 초기화한다. `OnDestroy`는 별도 초기화를 하지 않지만 해당 객체가 소멸해 진단 getter가 더 이상 유효하지 않다. 다른 actor로 `Show(newActor,true)`를 호출한 직후 첫 LateUpdate 전까지는 이전 actor의 진단값이 잠시 남을 수 있으나, 다음 LateUpdate에서 0으로 갱신되고 실행 경로에는 영향을 주지 않는다.
