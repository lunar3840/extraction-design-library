## 실제 결함과 조치

1. 여러 작은 버튼/캡슐의 둥근 면 양끝에 직선·코너 겹침이 보였다. 메인이 확인한9-slice border 합계가 버튼 높이를 초과하는 문제와 일치한다. `UiTheme`의 Surface border와 compact 버튼/InventoryButton 재질 교정은 메인이 소유해 처리했다. 이 담당자가 해당 파일을 수정하지 않았다.
2. 무기 개조 요약/긴 안내 사이의 clipping·간격 문제는 before보다 after에서 드러났다. 공통 InventoryCaption이11에서12로 커진 상태에서 이 글은2줄→3줄로 늘어났으나 무여백 MedicalCaption을 사용했다. 메인의 후속 승인으로 `InventoryWeaponModding.cs` **한 파일**만 추가 백업 후 수정했다. 해당2 caption에 UpperLeft·상하 padding/margin을 가진 전용 스타일을 사용하고, 현재 detail 폭/scrollbar를 반영한 CalcHeight 기반 최소 높이와 grid 앞4px 여백을 확보했다. 문구·수치·거래/장착/드래그 callback은 바꾸지 않았다. 전체 런타임 정적 재컴파일 오류0, 기존 경고21. 최종 실제 after 재확인이 필요하다.

## 추가 개선 제안 — 동작 결함으로 판정하지 않은 것

- 비어 있는 무기2와 퀵5는 바탕이 매우 옅어 숫자/‘비어 있음’이 주로 보인다. 빈 슬롯에도 약한 공통 테두리를 유지하면3개 소모품 구조를 더 빨리 읽을 수 있다. 기존 클릭 실패를 관찰한 것은 아니며 실제 input 검사는 메인이 소유한다.
- 작은60 logical 아이템에서 V배지와 묶음 수량이 가깝고 긴 이름은 줄임표가 생긴다. 기존에도 있던 작은 슬롯의 제약이며 이번 카드에는 큰 hover로 보완하는 구조다. 티어 badge·수량 좌우 padding을 추가로 분리할 수 있다.
- HP/스태미너 bar는 현재 top-down 캐릭터보다 넓다. 머리 위 위치 자체는 의도에 맞고 화면 가독성도 확보됐다. 최종 bar 길이는 실제 전투 밀도에 맞춰 후속 튜닝할 수 있다.

## 검증 한계

- 요청된7장에는 hover 카드가 없다. 클릭 상세와 이전 hover 검사를 혼동하지 않는다. 새 폰트/공통 테마가 반영된 실제 hover를 주장하려면 별도 마우스 hover 캡처가 필요하다.
- 물/에너지가100인 화면이므로 부분 fill의 실제 모양은 이 이미지들로 검증하지 않았다. bottom-up Rect/clamp 및112px 크기는 외부118항목 좌표 검사로만 검증됐다.
- 스크린샷만으로 클릭/drag callback 실행 통과를 주장하지 않는다. 표시와 hit는 같은 geometry를 사용함을 코드에서 확인했으나 동작은 별도 실제 입력 검증이 필요하다.
- 전투 before/after는1920×1080과 같은 fixture이지만 캐릭터/카메라 투영 위치가 다르다. 고정 HUD 좌표는 비교 가능하나 동일 조명·배경 픽셀을 유지한 색 대비 측정으로 취급하지 않는다.

최종 after가 도착하면 공통 코너와 개조 안내 재검토 결과를 추가한다.

## 최종 after_r02 재검토

`after_r02_inventory_1920x1080.png`, `after_r02_weapon_modding_1920x1080.png`, `after_r02_combat_hud_1920x1080.png`를 각각 다시 직접 열어 확인했다.

- **개조 caption 문제 해결:** 요약과3줄 드래그 안내가 분리되어 읽히고 부품 grid 앞에도 여백이 생겼다. 안내 첫 줄이 잘리거나 요약과 겹치던 상태가 사라졌다. 긴 설명 때문에 아래 컨텐츠가 내려간 부분은 기존 scrollbar로 접근하는 구조다.
- **일반 작은 control 코너 문제 해결:** 정렬/신체 상태/닫기, 개조 접기·장착 여부 버튼의 코너/수평선 겹침이 사라졌다. 인벤토리 큰 면의 라운드/반투명·단차는 유지된다.
- 캐릭터 모자와 부츠, 장비와의 간격 및 HP/스태미너 머리 위 표시가 유지된다. 큰 물·에너지 아이콘, 하단 중앙 무기와 오른쪽3퀵슬롯 및 E/X도 정상 배치다.
- **잔여 작은 시각 문제:** 인벤토리 우상단 ‘블랭크5,000’ 상자에는 좌우의 얇은 직각 bracket 형태가 남아 있다. 이 면은 compact control이 아니라 높이32 rect에 `InventoryBox`/InventoryPanel26 border를 사용하기 때문이다. 메인에 알렸으며 `UiTheme.Pill`로 변경하면 해결 가능한 presentation 문제다. 이 담당자가 임의 수정하지 않았다.
- 실제 hover/부분 fill 및 물리입력 검증은 이3장에도 없으므로 해당 통과를 추가하지 않는다. 메인이 이어서 별도 검증한다.

메인의 마지막 textField radius10 추가는 이 담당자의 이전 정적 compile 이후 변경이다. 새로운 실제 Unity runtime/Editor DLL과 최종 source_after는 메인이 관리하며, 이전 compile 결과의 SHA와 새 소스를 동일 버전으로 표현하지 않는다.
