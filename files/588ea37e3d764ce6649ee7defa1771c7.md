## 동일 입력 A/B 원자료 재집계

`paired_results.json`의 순서는 reference/optimized/optimized/reference/reference/optimized/oracle이고, 매 회차 fresh Bind 뒤 같은 80 source pose를 사용했다. 기준 첫 회차와 나머지 여섯 회차의 각 행을 다시 비교한 **480쌍 모두** full digest와 body queries/triangle tests/witnesses/unverified 작업 카운터가 동일했다. 회차당 80행을 포함한 560행의 일치다. reference의 cache reads는 0, optimized의 각 회차 reads는 2,189,025다. oracle 회차에서 reads=checks **2,189,025**, mismatch=0이다. Hair가 원본이므로 Hair skin oracle 수치는 0이 정상이다.

처음 10자세를 각 회차에서 제외하고, reference 3×70행과 optimized 3×70행의 원시 `wallMs`를 직접 평균했다. reference **58.68247ms**, optimized **56.88107ms**로 차이는 **1.80140ms, 3.06975%**다. 이는 `Step` 호출 전체를 바깥 Stopwatch로 잰 CPU 시간이다. 같은 행의 `CurrentRootBudgetRefreshMs` 평균은 12.88366→11.06576ms, 차이 1.81791ms다. 내부 Hair Step 타이머는 BeginFrame을 제외하므로 이 값들을 서로 합산하지 않는다. oracle은 원래 수식을 다시 계산하므로 시간 평균에서 제외했다.

이 결과는 같은 Play 안의 source pose replay 80개를 연속 Step한 **CurrentSource 포함 CPU 경로**의 개선이다. source pose는 이동·조준·발사·재장전이 있는 플레이에서 채취됐지만 80 Step 연속 replay는 실제 프레임 간 간격, GPU, 렌더, AI·날씨 전체 부하 및 빌드 환경을 재현하지 않는다. cache 첫 할당과 Bind 비용은 warm10 이후 평균에 포함되지 않는다. CurrentSource cache의 추가 저장량은 `48 × Σ skinned part.ids.Length` 바이트와 배열 헤더다.

리브·유이의 별도 6자세 Current-only 회귀 원자료도 각각 3회×6행에서 digest와 작업 카운터 불일치0, Current oracle reads=checks 281,470/278,865, mismatch0이었다. 짧은 회귀이므로 이들의 시간 차이를 대표 성능 수치로 사용하지 않는다. 세린 6자세는 **Hair V1+Current V2가 함께 있던 이전 후보**의 자료다. digest/카운터와 oracle mismatch0은 참고하되 최종 Hair 복원 조합의 성능·시각 회귀로 제시하지 않는다.

## 실제 Play와 외형 증거의 한계

`before_results.json`과 `fixed_results.json`은 각각 240행, 12발, 재장전 수락3회다. live frame 평균은 77.72063→73.75156ms, Main 평균은 77.71263→73.74234ms로 관찰됐으나, 검사량이 같지 않다. body queries 331,885→325,846, triangles 70,742→64,688, witnesses 2,671→2,567이며 Hair 내부 Step 평균은 44.01333→44.07270ms이다. 따라서 live 평균 변화 전체나 사용자 체감 렉 해소를 cache 효과로 귀속하지 않는다. Render recorder는 invalid이고 GPU·빌드 FPS는 미측정이다. 최적화 후에도 동일 입력 Step 평균 56.88ms 자체가 무겁고, Hair solver 및 기타 Main Thread 부하의 잔여 위험이 있다.

고정 자세 `before_results.json`과 `fixed_results.json`의 geometry digest 20개를 직접 배열 비교해 20/20 exact임을 확인했다. 이 digest에는 skinned 정점, 본 TRS, 표정, 일부 probe/witness 정보가 포함된다. 모든 개별 witness depth/valid, 모든 budget bound, 얼굴 보호 정책과 검지 가중치 자체를 별도 수치로 검사한 것은 아니다. `before_frozen.png`/`fixed_frozen.png`, `before_movement.png`/`fixed_movement.png`는 같은 구도의 게임 화면으로 보이고, frozen PNG는 파일 헤더 기준 1600×1000이다. 캐릭터·녹색 연기가 모두 남아 있다. 연기는 입자 시점 때문에 픽셀 형태가 다르며, 원거리 전경 사진만으로 헬멧 아래 머리, 얼굴, 검지, 목 접촉을 상세 판정할 수 없다.

## 연기 오류 수정

`verify_smoke_prefab.py`가 원본과 staged prefab 2,924,729행을 streaming 비교했다. 정확히 연기 ParticleSystem 22개의 y/z VelocityModule 44축에서 264행만 바뀌고 다른 prefab 행은 byte 동일이었다. 기존 min/max 값에 해당하는 평평한 TwoCurves이므로 수명 0→1의 속도 범위 함수는 동일하다. 개별 입자 난수 소비·궤적의 bitwise 동일성을 보증하지 않는다. 자세한 정적 판정은 `SMOKE_STAGE_REVIEW.md`에 있다.

최종 `fixed_smoke_validation.txt`는 live 22개 시스템의 xyz 모드가 모두 TwoCurves, runtime legacy repair 0, max velocity function error 0, live particle errors 0, sample pairs 5,324라고 기록한다. `SMOKE_LOG_WINDOW_START.json` offset 34,873,667부터 `SMOKE_LOG_WINDOW_RESULT.json` offset 34,905,303까지의 **asset import 이후 fresh Play 입장→360프레임→퇴장→Edit scene 복원** 창에서 신규 Particle Velocity 오류0 및 compiler 오류0이다. 이 창의 성공은 확인되지만 다른 lifecycle·씬·빌드의 오류0을 보증하거나 이전 누적 Editor.log 오류 수가 지워졌다는 의미는 아니다. 연기 수정 자체의 FPS 개선도 분리 입증되지 않았다.

## 최종 판정

최종 CurrentSource 단일 cache 채택은 같은 입력의 정점·본·관찰된 충돌 결과/작업량 동일성 및 약 3.07% Step CPU 감소라는 근거가 있다. Hair cache 반려는 matched 자료에서 Hair 내부 시간이 개선되지 않았던 판단과 부합한다. 연기 직렬화 수정은 변경 범위가 좁고 최종 lifecycle에서 해당 경고가 재발하지 않았다. 남은 검증 범위는 실제 플레이 전반의 프레임·GPU와 근접 외형, 다양한 캐릭터·표정·의상·장기 실행 및 cache 첫 Bind/메모리 영향이다.
