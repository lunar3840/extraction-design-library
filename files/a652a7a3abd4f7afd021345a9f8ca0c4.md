## 호출 경로별 판단

1. **매 프레임 공통 머리카락 충돌: 실측된 CPU 부담.** 라이브는 `SdHairCollisionMotion.cs:471-487`의 `Update` 복원과 `LateUpdate`의 `Step`을 실행한다. `Step`은 몸 표면 갱신, 무기 장애물 갱신, 연결과 메시 표면 계산을 잇는다(`:489-545`). `StepSurface`는 본 행렬, 표정 반영, 고정/선택 정점 스키닝, 충돌 해결, 역스키닝을 수행한다(`:612-637`). `RestoreBeforePose`와 `StepSurface`가 각각 `owned.vertices`에 전체 정점 배열을 넘긴다(`:474`, `:637`). 선택 정점만 바뀌더라도 전체 메시 버퍼가 Unity로 전달되는 비용 후보이며, 정확한 native/GPU 업로드 비용은 측정하지 않았다. `AssignMesh`는 메시가 이미 맞아도 `skin.bones`를 매번 재지정한다(`:614`, `:1327-1336`). 초상화에서 본 목록 복구를 위해 의도된 코드라 제거 전 실제 비용 및 미러 동작 확인이 필요하다.

2. **에델 braid 연결 접촉: 에델 live Step 안의 큰 부분.** `SolveBraidSurface`는 접촉 시 여러 후보의 본 회전과 실제 피부 표면 점수를 반복 평가한다(`SdHairCollisionMotion.cs:965-1026`). 점수마다 본 행렬을 갱신하고 최대 96개 probe의 몸/무기 접촉을 확인한다(`:896-911`). 10월 26일 에델 live 마지막 프레임은 braid 23.633ms, 내부 Populate 4.450ms, Adaptive 9.406ms였으며 이는 **해당 프레임의 하위 타이머**다. 실제 관통 시 탐색 횟수와 비용이 달라지는 경로다. 옛 측정 `work/hair-collision-20261024/RESUME_20261025_ACTIVE.md`는 Populate/Adaptive가 과거 주비용이었다고 기록하지만 현행 후보12의 숫자를 대신하지 않는다.

3. **인벤토리 초상화: live와 별도 Step.** `InventoryPortrait.cs:374-376,506-511`은 초상화가 요청된 동안 독립 `previewHair.Step`을 실행한다. 라이브 캐릭터의 Step을 대체하지 않으므로 인벤토리 표시 때 두 인스턴스의 CPU 비용과 복제 렌더링 비용이 같은 프레임에 생길 수 있다. 다만 live·portrait 각각의 누적 평균을 단순 합쳐 실제 프레임 시간을 주장하지 않는다. `InventoryPortrait.cs:380-384`의 매 프레임 계층 열거도 추가 CPU 후보이나 자료에 해당 타이머는 없다.

## 품질 손실을 최소화하는 확인·최적화 순서

1. **측정 분리.** 같은 씬·화면 크기·캐릭터·무기·대기/Curious·인벤토리 닫힘/열림에서 Unity Profiler의 Main Thread, Render Thread, GC Alloc, GPU, SkinnedMeshRenderer 및 현재 `LastStepMilliseconds` 하위 타이머를 함께 기록한다. 현재 원시 타이머는 이미 머리카락 CPU 비용을 보여 주므로, 새 프로파일링은 원인 확인과 전후 비교에 집중한다.
2. **결과 동일성 유지형 중복 계산 개선.** `SolveBraidSurface`의 동일 입력 접촉 질의/후보 재평가와 `RefreshBraidSkin`의 본 행렬·선택/고정 정점 갱신(`SdHairCollisionMotion.cs:867-895`)에서 실제 반복을 계수하고, 동일 입력·동일 출력임을 확인한 부분만 캐시한다. 과거 적응형 캐시는 실제 재사용 0회여서 제외되었다(`CHANGE_RECORD.md:159-161`); 캐시가 이득이라는 가정은 금지한다. subphase 타이머가 중첩되므로 독립 exclusive 시간으로 해석하지 않는다.
3. **native 전달 비용 검증 후 메시 갱신 정리.** `owned.vertices` 두 번과 `skin.bones` 매 프레임 setter의 Profiler 비용이 유의하면, 한 프레임 최종 표시와 초상화 미러의 원본/소유 본 복원을 보존하면서 호출을 줄인다. 소스 mesh·표정·UV·실제 접촉 판정은 그대로 비교하고, 실제 게임 화면의 전후/다각도 및 관통 증빙으로 회귀 검증한다.
4. **렌더 후보 확인.** 13개 renderer의 offscreen 스키닝과 재질/텍스처 비용은 GPU 계측으로 순위를 정한다. 화면에 보이는 헤어·헬멧 아래 원래 머리색과 내부/외부 관통 검사 없이 단순 비활성화·축소하지 않는다.

충돌 검사 빈도 감소, witness/프록시/정점의 임의 생략, 허용 관통 기준 완화는 최신 머리카락 회차가 아직 모든 전환 프레임에서 완료 판정이 아니므로 우선안이 아니다. 프레임 전체 FPS와 최신 체감 렉의 인과 관계는 미측정 상태로 남긴다.
