# v0.2 실배치 기준
사용자의 '실제 Unity/Blender에서 구현 가능한 구조' 요청을 반영한 마스터 치수. 아래 수치는 개념 이미지의 도형보다 우선한다.

## 좌표
지리 도면 (x,y): x동쪽0~520, y남쪽0~400.
Unity (X,Y,Z): (x-260, 높이, 200-y). 북쪽은 +Z. 1 Unity unit=1m.
블록아웃 원점은 지도 중앙, 지상 보행면Y=0, 지하 보행면Y=-6.
기존 게임 확인 기준: 플레이어 CharacterController와 인간 적 NavMeshAgent는 반지름0.4m/높이2m다. 기존 EnemyTestWorld의 agentClimb은0.25m다. 인간 보행 검사는 이 치수를 기준으로 삼으며 대형 기계의 이동 가능성까지 대표하지 않는다.
Blender로 가져갈 경우 Unity 좌표를 Blender의 Z-up 축으로 변환하여 배치하며 파일 importer의 축 설정을 확인한다.

## 주요 구조물과 도로
| 요소 | 도면 중심 | 크기/높이 |
|---|---|---|
| L1 기록진료원 | (55,110) | 44×32m, 2층, 층고3.6m |
| L2 중계관제소 | (390,125) | 40×30m, 2층, 층고3.6m |
| L3 화물정비고 | (380,240) | 48×32m, 1층 내부높이5m, 정비피트깊이2.4m |
| 기계 이동 주도로 | layout_graph.json 연결 | 폭12m |
| 보행 우회로 | 지상 서비스 경로 | 폭6m |
| 짧은 보행 통로 | 건물 내부/측면 | 유효폭3m 이상 |
| 사람 출입문 | 각 건물3개 이상 | 유효폭2.4m 이상 |
| 사람 계단 | 실내/비상계단 | 유효폭2.4m, 단높이0.18m, 디딤폭0.30m |
단 높이3.6m는20단. 시각계단과 일치하는 매끈한 경사 충돌체를 사용할 수 있다. 계단 상단은 실제 바닥 구멍과 이어져야 한다.
기계 통과 주도로폭은 초안이며 대형기계 폭·회전반경을 확정한 뒤 재검증한다. 사람용 문을 대형기계도 통과한다고 가정하지 않는다.
L1/L3를 초기 좌표에서 서쪽으로 옮겨 주도로와 건물 footprint 충돌을 제거했다. NW/NE/E 노드는 건물 중심이 아닌 외부 교차점이다.

## 수로와 교량
수로는 x340~510, y280~300의 한 구간으로 제한한다. 수면/바닥은 보행면보다 낮게 하고 물길 자체는 일반 보행 NavMesh에서 제외한다.
교량 중심 x402 및490, y290. x402 주교량은 폭28m, x490 보조교량은 폭16m, 모두 남북길이30m로 물길20m와 양끝 접속을 덮는다. 대각선 E-SE 도로가 수로를 지나는 동안 중심x408→395로 이동하므로 주교량 폭16m는 도로 가장자리를 충분히 덮지 못해28m로 넓혔다. 교량 유효폭 안을 난간이나 기둥으로 막지 않는다.
중앙을 거대한 운하/수역으로 잘라 필수교량 한 개에 모이지 않게 한다. 남부 S-SE와 북부 NE-E 우회연결을 유지한다.
실제 지오메트리의 수로/교량/도로 높이와 충돌체를 우선하며 도면의 장식 수면은 구현 지침으로 사용하지 않는다.

## 지하 경사로
| 입구 | 지상 시작 (x,y,Y=0) | 지하 도착 (x,y,Y=-6) |
|---|---|---|
| U1 남서 | (130,275) | (130,315) |
| U2 남부 | (245,280) | (245,320) |
| U3 동남 | (350,350) | (390,350) |
| U4 동부 | (475,235) | (475,275) |
경사로 수평길이40m, 고저차6m, 경사각약8.5도. 통로폭6m, 머리 여유3.2m 이상. 사다리/점프 신기능을 전제로 하지 않는다.
지상 지형에는 해당 경사로 자리에 실제 구멍을 낸다. 평지 지면을 경사로 위에 덮어놓지 않는다.
U1은 초기 x95에서 x130으로 옮기고 U1/U2 모두 10m 북상했다. 초기 위치가 SW-C1 대각 주도로 및 남부 도로를 일부 침범했기 때문이다. 최종 경사로 구멍과 폭12m 도로의 보수적 사각 경계 검사에서 간섭이 없음을 확인했다.
지하 도착4곳은 U1-U2-U3-U4로 연결한다. 굴곡 교차점에서 바닥·벽·천장·충돌체가 이어지는지 확인한다.
P08에서 E로 접근하는 경로는 U4 경사로 위를 무심코 가로지르지 않도록 동쪽 서비스로를 이용한다. P07에서 SE로 접근할 때도 U3 경사로 구멍을 피해 서쪽으로 돌아가도록 연결한다.
이 경로는 P08→(505,225)→E, P07→(335,380)→(335,325)→SE를 기준으로 검토한다. 넓은 평지에서 경사로를 옆으로 돌아갈 수 있더라도 도면과 경로 표시를 일치시킨다.

## 플레이어/적 배치 데이터
P/E 좌표와 등급은 layout_graph.json을 기준으로 한다. P03는 C1뿐 아니라 W에 접근하는 대체길을 갖는다.
적 보스·인간 패턴은 이름있는 빈 Transform과 범위/웨이포인트 데이터로 표시한다. 인간 무리는 H1 SW-W-NW-N, H2 NE-E-SE, H3 S-C1-C2-E 범위의 분기형 수색망을 갖고 각 관련 랜드마크로 수색 가지가 있다.
인간 적의 탈출/맵 이탈 데이터는 만들지 않는다. E 표식은 플레이어 전용이다.
무장별 스폰풀은 Tier0 P01~04, Tier1 P01~08, Tier2 P01~12다. 이 자료는 위치·규칙 제안이며 기존 세이브/가격계산/실제 AI를 수정하지 않는다.

## 검증과 제공 형태
독립 Unity6000.1.0f1 프로젝트에서 생성한 .unity 씬, 가져오기 패키지, 생성기 및 배치 데이터를 제공한다.
NavMesh 검사는 P→실내 진입, 계단→2층, 지하입구→지하입구를 실제 지오메트리로 확인한다.
이는 걷기 가능성 검사다. 총격/시야/엄폐 효율/루팅속도/보스 회전반경/부상 원정의 게임성 시험과 구분한다.
