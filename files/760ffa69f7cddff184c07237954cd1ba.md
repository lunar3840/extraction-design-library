## 최초 제작안의 메시 변경 — 후보 01 중간 시도

이 절은 후보 01에 사용된 최초 제작안의 이력이다. 아래의 다각형 구멍·벽 상단 설명과 최초 검증 수치는 최종 외형 승인 결과가 아니며, 실제 화면 검토에서 반려된 뒤 후반의 **revision 02** 절에 적은 방식으로 재작업했다. 과거 수치는 당시 중간 시도를 추적하기 위해 보존한다.

생활 폐허 11동 `S01`–`S10`, `S12`:

- 기존 문/창을 가진 `Shell_Ruin_ExposedBrick_*` 낮은 벽은 그대로 두고, `Shell_Ruin_BrokenDomesticWall_F/B/R/L` 상부만 0.45m 두께의 닫힌 파손 벽으로 교체한다. 7개 직사각 블록 대신 큰 붕괴 어깨와 벽돌 줄눈 규모의 사선/단차를 조합했다.
- 회반죽 표피가 벽돌 코어보다 불규칙하게 낮게 끝나 실제 붉은 단면과 박락 두께가 보인다. 선택된 줄눈에는 얕은 물리적 요철을 넣었다.
- 건물별로 서로 다른 좌우 지붕 전단 경계 9개 지점과 1–2개 국소 다각형 붕괴를 저작했다. 같은 긴 결손 띠를 복제하지 않았다.
- 잔존 지붕은 0.16m 닫힌 기와 데크, 두 면으로 완만하게 굽은 겹기와, 깨진 기와 끝단, 목재 서까래/도리/벽체에 연결된 트러스로 구성한다. 서까래 일부 끝은 비스듬히 갈라진 닫힌 단면이다.
- 지붕 아래 후면·측면 벽은 한 연속 `Facade` 석조 벽으로 만든다. 기존 별도 `Roof` 벽돌 받침띠는 **3개 실제 목재 벽받침**으로 교체하여 동일 평면의 중첩 벽돌 면을 없앴다.
- 후면 박공은 연속 벽에 받치고, 붕괴 전면에는 측벽에 접속된 짧은 박공 어깨만 남긴다.
- D09의 `ww` 변수가 S02/S06 쇼윈도 폭으로 재사용되어 후면 지붕 폭도 좁아지는 문제를 확인했다. D10은 쇼윈도와 독립적으로 **실측 전체 폭**을 사용하여 측벽/서까래/지붕이 연결된다.
- `DomesticWindow`, S02/S06 `Storefront`, 남은 발코니/상점 표지는 유지한다. 새 주요 지붕 이름은 `SurvivingGable`, 목재 이름은 `Rafter` 토큰을 유지한다.

곡면 차고 5동 `W08`, `S11`, `Y01`, `Y02`, `Y05`:

- 동일 격자 직사각 구멍 대신 건물별 국소 비대칭 판금 찢김을 낸 0.15m 닫힌 곡면 지붕으로 교체한다.

- 곡선 구조 리브는 지붕 아래에 연속 배치하고, 판금 접힌 선은 실제 구멍 경계에서 끊긴다. 일부 찢긴 가장자리만 지붕에 뿌리를 둔 접힘으로 들어 올렸다.

## 패치 계약·실행

정확한 D09 대상 이름:

`D09_<category>Part_<old part.name>`

출력 JSON:

```json
{
  "schemaVersion": 1,
  "coordinateSystem": "Unity local X right,Y up,Z forward; metres",
  "materialKeys": ["13 existing D09 keys"],
  "baselineSource": "absolute D09 JSON path",
  "baselineSHA256": "source hash",
  "buildings": [{
    "id": "S07",
    "replacements": [{
      "targetName": "D09_FacadePart_Shell_Ruin_BrokenDomesticWall_F",
      "part": {
        "name": "FracturedDomesticWall_F",
        "category": "Facade",
        "collider": true,
        "vertices": [{"x": 0, "y": 0, "z": 0}],
        "uv": [{"x": 0, "y": 0}],
        "materialIds": ["BrickRed"],
        "submeshes": [{"indices": [0, 1, 2]}]
      }
    }],
    "additions": ["same Part schema"],
    "design": {"kind": "domestic_ruin", "profileSignature": []}
  }],
  "validation": {}
}
```

위 JSON은 형식 예시이며 단독 실행 메시가 아니다. 실제 모든 표면은 삼각형 인덱스와 정점당 UV를 내보낸다.

실행 예:

```text
Blender --background --python <D10>/blender/build_fractures.py -- --out <D10>/blender/fractures_v01 --render
```

`--only S07,S11`로 대표만 미리 볼 수 있다. `--json-only`는 JSON만 저장하며, `--validate-only`는 파일 생성 없이 순수 기하 검증만 한다. `--survey`, `--source`는 D09 원본 경로를 기본으로 사용한다. `--materials`로 기존 재질 .blend를 선택할 수 있다.

출력: `D10_FRACTURES.json`, `FRACTURE_VALIDATION.json`, `D10_Fractures.blend`, `--render` 사용 시 `blender_<ID>_threequarter.png`. D09 미리보기 helper가 출력 폴더 안에 `D09_Architecture.blend`라는 중간 저장도 남기지만 원본 D09 파일을 덮어쓰지 않는다.

Unity 통합은 정확히 일치하는 기존 D09 메시만 교체하고, 새 부품을 해당 건물의 기존 `D09_Facade_<ID>` / `D09_Roof_<ID>` 아래에 넣어 컷어웨이를 상속한다. 메인은 독립 지붕 검사 결과에 따라 기존 메시를 지붕 아래에서 단순 비활성 보존하는 대신 **장면/프리팹 백업과 원본 JSON을 확보한 후 정확한 교체 대상만 제거**하는 방식을 선택했다. 이는 메인 통합 범위이며 제작 에이전트가 Unity에서 실행하지 않았다.

## 후보 01 반려 → revision 02 재작업 및 최신 생성 결과

2026-10-14 메인의 실제 화면 검토에서 후보 01을 반려했다. 제작 에이전트도 `unity_attempt_01_S07_front.png`, `unity_attempt_01_S02.png`, `unity_attempt_01_S11.png`, `unity_attempt_01_Y01.png`를 직접 읽었다. 벽 상단의 연속된 붉은 띠가 부서진 석조보다 물결 모양 벽돌 장식/두겁으로 보였고, 기와 지붕 구멍은 가장자리가 반듯한 볼록 다각형 절삭처럼 보였다. 차고 구멍도 판금 패널이 벗겨진 모습과 구별이 부족했다. 배경 지붕 아랫면의 수평 점무늬는 표면 겹침 가능성이 있어 수정 대상으로 삼았다. 기술 검증에서는 Y01의 실제 새 리브 이름에 `ExposedRib` 토큰이 없어 호환성 실패가 확인됐다.

revision 02에서 바꾼 실제 형상과 표현:

- **각진 벽돌 줄눈형 윤곽:** 연속적인 완만한 높이 곡선을 없애고, 건물별 큰 잔존 벽 덩어리와 벽돌 한 줄 또는 개별 벽돌이 빠진 계단형 윤곽으로 바꿨다. 단순히 다수의 닫힌 기둥을 붙이지 않고, 오목한 전체 벽 실루엣을 ear clipping으로 삼각분할해 하나의 닫힌 0.45m 석조 벽으로 만든다. 내부 기둥 사이의 중복 평면도 제거했다.
- **모르타르 코어·국소 박락:** 파단 상단과 노출 단차 끝을 회색 `ConcreteLight` 모르타르 코어로 표현했다. 회반죽은 대부분 벽 꼭대기까지 남기고, 열린 면의 두 군집에 벽돌 노출과 두꺼운 불규칙 회반죽 가장자리를 집중시켰다. 일부에는 벽 본체에 연결된 비스듬히 깨진 개별 벽돌을 넣었다. 내측 벽면은 `PlasterIvory`로 지정해 실내 쪽 연속 붉은 벽돌 띠도 제거했다.
- **기와 코스 결손:** 볼록 다각형은 붕괴 위치를 고르는 범위로만 사용한다. 실제 지붕 경계는 약 0.48m × 0.44m 단위의 기와/코스 결손, 인접 기와의 추가 누락, 일부 짧은 사선 깨짐으로 생성해 오목한 계단과 서로 다른 기와 끝이 생기도록 바꿨다. 온전한 내부 기와의 불필요한 세분을 줄이고 파단 주변의 융기·끝단에 상세를 집중했다.
- **표면 중첩·서까래 접속:** 기존 기와 표피끼리 조금씩 겹치던 좌표 범위를 제거하고 작은 간격을 뒀다. 서까래·도리를 구조 데크 아랫면보다 아래로 옮겼으며, 잘린 서까래 끝은 고정 길이가 아니라 해당 파손 범위의 실제 첫 경계에 맞췄다. 이 변경은 배경 점무늬 원인을 줄이기 위한 조치이며 실제 깜빡임 소멸 여부는 메인의 화면 검증 대상이다.
- **금속별 판금 패널 손상:** 차고는 약 0.77m 폭의 골판금 패널/이음선 단위로 누락 길이를 다르게 했다. 인접 패널의 서로 다른 끝과 일부 추가 결손이 실제 개구부를 결정하며, 석조 같은 다각형 구멍을 직접 뚫지 않는다. 읽히는 크기의 붙어 있는 판금 1–2장을 서로 다르게 위/아래로 접고, 곡선 리브는 벽체에 연결된 구조로 유지한다.
- **`ExposedRib` 복구:** 실제 구조 리브 이름을 `BarrelExposedRib_CurvedContinuousBearingStructure`로 바꿨다. 최신 Y01 교체 메시 JSON에서도 이 이름을 직접 확인했다. `SurvivingGable`, `Rafter`, 기존 `DomesticWindow`/`Storefront` 보존 범위는 유지한다.
