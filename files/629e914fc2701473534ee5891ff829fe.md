# A맵 장거리 자동 길찾기 수정

## 사용자 지시
- B2 기본 진입점에서 X6 탈출구로 가는 자동 길찾기의 `PathPartial` 경고를 수정합니다.

## 기획 의도와 해결할 문제
- 실제 NavMesh 연결은 존재하지만 기본 장거리 경로 검색이 중간까지만 결과를 반환합니다.
- 먼 목적지를 AI가 선택할 때 멈출 수 있는 실제 호출 경로도 함께 확인합니다.
- 스폰·탈출 지점, 맵 지형과 건물 배치는 변경하지 않습니다.

## 변경 전 실제 상태
- 2026-09-24 10:08:05, Unity A맵 편집 씬에서 화면 3개 시점과 `BEFORE_NAVIGATION.txt`를 저장했습니다. 맵과 코드 수정 전 상태입니다.
- 기본 V14 검사 결과 `result=FAIL`: B2→X6 `PathPartial`, 기본 진입점→탈출구 28쌍 중 26쌍이 기본 경로 검색에서 완전 경로였습니다. B1→X6은 기존 경고로 별도 분류됐습니다.
- 고예산 경로 검색에서는 B2→X6이 95개 polygon을 거치는 완전 연결임을 직전 작업에서 확인했습니다.
- 변경 전 코드 원본은 `backup/`에 별도로 보관했습니다.

## 실제 변경과 방식
- `StageALongRouteV17`을 추가했습니다. Unity 기본 장거리 쿼리가 `PathPartial`을 반환하는 경우에만 더 큰 검색 예산으로 전체 polygon 통로를 찾고, 이를 기본 쿼리로 각각 `PathComplete`가 검증되는 짧은 구간으로 나눕니다. 지상형 NavMeshAgent가 통과할 수 없는 off-mesh link는 배제합니다.
- `EnemyController.Move`가 A맵에서 위 구간을 순서대로 따라가도록 연결했습니다. 현재 구간을 끝내면 다음 경유점을 사용하고, 목적지가 3m 넘게 바뀌면 즉시 경로를 새로 계산합니다. 분할에 실패한 경우에만 3초 재시도 간격을 둡니다. 다른 스테이지에서는 기존 경로 처리를 유지합니다.
- V14 검사도 실제로 완전 경로가 확인된 구간만 연결 성공으로 인정하도록 강화했습니다. 기존의 고예산 통로 연결성만으로 성공 처리하지 않습니다.
- Unity 플레이 모드 검증 하네스를 추가해 실제 적의 `EnemyController`와 `NavMeshAgent`를 사용합니다.
- 맵 지형, 건물, 30종 배치 에셋, 진입·탈출 위치, 씬/프리팹 데이터는 수정하지 않았습니다.

## 예상 효과와 확인 결과

- `V16_REGRESSION.txt`: 건물·소품·진입점 보존 포함 392 통과·0 실패입니다. `V15_REGRESSION.txt`: 건물 겹침·핵심 구조 검사 67 통과·0 실패·0 발견입니다.
- 독립 코드 검토에서 목적지 변경 후 최대 3초간 멈출 수 있는 결함을 찾아 즉시 재계산하도록 보완했고, 수정본으로 V14/V15/V16을 다시 통과했습니다.
- 원래의 Unity 단일 장거리 `NavMesh.CalculatePath` 응답은 여전히 `PathPartial`일 수 있습니다. 이번 수정은 게임의 A맵 AI가 이를 감지해 검증된 짧은 구간을 따라 이동하게 하는 것입니다.
- `PLAY_VALIDATION.txt`: 실제 A맵 Play 모드에서 B2에 `EnemyController` 적을 생성해 X6까지 이동했습니다. 테스트 인스턴스 속도만 32m/s로 높였고, 9개 경유점과 각 활성 구간의 `PathComplete`를 확인했습니다. X6에서 1.38m 거리까지 약 29.9초에 도착했으며, 이후 목표를 B2로 바꾸자 즉시 완전 경로로 전환됐습니다. `RESULT PASS`입니다. 실제 게임 적의 속도·규칙은 바꾸지 않았습니다.
- 이 검사는 B2→X6 실제 전 구간 이동 한 사례입니다. 28개 진입·탈출 조합은 완전 경로 구간 연결성으로 검증했으며, 모두 실제 적을 이동시킨 검사는 아닙니다.
