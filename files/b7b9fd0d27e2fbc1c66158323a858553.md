# 총기 · 탄약 · 아이템 가치 티어

## 사용자 지시와 범위

소총/샷건/권총/저격총/DMR/기관총을 현재 Unity 프로젝트에 맞게 구현하고, 총기 간 초기 밸런스를 조정한다. 탄약 티어, 아이템 가치에 따른 슬롯 색, 파밍 개체별 작은 옵션 차이, 교체 가능한 단순 외형을 구현한다. 애니메이션은 기존 소총 것을 공유한다. 캐릭터 속성은 구현하지 않는다. 전체 적/맵 밸런스는 후속 작업이다. GPT-6.1 Sol, xhigh 에이전트로 코어·데이터/UI·독립 검증을 분담했다.

## 기획 의도와 변경 전 상태

- 기존에는 소총/권총/샷건/저격총과 근접무기가 있었고 DMR·기관총 분류가 없었다. 고등급 총기의 성능 상승이 컸으며, 탄약은 4개 기본 ID만 실사용했다.
- 총기 UID와 장전 수량은 저장했지만 개체별 옵션과 혼합 티어 탄창은 없었다.
- 아이콘 슬롯은 공통 색 중심이었고 권총·샷건·저격총에도 소총 임시 외형/썸네일이 쓰였다.
- 작은 옵션 차이와 사격 역할 차이로 파밍 선택을 만들되, 높은 가치가 모든 전투 성능의 우위로 이어지지 않도록 한다.

## 실제 변경

- 소총 7/권총 5/샷건 7/저격총 7/DMR 3/기관총 3, 총기 32종. 기존 근접 5종은 유지한다. 기본 성능은 연사·한 발 피해·반동·탄창·거리·재장전의 교환 관계로 조정했다.
- 탄약 4계열 × T1~T6 = 24종. 원래 item_017~020은 T1로 보존하고 _t2~_t6을 추가했다. DMR/기관총은 소총탄을 쓴다.
- 탄약 선택은 다음 재장전에 적용된다. 장전 완료 시 예비탄을 소비하고, 보충 장전한 탄약은 기존 탄약 뒤에 쌓여 순서대로 발사된다. 산탄총의 각 펠릿은 같은 발사 탄종의 관통을 사용한다.
- 탄약의 생체 피해 배율은 전부 1이다. 보호등급에 따라 제한된 관통/방어구 마모 이점만 제공한다. 현재 적은 장비형 방어구가 없으므로 무방어 적에 대한 T1/T6 생체 피해는 동일하다. 적 방어구/전역 밸런스 추가 구현으로 확대하지 않았다.
- 새 총기에 재장전/산포/반동/사거리/취급 중 서로 다른 2~3개의 2~6% 옵션을 생성한다. 피해/연사/탄창 증가 옵션은 없다. UID와 옵션을 저장해 이동·창고·장착·드랍·탈출·재로드 중 재추첨하지 않는다. 기존 저장 총기는 옵션 없는 개체로 유지한다.
- 슬롯 배경/테두리에 개당 판매가의 V1~V6 색(흰색/초록/파랑/보라/금색/빨강)을 적용한다. 문턱은 0/100/500/2,000/10,000/30,000이다. 탄약의 관통 T는 별도 색 표기이며 수량과 무관하다.
- 장착 무기 우클릭과 가방 상세에서 옵션/능력치/현재 탄약/다음 재장전 탄종을 확인하고, 소유 중인 현재 UID를 다시 확인한 후 선택을 변경한다.
- 기존 재료·보급 파밍표와 맵 배치는 유지한다. 탄약 상자에 높은 탄약 티어와 32종 총기 후보를 추가하고, T2/T3 탄약과 새 DMR/MG를 기존 거점 보급 해금 규칙에 연결했다.
- 기존 소총 외형은 유지하며 다른 5분류에 단순 입체 모델을 연결했다. `SdGunLibrary.modelReplacements`의 ID/프리팹으로 완성 모델이 임시 모델보다 우선하도록 했다. 캐릭터/헤어/헬멧 아트는 변경하지 않았다.

## 방식과 저장 호환

실제 프로젝트 수정 전 Runtime/Editor/JSON 원본을 `source_before`에 보관하고 `work/weapon-ammo-src`에서 작업했다. 본 프로젝트의 다른 파밍·컷씬 작업과 소유 범위를 조율했다. 배포는 전체 Runtime 복원이 아니라 변경 파일별 기준/최신/작업본 SHA 비교와 직전 백업을 거친다. 배포 내역은 `deployed_hashes.json`을 기준으로 확인한다.

`RifleSnapshot`은 기존 schema1을 읽고 새 schema2에 선택 탄약/장전 FIFO/옵션을 저장한다. 탄창을 줄인 20종에는 실제 이전 최대 용량을 남겨 기존 장전탄을 보존하고 추가 장전만 제한한다. 사망 회수품에서 기존 규칙에 따라 장전탄을 비울 때 FIFO도 비운다. Unity JSON에서 null 문자열이 빈 문자열로 변환되는 경우를 처리해 빈 탄창을 재로드할 수 있게 했다.

## Roblox 참고의 출처와 제한

현재 Roblox Studio 연결 목록은 비어 있었다. `work/reference`와 이전 이식 작업의 Lua 원본 보관분을 읽기 전용으로 확인했다. 총기·아이템·장비 규칙은 있으나 당시 UI의 정확한 티어 RGB/가치 문턱은 찾지 못했다. 따라서 이번 6색과 문턱은 사용자 요청에 맞춘 초기 구현값이며 Roblox 원본과 완전히 동일한 복원이라고 주장하지 않는다. 다른 프로젝트의 불명확한 규칙을 공통 규칙으로 가져오지 않았다. 세부 출처 조사/성능표는 `ITEM_TIER_NOTES.txt`에 보관한다.

## 검증 상태

- 코어 제작 검증 6,261개 assertion 통과. 별도 검증 에이전트의 81개 항목과 60,000회 무작위 상태 전환 검사 통과(`WEAPON_CORE_NOTES.txt`, `independent_core_checks.txt`).
- 실제 Unity 통합 검사 73개 통과(`unity_integration_checks.txt`). Unity JSON과 실제 디스크 저장/재로드, 창고 이동, 상자 중복 회수 방지, 출격·탈출·사망 회수, 저장 실패 롤백, 20종 구형 초과 장전탄, 60,000회 상자 추첨에서 모든 32종 총기/24종 탄약 도달, 실제 RifleController의 산탄 6펠릿과 탄약 1발 소비·T6 관통 전달을 확인했다.
- 별도 Unity 6000.1.0f1 프로젝트에서 최종 Windows 실행본 빌드 성공(`after_build_integrated.log`). 마지막 검증에는 병행 작업이 수정한 최신 `LootItemVisuals.cs`도 포함했다. 주 편집기의 Play/씬/카메라는 조작하지 않았다.
- 실제 변경 전/후 1600×900 화면을 확인했다. 총기 상세의 2~3개 옵션, 24종 탄약의 T 표기, 가치 V 슬롯색, 장착 DMR 탄종 선택 패널, 6분류 모델을 검토했다. 발견한 빈 탄창의 잘못된 T0 표시를 '탄창 비움'으로 수정하고, 임시 권총의 총구 연결 틈을 메운 뒤 다시 빌드했다.
- 별도 실행본의 실제 T6 버튼 클릭 후 다음 장전 탄종과 선택 체크가 갱신되는 것을 확인했다. 내부 선택 결과는 `interactive_ammo_selection.txt`, 화면은 `after_selected_t6.png`로 저장한다. 실제 사용자 프로필은 쓰지 않는다.
- GPT-6.1 Sol xhigh 최종 독립 검토에서 P1/P2 지적 없음. 유일한 P3 빈 탄창 T0 표시 지적은 수정했다. 검증 결과와 소스를 메인이 직접 읽고 통합했다.
- 실제 프로젝트의 변경 39파일과 안내 문서를 배포했다. 모든 변경 파일을 수정 직전 백업하고 기준/최신/작업본 충돌이 없는지 확인했으며, 복사 후 SHA256이 검증본과 동일함을 확인했다(`integration_plan.json`, `deployed_hashes.json`, `pre_integration/`). 검증용 실행기/테스트 씬은 실제 프로젝트에 넣지 않았다.
- 이 검증은 시스템·저장 호환·실제 UI/사격 경로 확인이다. 모든 적과 32종 총기의 장시간 실전 난도/경제 밸런스가 완성되었다는 의미는 아니다. 그 수치는 후속 전체 레벨 디자인 작업의 조정 대상이다.

## 후속: 기존 회귀 검사 갱신 및 최신 통합 검증

병행 컷씬/파밍 검토에서 기존 검사에 남은 63상품·169아이템·31무기·48파밍 후보 고정값과 새 계약의 충돌을 전달받았다. 총기 변경에 필요한 기존 검사의 유지보수로 처리했으며, GPT-6.1 Sol xhigh 에이전트가 Arsenal/LootEconomy와 나머지 fixture를 분담하고 메인이 Basecamp/Weapon 및 통합 실행을 맡았다.

- `BasecampChecks`: 기존 63상품의 ID를 모두 확인하고 추가 탄약·DMR·기관총의 실제 구매, 비용, 무제한 탄약, 유한 총기 재고, StageA/B 해금 거절/허용, T4~T6 상점 제외를 검사한다.
- 기본 성능/성장 검사는 `rollAffixes:false`로 무작위 옵션과 분리했다. 총기 37정(화기32/근접5), 7 enum, 현재 산탄 장전 시간의 중간·완료·취소·재개 경계를 검사한다. 개체 옵션 자체는 앞선 코어/Unity 통합 검사의 대상이다.
- 파밍 검사는 기존 32재료/12소모품과 새 24탄약/32총기, 퀘스트 아이템 제외, 전체 도달성, 가치 분포, 재료 연구·거래·그리드 계약을 유지한다.
- 장전 수량만 수동 변경하던 오래된 테스트 fixture는 실제 장전 후 Capture하여 schema2 FIFO와 수량이 정합하도록 수정했다. 실제 저장 검증을 느슨하게 하거나 게임 코드를 되돌리지 않았다.
- `EquipmentChecks`의 오래된 공급품 무게 기대값 2.4kg도 발견했다. 변경 전후 물/탄약 무게는 각각 0.6/0.018kg로 동일하며 실제 2개/10발의 합은 1.38kg이다. 장착 전후 방어구 무게 보존과 실제 카탈로그 공급품 무게를 분리해서 검사하도록 수정했다. 이 후속 작업에서는 Runtime/가격/무게/밸런스 데이터 변경이 없다.
- 기존 규칙 검사 11그룹 **2,241개 PASS**. Basecamp/Weapon/Arsenal/LootEconomy/Inventory/Enemy/LootEquipment/InventoryRegionSwap/GrowthRework/Session은 첫 배치에서 통과했고, Equipment는 fixture 수정 후 별도 재실행하여 통과했다. 보고서: `legacy_checks_final_summary.txt`, `legacy_results/`, `legacy_checks_final.log`, `equipment_recheck.txt`. 초기 실패 보고도 `legacy_checks_initial_summary.txt`에 보존했다.
- 추가로 32총기의 모델·그립/총구 앵커·아이콘 경로를 확인했다. `SerinGunChecks`의 26종/PNG 강제 조건은 새 32종과 6개 도식 아이콘 경로에 맞췄으며 컴파일 및 변경된 카탈로그 부분은 검증했다. 전체 Serin 씬 애니메이션 검사는 이번 후속 실행에 포함하지 않았다.
- 복제본에 최신 실제 Runtime/Resources를 다시 복사한 뒤 검사했다. 검사 입력 SHA256은 `regression_source_manifest.json`이다. 파밍 측이 지정한 LootCatalog/LootInteractor/SessionInventoryPresentation/ItemCatalog/ShopCatalog 5파일을 포함해 기록된 Runtime/Resources와 당시 실제 프로젝트의 불일치는 0건이었다. 앞선 파밍 스냅샷의 검사 결과를 이번 통합 검증으로 대신하지 않았다.
- 첫 검사 준비 시 복제본의 Tests 의존 파일 누락으로 컴파일이 중단되어 실제 Tests 폴더를 보완했다. 이후 전체 Editor 컴파일과 위 검사 실행에 성공했다.
- 수정된 기존 Editor 검사 10파일만 원본과 충돌 확인 후 실제 프로젝트에 반영하고 해시를 대조했다(`checks_deployed_hashes.json`). 직전 원본은 `checks_before/`에 보관한다. 최초 Runtime/데이터 39파일 배포 내역과 별도로 기록한다.
- `before_checks_editor.png` ↔ `after_checks_editor.png`: 동일 주 편집기의 읽기 전용 확인 화면. 검사 코드 수정은 게임 화면에 시각적 차이가 없으며, 결과 증거는 위 실행 로그와 PASS 보고서다. 주 편집기 Play/씬은 조작하지 않았다.
