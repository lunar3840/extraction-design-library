# 인벤토리 확대 및 전투 HUD 적용

상태: 코드 구현 및 정적 컴파일 완료. 메인의 실제 Unity after 캡처와 시각·입력 검증 대기. 이 문서는 런타임 시각 통과를 주장하지 않는다.

## 지시와 의도

사용자는 인벤토리 캐릭터 영역 확대와 승인된 UI 키트의 Unity 적용을 요청했다. 큰 전신 캐릭터를 유지하면서 장비가 신체를 가리지 않게 정돈하고, 반투명 원형 수분·에너지와 하단 중앙 무기·오른쪽 소모품·확대 E/X 스킬 구성을 실제 게임 데이터에 연결한다.

## 전 상태와 증빙

- 실제 변경 이전 메인이 확보한 `before_r02_inventory_1920x1080.png`, `before_r02_inventory_medical_1920x1080.png`, `before_r02_combat_hud_1920x1080.png`, `before_r02_companion_abilities_1920x1080.png`, `before_r02_camp_hud_1920x1080.png`를 비교 대상으로 사용한다. 전체 before는 34개이고 이 담당자는 inventory 정면을 직접 열어 확인했다.
- 기존 portrait 표시 폭406 logical과 하단의 넓은 무기 카드가 겹쳤다. HUD는 좌측 숫자 HP와 작은 수분·에너지 링, 하나로 길게 이어진 무기/소모품 줄, 작은 스킬 문구 박스였다.
- 수정 이전 원본 6파일과 .meta를 `source_before/`에 경로를 보존하여 저장하고 SHA256 목록을 남겼다. 새로 추가한 두 파일은 before가 없는 신규 파일이다.

## 실제 변경

- 공통 UiTheme geometry는 메인이 소유한다. 합의한 캐릭터600/portrait460/가방x648/우측x1076 배치에 맞춰 무기 카드 두 개를 장비 우측 열의122×108로 이동했다. 신체 숫자·버튼은 아래54px compact footer로 정리했다. portrait 카메라 프레이밍·포즈·모델·재질은 유지하고 render texture만768×1152로 높였다.
- 인벤토리 퀵슬롯을64 logical로 키웠다. 가방의 실제60 logical 격자 및 드래그/장착/빠른이동 callback은 유지했다. 셀과 아이템 면을 라운드·반투명·얇은 파스텔 테두리/상단 표시로 바꿨다.
- `ItemTierPresentation.ColorForTier/Tint`와 `ItemValueTier` 규칙은 변경하지 않았다. 아이템 배경/배지에만 기존 색을 white28% 혼합해 파스텔로 표현한다. 가격 V와 탄약 관통 T는 그대로 별도 표기한다.
- 신규 `InventoryHudLayout`은 무기/소모품 표시 좌표와 pointer 차단을 공유한다. 하단 중앙 무기400 logical 폭, 그 오른쪽 실제3개 퀵슬롯만 표시한다. 참고 Figma의4번째 슬롯/새 키/신규 기능을 게임에 추가하지 않았다. UiTheme의 이에 대한 위임과 pointer 결합은 메인이 반영했다.
- 신규 `InventoryHudView`는 수분·에너지 원형을1920×1080 기준112px로 키워 수치 없이 아래에서 위로 채운다. 화이트 아이콘과 얇은 외곽선은 유지한다. 생성한 두 mask texture를 재사용하며 값 변화마다 texture를 생성하지 않는다.
- 현재 캐릭터의 humanoid Head를 카메라로 투영해 HP/스태미너 두 bar를 표시한다. Head를 찾지 못할 때만 실제 CharacterController 높이를 사용한다. 사용 진행 카드는 같은 anchor 위 별도 위치로 옮겨 bar와 겹치지 않게 했다.
- 스킬은 E/X 각각76 logical 원형, 이름/실제 충전·쿨다운·활성 시간으로 바꿨다. gameplay 함수와 E/X 입력은 변경하지 않았다. 기존 관측 표식·scout 물자 용기 표식도 유지한다. 스킬 진행 arc는 Repaint 선분으로 그려 수치별 texture 누적이 없다.
- 출혈/외상/진통 표식, 추천 치료/V 힌트, 의료품 휠과 취소·사용은 유지한다. 기존 item hover의 지연/실제 데이터/DetailsVisible/drag hide/GUI.depth는 바꾸지 않았다.

## 파일

수정: `Inventory/InventoryGlassView.cs`, `Inventory/InventoryGridPresentation.cs`, `UI/ItemTierPresentation.cs`, `UI/InventoryPortrait.cs`, `Companions/CompanionAbilityController.cs`.

신규: `Inventory/InventoryHudLayout.cs`, `Inventory/InventoryHudView.cs` 및 .meta.

`InventoryCompanionChips.cs`는 사전 백업했지만 변경하지 않았다. UiTheme 및 다른 담당자의 파일은 이 담당자가 수정하지 않았다. 최종 코드는 `source_after/`와 SHA256 목록에 저장했다.

## 확인 결과

- Unity가 사용하는 Roslyn/Bee 응답 파일을 복사해 기록 폴더 안으로만 출력하는 정적 컴파일: runtime 오류0/기존 경고21, Editor 오류0/기존 경고35. Unity 앱 실행·종료·씬 변경을 하지 않았다.
- `compile_inventory_hud/hud_contract_checks.txt`: 8개 화면 크기에서 무기 중앙 정렬, 그룹 가림/화면 경계, 실제3개 소모품 hit target, 빈4번째 위치의 pointer 통과, 수분·에너지 bottom fill과 clamping 및112px 크기 **118항목 통과**.
- `compile_inventory_hud/hover_contract_checks.txt`: 기존 hover 경계/반전/잘림과 V티어 문턱 **25항목 재실행 통과**. 실제 Editor hover33항목은 이전 hover 작업의 결과이며 이번 실행 숫자에 합산하지 않는다.
- CompanionAbilityController의 OnGUI 이전 gameplay 본문은 새 using을 제외하고 백업과 동일한 것을 비교했다.
- 기존 `GlassLayoutChecks.RunBatch`는 앱 종료를 포함하며544/550/49.8px 구배치값을 고정 검사하므로 이번에는 실행하지 않았다. 해당 old fixture 통과를 주장하지 않는다.

## 메인 실제 검증 제안

1. 동일1920×1080 인벤토리: 캐릭터 확대·모자/부츠 끝 클리핑·장비/footers와 겹침 없음. portrait drag 회전과 오른쪽 무기/방어구 click·drop hit 일치.
2. 정면/의료 tooltip: 흰 글자·V/T 표시·카드 전면 순서. 상세 열린 상태/드래그 중 hover 숨김 및 물품 수량 보존.
3. camp/combat HUD:112px 물/에너지와 아래쪽 fill, 숫자 미표시, 중앙 무기와 오른쪽3소모품, HP/stamina 머리 위 정렬. 밝은 배경/어두운 배경 가독성.
4. E/X ready/충전/쿨다운/활성 UI, 기존 입력과 관측/용기 표식 보존.
5. 의료 휠, V 추천/사용/취소, 출혈/진통 badge 및 사용 진행 카드가 새 위치에서 겹치지 않는지.

최종 before/after 대응과 시각 확인 결과는 메인이 실제 after를 확보한 다음 공통 `CHANGE_RECORD.md`에 통합한다.

## 첫 after 검토 후 후속 수정

요청된 실제 after7장과 before3장을 직접 검토한 결과는 `INVENTORY_HUD_VISUAL_AUDIT.md`에 기록했다. 캐릭터 확대/정면·측면 크롭/장비 겹침 및 headbar 위치, 물·에너지·중앙 무기·3quick·E/X 배치는 실제로 확인했다. hover와 부분 fill은 해당7장에 없어 검증에서 제외했다.

메인의 추가 승인으로 `Inventory/InventoryWeaponModding.cs` 1파일을 새로 원본 백업하고 무기 개조 요약·드래그 안내 caption의 높이와 여백만 보완했다. 해당 파일도 source_after와 SHA256에 추가했다. runtime 정적 재컴파일 오류0/기존 경고21이며 로그는 `compile_inventory_hud/runtime_compile_after_modding_spacing.txt`다. 공통9-slice 코너 수정은 메인이 별도로 수행했다. 최종 화면 재검토는 아직 대기 중이다.
