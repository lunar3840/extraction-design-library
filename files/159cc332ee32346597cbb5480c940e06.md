# 전체 장면 아웃라인 강화 — 독립 검토

판정: **PC 게임 카메라의 A/B 장면에서 요청한 점진적 외곽선 강화는 통과.** 모바일, HUD, 움직임 중 떨림, FPS는 이 증빙으로 판정하지 않는다.

## 정적 검토

- `PC_RPAsset.asset`의 기본 renderer는 `PC_Renderer.asset`이며, `Toon Outline` feature는 활성 상태다. 기본 PC 게임 카메라에 활성 `ToonOutlineCamera`가 있어야 패스가 실행된다. `RainCourtyardAtmosphere.ConfigureCamera`가 해당 marker를 붙이며 A/B 라우터는 같은 플레이어 카메라를 사용한다. A맵 자체의 `StageALookV16Atmosphere.Begin`이 marker를 보장하는지는 별도다. 실제 캡처에서 marker와 활성 renderer를 확인해야 한다.
- 기존 1.15 px, depth 0.025, normal 0.48, normal strength 0.25, alpha 0.72를 staged 1.7 px, 0.02, 0.46, 0.38, 0.88로 바꾸는 안은 `ToonOutlineFeature`와 shader의 0.5–2 px 범위 안이다. 동일한 단일 pass와 4방향 샘플 구조이지만 비용 및 FPS 안정성은 실제 측정 전 단정할 수 없다.
- pass는 깊이와 법선 텍스처에 실리는 불투명 장면의 경계를 처리한다. 캐릭터만의 후처리는 아니므로 건물·소품의 실루엣에도 적용될 수 있다. 다만 texture 색만 다른 면, 투명 유리/물/비 파티클, 모든 UI에 같은 결과가 생기는 것은 아니다. shader가 upward normal 표면의 depth edge를 0.3배, normal edge를 0으로 억제하므로 풀·젖은 지면의 윗면도 별도 시각 확인이 필요하다.
- 에델 피부 `.65`는 `ToonCharacterStyle`의 피부 재질 전용 값이다. 이 전역 후처리 조정과 무관하므로 헤어 및 조명을 함께 바꿀 근거는 없다. 피부/헤어가 실제 전후 화면에서 유지되는지 확인해야 한다.
- `ToonArtBuild.Apply()`의 49–56행은 renderer feature를 설치한 뒤 예전 outline 수치를 다시 저장한다. 향후 해당 메뉴를 실행하면 renderer 값이 되돌아갈 수 있다. 새 설정을 유지할 최소 동기화 범위는 50행 width `1.7`, 51행 normal strength `.38`, 52행 depth threshold `.02`, 53행 color alpha `.88`이며, 현재 코드에 없는 normal threshold `.46` 대입을 인접 위치에 추가하는 것이다. RGB `.025/.038/.05`는 그대로 둔다. 코드 수정 없이 renderer만 변경한다면 재실행 시 되돌림 위험을 완료 기록에 적어야 한다.

## 검증 도구 최종 정적 재검토

완성 회신본 `staging/probe/GlobalOutlinePass.cs.txt` SHA-256 `60BE4F45B6D752173CF390D97A87EA07211691847B13DAFC8E69251656B6CF32`를 다시 읽었다. 앞서 제작 중 작성본에서 발견했던 `CheckOutline()` 미정의와 `portrait` 미선언 참조는 해소되었다. `BuildPlan`은 현장 4 + 캐릭터 3 + 환경 2 = 총 9개로 현재 길이 검사와 일치한다. 코드 텍스트 기준 이전 세 차단 사항은 해소되었다. 실제 Editor 컴파일 및 실행 성공은 통합 담당자의 로그로 별도 확인해야 한다.

도구는 `after` 카메라의 활성 marker와 feature를 확인하고 `game_front`에서 marker를 일시 해제한 통제 이미지를 저장한다. 통제 이미지와 활성 이미지가 30픽셀 이상 달라야 통과하도록 되어 있어 패스 실동작 검출에 도움이 된다. `before`에서 marker가 없을 때는 그 상태를 기록하고 통제 촬영은 생략한다. 런타임 renderer feature 리스트 reflection 조회가 불가능하면 그 사실만 기록하며, on/off 촬영으로 실제 효과를 판정한다. `CheckEdelDefault`는 피부값을 로그에 기록하지만 값 `.65`를 assert하지 않으므로 최종 로그에서 값을 직접 확인해야 한다.

## 실제 전후 화면과 실행 로그

- `before_run.txt`와 `after_run.txt`는 각각 `RESULT PASS`다. 두 실행의 A맵 9시점은 발 위치·카메라 위치·회전·FOV·1600×1000 해상도가 일치한다. 실내 1층/2층 표시 값도 각각 0/1로 동일하다. 실내 1층의 화면 맨 위 NPC 한 개는 두 촬영 사이 이동했으므로 그 부위는 화질 비교 근거로 삼지 않는다.
- 두 로그에서 실제 `Player Camera`의 `ToonOutlineCamera`가 활성이고, 런타임 `UniversalRenderer`의 단일 outline feature가 `PC_Renderer.asset`의 feature와 같은 참조다. 설정은 1.15/.025/.48/.25/.72 → 1.7/.02/.46/.38/.88로 일치한다. `game_front` marker on/off 통제에서 변경 픽셀은 전 59,961, 후 170,946이며 평균 RGB8 절대차는 0.4716 → 1.1419다. 이 수치는 패스가 실제 작동하고 효과가 커졌다는 근거다. 전체 화질 점수나 FPS 수치는 아니다.
- 모든 실제 PNG 쌍을 원본 크기로 직접 열었다: 야외 햇빛/그늘, 실내 1층/2층, 에델 정면/측면/후면, A맵 환경 조감/도로 잔해, B맵 기본 카메라. 에델 외형선과 머리카락 잔가닥, 벽 윗면·파손 지붕·창틀·실내 칸막이·차량/드럼/잔해 경계가 전보다 진하고 또렷하다. 조감에서는 변화가 의도대로 절제되어 있고, 근접 캐릭터 및 B맵 바닥 타일 이음매에서 더 읽힌다. 큰 이중 halo, 검은 덩어리, 지면 잉크 얼룩, 얼굴·헤어 색 훼손은 정지 화면에서 보이지 않는다. 별도 재질이나 조명 변경 없이 기존 건물 색과 에델 머리색이 유지된다.
- `EDEL_DEFAULT`는 전후 모두 피부값 0.65, 활성 피부 재질 3개가 같은 값을 기록한다. A→B는 기본 Hybrid Toon 31재질로 전환하고 B→A는 D15와 원래 재질 연결을 복원했다. B맵 이미지에서도 캐릭터와 습식 바닥 경계 강화가 확인된다.
- `game_front`의 큰 회색 가로띠와 `indoor_2f` 밖의 짙은 파란 시야 덮개는 변경 전에도 존재한다. after에서는 덮개 아래 멀리 있는 정적 지오메트리의 잔윤곽이 소폭 더 읽힌다. `PlayerVisionOverlay.shader`는 투명 화면 덮개로 장면 색을 어둡게 하고 깊이에는 쓰지 않으며, outline 패스는 이후 원래 깊이/법선 경계를 색에 합성한다. 시야 밖 적은 `PlayerVisionController.UpdateEnemyVisibility`가 `EnemyController.SetPlayerVisionVisible(false)`로 적 Renderer를 끄므로 이 패스만으로 숨긴 적의 깊이 실루엣을 직접 되살리지는 않는다. 그러나 시야 밖 적을 배치한 전용 동적 시험은 없으므로 모든 적 연출의 누출 부재를 실기 입증했다고 말하지 않는다. 기존 덮개 아래 **정적 배경의 잔윤곽 증폭**은 좁은 잔류 가능성으로 남긴다.
- 전역 장면의 사진적 재질·조명 자체는 그대로여서 모든 표면이 만화 재질로 바뀐 결과는 아니다. 얇은 풀/나뭇잎, 지면 윗면, 투명 물·유리·비, HUD는 이 depth/normal 패스의 일괄 적용 대상으로 보장할 수 없다. 현재 캡처는 게임 카메라의 UI 없는 렌더이므로 HUD 보존/강화 판정은 없다. 정지 PNG는 움직임 중 깜빡임이나 안정 FPS를 증명하지 않는다.

## 남은 확인 경계

Unity Editor 컴파일 오류 0건, 임시 helper 제거, 씬/요청 파일 상태 및 최종 라이브러리 게시 검증은 통합 담당자의 별도 마감 증빙을 따른다. 이 독립 판정은 위에 직접 읽은 PNG와 before/after 실행 로그에 한정한다.
