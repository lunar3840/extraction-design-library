# 루팅·상점 티어 색상 통일: 코드 변경

## 범위와 변경 전 문제

- 루팅의 공개 완료 슬롯은 이미 최신 `ItemTierPresentation.DrawSlot`을 사용하고 있었다. 미수색/수색 중 슬롯은 중립색이며 hover 정보를 공개하지 않는다.
- 일반 아이템 슬롯은 판매 가치 V 티어, 탄약 슬롯은 관통 T 티어를 색상 기준으로 사용한다. 기존 hover는 항상 V 티어를 읽어 탄약 슬롯과 색이 달랐고, 정보창 배경·외곽·아이콘 영역이 중립색이었다.
- 상점은 아이콘 슬롯이 없는 텍스트 상품 목록이며 상품 자체의 hover 정보창 등록이 없었다.

## 실제 수정

1. `ItemTierPresentation.SlotTint`로 기존 슬롯 색상 해석을 공통화했다. 탄약은 T, 그 외 아이템은 V를 읽고 기존 파스텔 혼합과 6색 순서를 그대로 사용한다. 기존 `DrawSlot`의 색·불투명도·외곽선·선택 상태 수치는 변경하지 않았다.
2. 공용 hover 정보창의 배경·외곽·상단선·아이콘 슬롯이 `SlotTint`를 사용한다. 카드 배경은 짙은 기초색에 티어색 24%를 혼합하고 불투명도 92%, 외곽선은 티어색 70%다. 작은 `가치 Vn` 배지는 V의 의미와 기존 색을 유지한다. 탄약의 관통 T 본문도 유지한다.
3. 상점 상품 행 왼쪽에 64×64 논리 크기의 공용 티어 슬롯, 큰 아이콘, 우측 하단 구매 단위 1을 추가했다. 상품명/가격/조건과 구매 버튼은 기존 정보와 거래 동작을 유지한다.
4. 상점 아이콘과 상품 정보 영역에 공용 hover를 연결했다. 구매 버튼 측 열은 hover 영역에서 제외한다. 스크롤 종료 후 실제 viewport와 후보 영역을 교차해 보이는 부분만 등록한다.
5. 상점 preview는 상품 ID를 가진 읽기 전용 `SlotView` 값이다. 소유 가방·재고·무기·의료 잔량 객체를 만들거나 변경하지 않는다. 실제 인벤토리의 잔량과 장탄수로 오인할 가짜 상태를 표시하지 않는다.

## 보존 확인

- 루팅의 `SearchState.Completed` 분기와 공개 완료 때만 hover를 등록하는 경계는 소스 변경 없이 유지했다.
- 판매 가치 문턱, 탄약 규칙, 가격, 해금, 수량 한도, 구매 가능 조건, `Session.Buy`/`Session.SellInstance` 및 `Queue`/`CampMutation` 콜백은 그대로다.
- 실제 수정은 아래 4개 파일의 표시 함수와 새 hover 보조 상태·함수뿐이다. 명시한 변경 부분을 제외한 소스의 정확한 텍스트 보존을 `code-preservation-audit.json`에서 확인했다.
- 상점은 `OpenPanel(1)`이 `ShowInventoryContent`와 `InventoryOpen`을 활성화한다. 기존 `CanShowItemHover`는 정상 거점 상점에서도 허용되며, 사망·잠금·시뮬레이션 정지·맵 입력 차단·상세창·드래그 중에는 기존 차단을 유지한다.

## 검증과 한계

- 수정 후 전체 runtime C# 컴파일: 종료 코드 0, 오류 0, 기존 경고 21. 기록은 `compile/runtime_compile.txt`에 있다. 이전 기록 폴더와 DLL을 덮어쓰지 않았다.
- `code-preservation-audit.json`: 4개 파일 모두 허용된 표시 변경 밖의 소스 동일, 거래 조건·콜백 6개 원문 동일, PASS.
- 정확한 4개 파일 스냅샷은 `source_after/`, SHA256은 `source-after-manifest.json`에 저장했다.
- 실제 Unity 화면, OS 마우스 hover 및 스크롤 검증은 메인 에이전트가 별도 수행한다. 이 코드 검토만으로 실제 입력 검증 완료를 주장하지 않는다.
