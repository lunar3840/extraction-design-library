# 기준 측정 03의 범위와 제한

실제 측정: `runs/baseline03/`. RTX4050 Laptop, Unity 6000.1 WindowsEditor/DX12, PC 품질, Game1920×1080, vSync0/targetFrameRate−1, StageA Relay, 에델/새 S4 ON. 사용자 일반 저장과 분리한 StageScenePreview 프로필이다. 프로덕션 최적화는 이 측정 전에 적용하지 않았다.

## 유효하게 확보한 결과

- 실제 Game 대기 baseline90프레임, 헤어 ON/OFF/OFF/ON 각90프레임이 있다. 각 구간 전20 warm(실제 baseline40 warm), 스크린샷·기기·소스/몸 카운터가 별도다.
- 실제 Game baseline frame 중앙값189.57ms/native CPU166.22ms/native GPU5.89ms. 헤어 내부 Step 중앙값117.94ms와 Current BeginFrame61.62ms는 타이머 범위가 다르다. Apply/Braid/몸 Query는 중첩되므로 합산하여 시간·비율을 만들지 않는다.
- 위치·카메라·AI/input 제어를 유지한 헤어 진단 ON1/ON2 frame 중앙값82.01/70.55ms, OFF1/OFF2 20.73/20.55ms. OFF는 최종 품질 설정이 아닌 비용 분리다. 에디터·단일 위치·한 캐릭터 결과를 전체 게임/빌드 FPS로 확대하지 않는다.
- Native GPU는 실제 baseline90행 중89개의 양수 유효 표본이며 결측을0으로 취급하지 않았다. 초기 BASELINE_V3_SUMMARY.json에는 결측 파싱 오류가 있으므로 판정에는 보정된 INTERIM_ABBA_SUMMARY.json과 원시CSV를 쓴다. Recorder render_thread/script_late_update는 unavailable이며 별도 FrameTimingManager native 지표와 구별한다. GC.Alloc marker는 단위 미검증이고 frame bytes는 GC Allocated In Frame만 쓴다.

## 자세 고정의 한계

`hair_on/off` 구간은 AI/input 및 위치/카메라를 고정했지만 **완전히 동일한 애니메이션 자세가 아니다.** 도구는 Animator.speed0을 지정했으나 SdCharacterVisual이 매 LateUpdate에 speed1로 갱신하여 normalizedTime이 진행했다. 예: ON1 2.4773→6.9865. 그러므로 이 결과를 동일 소스 포즈의 알고리즘 동등성 시험이나 엄밀한 개선률로 사용하지 않는다. 헤어 계산이 큰 상시 CPU 부담임을 분리하는 초기 진단이다. 다음 단계에는 해당 드라이버/idle/무기/Animator 상태를 함께 보존·정지하고 원본 TRS/morph trace를 재생하는 검증이 필요하다.

## 실패/중단 보존

1. `runs/failed_start01`: 구형 StageA_Blockout 테스트 씬에 최신 encounter layout이 없어 실제 출발 실패. 120초 readiness timeout에서 자동 stop·원래 씬 복원. 게임 성능 표본이 아니다.
2. `runs/failed_inventory02`: 최신 Relay로 출발했으나 측정 도구의 ParticleSystemRenderer에 MeshFilter가 없고 Unity fake-null을 `?.`로 확인하여 inventory 스냅샷 예외. CSV 성능 표본 없음. TextureMemorySnapshot 자체는 정상 완료했고 별도 상태와 함께 보존한다.
3. `runs/baseline03/systems_command_ERROR.txt`: 실제 A맵은 StageARainV37인데 도구가 로비의 RainCourtyardAtmosphere를 선택해 weather 대상0. 시작 조건 검사에서 시스템 비교를 중단했다. baseline90/헤어360표본과 구별하고, 덩굴·맵·날씨의 분리 결과를 확보했다고 보고하지 않는다.

Unity는 stop 후 원래 Relay clean Edit로 복원됐으며 UI_TEMP_RETURN_CHECKPOINT.json에서 UI 썸네일 베이크 담당에게 일시 반환했다. 이후 명시 반환 전까지 이 채팅은 Unity/Assets/요청 파일을 변경하지 않는다.

## 후속 진단 도구의 제한
- V7 첫 normal 요약은 존재하지 않는 lod_reported_reference_size_px 열을 읽어 0으로 치환했다. INVALID_FIELD_HISTORY에 보존하고 최종에서는 실제 lod_reported_size_reference_px 열 존재 검증·빈/NaN 제외·유효 표본 수를 적용했다. 프레임/CPU/Step은 원시 CSV로 서브 에이전트 두 명이 재검산했다.
- Object.FindObjectsByType는 HideAndDontSave 인벤토리 studio hair를 제외해 manual_portraits=0이 나올 수 있다. 실제 InventoryPortrait가 없는 증거로 쓰지 않는다. 실제 인벤토리는 public ToggleInventory로 열어 after_inventory_native.jpg에 확보했다. Bind(...,true,true)와 ManualSimulation fallback 소스는 확인했으며 숨김 studio의 실제 상태 계측은 보완한다.
- final motion QA residual은 source precise와 동일 구간/검사 경로의 대조가 없으며, 원본의 braid early-continue는 같은 capsule/box 카운터를 실행하지 않는다. 최대치 12/24를 시각 무관통 또는 회귀 확증으로 판정하지 않는다.
- QA10 시작 중 assembly reload 실패는 QA10_HOT_RELOAD_FAILURE.md에 별도로 기록했다. 이후 clean restart11과 구분한다.

- Contact12 보완 계측도 두 애니메이션의 TRS/morph/시간이 완전히 같지 않아 sourceInputExact=false다. 공통 post-Step 감사에서 양쪽 모두 Braid01/02와 AR_A_Stock/Receiver_Up의 패딩 envelope 겹침을 보였다. LOD 전체 교차길이 최대8.69px, 정밀9.12px; 후진만 보면 LOD가 큰 항목이 있어 무회귀 동등성은 주장하지 않는다. 실제 mesh 관통 깊이가 아닌 원기둥·상자와 선분의 추정치다.
- Contact12 최악 첫 후진 프레임은 capture 조건 backIndex>=2 때문에 사진에 남지 않았다. 다음 검사에서는 첫 프레임부터 후진의 상승 peak를 최대6장 저장하도록 도구만 고쳤다.
- 숨김 studio status는 Resources 조회 뒤 scene.name이 null인 객체에서 검사 도구 예외를 냈다(QA12_HIDDEN_SCENE_STATUS_ERROR.txt). scene name null 처리와 BoundModel 필터를 보완했다. 게임 코드 오류나 정상 FPS 표본으로 세지 않는다.
