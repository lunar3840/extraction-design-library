# 전체 숫자 감사 및 수정 결과

2026-10-27 KST, 익스트랙션 데이터 편집기의 기존 소수점 수정 후속 검증이다. 다른 게임의 예시 수치나 규칙은 적용하지 않았다.

## 범위와 독립 대조

- 공개 카탈로그: 103분류, 12,931항목. 숫자8,530개·불리언1,349개·문자열3,052개.
- 현재 로컬 원본: 14,685항목. 숫자9,993개·불리언1,640개·문자열3,052개. C#5,686항목·JSON8,942항목·Settings57항목.
- Unity에 이미 포함된 별도 Roslyn 분석기로 원문83,137개 리터럴을 읽어, 편집기의 C# 값·음수 부호·실제 교체 위치를 대조했다. 빌드 조건문 양쪽 영역도 점검했다. Unity 편집기는 실행하지 않았다.
- JSON은 원문을 독립 파싱한 실제 포인터 값과 비교했다. Settings는 저장된 스칼라 범위와 비교했다.
- 로컬 소수2,201개, 선행0이 생략된 리터럴1,125개, 음수342개, 지수 표기233개를 포함한다. 비율/확률/배율 계열 이름의 숫자710개를 별도로 집계했다.
- 공개본 이후 코드가 바뀐4개 파일의291행은 현재 값으로 덮어쓰지 않았다. 보존된 공개 원문 문장과 행 내 리터럴 순서를 별도 Roslyn 분석으로 대조했다.291행 모두 일치했다. 나머지는 현재 원문 또는 동일 문장으로 대조했다.
- C# float의 일반적인 이진 표현 오차는 상대6e-8 범위로 허용했다. 숫자의100배/소수점·부호 차이와는 구별한다.

## 발견 및 실제 수정

원문의 소수점 위치 또는 퍼센트가100배로 달라지는 추가 오류는 없었다. 별도로 음수 부호 누락38개가 있었다. 이전 추출기는 `=`, 쉼표, 반환문 등 일부 문맥에서만 마이너스를 값에 포함했으므로, 비교식·곱셈·null 병합 뒤의 음수를 양수로 읽었다.

- 공개본에 포함된 오류는 `StageMapRouter.cs#L135:3` 참조 항목1개: 원문 `d.y>=-.3f`의 값0.3을-0.3으로 보정했다. 공개 서버의 저장 상태·일반 CSV도 실제로-0.3이 되며 참조 항목의 읽기 전용 상태는 유지된다.
- 나머지는 현재 로컬의 계산·검사 코드에서 확인되었다. 총38개를 원문 부호대로 읽도록 수정하고 실제 로컬 저장 CSV·기준값을 갱신했다. 파일·원문 문맥이 다른13곳에 걸쳐 있으며 세부 ID는 LOCAL_VERIFICATION.json에 보존했다.
- `#pragma warning disable 0649`의 경고 번호를 숫자로 수집하던1행은 스탯 목록에서 제외했다. 현재 로컬 항목 수가14,686에서14,685로 줄어든 이유다.
- 뺄셈 연산자와 음수 피연산자의 부호를 구별한다. 양수/음수를 바꾸어 반영해도 `--`로 합쳐지지 않도록 처리했다. 소수·지수·16진수·2진수와 원래 C# 접미사를 유지한다. 16진수 E/D는 지수/실수 문자가 아닌 숫자로 다룬다.
- 최신 CSV의 숫자 표기는 `csharp-literal-v3`다. 이전v2의 안전한 값은 계속 읽는다. 과거 파서가 실제로 부호를 놓치던 문맥의 양수 오류 값은 구형 파일에서 거부하고 재내보내기를 안내한다. 최신 형식으로 의도적으로 입력한 양수는 자동 음수 변환하지 않는다.
- 연결 도구가 보낸 숫자 원문과 결과값이 다르면 적용 완료를 승인하지 않는다. 원본 해시·반영 전후 값·백업·재추출 검사도 유지한다.

## 퍼센트 단위 확인

편집기는 원본 숫자 단위를 사용한다. 예를 들어 확률 조건 `random.NextDouble() <= chance`에 쓰이는0.9는90%의 확률이지만 CSV에는0.9로 저장한다. 퍼센트 수치 자체를 쓰는75는75로 유지한다. 배율0.75는 원래 값의75%라는 뜻이며, 원문을75로 바꾸는 뜻이 아니다. `%` 문자가 붙은 셀은 숫자로 잘못 처리하지 않고 가져오기를 거부한다. 모듈로 연산자 `%`도 백분율 변환으로 해석하지 않는다.

## 검증 결과

- 전체 로컬 대조: 값 불일치0, 교체 위치 불일치0, 미확인 리터럴0, 일반 CSV 왕복 불일치0.
- 실제 공개 사이트의103개 카테고리 CSV를 전부 내려받아12,931개 값/숫자8,530개의 일치를 확인했다. 로컬 CSV도14,685개 값/숫자9,993개가 모두 일치했다.
- 공개본은 확인된0.3→-0.3 한 값만 바뀌었고, 다른12,930개 값과 원본 지문은 유지됐다. 보정 이력은1번 추가되고 두 번째 조회에서 revision이 유지됐다.
- 복사 프로젝트의 C#·JSON·Settings에서 일반 CSV 및 PC 전달 CSV 가져오기·명시 반영을 검증했다. 비율0.625, 퍼센트 수치62.5, 음수-0.12, 작은 소수0.0000025가 각각 그대로 적용됐다. 웹의 인증 요청→작업 대기열→실제 연결 도구→원본 쓰기→재추출→완료 응답도 통과했다. 반영된 복사 C#를 Roslyn으로 재검사했다.
- 기능 검사120개와 설명 데이터 검사가 통과했다. 실 Unity 원본 파일 쓰기0회. 실제 게임의 밸런스 수치를 바꾸는 작업이 아니라 잘못 읽던 편집기와 전달 경로의 수정이다.
