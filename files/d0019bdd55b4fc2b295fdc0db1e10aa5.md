# 18쪽 구성 계획

사용자 후속 요청: “그래도 한게 많아서 10장은 훨씬 넘어야 한다..?”

분량을 18쪽으로 확대하되 각 쪽은 진행 작업·방법·현재 상태·남은 과제를 짧게 적는다. 완료작이나 확정 기획으로 표현하지 않는다.

1. 프로젝트 개요: 어두운 표지, 진행 중 표기, 플레이 흐름.
2. 전체 작업 요약: 밝은 화면, 네 묶음의 작업과 진행 방법.
3. 기획 의도와 플레이 구조: 어두운 구분 화면, 회수와 생존 선택 및 반복 구조.
4. 전투·생존·의료: 밝은 화면, 실제 피격·부상·치료 방법과 후속 조정.
5. 무기·탄약·모딩: 왼쪽 텍스트, 오른쪽 실제 개조 화면.
6. 인벤토리·파밍: 상단 설명, 큰 실제 리그·배낭 화면.
7. 거점·보관·거래: 밝은 화면, 회수·정비·재출격의 단계별 설명.
8. 성장·연구: 오른쪽 설명, 왼쪽 실제 성장 화면.
9. 동료와 칩 기반 교체: 왼쪽 설명, 오른쪽 실제 동료 화면.
10. 퀘스트·대화·기록: 넓은 실제 화면과 임시 대본/정식 콘텐츠 구별.
11. A맵 구조와 동선: 큰 실제 맵 화면, 기획 의도 및 후속 검증.
12. 기계 역할과 진영 AI: 왼쪽 설명, 오른쪽 실제 기계 화면.
13. 캐릭터 제작·통합: 넓은 캐릭터 결과 화면, 제작·재질·동작 검토.
14. UI·미니맵: 실제 화면과 Figma에서 Unity 적용까지의 방법.
15. 전투 피드백·음향: 밝은 화면, 표시·소리·피격 방향의 역할 설명.
16. 제작·검증·기록 방식: 어두운 화면, 문서·적용·검증·증빙의 작업 방식.
17. 향후 작업: 기존 마지막 쪽을 옮기고 최신 상태에 맞춘 과제.
18. 상세 기록 링크: 기획 라이브러리 전체 URL과 초안 성격을 큰 글씨로 표시.

## 공통 디자인

- 글꼴: Noto Sans KR Regular/Medium/Bold. 제목 64~78, 본문 28~32.
- 배경: 짙은 숲빛 charcoal / 따뜻한 흰색. 강조: 밝은 연두색.
- 반복 요소: 왼쪽 가는 연두색 띠, 간결한 구분선, 하단 진행 중 표기와 쪽수.
- 본문은 관계 있는 항목끼리 자동 배치한다. 텍스트 폭을 먼저 지정한 뒤 높이를 자동 계산한다.
- 실제 캡처를 사용하고 각 그림에 기능 확인 화면/개발 중 상태를 명시한다. 기획 이미지와 실제 게임 결과를 혼동하지 않는다.
- 텍스트 중심/이미지 중심/좌우 분할/어두운 구분 화면으로 리듬을 나눈다.

## 구현 공통부

색·글꼴·노드 생성 함수는 도구 호출 간 동일한 preamble을 재사용한다. 모든 appendChild 이후 위치를 설정한다. 모든 텍스트 변경 전에 현재 글꼴을 읽고 loadFontAsync를 완료한다. resize 다음 textAutoResize=HEIGHT를 적용한다. 각 배치에서 생성 노드 ID, 슬라이드 ID, 바깥 경계·텍스트 높이·형제 겹침 검사 결과를 반환한다.
