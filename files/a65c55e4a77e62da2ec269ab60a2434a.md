# 총기 모딩 독립 검토

- 검토일: 2026-10-20.
- 검토 담당은 런타임·에셋을 수정하지 않았다. 작성 범위는 이 기록, `Assets/Escape/Editor/WeaponModdingIntegrationChecks.cs`와 해당 meta, `work/weapon-modding-tests/`뿐이다.
- Unity 실행·Play 전환·사용자 세이브 조작은 메인 담당이 통제한다. 검증은 새 메모리 프로필 또는 미리보기 장면의 임시 오브젝트를 사용한다.
- 이전 조사인 `REFERENCE_RESEARCH.md`를 보존했다. 타 게임의 관찰 수치와 현재 구현의 자체 튜닝값을 혼동하지 않는다.

## 1. 검토 범위

읽은 실제 구현은 `RifleState.cs`, `WeaponAttachments.cs`, `InventoryWeaponAttachments.cs`, `WeaponModdingTransactions.cs`, `InventorySnapshot.cs`, `ProfileSession.cs`, `ProfileData.cs`, `BasecampTransactions.cs`, `RifleController.cs`, `RifleAttachmentPresentation.cs`, `PlayerMotor.cs`, `PlayerRules.cs`, `TopDownCamera.cs`, `CombatSignals.cs`, `EnemyController.cs`, `EnemyBrain.cs`, `InventoryWeaponModding.cs`, `InventoryWeaponDetails.cs`, `InventoryGridPresentation.cs`다. 생성·반환·호환성의 기본 단위 규칙은 제작 담당의 Core/Inventory checks와 중복하지 않고 교차 시스템 경계를 우선 검사한다.

## 3. 독립 검증 도구

호출할 클래스는 `Escape.Tests.WeaponModdingIntegrationChecks`다.

- `Run()` — Editor에서 실행 가능한 교차 시스템 검증. 결과 파일 `INDEPENDENT_INTEGRATION_CHECKS.txt`.
- `RunRuntime()` — 메인이 통제하는 적 없는 미리보기 Play 장면에서 호출. 자체 임시 캐릭터/카메라/총/청각 리스너를 만들고 finally에서 제거한다. 결과 파일 `INDEPENDENT_RUNTIME_CHECKS.txt`.
- 메인 하네스의 실행파일·종료·Play 관리를 대체하지 않는다. 생성한 테스트 오브젝트와 ScriptableObject만 제거하며 사용자 장면이나 설정 에셋을 저장하지 않는다.

`Run()`의 핵심 검증:

1. 확장 탄창·소음기·전술 장치가 달린 총의 완전한 프로필 JSON 왕복.
2. 거점 저장 실패와 성공 모두 탄약·현재 총 객체·연사 쿨다운·분산·전술 상태 보존.
3. 출격 시 같은 총과 쿨다운 유지, 출격 중 개조가 disk 실패에 영향받지 않고 체크포인트를 덮어쓰지 않는지 확인.
4. 부품 변경으로 연사 제한을 우회할 수 없고 재장전 중 변경은 원자적으로 거부하는지 확인.
5. 추출 저장 실패 → 동일한 raid 상태로 재시도 → JSON 재로딩까지 부품과 탄약 수량 보존.
6. 사망 저장 실패 재시도 → 장전 탄약 소실이라는 기존 정책 → 부품을 가진 묘비 총 회수 → 재추출 → 중복 청구 제거.
7. 생성된 상점 상품에서 실재 부품 구매·과금, 개조된 가방 총의 판매가에 총과 부품이 한 번만 포함되는지 확인.

`RunRuntime()`의 핵심 검증:

1. 실제 CharacterController의 기본/개조/조준 이동 변위 비교.
2. motor의 조준 진입 시간이 실제 PlayerState 타이머 완료를 제어하는지 확인.
3. 시야 배율이 실제 follow camera override로 이어지고 비조준 시 해제되는지 확인.
4. 고정 난수 fixture로 실제 FireDirection의 수직·수평 반동이 각각 포인터 오프셋에 적용되는지 확인.
5. 실제 발사 → CombatSignals → EnemyController.Hear의 같은 거리 적이 일반 발사는 듣고 소음기 발사는 못 듣는지 확인. 피격·탄착 인식은 유지되는지 확인.
6. 장착만 한 상태/활성/가방 열기/닫기/꺼짐에서 실제 방향성 Light의 활성과 사거리 확인. 일시 정지 및 지도 입력 소유 중에는 실제 조명만 꺼지고 전술 장치 상태가 보존되며, 해제 후 복원되는지 확인한다. 일시 정지 중에는 rifle.Clock이 진행하지 않아야 한다.
7. 활성 총이 사라지면 조명·카메라·이동 배율이 기본값으로 정리되는지 확인.

청각 fixture는 NavMesh 생성을 피하기 위해 리스너의 Brain/Target/Receiver 의존성을 테스트에서 주입한다. 실제 EnemyController.Hear와 실제 구독 메서드를 사용하며 AI 순찰·추격 전체를 통과시킨 것으로 주장하지 않는다. 조준 timer 검증은 motor의 공개 진입 시간과 실제 PlayerState 함수의 연결 확인이며 실제 마우스 입력 자동화는 메인의 UI 검증 범위다.

## 4. 실행 상태

- **정적 컴파일 통과**: `work/weapon-modding-tests/IndependentCompile.csproj`가 당시 최신 `Library/ScriptAssemblies/Assembly-CSharp.dll`와 UnityEngine DLL을 참조하여 빌드됐다. 경고 0, 오류 0. Unity를 새로 실행하지 않았다.
- **Run 실제 Unity 실행 통과**: 메인이 실행한 `INDEPENDENT_INTEGRATION_CHECKS.txt`를 독립 검토 담당이 직접 읽었다. 마지막 줄은 `PASS independent profile integration: 76 assertions`이며, 저장 실패·raid 무저장·탄약/쿨다운·추출 재시도·사망→묘비→회수→재추출·선택 총 판매의 각 PASS 결과를 확인했다.
- **RunRuntime 실제 Unity Play 실행 통과**: 메인이 실행한 `INDEPENDENT_RUNTIME_CHECKS.txt`를 독립 검토 담당이 직접 전부 읽었다. 마지막 줄은 `PASS independent runtime integration: 38 assertions`다. 실제 CharacterController 변위, motor 조준 지연, 카메라 override, 수직/수평 반동, 발사→적 청각 경로, 직접 피격/탄착 인식 유지, Spot Light 켜짐/꺼짐·거리, 일시 정지/지도/가방 중 해제와 복원, 활성 총 제거 시 정리의 개별 PASS를 확인했다. 일시 정지의 Clock은 101→101로 보존됐다.
- **메인 runtime 교차 확인**: `RUNTIME_CHECKS.txt`의 실제 Unity Play 12개 항목과 최종 `RESULT PASS`를 직접 읽었다. 확장 탄창·탄약 보존·반동·이동·조준·카메라·조명·레이저 활성 효과·실제 발사 소음 전달을 확인한다.
- **별도 카메라 검증 교차 확인**: `CAMERA_CHECKS.txt`를 직접 읽었다. 16:9/4:3/21:9/1:1에서 24방향·10개 요청 크기의 viewport 구도 및 단조로운 lookahead 증가, 기본 16:9의 4x 회귀·작은 오프셋·FOV/프레이밍 제한 유지가 PASS이며 최종 1,924 assertions 통과다.
- 독립 코드·프로필·런타임 검토에서 현재 검증 범위의 미해결 차단 문제는 발견하지 못했다. 마지막 UI 수정의 실제 재검증과 전후 화면 증빙·전체 변경 기록 마감은 메인 담당의 별도 완료 항목이다.

## 5. 검토 중 확인한 후속 사항·해석 제한

- 인벤토리 제작 담당이 기존 판매 UI의 같은 ItemId 여러 총 중 선택 인스턴스와 판매 인스턴스가 다를 수 있는 점을 발견하고 수정했다. `InstanceSaleCredit(uid)`와 `SellInstance(uid, now)`가 추가됐으며 `SessionTestWorld` 판매 UI가 선택 UID를 전달하는 코드를 읽어 확인했다. 독립 프로필 검증에서 같은 종류의 총 두 자루 중 두 번째 개조 총을 판매하여 다른 총 보존과 부품 포함 판매가를 확인하는 실제 Unity 실행 PASS를 읽었다.
- 플래시·레이저는 하나의 Tactical 슬롯을 공유하며 복합기가 둘의 기능을 제공한다. 별도의 두 전술 슬롯을 지원한 것으로 설명하지 않는다.
- 소음 값은 청각 범위 배율이다. 음량·피해·총구 화염 감소량으로 표현하면 부정확하다.
- 레이저의 은폐 불이익·빛에 대한 적의 새 인식 규칙은 이번 실제 코드에서 확인하지 못했다. 존재하지 않는 감지 비용을 구현 완료로 주장하지 않는다.
- 현재 발사 모델은 hitscan이다. 조사 제안의 탄속 손익은 이번 부품 데이터에 포함하지 않아 실제 탄속 개선이 구현됐다고 주장하지 않는다.
- 전후 게임 화면과 클릭·드래그 실제 UI 동작의 증빙은 메인이 별도로 남겨야 하며 이 검토의 메모리 체크가 그 증빙을 대체하지 않는다.
