# 테스트용 출격 중 캐릭터 칩 변경 허용

적용 및 실제 실행 검증 완료. 2026-10-22.

사용자 요청: 캐릭터 칩의 로비 전용 기획을 유지하되 테스트 중에는 출격 상태에서도 장착·교체·해제하여 캐릭터를 쉽게 확인한다. 기존 제한 코드는 삭제하지 않고 다시 활성화할 수 있게 둔다. 기존 칩 버리기 금지는 유지한다.

변경 전 상태: 세션 데이터와 실게임/UI 양쪽에서 출격 중 변경을 차단했다. 미니맵 채팅의 공유 Unity 검증 종료와 명시 인계를 기다리면서 staging만 준비했다. 본 프로젝트의 규칙 변경 전에 격리 프로필로 출격하여 실제 잠금 화면 `before_raid_slot.png`를 저장하고 장착·해제 차단 및 소유 상태 불변을 확인했다.

방식: `CompanionChipCatalog.AllowRaidChangesForTesting` 단일 설정을 true로 두어 장소 제한만 우회한다. false로 바꾸면 세션·실게임·UI가 기존 출격 제한을 다시 적용한다. 사망·저장 중·입력 잠금 제한과 칩 소유/드롭 방지는 유지한다. 창고 접근은 거점 전용으로 유지한다.

출격 중 변경은 정상 회수 전 전리품까지 저장되지 않도록 현재 세션에만 적용하고, 정상 탈출·사망 복귀의 기존 저장 절차를 따른다. 기존 가방의 정화 칩 칸만 원자적으로 변경해 무기·방어구·의료품의 실제 객체와 재장전 진행·발사 쿨다운·탄퍼짐·사용 진행을 보존한다. 출격 체크포인트, revision, RunId 및 전리품 저장 여부는 바꾸지 않는다.

수정 파일은 다음 7개다. 루트는 `C:/UnityProject/escape/Assets/Escape/`이다.

- `Runtime/Companions/CompanionChipCatalog.cs`: 테스트 허용 설정과 아이템 설명.
- `Runtime/Save/ProfileCompanions.cs`: 장소 조건·창고 제한·출격 중 메모리 변경.
- `Runtime/Inventory/Core/InventoryCompanionChipTransactions.cs`: 검증된 정화 칩 칸만 변경하는 내부 트랜잭션.
- `Runtime/Stage/SessionCompanionChips.cs`: 로비와 출격 페이지의 실제 변경 경로.
- `Runtime/Inventory/InventoryCompanionChips.cs`: 테스트 안내, 출격 중 가방 해제 허용, 창고 해제 버튼 비활성화.
- `Editor/PhysicalCompanionChipChecks.cs`, `Editor/CompanionChipChecks.cs`: 원래 제한과 임시 허용 양쪽의 회귀 검사.

기존 6개 파일의 변경 전 원본은 `source_before/`에 보관했다. 신규 트랜잭션 파일은 이전 파일이 없다. 캐릭터 모델·맵·인벤토리 레이아웃은 이번 변경 대상이 아니다.

사전 독립 검토: 처음 제안한 가방 스냅샷 재생성 방식이 재장전·발사 상태를 초기화할 위험을 발견하여 적용 전에 칩 칸만 변경하는 방식으로 교체했다. 새 트랜잭션은 전체 후보 검증과 칸별 사전 검사 후 적용하며, 다른 물품·장비 객체를 교체하지 않는다. static 컴파일 오류0과 독립 소스 검토 이후 main에 적용했다. `INDEPENDENT_SOURCE_REVIEW.md` 참조.

검증 결과:

- 수정 전 실제 실행 3항목 PASS. 출격 중 기존 잠금과 무변경을 확인했다.
- 최종 Editor 실물 칩 검사 71항목, UI 검사 27항목 PASS(20:42:50). 테스트 설정 false에서 기존 제한을 검사하고 true에서 출격 교체·정확 좌표 해제·창고 접근 차단·사망 보존·정상 탈출 저장·재로드·재장전·발사 간격·탄퍼짐 보존을 검사했다. 전역 설정은 검사 전 값으로 복원한다.
- 실제 Unity 격리 출격 실행 18항목 PASS. 진짜 소총 발사 및 재장전 중 교체 후 Bag/PlayerState/RifleState/Recoil/ItemUseState 객체와 재장전 종료 시각·다음 발사 시각·탄퍼짐을 유지했다. 사용 중인 의료품의 ActionId와 완료 시각도 해제 직후 유지했다. 탄약은 초기100+회수3−실제발사1=102로 보존됐다.
- 출격 중 칩 교체·해제·재장착 전후 모든 칩의 instance와 수량이 같고, 격리 저장 파일의 바이트·revision·RunId가 변하지 않았다. 회수 전 전리품을 저장하지 않는다.
- 테스트 설정을 실제 실행 중 false로 바꾸자 세션·실게임 변경이 모두 차단됐고 소유물이 유지됐다. true로 복원하자 다시 허용됐다.
- 실제 마우스 4항목 PASS: 가방→슬롯 장착, 슬롯→가방 해제, 더블클릭 재장착, 바닥 버리기 거부. 버리기 전후 가방 JSON이 정확히 같았다.
- `runtime_errors.txt`는 0바이트로 Error/Exception/Assert 없음. 원래 `StageA_Relay_Blockout_v08` 장면을 Edit 상태로 복원했다. 검증용 helper 3개는 main에서 제거하고 `work/chip-raid-test-20261022/`에 재현 소스로 보관했다. 실제 사용자 저장은 사용하지 않았다.

2026-10-23 마무리 확인: 현재 main 7파일은 검증한 staging과 해시가 모두 일치한다. 기본 테스트 허용값은 true이며, helper 제거 후 Runtime/Editor 어셈블리가 10월22일20:43:43/20:43:51에 다시 컴파일됐다. 실제 편집기 화면에서 원래 v08 장면·Edit·미저장 별표 없음 상태를 확인하고 `after_editor.png`를 저장했다. 이 최종 편집기 사진은 10월23일 촬영분이며 Game 뷰가 확대된 상태라 변경 전 편집기 사진과 창 배치는 다르다. 출격 인벤토리 전후 비교 사진은 같은 1920×1080 조건이다. 최종 해시와 확인 결과는 `final_source_hashes.json`, `final_verification.txt` 참조.

별도 관찰: 현재 편집기에 `Particle Velocity curves must all be in the same mode` 메시지가 표시된다. 발생 오브젝트는 확정하지 않았으며 이번 칩 접근 변경에서 파티클 시스템·맵 코드는 수정하지 않았다. 칩 변신 효과는 ParticleSystem 대신 별도 빌보드 메시를 사용한다. 이번 격리 칩 검사의 오류0 결과와 현재 프로젝트 전체 콘솔 상태를 구별하며, 프로젝트 전체의 오류가 없다고 보고하지 않는다.
