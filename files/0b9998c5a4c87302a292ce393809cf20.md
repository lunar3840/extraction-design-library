# 인벤토리 형태와 플레이 경험 분석서 40쪽 완료 기록

## 변경 이유

인벤토리가 플레이어에게 요구하는 조작을 나열하는 데서 그치지 않고, 선택의 차이가 어떤 경험으로 이어지는지 설명할 필요가 있었다. 결론도 개인적으로 만들고 싶은 게임을 적는 형식에서, 게임의 설계 목적에 더 유리한 인벤토리 형태를 제안하는 형식으로 바꿨다.

영상 사례는 화면만 보고 바뀐 물품과 빈자리를 직접 찾아야 해 핵심을 읽기 어려웠다. 장별 흐름을 안내하는 소목차와 인벤토리 영역을 설명하는 기존 UI KIT 역설계 도면도 필요했다.

## 실제 수정

- 최근 34쪽 구성에 장별 소목차, 대표 화면 구성 두 장과 최종 결론을 더해 최종 40쪽으로 정리했다. 이전 Figma 작업 페이지들은 보존했다.
- 대목차는 문서 개요 / 관찰과 설문 / 비교와 설계의 세 단계다. 03·15·34쪽에 현재 단계와 이어질 내용을 안내하고, 18쪽에서 사용자 설문을 별도 소개한다.
- 09·10쪽에 델타포스와 아크 레이더스의 기존 UI KIT 역설계 화면을 복원했다. 실제 물품 사진 대신 러프 심볼과 번호 범례를 사용한 편집 가능한 도면이며, 예시 숫자는 99·999 형식을 유지한다.
- 16·17쪽은 핵심 위치를 확대·표시하고, 담을 물품 → 시도한 조작 → 결과 또는 이후 행동으로 줄였다. 캡처 비율을 유지하고 불필요한 사이드를 잘랐다. 타르코프의 협동 PvE와 델타포스의 PvP 사례를 동일 강도의 위협이나 복귀 속도로 비교하지 않는다.
- 이전 33·34쪽의 결론은 현재 38·39쪽으로 이동했다. 공간 운영을 파밍의 전략으로 삼는 목적, 수집 뒤 전투·탐험의 흐름을 이어가는 목적에 맞춰 형태를 제안한다.
- 40쪽에는 두 선택을 간결하게 종합했다. “이런 목적의 게임을 설계한다면 이 형태를 차용하는 것이 더 유리함”이라는 조건문으로 정리했다.
- 영상의 출처 표현은 07·15·16·17쪽에서 모두 “유튜버 빅헤드의 영상”으로 통일했다.
- 문서 내 작업 이력 설명은 제외하고 조사 기준과 결과를 설명한다. 이 변경 기록은 분석서 본문과 별도로 관리한다.
- 편집 후 Figma에서 직접 고화질·sRGB PDF를 출력했다. 최종 산출물은 40쪽, 16,822,846바이트다.

## 조사와 해석 범위

영상 관찰과 사용자 설문은 별도 근거로 구분한다. 영상 속 행동에 설문 점수를 붙이지 않는다. 설문은 7명이 답한 경험 중 83건을 점수 계산에 사용했고, 두 유형의 모든 조건을 답한 같은 4명의 60건도 따로 비교했다. 여러 게임을 답한 사람의 비중이 커지지 않도록 개인 안의 게임별 평균을 먼저 계산한다.

같은 4명의 급박·배낭 부족 조작성은 격자형 3.3점, 균일 슬롯형 6.5점으로 나타났다. 이는 이 표본의 주관적 수월함이며, 실제 소요시간이나 전투 성과를 측정한 값이 아니다. 정리를 중단하거나 물품을 포기하는 선택은 두 유형에 공통으로 나타나므로 격자형만의 특징으로 설명하지 않는다.

## 최종 결론

공간 배분과 정리, 무엇을 포기할지 고르는 과정을 파밍의 핵심 재미로 삼는 게임을 설계한다면 격자형을 차용하는 것이 더 유리하다. 수집·보급 조작을 간결하게 하고 전투·탐험의 흐름을 이어가는 게임을 설계한다면 균일 슬롯형을 차용하는 것이 더 유리하다. 형태를 선택한 뒤에는 용량·중첩·정보 표시를 함께 조절한다.

## 검증

- 40쪽의 순서와 1920×1080 크기, PDF 본문에서 수정된 결론과 영상 표기를 확인했다.
- 40쪽 전체를 이미지로 렌더하고, 결론·영상·설문 설명 페이지를 확대해 확인했다.
- 최종 문구 기준으로 화면 밖 텍스트, 글자 겹침, 푸터 충돌은 각각 0건이다.
- 구조 수정 과정에서 보호 대상으로 둔 설문 본문과 수치의 차이는 0건이다.
- PDF는 16.8MB로 500MB 미만이다. 링크 11개를 보존했다.
- 이번 인계는 완료 산출물 확인과 열람본 생성만 수행했다. Figma 재편집, 영상 재조사, 설문 재수집은 하지 않았다.

## 인계 및 게시 상태

변경 기록과 선택 이미지를 기존 기획 라이브러리 담당 채팅에 전달한다. 새 대표 주제를 임의 생성하지 않는다. 자료 수신과 해시 확인, 기존 주제의 후속 회차 연결, 실제 공개 열람 검증은 게시 담당 채팅에서 완료해야 한다. 이 로컬 기록만으로 라이브러리 게시 완료를 의미하지 않는다.
