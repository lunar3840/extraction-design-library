# CSV로 PC 이동 기능 독립 검증

- 검증일: 2026-10-23 (Asia/Seoul)
- 검증 파일: `data-editor/verify-transfer.mjs`
- 실행: `node data-editor/verify-transfer.mjs`
- 결과: **28개 검사 모두 통과**. 별도 Node 구문 검사 통과.
- 범위: 실제 `data-editor-web/worker.mjs`, 실제 로컬 `createEditor` 및 CSV 전달 공통 모듈을 사용했다. 클라우드 저장소는 인메모리 SQLite, Unity는 매 검사에서 새로 만든 임시 프로젝트만 사용했다. 실제 Unity 프로젝트를 읽거나 복사하거나 수정하지 않았다.

## 확인한 정상 경로

1. 공개 열람 상태에서는 변경값 CSV 내보내기가 거부된다.
2. 비밀번호 로그인 후에도 CSRF 누락 또는 다른 출처의 요청은 거부된다.
3. 저장하지 않은 플레이어 체력 `100 → 110`과 경제 값 `15000 → 18000`을 하나의 BOM CSV로 내보낸다. 내보내기는 웹 저장, 반영 작업 생성 또는 Unity 변경을 수행하지 않는다.
4. 별도 PC 역할의 임시 프로젝트에서 분류 선택 없이 같은 파일을 가져온다. 가져오기는 값 비교용 변경 목록만 반환한다. 로컬 저장 CSV와 게임 원본 모두 그대로다.
5. 검증 결과의 변경 전후 값과 두 파일을 확인한 다음 별도로 `apply`를 호출하면 임시 게임 원본 두 파일이 바뀐다. 기존 원본 백업, 반영 명세 및 재추출 값까지 확인했다.
6. 같은 파일을 다시 가져오면 이미 적용된 값으로 처리하며 추가 파일 수정이나 백업 생성을 하지 않는다.

## 거부·보존 검사

- 다른 프로젝트, 다른 형식, 없는 ID, source/field/entity/type 변조, 잘못된 숫자, 정수 항목의 소수, 중복 ID를 거부한다.
- 읽기 전용 ID, 필수 열 누락, 알 수 없는 열, 닫히지 않은 따옴표를 거부한다.
- 한 행의 이전 값이 현재 원본과 다르면 다른 분류의 정상 행도 가져오지 않는다. 거부 후 소스 해시와 저장 CSV 값이 그대로인지 확인했다.
- 최소 드롭 수량이 최대 수량을 넘는 조합처럼 단순 자료형 검사만으로 잡히지 않는 오류도 로컬 원본 도메인 검증에서 거부한다.
- 편집기를 연 뒤 원본이 바뀌면 가져오기/반영이 이를 덮어쓰지 않는다.
- 같은 행 ID가 유지되는 다른 항목 또는 다른 파일의 변경은 허용한다.
- 이미 적용된 값과 다른 로컬 대기 편집본이 남아 있어도, CSV의 목표 값을 변경 목록에 포함하여 명시적으로 덮어 스테이징한다. 저장 CSV를 정리하려면 화면에서 CSV 저장을 사용한다.
- 문자열 값과 이전 값은 JSON 문자열 표기로 CSV에 보관한다. `=HYPERLINK(...)`로 시작하는 값이 스프레드시트 수식으로 시작하지 않으면서 쉼표·따옴표·개행까지 손실 없이 가져와 반영되는 것을 확인했다.
- 로컬 HTTP 가져오기 역시 로컬 편집기 토큰을 요구하고, 가져오기만으로 원본을 적용하지 않는다.

## 편집기 재시작 시 줄 ID 재사용 회귀 검사

공유 프로젝트에서 다른 작업이 C# 코드를 수정한 뒤 로컬 편집기를 재시작할 때, 기존 숫자 행의 줄 ID를 새 불리언 필드가 재사용하는 상황을 임시 프로젝트에서 재현했다. 수정 전에는 저장 CSV의 숫자 `2`를 새 `UseAllowsReload` 불리언으로 읽으려다 시작에 실패했다. 초기화 보완 후 아래 네 검사가 모두 통과했다.

- 기존 CSV에 미반영 편집이 없다면 `Charges` 숫자 행이 `UseAllowsReload` 불리언으로 바뀌어도 현재 원본의 `false`를 다시 수집하여 시작한다. 저장 CSV의 field/type/value도 새 메타데이터로 갱신된다.
- 숫자 자료형이 그대로라도 필드가 바뀌었다면 기존 값 대신 현재 새 필드 값을 수집한다.
- 이전 숫자 행에 미반영 값이 있고 새 불리언 행으로 재사용되었다면 자동 시작을 409로 거부한다. 모든 기존 CSV와 기준 파일의 바이트가 보존된다.
- 숫자 자료형이 그대로인 필드 재사용에도 미반영 편집이 있으면 동일하게 거부하고 기존 파일을 보존한다.

## UI 코드 읽기 검토

- 상단 `CSV로 PC 이동` 진입점과 웹/로컬별 내보내기·가져오기 동작을 확인했다.
- 웹 내보내기는 현재 미저장 값을 포함하고 인증 여부를 다시 확인한다. 실제 권한 판단은 Worker에서도 시행한다.
- 로컬 전달 CSV 가져오기는 분류 선택을 생략하고 변경 비교 화면을 연다. 최종 반영 버튼을 누르기 전에는 원본을 변경하지 않는다.
- 변경 비교/오류 표시는 HTML 이스케이프를 사용한다.
- 이는 코드 읽기 결과다. 실제 공개 배포 성공, 브라우저 클릭 동작 및 전후 스크린샷 증빙은 메인 담당 검증과 구분한다.

## 현재 식별 방식의 제한

C# 수치 행 ID는 소스 줄 번호를 포함한다. 웹 스냅샷 작성 후 코드에 줄을 삽입하여 해당 ID가 바뀌면 이전 CSV를 추측해서 다른 항목에 적용하지 않고 거부한다. 이 경우 최신 원본을 다시 읽고 게시한 기준에서 변경 CSV를 다시 만들어야 한다. 이 안전 거부도 별도 검사에서 통과했다.
