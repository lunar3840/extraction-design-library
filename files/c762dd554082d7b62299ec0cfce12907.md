# 슬롯 상시 메타데이터 제거 / 큰 아이콘과 수량

상태: 코드·정적 검증, 실제 r06 화면 및 최종 마우스 치료/hover 검증 완료. 독립 검토 기록을 메인이 읽어 통합했다. 기존 간격/tight-fit 작업을 대체해 위장한 기록이 아니라 사용자의 새 후속 지시에 따른 별도 단계다.

## 지시 / 전 증빙

사용자는 아이템 슬롯의 V1/V2 등 텍스트와 의료 잔량/내구 등 상시 정보를 없애고, 슬롯 외곽선·배경색으로 티어를 구별하며 큰 아이콘과 우하단 수량만 표시하도록 명확히 지시했다. 메인의 추가 확정으로 수량1도 생략하지 않고 ‘×’ 없이 흰 숫자로 표시한다. 상세/hover의 V/T/잔량은 유지한다.

메인은 실제 `before_slot_simplification_native.jpg`를 확보했고 Figma의 현재 수정 전 export 사본 `before_slot_simplification_figma_inventory.png` provenance를 기록한 뒤 코드 수정을 승인했다. 승인 신호 이전에는 읽기만 했다. 대상4파일/.meta는 기존 before를 덮지 않고 `source_before_slot_simplification/`에 추가 보관했다.

## 실제 변경

- grid 공유 `DrawGridCardContents`는 카드 안4px inset의 큰 아이콘과 우하단 수량만 그린다. V/T 배지, 의료 resource 수치, 이름, 보호/손상 문자 overlay를 모두 제거했다. 실제 item/protection/durability/quantity 데이터와 조작은 바꾸지 않았다.
- 가방/보관함/완료된 전리품 grid가 같은 렌더를 공유한다. 전리품 helper 부재 fallback도 같은 큰 그림/수량 구조를 사용한다. 미검색/수색 중의 ‘?’/수색 중/남은 시간은 그대로이며 공개 전 item 정보/hover를 추가하지 않았다.
- 의료 아이콘의 기존 tight alpha fit과 non-readable fallback을 유지한다. 비의료/회전 무기 렌더도 기존 `GlassIcons.Draw`를 사용한다.
- `ItemTierPresentation.DrawQuantity`는 수량1을 포함해 흰 숫자를 우하단의 최소28×18 논리 영역에 표시한다. ‘×’를 붙이지 않는다. 사용자의 추가 지시에 따라 티어 RGB/가격 문턱/outline 두께/shape/fill alpha .65/.79는 유지하고, 슬롯 자체 색의 tier 식별력을 위해 최종 tint 혼합을 일반 .24/선택 .32, edge alpha를 일반 .70/선택 .95로 보강했다. 이전 .14/.60의 중간값은 최종 구현으로 기록하지 않는다.
- 인벤토리 퀵슬롯도 의료 잔량 대신 실제 bag 총개수를 같은 quantity renderer로 표시한다. 새 공개 helper `QuickSlotItemCount(string id)`는 bag.Count를 읽기만 한다. null ID/controller는0이다. 기존 `QuickAmount` 함수의 본문은 보존했으나 현재 슬롯에서는 호출하지 않는다.
- full inventory quick 그림을 넓혀 같은 icon rect에서 의료 tight fit→기존 fallback을 적용했다. 키3/4/5와 빈 슬롯 ‘등록’은 조작 안내이므로 유지했다. compact quick row는 기존23px 높이 예외를 유지한다.
- 메인은 자신이 소유한 `InventoryHudView.cs`에서 동일 새 count/quantity helper와 tight fit을 별도로 연결했다. 이 담당자가 HUD 파일을 수정하지 않았다. MedicalIcons의 경로 범위 주석 갱신도 메인 소유다.

## 유지 / 검증

- 변경 소유4파일: `InventoryGridPresentation.cs`, `ItemTierPresentation.cs`, `LootInteractor.cs`, `InventoryGlassView.cs`의 인벤토리 quick 표시 부분. Main UiTheme/HUD/캐릭터·카메라·모델·장비 rect·6px gap·pitch·슬롯 원점을 이 담당자가 변경하지 않았다.
- hover 및 details 코드는 수정하지 않았고 그 안의 V/T/medical resource/이름/관리 기능을 유지한다. Runtime에서 기존 DrawBadge/DrawAmmoBadge를 호출하는 grid 경로가 없는 것도 검색 확인했다. API 자체를 삭제할 필요는 없어 그대로 남겼다.
- 최신 전체 runtime 정적 compile 오류0/기존 warning21: `compile_inventory_hud/runtime_compile_slot_simplification.txt`. 메인의 최신 HUD helper 사용 코드도 함께 컴파일됐다.
- `slot_simplification_ast_audit.json`: 기존80메서드와48 lambda callback이 동일하다. 변경은 공유 card 표시와 사용하지 않는 grid 메타 스타일 helper 제거, 슬롯 tint/edge, 전리품 fallback 표시, 인벤토리 quick 표시뿐이다. `QuickAmount` 본문도 동일한 것을 별도로 확인했다.
- `source_after/`의4파일과 `slot_simplification_source_manifest.json`을 갱신했다. 새로운 after 이미지는 메인이 실제 캡처한 뒤 기록한다. 앱/native 조작·reload는 하지 않았다.

## 실제 화면 확인 대상

큰 아이콘이 qty backing 밖으로 잘리지 않는지, 모든 카드의 수량1/2/50 등이 우하단에 읽히는지, V/T/잔량/이름이 card에 남지 않는지 확인한다. 티어는 fill/outline/stripe 색으로 구별되고 hover/details에서는 기존 정확한 V/T/resource가 계속 표시돼야 한다. 실제 drag/click/quick 사용과 개수 감소는 별도 입력 검증이며 정적 결과로 통과를 대신하지 않는다.

## 메인 증빙 출처 보충

`before_slot_simplification_figma_inventory.png`는 지시 직전의 실제1×Figma export `after_figma_inventory_final.png`의 원본 복사다. 이후 해당 Figma 편집 전까지 같은 상태였으며 재구성/합성하지 않았다. `before_slot_simplification_hud_1920x1080.png`도 직전 코드가 반영된 실제 r04 combat 캡처의 원본 복사이며 새로운 시점으로 위장하지 않는다. 별도로 이번 지시 후 실제 Unity 네이티브 화면을 새로 촬영한 것이 `before_slot_simplification_native.jpg`다. r04 34장과 기존4개 Figma 최종 export는 모두 보존한다.

이전 r04 입력에서 새54px 카드의 실제 hover, UID/수량50 보존 드래그0,0→5,5와180px 무기 카드의 확장된 왼쪽 클릭을 확인했다. 증빙은 `after_r04_input_hover_native.jpg`, `before_r04_input_drag_native.jpg`/`after_r04_input_drag_native.jpg`, `after_r04_input_weapon_left_hit_native.jpg` 및 input_r04 상태 파일이다. 이 결과를 이번 후속 색/표시 변경 뒤의 새 이미지로 대신하지 않는다.

## R05와 마지막 탄약 색 정합

- 실제 r05 34장 및 상태/manifest를 별도로 보존했다. 큰 그림·우하단 개수·일반 아이템의 tier 색 배경과 메타 제거를 직접 확인했고 독립 검토도 통과했다. 단, 보관함 탄약6종은 판매가 V가 모두1이라 같은 회색으로 보이는 정보 손실을 발견했다.
- 사용자 ‘색으로 티어를 명확하게 구분’ 지시를 만족시키기 위해 main이 `DrawSlot`의 색 선택만 추가 보완했다. 탄약은 실제 `AmmoRules`의 관통 T를 색으로 읽고, 다른 아이템은 기존 판매가 V 등급색을 쓴다. 공통 `Tint`, 가격, 관통 수치, `DrawBadge` 및 hover/details의 V/T 표현은 그대로다. UI 색 해석만 항목 종류에 맞게 구별한다.
- `before_ammo_slot_color_storage_1920x1080.png`는 실제 r05 보관함 원본 복사이며, 코드 원본은 `source_before_ammo_color/`에 있다. 직전 담당자의4파일 manifest는 이 보완 이전 단계 fingerprint이고, 최종 현행21파일은 `final-source-manifest.json`을 따른다.
- main 전체 runtime 컴파일 exit0/오류0/기존 경고21: `compile_inventory_hud/runtime_compile_ammo_slot_color.txt`. r06에서 탄약6종 색과 전체 렌더를 최종 확인한다.
