# post-UI 재구성 전 상태 독립 검토

상태: **재구성 before 미생성, checkpoint 차단.** Unity 편집기·Assets·Library·request는 조작하지 않고 기록과 현재 YAML을 읽었다.

## 반환 기준

- 메인 기록 `rounds/post_ui_checkpoint/BASELINE_POST_UI.json`은 2026-10-30 05:56 KST clean Edit의 scene/prefab SHA와 백업, 외부 보호 파일 29개를 저장했다. 현재 V33 C# SHA는 `F111015D27458340EAD4746CBEBAB46E52DF9694C402371A61ADE166A07F02E1`, reveal shader SHA는 `9834B4769BA6D067BB622BE495A06AB331ADBA1AA1D451B4EDCD07E2494DCE48`로 기록과 일치했다. 이는 UI 담당이 반환한 현재 checkpoint이지 V33의 최종 시각 품질 PASS라는 뜻이 아니다.
- `before_editor_native.jpg`는 전체 A맵 편집기 화면이다. CLINIC 상세 Game 전 상태의 증빙이 아니며, `before_reconstructed_` 파일명을 대신할 수 없다.

## snapshot 차단: 후보01 root 중복

- `INVENTORY_EXACT_DIFF_20261029T2100072188896Z_9b3c73bba2074717ba4ff41142fcaac4.txt`는 원본 inventory 46,685행과 현재 46,694행을 비교해 A34 root와 자식 8개, **정확히 9행 추가**를 기록했다. 그 밖 기존 행의 변경·삭제는 0이다. 검증 도구는 현재 두 A34 root 중 첫 번째만 제외하고 두 번째를 기존 씬 외부 추가로 발견했으므로 snapshot을 실패시켰다. 이 실패는 올바른 차단이다.
- 디스크 YAML에서 `StageA_Relay_Blockout_v08.unity`의 A34 GameObject는 `m_CorrespondingSourceObject: {fileID: 0}`인 scene-added child다. 동시에 `StageA_Relay_Blockout_v08.prefab`에도 같은 이름의 A34 root가 있다. prefab 저장 후 scene override가 남은 중복으로 해석된다. 동일 위치의 중복 렌더러는 candidate01의 실제 색·깊이·그림자 관찰과 6-renderer 계측을 왜곡했을 수 있다.
- 새 baseline의 예외로 9행을 허용하거나 두 root를 함께 숨겨 재구성 화면을 촬영해서는 안 된다. 메인은 백업 보존 후 scene-added override만 제거하고 prefab 소유 단일 root를 유지해 clean reload, CLINIC direct root 1개/전체 renderer 6개, 기존 행·29개 보호 hash를 다시 확인한 다음 snapshot을 재시도해야 한다. 그 후에야 `before_reconstructed_` 10 Game PNG와 report를 독립 판정할 수 있다.

재구성본은 새 UI 코드 아래 후보01 전용 root 한 개를 임시 Play에서 숨긴 화면이다. 원회차의 진짜 pre-change 이미지와 구분해 파일명·보고서·변경 기록에 그 출처를 유지해야 한다.

## 중복 복구 staging 정적 검토

- Bridge staging SHA `02F20990783B50EF5E4D88F9920886FD4C937E3BE322A000245AD3CD5C5B7AD1`는 `repair_own_duplicate`를 추가했다. clean Edit에서 CLINIC 직계 A34가 정확히 둘, 하나는 prefab source·하나는 scene-added override, 각 6 renderer·0 collider/light일 때만 `PrefabUtility.RevertAddedGameObject`로 **scene-added 한 개만** 지운다. 이후 기존 inventory 정확 일치, SaveScene, reload, prefab SHA 불변, root1/renderer6을 확인한다. 실제 Unity 실행 전 코드 수준의 범위 통제로 적절하다.
- 같은 Bridge의 `Save()`는 prefab 저장 후 새 scene-added A34 override를 되돌리고 scene 저장·재로드 뒤 root1/renderer6, Builder Audit, Validator CompareWorkingCopy를 요구한다. candidate01의 저장 중복을 반복하지 않으려는 보완이다. Unity native에서 override가 예상대로 분류되는지는 실행 로그로 확인해야 한다.
- **복구 전 추가 권고:** 두 root가 단순히 이름·renderer 수가 같은지만 확인하면 scene-added 쪽에 다른 mesh/material/transform/marker 설정이 있어도 삭제될 수 있다. Builder의 진단 함수에는 두 root의 `DiagnosticVisualSignature` 비교가 이미 있다. 복구의 같은 호출 안에서 이 시각 프로필 동등성을 필수 gate로 사용하고 다르면 중단해야 한다. 메인에게 전달했다.

후속 Bridge SHA `46E1F6D62CBBB3AD854BA2984DBACE3C9426B5E3D1ADC11C04C80A5A6BE914B3`에서 이 권고를 반영했다. `OwnedGeometrySignature`는 root 상대 자식 경로와 Validator `Describe()`를 써 두 root의 active/layer/tag/local transform, mesh/material GUID·path, renderer 상태, component JSON을 정확히 비교한다. 별도로 두 ivy marker의 실제 `sourceTarget`과 `sourceRenderers` 참조 동일성을 확인한다. 동일하지 않으면 scene-added root를 삭제하지 않는다. Builder의 별도 진단 `sceneTwoRootsVisualSignatureEqual=false`는 시각내용 차이보다는 `DiagnosticPath(t, root)`에 root 자체의 sibling `#0/#1`이 포함되는 서명 버그로 보이며, Bridge의 새 repair gate는 해당 진단 값을 사용하지 않는다. 실제 Native repair 및 reload 결과는 여전히 필요하다.

- `COMMAND_postui_snapshot_003.txt`는 완료됐다. `RECONSTRUCTION_SOURCE.txt`는 `rounds/post_ui_checkpoint` 전용 context, `allowedUiSerializedRows=0`, 단일 A34 root `#0`의 임시 Play 숨김, renderer 6개, 전용 asset 14개를 기록한다. 원회차의 변경 전 이미지가 아니라 **새 UI 코드 아래 재구성한 비교 화면**이라는 출처를 명시한다.
- 새 TSV를 독립 계수한 결과 기존 inventory 46,685행, 보호 소스 4개, frozen 참조 asset 8,497개, 후보01 root inventory 9행, root 및 의존 asset 해시 25개(전용 14개·누락 0)다. snapshot 구조는 유효하다. 실제 Game `before_reconstructed_` 10뷰와 루트 숨김·복원 보고는 아직 확인 전이다.

## 실제 `before_reconstructed` Game 10뷰 판정

- 원시 `play_before_reconstructed/PLAY_REPORT.json`은 `phase=before_reconstructed`, `comparisonContext=rounds/post_ui_checkpoint`, status `CAPTURED_STATIC_AND_MOVEMENT_REVIEW_REQUIRED`, 실제 문 PlayerMotor 통행 PASS다. 10개 기대 ID가 순서대로 모두 있고 각 view는 1920×1080의 실제 Game·camera 이미지, 90 sample, `CAPTURED_REVIEW_REQUIRED`, 새 root 활성 renderer 0개를 기록한다. `rootWasActive`·`rootHiddenDuringCapture`·`rootStateRestored`가 모두 true다.
- 10개 Game PNG를 전부 직접 열었다. `true_exterior`·`north_seam_close`에서 새 후보01의 민트 잎·긴 줄기·지면 패치가 사라지고 원래 백색 외벽, 회색 하부, 창틀/유리, 진녹색 기존 아이비, 잔디 접합이 보인다. `gameplay`도 북측 외벽과 잔디에 새 A34가 없다. 이 두 근접/원경 시점은 후보02 후의 주 비교로 적절하다.
- `entrance`·`approach`·`outside_inside`에서는 현 V33 가림 아래 밝은 실내 타일과 노란 문턱이 보인다. 이는 새 A34를 숨긴 **현재 기존 상태**이며 CLINIC 북측 외벽 시범의 대표 완성 화면은 아니다. 출입구의 프레임·개구부와 실제 통행은 확인된다. `inside_out`에도 새 A34의 실내 누출은 없다.
- W05, 남쪽 다리, HALL1 통제 화면은 각각 해당 장소가 실제로 캡처됐고 CLINIC의 새 시각 요소가 보이지 않는다. 재구성 증빙은 비교 기준으로 수용 가능하다. 원회차 진짜 pre-change 이미지로 표기해서는 안 되며 후보02의 시각·가림·성능 PASS를 뜻하지 않는다.
