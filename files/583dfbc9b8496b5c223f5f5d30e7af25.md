# 의료 UI 간소화 · 변경 기록

작성일: 2026-10-15. 상태: 독립 복제 프로젝트 실행 검증 및 공유 Unity 통합·컴파일 검증 완료.

## 사용자 지시와 기획 의도

- 의료 키트 사용과 정보 확인을 간소화하고 상태이상을 아이콘으로 표시한다.
- V 길게 누르기는 치료 용도 4개로 통합하지 않고 **보유한 의료품 종류**를 직접 선택하도록 유지한다.
- 보유품을 모두 펼치지 않고 표시 상한을 두며, 보유 구성에 따라 위치가 바뀌는 대신 큰 아이콘으로 빠르게 구분한다.
- 이번 첫 적용 상한은 6종이다. 같은 종류의 여러 개체는 하나의 선택 칸으로 묶는다.
- 요청한 GPT-6.1 Sol / Very High에 대응하는 `gpt-6.1-sol / xhigh` 서브 에이전트가 선택 로직·상세창 구현과 독립 검토를 맡았으며, 메인이 시각 요소·통합·실행 검증을 담당했다.
- 후속 요청: 위/아래 아이콘의 중심 거리를 같게 맞추고, 사각 카드를 원 위에 늘어놓는 형태가 아니라 델타포스 참고처럼 자연스러운 원형 의료 휠로 만든다.

## 변경 전 상태

- 휠이 9개 고정 카탈로그를 펼쳐 보유품 구성과 표시 목록이 맞지 않고, 여러 의료품의 아이콘이 비슷했다.
- 카드에 이름·자원·효과·시간이 함께 들어가 빠른 식별이 어려웠다.
- 의료품 상세창에 아이템 설명·치료 규칙·신체 정보·장비/관리 정보가 함께 표시됐다.
- 상태 HUD는 작은 문자 중심이어서 출혈·외상 부위·진통 남은 시간을 구분하기 어려웠다.

## 실제 변경 내용과 방식

1. **V 짧게 / 길게 분리 유지**
   - 짧게 누르면 기존 추천 치료 우선순위를 유지한다. 자동 수술은 추가하지 않는다.
   - 길게 누르면 실제 잔량이 있는 보유 의료품 중 최대 6종을 표시한다.
   - 기본 구성은 지혈·진통·수술·회복 대표 품목이 과도하게 빠지지 않게 고른 뒤 최근 직접 선택을 반영한다.
   - 인벤토리의 ‘의료휠에 우선 표시’로 원하는 종류를 우선할 수 있다. 6종 초과분도 인벤토리에서 직접 사용 가능하다.
   - 보유 구성 변경 시 다음 열기에서 목록을 다시 구성한다. 열린 동안은 목록·각도를 고정하고, 사용 확정 시 정확한 종류·UID·잔량·조건을 다시 검사한다.
   - 중앙에서 놓으면 취소한다. V를 누르기 전 멀리 있던 커서 때문에 바로 품목이 선택되지 않도록 의도적인 이동 감지를 둔다.
   - 전술 의료가방은 한 칸으로 표시하며 스크롤로 회복·지혈·진통 기능을 선택한다.

2. **표시 간소화**
   - 의료품별 구분 가능한 큰 픽토그램, 짧은 이름, 남은 용량/횟수를 외곽 카드에 표시한다.
   - 효과와 사용 시간은 선택한 한 품목만 중앙에 표시한다.
   - 실제 실행 검수에서 상속된 글자 여백 때문에 잔량·상태 이름이 사라지는 현상을 발견해 의료 UI 전용 글자 스타일의 여백을 제거했다.
   - 의료품 아이콘은 기존 코드 기반 아이콘 체계를 확장했다. 지정된 실제 아이템 이미지가 있으면 기존처럼 우선 사용한다.
   - 후속 원형 수정에서 외곽 사각 카드와 중앙 사각 패널을 제거하고 원형 가이드·반투명 중앙 원·선택 원형 강조로 바꿨다.
   - 이전에는 카드 중심을 원 위에 놓았지만 실제 아이콘은 그보다 20px 위에 있었다. 그 결과 3종 구성에서 상단 아이콘은 중앙에서 286px, 아래 두 아이콘은 약 256.6px였다. 실제 아이콘 경계를 기준으로 공유 배치 API를 만들고 모든 아이콘 중심 반지름을 250px로 통일했다.
   - 아이콘 88×88, 중앙 원 지름 256, 이름 160×22, 잔량 160×20으로 구성한다. 1~6종은 보유 종류 수에 따라 등각 배치하며 2종은 마주 보고 3종은 정확히 대칭이다. 실제 입력의 선택 각도도 같은 배치 데이터를 사용한다.
   - 전술 가방 기능 선택은 작은 사각 칸 대신 텍스트·밑줄로 표현한다. 추천/우선 표시는 중앙 안내와 겹치지 않게 아이콘 양옆에 둔다.
   - 중앙 취소 영역도 보이는 중앙 원과 같은 반경 128px로 맞췄다. 원 안쪽 127.5px에서 취소되고 바깥 128.5px에서 해당 각도의 품목을 선택하는 경계를 검사한다.

3. **의료품 상세창**
   - 기본 정보는 이름·등급·핵심 효과·사용 시간·남은 자원·중요 중단 조건과 주행동으로 제한한다.
   - 상세 규칙·물품 관리·신체 상태·퀵슬롯 등록 선택은 접고 펼치도록 분리한다.
   - 전술 가방의 3가지 행동, 선택한 수술 키트의 부위 직접 수술은 유지한다.
   - 외부 전리품에는 가방에 넣기 전 사용·휠 우선 표시·퀵슬롯 등록을 제공하지 않는다.
   - 비의료품의 기존 상세 기능과 인벤토리 교환 로직은 유지한다.

4. **상태 HUD**
   - 체력 위에 출혈·팔 외상·다리 외상·몸통 외상·진통 아이콘과 짧은 이름을 표시한다.
   - 진통 중에도 외상 아이콘은 남기고 억제 중 표시를 덧붙인다. 진통 남은 시간을 함께 표시한다.
   - 추천 치료 안내와 사용 중 진행 표시를 짧게 정리한다.
   - 새 외상 알림에서 기존 출혈 상태를 새 출혈 발생으로 잘못 알리는 경로를 보완했다.

5. **활성 프로필 범위의 선호 유지**
   - 거점 거래·출격·복귀 시 가방/플레이어 상태가 재생성되더라도 같은 활성 저장소 객체를 기준으로 휠 선호만 보존한다.
   - 다른 프로필 로드는 선호를 초기화한다. 진행 중 사용·열린 휠·입력 상태는 재바인딩마다 초기화한다.
   - 선호는 현재 활성 플레이 세션 범위이며, 앱 종료 후 영구 저장하는 프로필 스키마는 추가하지 않았다.

치료 수치·의료품 종류·부상 효과·맵·적 AI·장비 외형은 변경하지 않았다.

## 전후 증빙과 촬영 조건

실제 제품의 `InventoryTestWorld`, `InventoryController`, HUD/상세창 렌더링을 **별도 복제 Unity 프로젝트의 동일한 검증 장면**에서 실행했다. 그림이나 합성 UI가 아니다. 공유 Unity가 다른 승인 작업에서 사용 중이어서 공유 씬을 조작하거나 덮어쓰지 않았다.

## 검증

- 변경 런타임 소스가 포함된 Unity Windows 실행본 빌드 성공.
- 원형 배치 후 기본/의료 회귀 검사 708항목 통과: 의료 UI 244, 부위/부상 69, 인벤토리 49, 장비 53, 전리품 48, 세션 43, 거점 52, 격자 인벤토리 53, 영역 교환 54, 무기 43.
- 부상 Play 실행 검사 81항목을 추가 통과했다(부위/부상 최종 보고서 150항목). UI 전환/인벤토리 Play 검사 101항목까지 포함한 최종 보고서는 총 890개의 PASS를 기록한다. 단순 합계가 아니라 각 원문 보고서와 실제 화면을 검토했다.
- 6종 상한, 보유품만 선택, 중복 통합, 열림 중 동결, 정확한 품목 사용, 소진/상태 변경 시 안전 거부, 표시 밖 품목 직접 사용, 전술 3기능, 프로필 선호 분리 등을 검사했다.
- 실제 보관함 거래·출격·탈출·세션 복구에 따른 가방 교체/선호 수명도 검사했다.
- 실제 화면에서 1600×900 및 1280×720의 카드 이름·잔량·중앙 효과·상태 이름을 확인했다.
- 기존 전체 UI Play 검사 첫 시도는 복제 프로젝트의 오래된 A맵 프리팹에 새 적 배치 데이터가 없어 출격 단계에서 실패했다. UI 결함으로 판정하지 않았으며 원래 실패 로그도 보관한다. B맵 시도는 잠금 조건으로 막혀 대체하지 않았다. 최종 UI 전용 검사는 복제본의 검사 코드에서 일시적인 MapRouter 컴포넌트를 제거해 이미 존재하는 절차형 테스트 구역 fallback으로 출격/복귀를 확인했고 통과했다. 공유 프로젝트의 맵이나 해당 기존 검사 파일은 바꾸지 않는다. 검증용 readonly MapRouter property를 대입하려던 중간 시도도 실패했으며, 최종 검증 도구는 직접 프로퍼티 대입을 사용하지 않는다.
- 원형 배치 검사는 1~6종과 두 해상도의 실제 아이콘·이름·잔량 경계, 동일 반지름, 입력 선택 일치, 3종 좌우 대칭을 포함한다. 최하단 잔량 끝은 논리 y791, 하단 HUD 시작은 y800이다.

독립 정적 검토에서 발견한 소진된 6개 우선 품목이 신규 우선 등록을 막는 문제와 초기화 경로의 선호 유실 문제를 보완했다. 최종 추가 정적 지적 없음. 서브 에이전트의 제작 완료 보고만으로 통과 처리하지 않고 메인이 실행 결과와 화면을 확인했다.

## 공유 Unity 최종 통합 확인

- 그래픽 작업이 저장·재로드 검증을 마친 후 명시적으로 UI에 인계했고, 이 작업이 소스 통합·검사를 마친 뒤 인간형 배치 작업에 반환했다. 동시 Play/저장/Refresh를 수행하지 않았다.
- 21:49:59 통합 전, 기존 변경 대상 7개 파일을 `source_before`와 hash로 비교해 변하지 않았음을 확인했다. 새 파일의 기존 대상 충돌도 사전 검사한 뒤 11개 `.cs`와 신규 meta만 복사했다.
