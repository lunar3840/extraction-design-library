# D08 A맵 69동 건축 외형 적용 계획

기준: `outputs/concept_art/2026-10-12/a-map-building-identities-v01/BUILDING_DESIGN.md`의 3장 비교 이미지와 10군·69동 매핑, D07 `ASSET_PLAN.md`의 T01–T14/B1–B6. 이 문서는 적용 전 구조 조사와 구현 판단이다. 실제 씬 적용과 검증 결과는 `CHANGE_RECORD.md`에 기록한다.

## 현행 구조 실측과 접속점

- 활성 계획은 69동이다. HALL·CLINIC·POWER·PARTS·TOOLS 다섯 동은 V08 유지 건물, 나머지 64동은 V33 건물이다. V33 보조 건물의 `StageAEnclosuresV33Building`은 ID, 실제 풋프린트, `VisualRoot`, `CollisionRoot`, `RoofCutawayRoot`, 양쪽 문 안팎 앵커를 소유한다. 보조 건물의 실제 폭·깊이는 약 13–33m이고, 유지 건물은 약 21–105m이므로 치수 고정 모듈을 전체에 그대로 늘려 쓰지 않는다.
- D04는 HALL을 제외한 68동에 각각 `D04_Facade_ID`와 `D04_Architecture_ID`를 생성한다. 전자는 건물 owner, 후자는 기존 `RoofCutawayRoot` 아래에 있다. D04의 이름 기반 지붕 분류는 S11을 폐허로 처리하지만 이번 콘셉트에서는 차량 차고다. HALL은 비활성 V08 원본 대신 활성 `V13_HallRoot`가 실제 외형이며, B1은 그 `Exterior/Facade`와 `Roof/TallCentralRoof`에 접속한다.
- `StageABlockoutMap.ConfigurePreviewVisibility`와 `SetCutaway`는 roof zone 아래 모든 렌더러를 토글한다. D08 지붕은 정확히 기존 `RoofCutawayRoot` 아래에 부착해야 한다. V33 플레이어 가림은 렌더러 이름의 `Roof`, `Facade`, `Wall`, `Eave` 등을 식별한다.
- D04 지붕과 새 지붕이 겹치지 않도록 정확한 D04 facade/architecture 루트만 비활성화하고 삭제하지 않는다. 경로·원래 activeSelf·변경 결과를 allowlist로 기록한다. 원본 Factory/V33 시각 셸, 충돌, 실내, 문/스폰 자료는 유지한다. 신규 D08에는 Collider와 NavMesh 변경을 넣지 않는다.
- D06의 E05 하역대/차양, W02 문 포털과 기존 설비 소품은 중복 생성하지 않는다. B4/R8은 약 62m이며 R8은 비활성 위험 진입점이다. D08은 건물 풋프린트·동선·스폰을 옮기지 않는다.

## Unity 적용 계약

- API: `StageABuildingD08Architecture.Apply(StageABlockoutMap map)` → 적용 내역 문자열. `FamilyOf(id)`와 `VariantOf(id)`는 69동 명시 매핑/역할 식별에 사용한다. 적용 마커는 `map/D08_IdentityRoot`다.
- 소유 루트: 건물 owner의 `D08_Facade_ID`, 기존 roof cutaway root의 `D08_Roof_ID`. 각 건물의 identity 자식에는 군·ID·역할코드를 남긴다. ID별 메시/재질 에셋과 루트는 교체 가능하게 고정 이름을 사용한다.
- 기존 D04 루트 비활성화는 정확한 경로 allowlist만 허용한다. 원본 오브젝트 삭제, 기존 collider/transform 수정, V33 plan 및 스폰 수정은 허용하지 않는다. 소스 roof 시각은 D08 구조보다 아래에 남겨 두며, D04 구조 중복은 비활성화로 제거한다. HALL의 D08 지붕은 V13 카메라 가림이 인식하는 `HighBayRoof_` 래퍼 아래에 두며, 나머지 지붕은 기존 컷어웨이 루트 아래에 둔다.
- Tripo 원본 GLB는 사용자 다운로드를 받은 뒤 별도 importer가 T01–T14 모두를 실제 prefab으로 반입했다. `IMPORT_BOUNDS.json`과 각 4방향 `import_preview_D08_T##_plus/minus.png`를 직접 확인했다. T02–T07/T09/T14 벽 창의 정면은 모델 +X, 폭은 모델 Z이며 T12는 관찰실 +Z 면을 향하도록 -90° 회전한다. prefab 실재·삼각수·렌더러·Collider 0을 적용 시점에 재검증한다.
- `StageABuildingD08TripoFacade.Apply(map)`가 구조 이후 선택한 슬롯에 실배치한다. T01은 녹색 타일/둥근 양면 코너가 원본 셸과 겹치지 않는 CLINIC/N04 두 곳에 한정한다. T02–T09와 T11–T14는 용도별 선별 배치하고 지붕 T08/T11 및 상부 관찰창 T12는 기존 컷어웨이 루트 안에 둔다. T10은 원본 실측이 약 0.90×1.00×0.79 단위의 두꺼운 L자 붕괴벽이라 폐허의 빈 통행/노천 영역을 메울 위험이 크므로 초기 실배치에서 제외한다. 수량·위치·원본 해시는 `D08_TRIPO_PLACEMENT.csv`로 기록한다. 모든 군의 기본 구조와 B1–B6은 Tripo와 별개로 procedural mesh다.

## 완료 판정

69개 ID 중 누락·중복 0, 각 군의 구조 silhouette와 군 내부 역할 변주 확인, D04 중복 렌더 0, 신규 Collider 0, 기존 문/실내/지붕 가림/플레이어 가림 유지가 필요하다. 메인의 동일 시점 전후 이미지와 독립 검증 결과를 읽고 `CHANGE_RECORD.md`에 반영한 뒤 완료한다.
