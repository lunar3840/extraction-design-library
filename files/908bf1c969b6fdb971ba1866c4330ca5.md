# 이끼 후보 02 — 번져 자라는 작은 조각으로 군락 만들기 (2026-11-25)

## 사용자 지시 요약

- 2026-11-25 22:38 KST "이끼 디자인이 너무 저폴리곤 형태인데 담쟁이처럼 디테일하게 이끼 모양 구성하는건 불가능한지?"
- 지시 1회, 구현 3회차(촬영 3번: after_20 실패, after_21 중간, after_22 후보).

## 해석

- 이끼 01은 큰 판(0.4~1.5 m) 한 장에 둥근 윤곽을 잘라 낸 것이라 저폴리곤으로 보였다. 담쟁이 도구가 잎 수백 장을 줄기를 따라 놓듯, 작은 조각 여러 개가 면 위에서 번져 군락을 이루게 바꾼다.
- 기존 담쟁이 도구·셰이더·에셋·맵은 그대로. `StageALookMoss.cs`(이번 대화에서 만든 에디터 전용 도구)만 고친다.

## 바꾼 것 (`Assets\Escape\Editor\StageALookMoss.cs`)

- **자라는 방식**: 물이 고일 자리에 씨앗을 놓고(자리 규칙은 01과 같음), 조각에서 조각으로 번진다. 새 조각마다 실제 면 위인지 검사하므로 군락 윤곽이 벽 모서리·창·지붕 끝에서 멈춘다. 벽 밑은 옆과 위로, 처마·창틀 아래는 옆과 아래로 번진다.
- **조각**: 지름 약 12~50 cm의 작은 판(삼각형 2개). 조각마다 방향과 기울기를 다르게 주고 면에서 살짝 띄워 겹치게 한다. 군락 하나에 3~60조각.
- **텍스처**: 실행 중에 만드는 4×4(512px) 한 장. 줄 = 색 계열(짙은 초록, 초록, 올리브, 마른색), 칸 = 모양(작은 돌기가 모인 방석 2종, 뾰족한 잎 로제트, 흩어진 부스러기). 색을 텍스처에 넣어 재질은 하나다.
- 건물당 조각 상한 2,600.
- 촬영 도구와 낡음 도구는 수정하지 않음.

## 시도 기록 (실패 포함)

1. `after_20` (v4, `source/StageALookMoss_v4_after_20.cs.txt`): **실패.** 조각 무늬에 빈틈이 많아 멀리서 속이 비어 보였다(가루를 뿌린 것처럼). 조각 250,359개, 삼각형 50만으로 양도 과했다.
2. `after_21` (v5): 조각 무늬 밑에 속을 채우고 조각을 키워 수를 줄임. 지붕은 읽히나 벽 밑이 풀에 묻힘.
3. `after_22` (v6, 현재 소스 = `source/StageALookMoss_final.cs.txt`): 벽 밑 군락이 풀 위로 올라오게 하고 지붕 군락을 키움. 이 회차의 후보.

## 확인 결과

- 지붕: 군락이 여러 색 조각이 섞인 얼룩덜룩한 덩어리로 보이고 가장자리가 잘게 갈라진다. 01의 둥근 판 모양은 사라졌다.
- 벽 밑: 풀 위로 올라온 군락이 벽을 타고 번진 모양으로 보인다. 그늘진 벽에서는 꽤 어둡다.
- 처마 아래·담 머리: 작은 덩이.
- 게임 카메라 거리에서는 여전히 작게 보인다(지붕 군락 지름 1~2 m).

## 한계 / 확인하지 못한 것

- 삼각형이 01의 약 17만에서 약 31만으로 늘었다. 성능 측정 안 함. 건물당 그리기는 3번에서 1번으로 줄었다.
- 조각은 납작한 판이다. 아주 가까이 옆에서 보면 판이 겹친 것이 보일 수 있다(게임 카메라에서는 확인한 지점에서 안 보임).
- 조각 무늬는 여전히 코드로 만든 것이다. 손그림이나 실제 이끼 텍스처, Tripo 덩이로 바꾸면 더 나아질 부분.
- 대상은 건물뿐(담장·차량·소품·거점·홀·땅 제외). 화면으로 본 건 6동 안팎.
- 건물 안에 들어가 지붕·벽이 걷힐 때 처리, 직접 플레이, 빌드 미확인.
- Play 중에만 얹힌다. 맵 저장은 별도 승인과 저장 방식 작업 필요.
