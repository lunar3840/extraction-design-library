# 전리품 무기·방어구 직접 장착 및 맞교환

## 사용자 지시와 기획 의도

- 수색한 전리품 무기를 무기 장착 칸으로, 방어구를 해당 장착 칸으로 바로 드래그하여 장착한다.
- 기존 장비 처리에 관한 사용자 확정: **기존 장비를 가져오는 전리품 자리로 맞교환**한다. 가방으로 보내지 않는다.
- 가방을 거치는 불필요한 조작과 임시 가방 공간 요구를 제거한다. 기존 인벤토리 영역 교환과 의료 UI 등은 유지한다.

## 변경 전 상태

전리품 드래그는 가방 격자 배치 경로에만 연결되어 있었다. 장착 칸 위로 드롭해도 전리품 직접 장착 경로가 없어 교환할 수 없었다. 변경 전 실제 화면은 사용자 첨부 원본을 수정 전에 복사하여 `before_user_loot_drag.png`로 보존했다. 수정한 기존 소스 두 파일은 `source_before/`에 보존했다.

## 실제 변경과 방식

- 전리품 외부 드래그에 장착 대상 미리보기·실행 콜백을 추가했다. 무기 1·2, 헬멧, 방탄복 칸으로 직접 장착할 수 있다. 기존 캐릭터 영역 드롭 방식도 외부 장비에 연결했다.
- 점유된 장착 칸은 기존 장비와 가져올 전리품을 직접 교환한다. 기존 장비는 원래 전리품의 페이지·좌상단 칸으로 돌아간다. 같은 방향으로 안 들어가면 그 자리에서 회전한 방향도 검사한다.
- 기존 장비가 더 크더라도 원래 위치와 인접한 빈 칸에 실제로 들어가면 허용한다. 경계를 넘거나 다른 전리품을 침범하면 교환하지 않는다. 다른 전리품을 임의로 이동하거나 다른 자리에 자동 수납하지 않는다.
- 가방의 빈 칸을 사용하지 않고 실물 장비 객체와 UID를 양쪽 소유자 사이에서 이동한다. 탄창·탄약·내구도·보호 상태를 새 장비로 초기화하지 않는다. 무기 교환 시 재장전은 취소하고 해당 무기 칸을 활성화한다.
- 양쪽 소유 상태·전리품 배치·무게가 모두 확정된 뒤 변경 알림을 발행한다. 수색 완료, 정확한 UID, 장비 종류·장착 부위, 전리품 거리와 UI/플레이어 상태를 실행 시 다시 검사한다.
- 장착 대상에 가능/불가 색상과 간단한 안내를 표시한다. 잘못된 장착 부위, 공간 부족, 오래된 드래그 요청은 물품을 소모하지 않는다.

## 스크린샷과 비교 범위

- `before_user_loot_drag.png`: 변경 전 사용자 제공 실제 게임 화면.
- `after_ready_to_equip.png`: 변경 후 격리 검증 씬의 드래그 시작 직전 상태. **변경 전 코드 화면이 아니다.**
- `after_weapon_swap.png`, `after_helmet_swap.png`, `after_body_armor_swap.png`: 같은 검증 씬·카메라·1600×900 해상도·UI 상태에서 실제 입력으로 각 장비를 교환한 결과.
- 사용자 제공 변경 전 화면과 검증 씬은 맵·해상도가 다르므로 정확히 같은 구도의 시각적 전후 비교라고 주장하지 않는다. 장착 경로의 유무는 사용자 전 이미지와 변경 후 실행/검사 결과를 함께 참조한다.
- 복제 프로젝트에 없던 기존 Toon 셰이더 리소스만 복사하여 검증 화면의 누락 셰이더 문제를 방지했다. 본 프로젝트 캐릭터·셰이더·재질·맵·AI·씬에는 변경이 없다.

## 주요 수정 파일

본 프로젝트 `C:/UnityProject/escape/Assets/Escape/` 기준:

- `Runtime/Inventory/Core/InventoryExternalEquipment.cs` (신규): 외부 장비 교환의 검증 및 알림 전 확정.
- `Runtime/Loot/Core/LootEquipment.cs` (신규): 원래 전리품 위치의 반환 공간 검사·직접 장착/맞교환.
- `Runtime/Inventory/InventoryGridPresentation.cs`: 외부 드래그 장착 대상 판정·미리보기·드롭 실행.
- `Runtime/Loot/LootInteractor.cs`: 전리품 수색/거리/상태/UID 재검증과 획득 알림 연결.
- `Editor/LootEquipmentChecks.cs` (신규): 직접 장착 검사와 일회성 안전한 편집기 통합 확인. 요청 파일이 없으면 자동 검사를 실행하지 않는다.

테스트 전용 실행/빌드 도구는 `validation_tools/`에 보관했으며 본 프로젝트에는 배포하지 않았다. 기대 효과는 가방에 먼저 넣을 필요 없이 드래그 한 번으로 장비 교체가 가능해지고, 실패 시에도 어느 물품도 사라지지 않는 것이다.
