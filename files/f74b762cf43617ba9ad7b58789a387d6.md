# 동료 칩 장착과 현현 외형 교체

## 사용자 지시와 기획 의도

로비에서 동료 한 명의 칩을 장착하면 그 동료의 신체로 외형을 바꾼다. 인벤토리의 무기·방어구 위에 전용 칩 슬롯을 둔다. 거점에서는 교체·해제가 가능하고, 지상 출격 중에는 오염 위험 때문에 교체·해제가 불가능하다. 정화된 동료 칩은 일반 가방에 들어가지 않는다. 추후 현장에서 구조하는 미정화 칩만 일반 화물로 운반한 뒤 기지에서 정화하는 별도 경로를 사용할 예정이다. 에델은 현재 아트 작업과 분리하고, 이미 프로젝트에 있는 캐릭터로 두 번째 외형을 시험한다.

출처는 사용자의 이번 직접 지시와 ‘세계관 설정 작성’ 대화의 현현 소켓·에고 코어 개념이다. 다른 게임의 캐릭터 교체 규칙이나 가챠·중복 획득을 추가하지 않는다.

## 변경 전 상태

`SdCharacterVisual.Attach`가 플레이어 생성 시 세린 외형을 한 번만 붙였고 이후 모델을 바꾸는 경로가 없었다. 무기·방어구는 가방 물품을 장비하는 구조여서 칩을 같은 물품으로 넣으면 탈착·사망 전리품·바닥 버리기 경로로 흘러갈 수 있었다. 기존 모델 생성은 Animator, 총기 손 위치, 방어구, 부위 피격 판정 및 인벤토리 인물 화면에 각각 연결돼 있었다.

수정 전 실제 본 Unity 화면을 `before_main_editor.png`로 저장했다. 별도 복제 프로젝트의 원래 UI를 실행하여 `before_inventory.png`도 저장한다. 원래 코드 사본은 `source_before/`에 보관한다.

## 구현

- 정화된 칩은 일반 아이템 카탈로그와 분리된 동료 목록에서 선택한다. 현재 시험 목록은 세린과 테스트 동료 두 개다. 테스트 동료의 외형은 기존 `Player_UnityChan`(Haon SD) 프리팹이며, 미장착 기본 신체는 기존 `Ranged_Misaki`를 임시로 사용한다. 이 임시 외형은 세계관상 새 캐릭터 확정이 아니다.
- `ProfileSession.SelectCompanionChip`이 거점·저장 상태·칩 ID를 검사하고 저장 성공 후에만 선택 변경과 알림을 확정한다. 기존 가방 객체·UID·탄약·내구도는 유지한다. 출격·사망 상태에서는 내부 API가 교체와 분리를 거부한다.
- 칩 선택과 버전을 프로필에 저장한다. 기존 저장에는 세린 연결을 기본으로 이전하며, 새 버전에서 사용자가 해제한 상태는 다시 불러와도 빈 상태로 유지한다. 실제 사용자 프로필을 검사 도구로 불러오거나 변경하지 않는다.
- 칩 미장착 상태의 출격은 거점에서 거부한다. 선택한 정화 칩은 출격·탈출·사망 귀환 후에도 유지하며 사망 가방이나 무덤 전리품에 들어가지 않는다.
- 전용 칩 슬롯을 무기·방어구 위에 배치하고 클릭하여 동료 목록을 연다. 로비 화면에서도 장비 화면으로 바로 진입할 수 있다. 지상에서는 잠금 이유를 표시하고 선택·해제 버튼을 비활성화한다.
- 외형 후보의 모델·Humanoid·필수 뼈·애니메이션을 준비한 뒤 기존 표시용 모델을 교체한다. 모델 교체 시 총 손 위치, 방어구, 부위 피격 뼈 연결, 툰 재질 및 인벤토리 인물 화면을 새 모델에 다시 연결한다. 플레이어 이동·체력·가방·실제 무기 상태는 유지한다.
- 선택창 닫기와 Esc는 예약된 선택도 취소한다. 저장 실패·모델 준비 실패는 기존 상태를 유지하도록 검사한다.

## 검증

별도 복제 Unity 프로젝트에서 새 코드와 기존 의존 에셋으로 Windows 실행본을 빌드하고 실제 실행했다. 본 프로젝트의 Runtime/Editor 소스도 반영·컴파일되었으며, 본 프로젝트 어셈블리의 `CompanionChipOverlay`, `CanApplyCompanion`, `SelectCompanionChip` 포함을 확인했다.

- 칩 규칙 42개 PASS: 구버전 JSON 이전, 명시적 해제 저장/로드, 가득 찬 가방에서 선택·해제, 일반 가방/창고 진입 거부, 위조된 인벤토리 복원 거부, 저장 실패 시 선택·revision·가방 유지, 출격·사망 중 변경 거부, 탈출/사망 귀환 후 유지, 잘못된 ID/버전 거부, 선택창 Esc 취소, 슬롯 배치와 UI 동결 검사.
- 기존 관련 회귀 검사와 함께 8개 모음 총 435개 PASS: 칩 42, 인벤토리 49, 장비 53, 세션 43, 거점 52, 인벤토리 영역 교환 54, 전리품 직접 장착 77, 바닥 버리기 65. 최종 표시 수정 후 다시 실행했다. `validation_reports/` 참조.
- 실제 그래픽 실행에서 세린/테스트 동료/미장착 신체를 9회 반복 교체했다. 한 개의 표시 모델과 새 Humanoid/부위 피격 뼈만 남고, 실제 플레이어·가방·총 인스턴스·탄약·체력은 유지됨을 검사했다. 인물 미리보기의 아바타·컨트롤러·고정 손 위치도 새 모델로 갱신됐다.
- 테스트 동료의 실제 가방 방어구 장착/해제에서 원래 몸체·헤어 메시, 원래 재질의 텍스처·색·UV 연결과 표시 상태 복원을 검사했다. 13개 종합 시각/연결 검사 PASS, 최종 실행의 Unity 오류/예외 기록 없음. `visual_acceptance.txt`, `runtime_complete.txt` 참조.
- 실제 마우스로 지상의 칩 선택창을 열고 세린을 눌러도 테스트 동료가 유지되는 것을 확인했다. 격리 슬롯 귀환 후 세린 선택, 칩 해제, 테스트 동료 선택으로 실제 외형이 바뀌었다. 칩을 누른 입력이 뒤쪽 방어구 슬롯의 변경으로 전달되지 않았다.
- 교체한 동료에게 기존 헬멧을 실제 장착하고 인물 화면을 회전해 측면·후면을 확인했다. 헬멧 아래의 보완 뒷머리가 원래 동료의 금발을 사용한다. 기존 헬멧/무기 아트 리소스와 프리팹 자체는 변경하지 않았다.
- 본 편집기의 추가 규칙 실행 요청은 당시 Play 중이어서 안전 가드가 거부했다(`MainEditorImport.txt`). 본 씬/Play를 강제로 중단하지 않았다. 이 보고의 FAIL은 기능 규칙 실패가 아니라 본 편집기에서 중복 검사를 건너뛴 이유다. 위 435개 검사는 격리 프로젝트에서 실제 통과했다.

최초 복제 환경에는 기존 툰 셰이더가 빠져 마젠타가 나타났다. 본 프로젝트의 기존 `Art/Toon` 의존 파일을 복사한 후 변경 전과 변경 후를 동일 조건으로 다시 촬영했다. 본 프로젝트 셰이더는 수정하지 않았다. 개발용 네트워크 요청을 없애기 위해 검증 실행본의 Development/Profiler 옵션을 끈 뒤 빌드했다.

## 화면 증빙과 비교

- `before_main_editor.png`: 실제 수정 전 본 Unity 화면. 이후 본 창은 다른 맵 작업에서도 사용되므로 동일 화면 비교라고 주장하지 않는다.
- `before_inventory.png` ↔ `after_inventory_serin.png`: 원래 UI와 새 UI, 같은 격리 씬·카메라·고정 인물 자세·1600×900 게임 프레임. 새 칩 슬롯을 위해 방어구를 아래로 옮겼다.
- `after_inventory_prototype.png`, `after_inventory_unbound.png`: 같은 인벤토리 화면에서 칩 선택/해제에 따른 외형 변경.
- `after_stage_locked.png`: 출격한 상태의 칩 잠금 표시.
- `after_native_stage_picker.png`, `after_native_stage_rejected.png`: 실제 마우스 입력 전후의 지상 변경 거부.
- `after_native_camp_picker.png`, `after_native_serin_equipped.png`, `after_native_unbound.png`, `after_native_prototype_equipped.png`: 실제 클릭으로 로비 교체와 해제를 확인한 Windows 창 캡처. 창 캡처는 DPI에 따른 1069×631 크기로, 1600×900 게임 프레임과 별도로 구분한다.
- `after_native_helmet_front.png`, `after_native_helmet_side.png`, `after_native_helmet_rear.png`: 교체 후 헬멧과 원래 머리색 확인.

실제 사용자 저장 파일은 검사에 사용하지 않았고, 모든 실행 검증은 이 기록 폴더의 `isolated_profiles/`에 생성한 별도 슬롯을 사용했다.

## 범위

이번 작업은 칩 장착, 외형 교체, 저장 및 지상 잠금의 첫 구현이다. 캐릭터별 능력치·스킬·성장, 새 동료 구조 임무, 미정화 칩 파밍 생성과 정화 시설은 추가하지 않는다. 현재 두 번째 프리셋과 미장착 기본 신체는 임시 에셋이다. 에델 Blender 작업은 재개하지 않는다.
