## 키보드와 API fixture의 구분

- 네이티브 자동화의 E/I 키 호출에서는 화면 변화가 관찰되지 않았다. E가 성공했다고 기록하지 않는다. 상태·focus·Input System 수신을 별도로 확인해야 하며 생산 키 설정은 바꾸지 않았다.
- Sky의 문서화된 API에는 키를 누른 채 유지하는 기능이 없어0.25초 이상 V hold를 OS 경로로 확인하지 못했다.
- 자동 전체 route의 medical_wheel_api_fixture는 실제 열린 휠 렌더링을 증명하지만 물리 V 입력 통과를 대신하지 않는다.
- Editor 전용 simulated Input System 가상 키보드 E/I/V를 실제 실행했다. E는 전방 관측 실행과 cooldown, I는 inventory False→True, V는 길게 누르는 동안 실제 의료휠 열린 PNG 및 키를 놓은 뒤 닫힘을 확인했다. 실제 Dynamic PlayerLoop를 통과시키되 기존 OS keyboard/device와 분리하고, keyup/제거/원래keyboard 복원을 확인했다. 세 txt와 V PNG, 독립 검토는 INPUT_SIMULATED_AUDIT.md를 따른다. OS 입력 성공으로 확대하지 않는다.

## 이미지 형식

native 스크린샷 원본은 JPEG였다. PNG 이름으로 저장된9파일은 원본 JPEG bytes를 .jpg로 보존한 뒤 디코딩된 픽셀 그대로 PNG로 변환했다(native-format-conversion.json). 확대/보정/크롭/내용 변경은 하지 않았다.
