# 이미지 기반 미니맵 및 현재 위치 정합 수정

## 사용자 지시와 범위

델타포스 첨부 예시처럼 실제 맵을 이미지화하고 현재 플레이어 위치를 동기화한다. 현재 위치 표식이 제자리에 있지 않은 문제를 확인해 수정한다. 첨부는 이미지 표현의 참고이며 다른 게임의 맵·파밍·적·스폰 규칙을 이식하지 않는다.

대상은 현재 익스트랙션 Unity의 원형 미니맵과 M키 전체 지도다. 맵 배치·진입 후보·NPC 행동·정상 저장 프로필을 변경하는 작업이 아니다.

## 변경 전 상태와 증빙

- `before_editor.png`: 최초 관측한 SystemsTest Edit 화면. 화면 조작 전에 확보했다.
- `before_gameplay.png`, `before_gameplay_state.txt`: 수정 전 실제 A맵 1920×1080 화면. 기존 격리 프로필 검증 도구의 2026-10-22 19:53:00 KST 원본 캡처를 복사했다. 재구성 화면이 아니다. 원본 이름은 `loot-shop-tier-consistency/interactive_20261022T105300098_1920x1080.png`다.
- 실제 저장된 변경 전 화면의 플레이어 월드 위치는 (-119, 0.02, -129), 맵 좌표는 (141,329)다. 원형 지도에서 화살표가 중심을 벗어난 현상을 직접 확인했다.
- 기존 배경은 충돌체·일부 지형 메시를 단색 다각형으로 채운 그림이며, 실제 텍스처·시각 메시·자연물과 다르게 보였다.
- 수정 전 Mapping 원본 3개 및 TacticalMapChecks를 `source_before/`에 보관했다.

## 원인과 기획 의도

독립 검토 `review_coordinate.md`에서 WorldToMap/MapToWorld 수식은 A맵 배치식과 일치함을 확인했다. 임의 오프셋을 더하지 않는다. 실제 화면에서 확인한 표식 오차는 `GUIUtility.RotateAroundPivot`이 HUD 배율 행렬 앞에 화면 좌표 회전을 합성하는 문제와 관련된다. 배경 크롭의 100ms 제한 또한 이동 중 표식과 배경의 시점을 다르게 만들었다.

실제 활성 맵 메시·재질을 북쪽 고정 직교 투영 이미지로 한 번 굽고, 이미지 원점/범위/해상도와 동적 표식이 같은 좌표를 공유하도록 한다.

## 진행과 공유 편집기 조율

2026-10-22 다른 관련 채팅의 공유 Unity 검증 사용 인계를 확인했다. 사용자 지속 조율 승인 원문을 확인한 뒤 `Edel 변신 캐릭터 적용` 채팅과 직접 조율했다. 인계 전 사용했던 격리 UiKit 프로필은 cleanup 완료했고 stop_play를 요청했다. 이후 본 Assets·검증 request·창 조작을 중단하고 `work/image-based-minimap/`에서만 후속 구현했다. 앞서 반영한 TacticalMapView 및 초기 베이커 2파일은 다른 채팅에 정확히 알렸으며 보존하기로 조율했다. 명시 반환 후 통합·실기 검증을 진행한다.

## 실제 변경과 방식

- `TacticalMapData.cs`: 충돌체를 단색 도형으로 채우던 배경 제작을 제거했다. 실제 맵의 직교 항공 PNG와 같은 이름의 JSON 보정값을 읽는다. 시설·탈출·현장에서 발견한 보관함의 기존 동적 표시는 유지한다.
- `TacticalMapImage.cs`: 이미지 원점·미터 범위·실제 픽셀 크기를 검증하고, 이미지와 모든 동적 표식에 같은 월드→맵 변환을 적용한다. A는 원점 local(-260,+200Z), 520×400m, 2600×2000px(5px/m)다. B 보존 맵은 별도 원점(-24.5,+24.5Z), 49×49m, 245×245px다. 가로/세로 자동 크롭이나 표식 임의 오프셋을 적용하지 않는다.
- 원형 크롭은 매 Repaint에서 현재 플레이어 중심과 같은 시점으로 갱신한다. 예전 100ms 제한을 제거했다. 알파 마스크·축별 인덱스·고정 소수 보간을 캐시해 매 픽셀 좌표 변환과 제곱근 계산을 줄였다. 동일 객체를 다시 굽더라도 ImageRevision으로 이전 크롭을 무효화한다.
- `TacticalMapView.cs`: 최종 방식은 48×48 투명 화살표 비트맵 내부를 회전시켜, 기존 GUI 행렬은 바꾸지 않고 정확한 `pin`에 그린다. HUD 배율 및 `GUI.BeginGroup`의 잘린 영역 원점에 영향을 받지 않는다. 화살표의 비대칭 실루엣 외접상자 중심과 실제 회전 기준점은 구별한다.
- `TacticalMapImageBaker.cs`: 현재 활성 맵의 실제 메시·재질·지붕·도로·물·식생·정적 소품을 북쪽 고정 직교 카메라로 한 번 촬영한다. 플레이어·적·임시 UI·스폰/디버그 표시·파란 계획 슬롯은 이미지에 포함하지 않는다. 건물 가림 대상만 명시 복구하고 은퇴한 비활성 메시를 일괄 켜지 않는다. 지하 상태에서 교체되는 중정비동 표면 메시도 외부용으로 잠시 교체하고 복구한다.
- 베이크 후 렌더러 enabled/forceRenderingOff, 표면 메시, 런타임 reveal 재질 값, fog·전역 veil, RenderTexture를 원상 복구하며 임시 카메라·진단 물체·재질은 파괴한다. 일반 플레이에 미니맵 촬영 카메라를 계속 두지 않는다.
- PNG는 읽기 가능·무손실 비압축·mipmap 없음·Clamp·Bilinear·NPOT 크기 유지로 가져온다. 자산이 없거나 JSON이 손상되면 부정확한 옛 도형으로 돌아가지 않고 `지도 이미지 없음`을 명시한다. 공유 Resources 텍스처를 Data.Dispose에서 파괴하지 않는다.
- `Escape > Tactical Map > Bake Current Stage Image`는 이후 맵 시각 변경 시 이미지를 다시 굽는 편집용 메뉴다. 씬이나 프로필 저장·배치를 변경하지 않는다. 일반 사용자 Play에서도 현재 맵의 이미지 자산을 제작할 수 있도록 의도적으로 제공한다. 자동 증빙 명령 도구는 별도로 격리 프로필 소유권을 확인한다.

1. 처음 행렬 합성만 보완한 화면에서는 `BeginGroup` 안 화살표가 여전히 실제 중심에서 벗어났다. 이를 통과 처리하지 않았으며 `iterations/after_gameplay.png`, `iterations/after_full_map.png`를 남겼다. 최종 비트맵 회전 방식으로 교체한 뒤 새 `after_gameplay.png`와 전체 지도 및 배율별 실제 화면을 확인했다.
2. GPU 좌표 시험의 첫 임시 probe에 DontSave를 지정해 Unity의 renderer 검색에서 제외되었다. 진단용 HideInHierarchy로 바꾸고 재실행했으며, 실제 제품 이미지의 좌표 오류로 판정하지 않았다. 임시 probe는 제품 PNG에 굽지 않았고 모두 제거했다.
3. B의 첫 원형 색상 비교는 Unity native `GetPixelBilinear`와 CPU 고정 소수 보간의 한 고대비 샘플에서 실패했다. 이전 결과를 `iterations/image_checks_StageB_initial.txt`에 보존했다. native sampler의 좌표·색·반올림 규약을 동일하다고 가정하지 않도록 검사를 정리하고, 별도로 검증한 비최적화 텍셀 중심 `SampleImage`와 최적화 크롭을 비교했다. 이 검사가 일부 좌표식을 공유한다는 한계는 독립 GPU 등록·보정 모서리·합성 픽셀 검사와 구별해 기록한다. 최종 B 검사는 전체 PASS다.
4. 마지막 검증 도구 반영 후 기존 `StageV08ImportReceipt.Inspect` 자동 콜백이 prefab dependency 검사에서 수십 초간 편집기를 점유했다. 해당 다른 기능을 수정하거나 앱을 강제 종료하지 않고 완료를 기다렸다.
