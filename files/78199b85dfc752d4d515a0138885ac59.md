## Correctness and ownership

The public HUD/audio methods, properties and enum usages required by production are preserved. ## Source-null and directional semantics

Known-source directions still use victim-to-attacker ground-plane vectors and camera ground-plane forward/right, with the existing camera-up fallback for near-vertical views. World direction is not mistaken for screen direction when camera yaw changes.

Unknown/environmental sources invoke four symmetric edge marks using `showBearing=false`. That branch returns before chevron drawing, and the four marks use equal span/strength. It therefore does not invent one attacker bearing. Existing direction versus environmental cue counts are preserved.

**Resolved intent check:** the first staged helper described an inward chevron, but the geometry points outward toward the incoming bearing. Main confirmed outward is intended and corrected the comment. The geometry is consistent with that clarified purpose; no behavior correction is required.

## Camera, resolution and presentation lifecycle

The overlay uses the actual camera pixel rectangle and a clipped GUI group, converts bottom-left screen coordinates to top-left GUI coordinates once, and restores GUI color/matrix/depth. Shape scale derives from the smaller normalized viewport dimension and is bounded. Thick warning bands deliberately approach/cross the viewport edge and are clipped there; they do not extend into another camera viewport.

The controller continues clearing/pausing on frozen simulation, map/menu locks, listener pause and dead state outside its existing 0.18-second final-impact window. Inventory remains live: it clears outgoing hit marks while retaining incoming warnings and world gunfire. No audio/HUD component should independently freeze inventory gameplay.

**Harness isolation issue:** old acceptance `Gap()` of 0.85 seconds is shorter than the new possible 1.15-second damage lifetime. Tests expecting no previous directional cue before a source-null event must either clear cues explicitly or wait at least 1.25 seconds. Otherwise failures indicate a stale test assumption, not an invented null-source direction. This was sent to the main agent before the after run.

## Performance and gain headroom

Damage slots remain capped at four. Arc tessellation remains fixed at twelve segments; drawing uses value types and the shared white texture rather than allocating textures/materials per frame. The new warning does increase immediate-mode draw work. A directional warning uses approximately 52 GUI texture draws, or 76 with its armor rail; one environmental warning uses approximately 192 because it draws four symmetric bands. With one environmental plus three separate armor directions, the bounded worst case is about 420 draws during repaint, before the hit marker. This is a source-derived upper bound, not a measured frame-time claim; no profiler was run.

Confirmation gain changes from 0.62 to 0.72/0.78/0.84 for ordinary/head/kill. Incoming gain changes from 0.15–0.60 to 0.32–0.78, with slightly lower pitch for stronger hits. Local/remote gunshot gains and the 18-source pool sizes are unchanged. Each source gain is clamped, but this does not guarantee summed mixer headroom when multiple voices overlap. A stronger cue is not itself a clipping defect; actual overlapping local shot + confirmation + incoming impact and NPC gunfire must be checked from captured listener PCM. Nonzero output and playback counters alone are insufficient to prove absence of clipping or subjective balance.

## Revised final candidate source review — smooth masks and foreground mixing

The main agent reported and preserved a genuine failed earlier overlap test (float peak **1.331546**) in `iterations/segment-bands-overlap-clipping`. That candidate is not accepted as clipping-free. The current staged candidate was reread after its revision; its differences supersede the earlier segmented-band performance description above.

### Cached mask implementation

The HUD now generates two 512×512 RGBA32 warning masks once in Awake. The texture's positive texture-Y angular sector maps to the top of a GUI texture; a positive GUI rotation moves that sector toward screen-right, matching `atan2(right, forward)`. Matrix order `old * Translate * Scale * Rotate` rotates the mask before applying elliptical screen-space scaling, so the outline remains aligned to the viewport ellipse when the camera bearing changes. The matrix is restored before drawing the chevron, and the outer GUI group continues clipping to the camera viewport. Source-null still renders four balanced outlined ticks and never invokes the directional-mask/chevron path.

The two textures cost approximately 2 MiB of RGBA GPU payload per HUD, excluding driver overhead; `Apply(false, true)` discards their readable CPU copies after upload. Temporary Color32 arrays exist during construction only. Both masks are explicitly destroyed in OnDestroy and are retained across enable/disable, avoiding repeated creation. This is a bounded startup cost, not a per-hit allocation. Known-source warning rendering falls to one textured quad plus four line draws for the chevron; environmental marks retain their bounded segmented fallback. Actual frame times and memory allocation were not profiled.

### Foreground mixing implementation

For 140 ms after a confirmation or player impact, existing and newly starting local gunshots receive a 0.78 multiplier and remote gunshots a 0.25 multiplier. Confirmation and player-impact gains retain the requested increases. Unmodified per-voice gain values are remembered in fixed arrays, and reapplying the focus state computes from those values rather than multiplying the already-ducked volume. Thus repeated confirmations cannot progressively attenuate a source by accident.

The end time uses unscaled time; Update restores remembered gains when the interval expires. Clear/disable/pause stops voices, clears their clips and resets foreground timing/state. Some stopped AudioSources can retain their last ducked numerical volume after Clear, but this does not leave future shots attenuated: every later Play overwrites its selected source volume from the requested unducked gain and current focus state. Reused/stolen voices update their own remembered gain before playback. Existing pool count, audio-data preload, playback counters, source distance/panning, gameplay noise events and damage paths are unchanged.

This fixes an evidenced overlap problem through local presentation gain only. It is **not a general hard limiter**; arbitrary maximum-pool simultaneous peaks are not proven bounded below 1. Final acceptance must cite the tested overlap scenario and measured final float-buffer peak, avoiding a claim that every possible raid mix is guaranteed unclipped.
