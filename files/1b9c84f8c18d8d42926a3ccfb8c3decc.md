# 컷씬 연출 독립 검토

- 검토 범위: `work/cutscene-direction-src`의 컷씬 카메라, 실제 맵 배우 연결, 대사 진행 및 출격 중 이야기 상태 처리.
- 담당 분리: 이 검토자는 `Editor/CinematicDirectionChecks.cs`와 본 문서만 수정한다. 런타임 구현·실제 프로젝트·Unity 실행·빌드는 메인 담당이다.
- 현재 상태: **독립 검사 17개 그룹 / 57,407개 검증, 실제 게임 자동 검사 199항목, 후속 회귀·화면 검토 통과. 수동 입력 증빙, 실제 19개 파일 적용 해시 불일치 0, 실제 편집기 컴파일 오류 0과 갱신 완료까지 확인. 독립 검토상 통합 완료 승인.**

## 실행 가능한 검증

`Escape.Tests.CinematicDirectionChecks.Run()` 또는 Unity 메뉴 `Escape/Tests/Cinematic Direction Checks`.

- 결과 파일: 검증 프로젝트 루트의 `CinematicDirectionChecks.txt`.
- 한 그룹이 실패해도 나머지 그룹을 실행한 뒤 전체 실패를 예외로 보고한다.
- 프로젝트의 씬·세이브를 변경하지 않으며, 검사 중 생성한 임시 카메라/배우 오브젝트는 정리한다.
- 제작 코드의 `IsFaceReadable` 판정을 그대로 믿지 않고 별도의 원근 투영 계산과 선분/AABB 충돌 계산을 사용한다.

## 정적 검토 진행 기록

1. 기존 `CutsceneStage`는 고정 배율과 화자별 외딴 스테이지 좌표만 사용했다. 새 구현이 도착하기 전에는 실제 맵 연출·장애물 회피 구현 여부를 판정하지 않았다.
2. `CutsceneDirector`의 새 예외 처리에서 재생 중 촬영 실패 후 `Stop()`을 호출하면 `Error`가 대화 UI에 보이지 않는 경로를 확인하여 메인에 전달했다. 종료 콜백의 오류 노출과 동일 실패의 자동 재시도 방지까지 통합 검토해야 한다.
3. `CinematicActorPose`는 원래 리그의 로컬 변환·애니메이터 상태·기존 블렌드셰이프 가중치를 캡처하고 종료 때 복원한다. 얼굴 표정은 실제 이름이 일치하는 블렌드셰이프가 존재할 때만 사용하므로, 현재 모델의 표정 지원 여부와 실제 게임 화면 확인은 별도로 필요하다.
4. 이후 `RestoreAfterStory`에서 종료 오류를 일반 상태 메시지에 노출하고 실패 이벤트 키를 자동 재시도 차단에 기록하는 수정이 도착했다. 정적 검토상 앞선 오류 은폐/무한 재시도 우려가 해소되었다. 당시 실제 실행 확인을 기다린 뒤, 후속 실행에서 준비 실패의 오류 정보와 상태 복원 통과를 확인했다.
5. 월드 촬영은 실제 배우를 참조하며 별도 카메라를 사용한다. 게임 카메라의 위치·회전·활성 상태와 `RenderSettings.sun`을 수정하지 않는다. 카메라 후보가 전부 막히면 표시 전에 예외로 중단한다. 월드 썸네일은 독립적인 실제 얼굴 구도를 먼저 검증하며 안전하지 않으면 명시된 초상 리소스만 대체로 사용한다.
6. `ProfileStory`의 필드 완료 경로는 `Persist`를 호출하지 않고 메모리만 교체하며, `Extract`와 `BeginDeath`에서 대기 중인 필드 이벤트를 제거한다. 이 코드를 읽은 것만으로 저장 경계 통과로 판정하지 않고, 별도 메모리 저장소의 호출 횟수와 체크포인트 전체 직렬화 비교 검증을 추가했다.
7. `model_channels.txt`에 기록된 현재 세린 메시에는 블렌드셰이프가 없다. 현재 세린의 눈깜빡임·미소·입 모양 변형을 구현했다고 보고하면 안 된다. 지원 모델에서는 실제 이름과 맞는 모프를 사용하고, 현재 세린은 시선·고개·목의 미세 움직임과 카메라 연출로 표현하는 제한이 있다.
8. 독립 검토에서 필드 완료 시 `RefreshReady`가 출격 중 물자를 보고 거점용 준비 대사를 예약하고, 사망 후 물자를 잃어도 그 대기가 남을 수 있는 문제를 발견했다. 메인이 필드 완료의 메모리 처리 뒤로 거점 준비 갱신을 분리했다. 해당 시나리오의 실행 검증을 추가했고, 아래 실제 Unity 독립 검사에서 통과를 확인했다.
9. 이후 스테이지 전용 조명이 방향광으로 조정되었다. 격리 대화 스테이지는 셰이더의 주광 슬롯을 임시 사용하고 기존 `RenderSettings.sun`을 보관·복원한다. 월드 촬영에서는 이 변경이 없다. `Create` 예외 경로도 `Dispose`를 호출하고, `Dispose`에서 기존 sun을 먼저 복구하는 것을 정적으로 확인했다. 실제 스테이지/월드 모드 양쪽의 종료 후 sun 복원도 최종 런타임 검사에서 통과했다.
10. 자동 진행은 이제 대사 표시/여운 시간과 `ChosenPlan.DurationSeconds` 중 긴 시간을 기다린다. 짧은 대사가 계획된 카메라 동작을 1~2초 만에 자르는 경로가 정적으로 해소되었다. 수동 진행의 즉시 응답은 유지한다.
11. 충돌 검사 제외 대상이 현재 촬영 대상/화자만으로 좁혀져, 관계없는 다른 실제 배우까지 장애물 검사에서 빠지던 범위를 제거했다.
12. 자동 `Discovery`는 별도 장소 표식이 없어도 Wide를 선택하고, 명시적으로 `automaticFraming=false`/Face인 대사는 Face를 유지하는 회귀 검증을 추가했다. README는 구조화된 감정/대상과 실제 공간에 기반한 로컬 선택 시스템임을 명시한다. 자유 메모를 해석하는 온라인 AI나 현재 세린의 얼굴 리깅이 제공된다고 과장하지 않는다.
13. 메인이 기존 `EnemyController.Frozen` 경로가 `CancelMachineRoleAttack`/`Stop`을 호출하여 컷씬 중 기계의 공격 준비를 취소한다는 추가 문제를 발견했다. 정적 검토에서 이를 확인했다. 별도 `CinematicPaused`가 Update와 Tick의 첫 분기에서 반환하고 SessionStory가 원래 Frozen/CinematicPaused를 모두 보관·복원하는 최소 수정이 들어왔다. 비활성화는 재장전·구르기·회복도 취소하므로 사용하지 않는다. 제작용 컴포넌트에 공격 단계/타이머/활성 재장전/경로를 심고 보존을 확인하는 16번째 검증을 추가했다.
14. 런타임 증빙 드라이버의 중첩 IEnumerator 직접 순회는 자식 예외를 잡아 완료 마커까지 진행하지 못하게 한다. 자동 진입 대기를 시작하기 전에 잡은 스냅샷과 실제 재생 시작 사이에는 정상 게임 프레임이 존재하므로 루트/게임 카메라/애니메이션의 완전 일치가 거짓 실패를 만들 수 있음을 전달했다. 동기 재생에서의 정확한 복원 검사는 유지하고 자동 재생에서는 재생 중 동결과 동일 배우/상태를 검사하도록 담당자가 보완했다. 기존 공격 단계·재장전 보존을 검사하지 않던 런타임 스냅샷의 거짓 통과 가능성도 함께 전달했고 후속 검사에 반영되었다.
15. 자동 구도의 안전한 후보가 전부 막힌 경우 Wide→UpperBody→Face, UpperBody→Face로 좁혀 재평가하는 보완이 도착했다. 기존 장애물 검증 그룹에 좁은 구형 방의 전체 카메라 부피/경로 보존과 명시적 Wide 고정 동작을 검사하는 회귀 사례를 추가했다. 수동 구도는 이 자동 단계 변경을 사용하지 않는다.
16. 1차 실제 화면 후 `portraitFraming` 기본 false 요청과 `IsPortrait` 진단을 도입했다. Stage는 얼굴 썸네일 요청에만 이를 켜고 메인 촬영에는 적용하지 않는다. 실제 세린 기록의 combined bounds 2.06~2.10m, Head+0.085h 위치에서 얼굴 앵커 비율 약 0.695를 계산해 17번째 독립 검증을 추가했다. 썸네일에는 대사창 하단 여백을 강제하지 않되 모자/턱/머리 폭과 기존 정면·상하 시선각·충돌 기준을 유지하는지 검사한다. 추가 당시 실행을 기다린 뒤, 아래 최종 17그룹 결과와 실제 수정 화면에서 통과를 확인했다.

## 현재 정적 결론

현재 검증본에서 새로 확인한 차단 문제는 없다. 앞서 발견한 오류 노출/재시도, 실제 얼굴 썸네일, 탈출 전 물자 기반의 준비 대사, 자동 진행 길이 및 기계 공격 준비 취소 문제는 수정본에서 해소되었다. HUD·썸네일·스튜디오 노출 보완 후 실행과 화면을 직접 검토했다. 이후 메인의 수동 입력 QA 증빙, 실제 19개 파일의 해시 일치, 실제 편집기의 컴파일·갱신 완료까지 확인했으며 통합 완료를 승인한다.

검증 프로젝트는 메인이 최신 실제 Runtime/Editor/리소스에 이번 수정 파일 목록만 덮어써 구성한다. 작업용 staging의 수정하지 않는 나머지 Runtime은 완전한 최신 통합본으로 취급하지 않는다. 최신 실제 Runtime을 적용한 구성에서 독립 검사와 별도 게임 플레이어 빌드·실행·화면 확인이 완료되었다. 실제 프로젝트에도 검증한 19개 파일이 적용되었고 본 검토자가 manifest·현재 실제 파일·staging 해시 일치를 직접 재확인했다.
