# 중간 시안과 검증 이력

- 촬영 helper 첫 실행은 파이프 출력 인코딩 때문에 한글 작업 경로가 깨져 File.WriteAllText 전에 실패했다. Unity 원본 세션 로그를 보존했다. C# 경로를 Unicode escape 상수로 바꾸고 다시 컴파일했다. 이후 `COMMAND_before...`가 완료된 실제 사진을 확보한 뒤 production 파손 코드를 수정했다. 실패 상태를 변경 전 모델 촬영으로 부르지 않는다.
- baseline_renders의 차량6장·건물3장과 baseline_low의 낮은 no-ivy 상세는 새 회차에서 기존 production 엔진을 실제 실행해 촬영했다. 이전05회차 이미지를 이번 fresh before로 바꾸어 부르지 않는다. 24개 보호 파일의 새 해시와 기존 코어 사본도 먼저 보존했다.
- candidate01: 실제 삭제 삼각형 전체를 정점 법선에 따라 후퇴했다. 금속면은 생겼지만 좌석/대시보드 등 같은 Model에 합쳐진 내부 면도 새 밝은 철판으로 재출력되고, 분리 법선마다 위치가 달라 회색 쐐기·줄무늬가 나타났다. 저장/재열기와 건물 동일성은 확인됐어도 차량 아트는 FAIL이다.
- candidate02: 차체 바깥 위치·외향 면·파손 모서리 근접의 공간 조건을 적용하고, 공통 안쪽 이동 방향과1mm 중복 face/edge 정리를 사용했다. 큰 스파이크는 줄었지만 매끈한 새 회색 외판처럼 보이는 부분과 절단 테두리의 반복 명암 줄무늬가 남아 추가 개선 대상으로 판정했다. 사용자는 ‘빈 공간 메꾸기’를 요청했으며, 중앙 구멍을 항상 열어 두어야 한다는 요구를 추가하지 않는다.
- `LINING_VALIDATION_225221.txt`: backing의 tri80에서 world 면적 검사가 FAIL해 해당 backing/Bake 게이트의 이후 영속성 assertions은 실행되지 않았다. 이때 seed, 사전 극소 예산, 생성 후 예산 초과 rollback, 파손0, 건물 동일성 게이트는 PASS다. 시안 자체의 Bake/재열기 촬영 성공과 독립 하네스 전체 PASS를 혼동하지 않는다.
- 이후 개선 방향은 Vehicle에만 적용한다. 절단 테두리의 법선 방향을 일관되게 정렬하고 모든 새 면에 같은 물리 면적 검사를 적용한다. 평행한 외판 복제 대신 경계는 얕고 중앙은 깊은 연속 후퇴 및 약한 찌그러짐으로 안쪽 금속면을 읽히게 한다. 깊이 수치는 시안 튜닝값이며 영구 사용자 확정 요구가 아니다.

최종 채택 여부와 실제 검증 결과는 CHANGE_RECORD.md의 완료 기록을 따른다. 중간 파일과 실패 원문을 삭제하거나 최종 성공으로 덮어쓰지 않는다.

- 임시 진단 request 파일을 쓰는 순간 읽기 poll과 겹쳐 sharing violation 로그가 남았다. 이후 실제 요청은 정상 완료됐고 최종 status는 Play/dirty와 모든 미리보기 marker0을 확인했다. 이 request helper는 production 기능이 아니며 종료 시 Assets와 request를 제거했다. 기존 오류 이력을 UI/로그에서 지우지 않는다.
- candidate03은 Vehicle 전용의 일관된 안쪽 이동, 변화하는 깊이, 단면 방향 정렬, 물리 면적 필터를 반영했다. 새 면의 실측 검증 및 Bake 재열기가 PASS했고 독립 시각 검토에서도 창·좌석 공간을 유지한 파손 내부 철판으로 채택했다. 최종 건물은 fresh before와 생성 코어·3뷰 PNG가 모두 동일하다.
