# 68동 실내 방식의 검증 의미

`blender/contracts/INDEX.json`과 건물별 frozen contract는 10동을 `newRoom`, 58동을 `reuseExistingCompartments`로 표기한다. 이 값은 **제작 recipe의 의도**이며, 새로 통행 가능한 닫힌 방이나 새로운 실내 문이 실제 Unity에 생겼다는 증거가 아니다. 원본 모델/manifest의 SHA와 roomMode는 수정하지 않는다.

- **새 방 10동:** C01, C04, E02, E04, E07, HALL, N02, N04, N07, N17. 각 계약에 `candidateRoomDoorWitness`의 문 양면 local 점과 clear width, door jamb 2.25m 형상이 있다. 최종 validation contract는 이를 실제 D09 facade frame으로 world 변환하고 `implementation=newRoom`으로 선언한다. Editor 바닥·시각 삼각형·capsule·Nav 및 실제 PlayerMotor 양방향 20 lane 확인 전에는 통과가 아니다. HALL은 원래 열린 대형 구조이므로 새 방이 기존 개방감·파밍 동선을 해치지 않는지 실제 전후 게임 화면에서 별도 확인한다.
- **나머지 58동:** `candidateRoomDoorWitness`가 전부 없으며, detail geometry recipe는 존재한다. 별도 내부 문 양면 점을 발명하지 않기 위해 validation `roomWitness.implementation=detailRecipe`로 둔다. 이는 builder의 `reuseExistingCompartments` 표기를 삭제하거나 실제 구획 재사용을 부인하는 뜻이 아니다. 검증이 자동으로 새 내부 출입문을 주장하지 않는다는 뜻이다. 기존 메인 개구 102문과 실제 50 loot 접근은 별도 전수 검사한다. 내벽·바닥·소품·설비의 개선 실체와 기존 구획 사용성은 전후 화면으로 판정한다.
- **폐허 11동:** S01–S10, S12는 위 58동에 속한다. 열린 잔해·기존 동선을 유지하며 밀폐방을 강제하지 않는다. S11은 Garage 계열이므로 이 폐허 목록에 넣지 않는다.

실제 후보에서 기존 구획의 새 출입구를 별도 검사해야 한다고 확인되면, 그 구획의 실제 문 ID, 양면 발점, 폭·높이, 바닥 지지, 경로와 화면을 계측한 뒤 추가 witness로 기록한다. 선언만으로 새 방 통과를 수치화하지 않는다.
