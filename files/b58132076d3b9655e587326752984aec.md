## 공통 매핑

- 기본 1920×1080 시안 → 기존 logical 1600×900, 비율 1/1.2 유지.
- Panel / Dense / Tile / Selected / Border / Primary / Body / Caption / Heading / Keycap을 FigmaGameSkin과 UiTheme로 매핑한다.
- 기존 FigmaInventorySkin, 실제 아이템 썸네일·티어 색·드래그 하이라이트·푸터 등은 보존한다.
- Noto Sans KR Regular / Medium / Bold를 기존 Resources에서 공유한다. OS fallback만 소유·해제하며 공유 폰트를 파괴하지 않는다.
- 전체 화면 이미지를 UI 위에 덮지 않는다. 메인·로비의 분위기 배경만 별도 에셋이며 버튼·텍스트·아이템·슬롯은 native UI다.

## 예시 데이터와 실제 동작의 구분

Figma 캐릭터·총·아이템·지도와 수치는 배치 확인용 샘플이다. Unity에서는 현재 외형, 실제 장착 무기 모델, 실제 지도와 현재 상태를 계속 사용한다. 샘플 아이템을 지급하거나 샘플 수치·서사를 고정하지 않는다. 지도 지형이나 시설 좌표도 바꾸지 않는다.

상점·연구·저장 등은 기존 거래·조건·저장 API를 유지한다. Figma에 있는 예시 문구나 카드 개수가 새로운 게임 규칙은 아니다. 제작은 준비 중 표시만 유지한다. 새 pause/settings 등 현재 없는 화면은 만들지 않는다.

HUD의 구형 퀵슬롯, 의료휠, 고정 목표 카운터·나침반·탈출 거리·점선 탄창 샘플은 구현하지 않는다. 플레이와 탈출 시안은 실제 미니맵·작전 시계·두 무기·리그 치료·E/X 기반으로 정리했다. 월드 캐릭터와 상호작용 안내는 월드 앵커에 종속되며 중앙 고정 이미지로 바꾸지 않는다.

## 동시 작업 보존

캐릭터 채팅의 고정 orbit·발 위치·클릭/자동 반응·확대율과 인벤토리 채팅의 최신 footer는 해당 소유자의 결과를 우선한다. 스타일 후보의 오래된 전체 소스로 덮어쓰지 않고 최신 원본에 최소 context patch로 병합한다.

## 검증 구분

독립 C# 컴파일과 rect 수학 검사는 실제 Unity import·렌더·입력 검증과 다르다. 실제 전후 이미지/manifest가 생기기 전에는 Unity 적용 완료로 취급하지 않는다. 화면별 source 매핑은 스타일/기능 연결의 범위이며 모든 샘플 데이터나 Figma 합성 배경을 그대로 이식한다는 의미가 아니다.
