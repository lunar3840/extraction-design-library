# 에델 Game·인벤토리 성능과 재생 시간 점검

사용자 원문은 `USER_REQUEST.md`에 보존했다. 같은 대기 동작·성능 문제의 후속이므로 기존 주제와 2026-11-03-01 회차를 유지한다. 진행 확인·공간 확보·후속 재검증을 별도 구현 완료 횟수로 세지 않는다. 이 회차의 수정·측정은 끝났으나 **인벤토리 지연의 완전 해결을 뜻하지 않는다.** 최종 자연 인벤토리 CPU 중앙값은 94.04ms로 높다. 빌드는 미시험이다.

## 지시와 기획 의도

RTX4050 노트북의 Unity Editor Game에서 플레이가 어렵다는 보고에 따라 헤어 외 월드·렌더링·메모리 비용도 분리했다. 이후 인벤토리 지연과 느린 고개 회전이 렉인지 재생 속도인지 조사했다. 사용자가 선택한 **현재 대기 움직임 최대한 유지**에 맞춰 표정·회전·대기 애니메이션 빈도를 낮추는 방식은 생산안으로 적용하지 않았다.

환경은 i7-13700H/32GB/RTX4050 Laptop 6GB, Unity6000.1.0f1/URP17.1/DX12, StageA Relay, Game1920×1080이다. 실제 로그에서 RTX4050 사용을 확인했다. 초기 Game 표본은 CPU166.22ms/GPU5.89ms로 CPU 부담이 컸다. 모든 수치는 해당 Editor·맵·캐릭터·시험 조건의 표본이며 전체 게임이나 빌드 성능으로 확대하지 않는다.

## 적용한 부분과 방식

1. **Game 헤어 거리 단계:** 에델 live 카메라의 1080p 환산 크기180px 진입/240px 이탈 구간에 가벼운 충돌 경로를 사용한다. spring·기존 capsule/무기 box는 유지하고 정밀 mesh field/브레이드 표면 계산을 생략하는 의도된 품질 단계다. 수동 인벤토리·근접 화면은 정밀 경로다. 머리색·UV·원본 메시를 수정하지 않았다.
2. **덩굴 조회 캐시:** 동일 reveal 판정을 유지하면서 반복 sharedMaterials 배열·Shader 이름 조회를 재사용한다. 무기 아이콘은 이전 thumbnail Scene이 비동기 해제 중이면 기존 fallback을 쓰고 다음 요청을 기다리도록 했다.
3. **인벤토리 경계 계산:** 최초 고정 프레이밍 이후 매 프레임 정확 스킨 경계를 다시 구하지 않는다. 진단 getter가 요청되면 현재 경계를 다시 계산한다. 얼굴·총·발까지 정면/측면/후면 프레임에 유지됨을 확인했다.
4. **인벤토리 헤어 병렬 계산:** 수동 에델 초상화에만 body Refit와 거리 계산 worker를 opt-in한다. live Game·다른 캐릭터는 기본 OFF다. 같은 프레임 원본 mirror와 budget/taper/status를 대조했다. Refit 작업 실패는 commit 전에 원본 serial로 복귀하고, 거리 작업 실패는 사용 불가/UNVERIFIED로 닫힌 뒤 재바인드로 회복한다.
5. **재생 시간 보정:** 절차적 idle과 초상화의 수동 Animator.Update 양쪽이 정상적인 느린 프레임에서 시간을 0.1초로 잘라 동작이 느려지고 있었다. 표시 중인 인벤토리의 유한·비음수 dt≤0.5초는 실제 시간을 반영한다. 0.5초 초과 단일 공백은 기존0.1초 제한을 유지한다. 첫 fixed-frame 전 Update0, 로비의 기존 정책, authored clip 속도, 사격 자세·발 고정·입력 분리는 유지했다.
