# A맵 7종 기계 역할 배정 독립 검토

2026-10-16. 읽기 전용 설계·검토다. 검토자는 Unity 실행과 씬·프리팹·에셋 변경을 수행하지 않았다. 아래 적용 후 판정은 메인이 생성한 저장·Play 기록과 화면을 독립적으로 읽은 결과다.

## 기준과 배정 결과

현재 `density-v04/AFTER_ROSTER.txt`와 저장된 `StageA_Relay_Blockout_v08.prefab`의 슬롯 ID 73개가 빠짐없이 일치한다. 일반 기계 54, 일반 인간 14, 네임드 후보 5다. 별도 `ROLE_ASSIGNMENTS.json`은 **일반 기계 54개 ID를 정확히 한 번씩** 지정한다. 역할별 수는 Scout 33, Suppressor 4, Sniper 4, Grenadier 2, Discharger 4, ArcRifle 4, GuardTank 3으로 합계 54다. 7종을 모두 쓰되 수량은 첫 튜닝안이다. 인간 14명 및 N1의 역할은 바꾸지 않는다.

기존 `StageAEncounterKind`는 외형과 공간 점유 기준으로 유지한다. 보통 기계 중 GuardTank 3·Grenadier 2·ArcRifle 4는 모두 기존 SpiderMedium, Sniper 4는 모두 SpiderLight다. 기존 경량 반경/높이 0.9/1.35m와 중형 1.4~1.5/2.2~2.3m, leash·A/B/C 위치·순찰을 바꾸지 않는 안이다. 실제 프리팹의 종류를 역할 이름으로 일괄 치환하면 시각 모델·몸체·기존 검증 조건이 바뀌므로 역할은 별도 데이터로 연결해야 한다.

기본 진입부 G1~G4 여덟 기와 W5 접근 우려가 있는 G8 및 V4_G8_01은 전부 Scout다. 실내 일반 7기(`D_HALL_01/02`, `D_PARTS_01`, `D_POWER_01`, `D_TOOLS_01`, `G12_01/04`)에는 Scout 3·Discharger 3·Suppressor 1을 배정했다. 실내에는 GuardTank·Grenadier·Sniper·ArcRifle가 없다. G9 POWER, G10 PARTS, G12 HALL의 실외 중형에 전차·곡사·전격·제압을 나눠 배치해 위험 시설별 전투 읽기를 달리한다. G10 동쪽 다리 근접을 보정했던 `V4_G10_02`는 Scout로 남긴다.

N2~N5는 기존 고정 홈·외형·반경과 출격당 3~4종 선택을 유지한다. 권장 전투 역할은 N2 Discharger, N3 GuardTank, N4 ArcRifle, N5 Suppressor다. 이는 일반 몹 수치 복사가 아니라 각 고유 외형에 맞는 공격 전조, 강공격 및 회복 구간을 붙이는 권고다. N1은 인간 Breacher 그대로이며 기계 역할을 부여하지 않는다. 새 복합 보스 패턴·추가 홈·네임드 수 변경은 이 배정에 포함되지 않는다.

## 독립 검증과 실제 적용 시 통과 조건

사전 정적 대조 결과, JSON의 54개 일반 기계 ID와 저장 로스터의 일반 기계 집합이 완전히 같고 중복·누락·추가가 없다. 지정 역할의 경량/중형 적격성, 실내 제한, G1~G4·G8 Scout 제한 모두 통과했다. 이 사전 검증은 **ID와 설계 제약**의 합격이며 당시에는 무기 사거리·폭발 반경·감지 범위·시야·추격 시간·투사체 사선을 입증하지 않았다. 실제 적용 후 검사는 아래에 별도로 기록한다.

메인 적용 후 다음 결과를 실제 씬과 실행 기록에서 확인해야 한다.

1. 저장된 씬과 Resources 프리팹의 73개 슬롯, 54/14/5 구성, 실내 7기, N1~N5 고정 홈과 출격당 3~4종, 기존 A/B/C 후보·그룹 동시 선택, Kind·반경·높이·leash·순찰·진입 정책의 전후 동일성. B1~B4는 활성, R8은 비활성 위험 **진입 후보**다. B4/R8 약 62m 및 W5 공용 동선 문제를 역할 교체로 해결했다고 보지 않는다.
2. 각 역할의 실제 표적 획득·최대 사거리·발사 전조·피해·재장전/회복·엄폐 반응을 적어도 대표 1기씩 발사로 확인한다. Sniper와 Grenadier의 장거리/곡사 공격, GuardTank의 강공격은 위치가 그대로여도 B4/R8→W5와 B1~B4 초반 노출을 새로 만들 수 있다. 스폰 거리 완충만으로 안전을 선언하지 않는다. 특히 G7/G9/G10/G11의 Sniper와 G9/G10의 Grenadier, G12 실외 중형에서 초입 또는 탈출 동선을 실제 시야와 탄도 기준으로 검사한다.
3. POWER/PARTS/HALL 문과 좁은 실내에서 7기의 새 공격이 벽·천장·문틀에 바로 막히거나 방 안을 일방적으로 덮지 않는지, 1.4m 중형 `G12_04`의 실내 통행·제압 사선이 기존 경로를 막지 않는지 확인한다. 야외 GuardTank/Grenadier의 전투 중 이동이 PARTS 동쪽 다리 입구와 양쪽 시설 문을 봉쇄하지 않는지도 확인한다. 기존 v04 보정은 몸체와 짧은 순찰의 통행 여유 검증이지 새 역할의 전투 중 점유 검증이 아니다.
4. H1~H6와 인간 네임드 N1은 기계보다 먼저 인지해 우회하고, 눈에 보이는 기계의 지속 접근·조준에 방어 사격할 수 있어야 한다. 기계의 보이지 않는 내부 표적 지정으로 인간이 반응해서는 안 된다. Grenadier 곡사·ArcRifle 효과·Suppressor 탄막이 인간과 플레이어 중 실제 위협을 기준으로 표적을 택하는지, 기계/인간/플레이어의 삼자전에서 표적 전환과 피해·처치 기여도가 맞는지 확인한다. 새 역할이 기존 회피 거리를 무력화하거나 인간 수색조를 출격 직후 과도하게 지우는지 장시간 표본으로 본다.
5. 전후 동일 카메라의 기본 진입 4시점, W5 양쪽 접근, 실내 HALL/POWER/PARTS, 7종 대표 사격과 네임드 전조를 촬영한다. 기본 진입과 W5에서 바뀐 역할의 발사/폭발이 보이면 결과를 숨기지 않고 범위 또는 역할 배정을 조정한다. 적용 결과의 `CHANGE_RECORD.md`와 대응 전후 PNG가 있어야 완료 보고가 가능하다.

현재 스포너에는 일반 기계 인식 18m, 네임드 21m, 인간 일반 27m·네임드 30m라는 기준이 있다. 역할별로 이 수치나 사격 범위가 늘어나면 기존 배치 검증의 24m 기본 진입 보호, 15m 공용 초반 회랑 완충, 인간 순찰 활동 여유를 **새 능력 범위 기준으로 다시 계산**해야 한다. 특히 새 사격은 leash 밖으로 닿을 수 있으므로 위치와 순찰만 동일하다는 이유로 이전 안전 판정을 계승하지 않는다.

## 실제 적용 후 확인된 증거와 남은 판정

- `ROLE_ROSTER.txt`는 일반 기계 54기의 7역할 분포가 배정안과 정확히 같고, 기존 73개 ID·Kind·몸체·순찰·실내 표시·네임드 홈을 바꾸지 않았다고 기록한다. `SAVED_VALIDATION.txt`는 저장한 A씬/Resources 프리팹 검사를 PASS로 기록하며, `CHANGED_EXISTING_OBJECTS.txt`는 0바이트로 기존 객체의 변경 목록이 비어 있다. 별도로 `BEFORE_ROSTER.txt`와 `AFTER_ROSTER.txt`는 파일 길이 31,393바이트 및 SHA-256이 동일하고, `BEFORE_PROTECTED.txt`와 `AFTER_PROTECTED.txt`도 각 18,762,989바이트 및 SHA-256이 동일하다. 이는 저장 상태와 보호 객체의 전후 동일성에 대한 강한 증거이며 실제 출격 중 행동의 증거와 구분한다.

- `WEAPON_ENVELOPE_SAFETY.txt`는 67개 비정찰 특화 후보의 보수적 수평 공격 외피가 B1~B4와 B4/R8→W5 회랑에 닿지 않는다고 PASS를 기록한다. 최소 진입 여유 84.83m, 회랑 여유 39.15m다. 이 계산은 순찰 선분·전체 leash·몸체 반경·최대 무기 사거리·폭발 반경을 합치며, 실제 엄폐/수직 사선과 장시간 표적 추격을 대신하지 않는다.
- `EscapeStageAMachineRoleCombatChecks.txt`는 17개 검사 그룹 PASS를 기록한다. 7종 각각 실제 사전 피해 0·발사/피해·쿨다운, 네임드 N2~N5의 별도 연속 공격, 잠긴 조준 회피, 유탄·전차의 벽 충돌/엄폐, 직사탄 거리 상한, 가시 상실·동결·사망 시 전조 취소를 포함한다. 인간이 저격 첫 발 전에 보이는 조준을 인식해 방어 준비하는 검사도 PASS다. `PLAY_checks_132430.txt`는 기존 적·전투·진영 표적·인간 회피·인간 사격 검사 `COMPLETE PASS`를 기록한다. 이들은 통제된 시험이며 실제 A맵의 장시간 삼자 교전 결과와는 구분한다.

- idle 최적화 후 같은 seed의 최종 `PLAY_actual_135505.txt`도 세 변형의 `COMPLETE PASS`를 기록한다. 출격당 네임드 3/4/4종, 실내 7기 사거리 제한, B1~B4/R8 정책, POWER·HALL의 출입문 간 NavMesh 완주 경로가 확인됐다. 이동 샘플 계수는 변형 진행에 따라 **누적** 84,923→167,867→242,328개이며 offNav·점프·구르기·Animator 이탈은 끝까지 0이다. 실내 개체는 30초 동안 짧은 순찰을 수행했다. 이는 **문 양쪽의 경로 연결과 실내 이동** 검사로, 모든 기체·애니메이션 자세가 실제 문틀을 통과하는 장면을 촬영·검증한 결과는 아니다. 최종 실행의 평균 프레임은 변형별 25.32/26.24/29.10ms로, 기존 결과 및 교차 측정의 환경 편차를 고려해 성능 동등 판정에 사용하지 않는다.
- 동일 seed의 30초 기록에서 프레임 평균은 변형 0이 18.62→22.63ms, 변형 1이 17.71→28.36ms, 변형 2가 14.78→37.83ms로 증가했다. 표본 프레임 수는 각각 1,624→1,340, 1,700→1,065, 2,037→800이며 최대값도 241→333ms, 117→244ms, 128→274ms로 커졌다. 캡처/Editor 상태와 실행 순서의 영향이 통제되지 않았으므로 이 결과만으로 역할 구현의 성능 퇴행이라고 단정하지 않는다. 그러나 **성능 동일 또는 개선으로 판정할 수 없다.** 아래 동일 세션 교차 측정으로 범위를 더 좁혔다.
- 추가 `PERF_PAIRED_134427.txt`는 동일 Unity 세션, 같은 seed 61030, 각 3초 예열+12초 측정으로 legacy/roles/roles/legacy/legacy/roles 순서의 6회 교차 기록이다. 평균 프레임은 legacy 16.16·19.81·21.97ms, roles 16.70·17.67·30.05ms다. legacy도 순서가 뒤로 갈수록 느려져 역할 추가가 악화의 유일 원인이라고 볼 수 없고, 마지막 roles의 30.05ms도 무시할 수 없다. Render Thread 계측은 모든 회차 `valid=False`이므로 렌더 비용의 원인 분해는 실패했다. 역할 모델은 Renderer 675→725, Animator 72→119, Light 0→100개다. `StageAMachineWeaponVisual.EnsureLights`가 총구마다 Light를 만들고 대기 중 intensity=0만 적용하므로 상시 활성 컴포넌트 비용은 후속 점검 대상이다. 이 기록은 **성능 동일성을 입증하지 않는다.**
- 메인은 위 Light 비용 후보를 보고 대기 상태 `Light.enabled=false`, 전조/발사 때만 활성화하고 강도·색·반동 Transform의 동일값 반복 대입을 줄였다. 따라서 아래 최종 측정의 `lights=100`은 존재하는 **컴포넌트 수**이며 상시 켜진 조명 100개라는 뜻이 아니다. 이 최적화 후의 기능 회귀 결과는 아래 최종 검사에서 확인했다.
- 최적화 뒤 별도 같은 세션 6회 교차 `PERF_PAIRED_135045.txt`는 같은 seed/카메라/72개체에서 legacy 평균 24.533·21.324·21.954ms, roles 평균 26.995·24.077·27.294ms다. AB/BA/AB 인접 쌍의 역할 추가 평균 비용은 각각 +2.46·+2.75·+5.34ms로 남는다. Main Thread 유효 값도 같은 방향이며 Render Thread는 여전히 `valid=False`라 GPU 비용은 측정되지 않았다. 두 교차 세션의 환경 변동을 통제하지 못했으므로 idle 최적화가 몇 ms를 절감했다고 계산하지 않는다. Editor 측정이고 standalone 빌드의 성능·프레임 목표는 별도 확인이 필요하다. 현 증거에서는 **기능 구현과 성능 동등 승인 범위를 분리**한다.

**최종 독립 판정: 이번에 승인된 7종의 A맵 역할 적용과 저장, 기존 배치·진입 정책 보호, 대표 외형·전조·실제 피해 기능, 3개 출격의 기본 이동/경로 연결, 전후 증빙 및 변경 기록은 완료 범위로 통과한다.** 이는 후속 회귀 검사까지 읽은 판정이다. 동작 중 모든 문틀·천장 간극, 실제 A맵의 장시간 삼자 교전·밸런스, 모든 전투 거리에서 7종 외형의 즉시 식별, standalone 빌드 성능은 승인하지 않는다. 최적화 후 같은 세션 측정에서도 역할 모델의 프레임 추가 비용은 +2.46/+2.75/+5.34ms였으며 성능 동등성은 확인되지 않았다. 이 한계와 후속 튜닝 대상을 명시하는 조건으로 기능적 적용 완료를 인정한다.
