# A맵 기계형 몹 속성 색 표현 가능성 — 파일 구조 조사

2026-10-16. **읽기 전용 조사**다. Unity 에셋, 프리팹, 스크립트, 씬, Play 상태는 변경하지 않았다. 아래의 구현 방식과 색은 확정 사항이 아니며, 실제 게임 화면에서의 식별성은 아직 검증하지 않았다.

## 판단

현재 모델의 외형을 유지하면서 개체별 속성 표식을 넣을 수 있다. 가장 보수적인 방향은 원본 몸체·궤도 텍스처를 유지하고 별도 발광 포인트나 지정된 UV 영역에만 색을 입히는 것이다. 현재 프리팹과 URP 재질만으로는 **한 개체의 몸체 페인트와 여러 발광 부위를 서로 다른 속성색으로 독립 제어하는 기능이 이미 구현돼 있지는 않다.** 공유 재질에 색을 직접 쓰면 같은 재질을 쓰는 모든 기계에 영향이 간다.

다섯 게임 프리팹에서 조종석 렌더러 재질 슬롯을 동일한 `A_Spiders_Mat_8b80dc15_URP.mat` (GUID `a245be46...`)로 덮어쓴다. 변신형과 탱크의 일부는 `A_Spiders_Tracks_Mat_8edb0cb1_URP.mat` (GUID `3d788e79...`)를 사용한다. 조립 원본의 본체/궤도 재질 역시 각 종류가 동일한 원본 재질 GUID를 참조한다. 즉 **재질 공유와 다중 렌더러를 모두 고려**해야 하며, 조종석에만 색을 바꾸는 구현은 다리/차체에는 반영되지 않는다.

본체 URP 재질은 `_BaseMap`, `_BumpMap`, `_MetallicGlossMap`, `_EmissionMap`과 흰색 `_BaseColor`, 흰색 `_EmissionColor`를 가진다. `_EMISSION` 키워드가 활성이다. 실제 `_BaseMap`은 원본 `MC_Spiders_Diffuse_Red.png` (4096²)로 붉은 페인트, 청록 금속, 어두운 부분, 노란 표시와 마모가 한 아틀라스에 섞여 있다. `_EmissionMap`은 `MC_Spiders_Emission.png` (4096²)이며 대부분 검고 작은 주황 램프/선만 밝다. 궤도 재질은 파란 궤도 아틀라스(`MC_Spiders_Tank_Tracks_Blue.png`)를 쓰고 `_EmissionMap`이 비어 있으며 `_EmissionColor`가 검다.

원본 패키지에는 White/Yellow/Green/Blue/Black 등 다른 알베도와 `MC_Spiders_X_Color_ID.png`가 있다. Color ID 이미지는 부위별 구역을 담고 있지만 **현재 게임 재질에는 연결되지 않는다**. 원본 Readme도 새 색 제작에 알베도 페인트 레이어 편집을 안내한다. 이를 근거로 색상별 **별도 텍스처 변형**은 가능하나, 기존 재질 값 하나만 바꿔 모든 부위의 색을 선택적으로 재배치하는 상태는 아니다.

## 방식별 가능성 및 주의점

1. **개체별 포인트 발광:** 기존 몸체 발광 마스크를 별도 복제/가공하여 중립 명도 마스크로 쓰거나 지정된 발광 부품을 추가한 뒤 인스턴스별 색을 줄 수 있다. 원본 본체의 질감과 실루엣을 가장 잘 보존한다. 현재 주황색 발광 이미지에 `_EmissionColor`만 곱하면 청백·보라 등 임의 색으로 정확하게 바뀌지 않는다. 이 이미지에는 해당 색 채널의 정보가 거의 없기 때문이다. 큰 어두운 기계나 원거리에서 작은 발광 부위만으로 식별될지도 화면 검증이 필요하다.
2. **몸체의 제한된 페인트 구역:** Color ID 이미지를 마스크로 쓰는 전용 셰이더/텍스처 처리, 또는 원본 페인트 구역만 바꾼 별도 알베도 변형으로 가능하다. 녹·스크래치·금속 명암을 유지하도록 마스크와 원본 디테일을 합성해야 한다. 단순 `_BaseColor` 변경은 붉은 페인트뿐 아니라 금속·노란 표식 등 아틀라스 전체를 물들이므로 원본 외관 유지 목적에 부적합하다. 현재의 컬러 ID는 재질에 미연결이므로 실제 모델 UV와 구역 일치를 검증해야 한다.
3. **분리된 메시/렌더러 사용:** 특히 중형 다리는 렌더러가 많아 전체 조각 단위 재질 분리가 가능하다. 반면 경량/중량 다리는 스킨 메시 안에 여러 UV 구역이 통합되어 있으며 렌더러 단위 색 변경만으로 작은 페인트 포인트를 분리할 수 없다. 조립 부품을 통째로 다른 색으로 만드는 것은 가능해도 부품 안의 램프/장갑/금속을 따로 바꾸지는 못한다.
4. **다수 속성을 동시 표시:** 현재 본체의 단일 발광 재질/마스크에 하나의 `_EmissionColor`를 주면 그 마스크의 밝은 영역은 전부 같은 색이다. 서로 다른 표시 의미나 여러 속성을 동시에 보여 주려면 포인트 영역별 별도 렌더러·재질/프로퍼티 블록, 다중 채널 마스크가 있는 전용 셰이더, 또는 리깅에 붙는 구분된 표식 메시가 필요하다. 부위와 의미를 먼저 정의해야 하며, 공격 속성과 약점을 같은 색 신호로 섞으면 오독 위험이 있다.

**개체별 적용:** 게임은 `StageAEncounterSpawner.Create`에서 리소스 프리팹을 각 적의 자식으로 `Instantiate`한다. 생성된 `visual`의 관련 Renderer에 `MaterialPropertyBlock`을 적용하거나 그 개체 전용 재질 인스턴스를 배정하면 다른 적과 공유 에셋을 건드리지 않고 표현할 수 있다. `sharedMaterial` 속성 또는 `.mat` 에셋 자체의 색 변경은 피해야 한다. 여러 렌더러에 동일 의미의 색을 적용할 경우 본체/궤도 재질 슬롯을 필터링하고 필요한 렌더러를 모두 순회해야 한다. 기존 `_EmissionMap`의 주황 원색 한계는 프로퍼티 블록만으로 해결되지 않는다.

**애니메이션:** `StageAEnemyVisual`은 이동/공격/사망 애니메이션을 제어하고 기계의 root motion을 끈다. 재질 프로퍼티만 바꾸면 뼈와 애니메이터는 그대로지만, 별도 표식 메시를 추가한다면 실제 장착 `Mount_`나 움직이는 뼈에 맞춰 붙여야 한다. 스킨 메시의 버텍스/UV를 새로 분리하거나 변신·궤도 부위에 부착하면 변신, 보행, 회전, 사망 자세에서 접힘·관통·표식 가림을 확인해야 한다. 탱크 궤도 재질은 기본 발광 설정이 없으므로 본체 방식의 자동 전파를 가정하면 안 된다.

## 확인 범위와 미확정 사항

- 이 문서는 에셋의 YAML 연결, 이미지 자체, 코드만 확인했다. Unity 실행, 새 시안 제작, 전후 스크린샷, 실제 시야 거리/조명 테스트는 하지 않았다. 게임 에셋 변경이 없는 조사이므로 전후 비교 이미지는 없다.
- 현재 다른 대화에서 열·냉각·전격·충격의 최대 네 속성이 제안되었으나, **각 기계의 속성·약점·색상 대응이나 시각 채널은 확정되지 않았다.** 본 조사 결과가 특정 속성을 특정 기계나 색에 배정하는 근거는 아니다.
- 실제 적용 전에는 동일 조명·카메라의 정면/측면/후면 및 이동·공격/변신 자세에서 몸체 원본 외관과 표식 가독성을 비교해야 한다. 공격 속성 표시인지 약점 표시인지도 시안마다 명확히 구별해야 한다.
