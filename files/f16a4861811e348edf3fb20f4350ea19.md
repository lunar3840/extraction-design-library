# 소형 기지 출격 / 기존 출격 UI 병행

## 사용자 지시와 기획 의도

- 기본 로비를 작은 기지에서 직접 이동하며 출격을 준비하는 방식으로 변경한다.
- 기존 전체 화면 출격 UI는 삭제하지 않고 TAB으로 기지와 전환한다.
- 두 화면은 장비, 가방, 출격 지역, 저장 및 출격 처리를 공유한다.
- 하우징은 구현하지 않는다. 작업대는 준비 중 장식과 안내만 제공한다.

## 변경 전

- 프로필 진입 및 귀환 시 전체 화면 출격 UI가 기본으로 열렸다.
- TAB으로 자유 이동은 가능했지만 공간은 B의 이전 테스트 구역을 공유했다.
- 별도 소형 기지 및 물리 시설 접근 동선이 없었다.

## 실제 변경 내용

- `SmallBaseCampView`: 별도 16×14m 소형 기지, 중앙 통로, 출격 단말·보관함·보급소·의뢰 게시판·장식용 작업대.
- 기존 재질 재사용. 지붕 없이 카메라 쪽 외곽은 낮게 유지하며 큰 설비와 외곽만 충돌 처리한다.
- `SessionBaseCamp`: 기지/출격 지형 배타적 표시, 기지 진입 위치, 시설 근접 F 상호작용, 시설명/조작 안내.
- `SessionTestWorld`: 생성/로드/탈출/사망 복귀 시 기지를 기본 표시한다. 출격 저장 성공 후 기지를 숨기고 기존 맵 경로로 출격한다.
- `SessionGlassView`: TAB은 열린 창/드래그/의료 휠을 정리하고 같은 위치에서 두 모드를 전환한다. 전체 화면 UI의 기존 캐릭터·장비·출격 선택은 유지한다.
- 기지 좌상단 버튼 영역은 게임 포인터 입력을 차단하여 UI 클릭이 사격으로 전달되지 않도록 한다.
- 시설은 기존 패널에 연결한다: 출격 0, 보급 1, 보관 2, 의뢰 4. 새 출격 권한이나 저장 형식은 만들지 않는다.
- 기지에서는 카메라의 커서 앞보기만 일시적으로 끄고 출격 시 기존 값으로 복원한다.
- 기존 파밍/바닥 드롭의 F 상호작용이 있으면 그 입력을 우선하며 시설 입력은 겹치지 않는다.
- 기존 동료 칩 관련 병행 변경은 보존한다. A맵/적 배치/캐릭터 외형 에셋은 이번 작업에서 수정하지 않는다.

## 증빙 조건과 스크린샷

본 Unity의 열려 있는 작업 씬과 실제 저장 슬롯을 건드리지 않기 위해 별도 복제 프로젝트에서 임시 프로필로 실행했다. 변경 전 코드는 수정 착수 전에 실행하고 실제 게임 화면을 저장했다. 1600×900, 동일한 기본 카메라 설정, 커서 앞보기 0, 동일한 UI 배율을 사용했다. 기지 진입 위치 자체는 이번 변경 대상이므로 전후 좌표가 다르다.

| --- | --- | --- |

## 중간 검증에서 확인한 환경 문제

- 복제 프로젝트에 패키지 일부 파일이 빠져 첫 빌드가 실패했다. 원본 패키지 캐시를 복제본에만 보완했다.
- 첫 후속 화면에서 원본 `Art/Toon` 셰이더가 복제본에 없어 분홍색으로 표시됐다. 원본 셰이더를 복제본에만 보완하고 재촬영했다. 실패 화면은 `material_probe/`에 분리했으며 최종 화면으로 취급하지 않는다.
- `-nographics` 검사는 URP의 RenderTexture 오류로 실패하여 그래픽 장치가 활성화된 별도 배치 실행으로 변경했다.
- 첫 독립 검사의 동료 칩 미장착 가정은 현재 새 프로필의 기본 세린 칩과 달랐다. 검사에서 명시적으로 칩을 분리/재장착하도록 고쳤다. 제품의 칩 규칙은 바꾸지 않았다.
- 복제본의 오래된 A맵은 최신 적 배치 구성 요소가 없어 출격 검사에 실패했다. 이때 출격 취소 후 기지 복원 동작을 확인했다. 현재 A맵과 필요한 기존 적 에셋을 복제본에만 동기화해 정상 출격을 재검사한다.
- 작업 중 다른 채팅에서 동료/맵 검증이 진행 중이었다. 이 작업은 원본 씬의 Play 종료, 저장, 맵 배치 변경을 수행하지 않는다.

## 최종 확인

- **원본 반영 완료**: 위 6개 C# 파일과 신규 3개 메타 파일을 반영했다. 기존 파일 3개의 통합 직전 해시가 기준본과 동일함을 확인하고 적용했으며, 이후 6개 전체가 검사한 staging과 일치함을 확인했다(줄바꿈 정규화 기준).
- 원본 `Assembly-CSharp.dll` 13:48:48, `Assembly-CSharp-Editor.dll` 13:48:53 KST 재생성 확인. 적용 시각 13:48:29 이후이며 현재 Editor.log에서 C# 컴파일 오류는 발견되지 않았다. `INTEGRATION_VERIFICATION.txt` 참조.
- **독립 기지 검사 60개 PASS**: `EscapeSmallBaseCampChecksLegacy.txt`. 기본 기지, 실제 캡슐 보행/충돌, TAB 전환 함수와 위치 보존, 시설별 기존 창, 작업대 미연결, 공용 지역 선택, 저장 실패, B 출격/탈출/사망/귀환, 타이틀 및 재로드.
- **UI 회귀 검사 102개 PASS**: `EscapeGlassLayoutChecksLegacy.txt`. 기존 캐릭터 화면, 회전/고정 포즈, 장비·가방·성장·의뢰·저장 및 창 전환과 지연 동작 취소. B 구역을 사용하는 별도 검사 진입점으로 실행했으며 기존 A 검사 진입점은 유지했다.
- **A맵 정상 출격 전체 검증은 미완료**: 현재 복제본에 A 배경 중첩 프리팹 9종이 없어 원본과 동일한 맵을 재현하지 못했다. 최신 맵을 넣은 시도는 `Stage A spawn became obstructed: N1`로 취소됐다. 이를 원본 A맵의 확정 결함이라고 판단하거나, B 통과를 A 통과로 취급하지 않는다. 맵/적 배치/스폰 검사 코드는 수정하지 않았다. 실패 후 기지 원복은 실제 확인했다.
- 모든 기지 재질/렌더러 115개 항목의 셰이더가 지원 상태였다. 시설 접근, F 안내, 공용 창, 기존 전체 화면 UI의 실제 게임 PNG를 검토했다.
- 실제 게임 창에서 마우스 버튼을 통한 전체 UI↔기지 왕복을 확인했다. 원격 키 주입은 TAB 의도와 다른 반응이 있어 신뢰하지 않았으며 **실제 키보드 TAB 성공으로 보고하지 않는다**. TAB의 전환 함수·상태·위치 검사는 통과했고, 기존 입력 분기는 유지했다. 재생 재시작 후 실제 사용자 키보드로 확인할 수 있다.
- 화면 기록용 빌드는 최종 포인터 차단 보완 전의 동일한 시각 배치다. 최종 포인터 차단 코드는 검사 프로젝트와 원본에서 컴파일됐고 위 회귀 검사에 포함됐다. 화면에 드러나는 배치 차이는 없다.
- 원본 Unity의 Play를 종료하거나 씬을 열고/저장하지 않았다. 원본 재생 중 상태를 새로 로비 진입시켜 보지는 않았다. 실제 슬롯은 사용하지 않았다.
- 정상 로비 진입은 `Assets/Escape/Scenes/SystemsTest.unity`에서 생성/로드하거나 작전에서 귀환할 때 확인할 수 있다. 현재 A맵 전용 `StageScenePreview`의 재생 즉시 출격 동작은 지도 테스트용이므로 유지했다. 현재 Play는 재시작이 필요하다.
- 신규 UI 및 기지 코드만 제품에 반영했으며 임시 프로필/자동 캡처/검사 실행 씬은 원본 씬에 넣지 않았다. 하우징과 제작 기능은 추가하지 않았다.
