# 테트리스형 인벤토리 변경 기록

## 사용자 지시
2026-10-12: 아이템별 다중 칸·회전 인벤토리와 앞서 제안한 연계 UI를 Unity에 실제 반영. 모든 서브 에이전트 GPT-6.1 Sol extra high 사용, 메인이 통합 검토.

## 기획 의도 및 변경 전 상태
아이템 크기 값은 있으나 실제 수납은 한 물품당 한 슬롯이다. 배치 공간, 회수 후 부담, 물품 용도를 함께 판단하도록 변경한다.

## 변경 전 증빙
- before_field_hud.png / before_field_inventory.png / before_field_detail.png: 원본 Unity 에디터의 StageA_Relay_Blockout_v08 격리 미리보기에서 실제 촬영. 게임뷰16:9, 에디터창1587x1011. HUD는 시작 위치, 인벤토리는 근처 이동 후 촬영했으므로 배경 카메라·시간·잔탄 차이가 있다.
- before_source/: 변경 시작 전 원본 Assets/Escape의 cs/json/asmdef/shader/unity/meta 4,834개 파일 복사. before_source_hashes.csv SHA256 목록.
- 기지 창고·출격 점검의 동일 조건 전후 비교는 이 원본 백업을 기반으로 별도 검증 실행에서 추가 확보할 예정. 사후 이미지를 전 이미지로 사용하지 않음.

## 실제 반영한 내용
- 165개 아이템의 가로·세로 크기를 명시했다. 소총 4×2, 저격총 5×2, 헬멧 2×2, 기본 방탄복 3×3 등 실제 직사각형 공간을 차지한다. 90도 회전, 겹침·경계 검사, 교환 시 양쪽 공간 검사를 적용했다.
- 가방은 기본 6×6이며 확장 단계마다 1행·6칸과 기존 5kg 한도가 늘어난다. 창고는 10×10 페이지로 표시하고 기존 5,000개 항목 보유 한도를 보존한다. 전리품도 실제 격자에 배치하며 수색 순서와 창을 닫아도 이어지는 수색을 유지한다.
- 같은 배치 계산을 미리보기와 실제 이동에서 공유한다. 드래그, 회전, 합치기, 수량 선택 후 분할 이동, 부분 이동, 장비 교체 실패 시 보존을 연결했다. 드래그 시작 시의 개별 물품 ID와 수량을 확인해 뒤늦은 입력이 다른 물품을 움직이지 않도록 했다.
- 장비/초상은 왼쪽, 가방은 중앙, 전리품·창고는 오른쪽에 표시한다. 가방 위치를 유지하고 초상 접기를 지원한다. 상세 화면은 선택 물품의 설명·크기·중량·실제 잔량을 먼저 보여 준다. 세로로 긴 칸에서도 아이콘 비율을 유지한다.
- 창고 검색·종류별 강조·다음 검색 결과 이동·페이지·자동 정리·보호 표시를 추가했다. 검색으로 흐려진 물품도 원래 공간을 계속 차지한다. 일괄 보관은 보호 물품, 장착 장비, 진행 중 의뢰의 제출 필요 수량을 제외하고 먼저 수량을 보여 준다.
- 출격 준비에는 실제 장착 무기, 탄창/호환 예비탄, 방어구 상태, 의료품 용량·횟수, 신체 상태, 의뢰별 추가 물품의 수납 예상과 중량을 표시한다. HUD에는 간단한 중량 상태를 표시한다. 귀환 결과 요약을 추가했다.
- 기존 저장 형식 1/2를 3으로 이전한다. 물품 ID·수량·탄창·방어구 내구도·의료품 잔량을 보존한다. 등록된 퀵슬롯 종류를 우선 배치하며, 새 가방에 배치되지 않는 물품은 창고의 ‘이전 저장 복구함’에서 회수할 수 있다.
- 배치·정리·보호 변경은 기존 무기 객체와 발사 대기시간을 유지한다. 사용 중인 의료품을 실제로 이동·회전하면 기존 규칙대로 소비 없이 사용을 취소한다. 인벤토리 입력의 R/Shift가 재장전·달리기·의료 취소로 전달되지 않도록 분리하고, ESC는 진행 중인 드래그/수량 선택/일괄 보관 확인부터 취소한다.

## 변경 방식과 보존 범위
실제 Unity 프로젝트는 `C:\UnityProject\escape`이다. 코어 및 화면 구현을 GPT-6.1 Sol extra high 서브 에이전트에 나누어 배정하고, 별도의 동일 모델·추론 수준 에이전트가 독립 검토했다. 메인이 결과를 읽고 통합 검증 및 화면 비교를 수행했다. 최초 지정된 Astra 서브 에이전트는 사용자의 모델 정정 후 중지했다.

실행 전 `before_source`와 실제 저장본 복사본을 확보했다. 별도 Unity 검증 프로젝트에서 동일 소스를 컴파일·검사·Windows 빌드했다. 원본 에디터에서는 기존 맵의 격리 미리보기로 화면과 드래그를 확인했다. 사용자 저장본은 복사본으로만 이전·재저장을 시험했다.

- `changed_source_hashes.csv`: 변경/추가 파일과 최종 SHA256. 기존 27개 파일 수정, 6개 C# 파일과 대응 메타 파일 추가. 삭제 없음.
- 맵·씬·셰이더·모델·머리 재질 파일 변경 없음. 원본 장면을 저장하지 않았다.
- `catalog_balance_preservation.txt`: 165개 아이템의 기존 크기 이외 속성 값이 모두 동일함을 확인. 중량·가격·치료량·탄약 밸런스를 임의로 변경하지 않았다.
- `original_saves_preservation.csv`: 원본 slot-1, 백업 slot-1, slot-2의 SHA256이 작업 전 복사본과 동일하다.
- 추출 성공 시 가방 보유 유지, 의뢰 제출의 실제 가방 소비, 기존 전투/의료 규칙을 유지했다.

## 검증 결과
`after_all_rules_results.txt`의 9개 묶음이 모두 통과했다: 기존 인벤토리, 장비, 전리품, 저장/사망, 기지/의뢰, 새 격자/저장 이전, 독립 검토, 무기, 부상/의료.

이후 작은 이전/전리품 수정은 `after_final_rules_results.txt`로 재검증했다. 회귀 및 UI 보고서 9개 `Escape*Checks.txt`에는 총 502개 PASS 항목이 있다. 별도의 독립 검증 보고서는 `review_scratch/independent_review_checks.log`에 있다.

- 3,000회 결정적 혼합 조작에서 겹침·경계·개별 객체 중복/소실·수량 보존 검사 통과.
- 5,000개 큰 물품의 구형 창고 이전 및 정리 통과. 마지막 측정에서 이전 77ms, 정리 39ms였으며 실행 환경에 따라 달라질 수 있다.
- 실제 저장본 2개 및 별도 백업 1개의 물품/개별 상태 보존 검사 통과. 복사본의 실제 저장소 로드→이전→저장→재로드 통과.
- 가방이 큰 장비로 가득 찬 구형 저장에서도 퀵슬롯 3종 보존, 초과 물품 회수, 저장 실패 시 원상태 유지 통과.
- 무기 발사 대기시간/재장전과 의료 잔량, 사용 중 의료품 이동 취소 검사 통과.
- `EscapeGlassLayoutChecks.txt`: 실제 Play Mode에서 UI 배치, 포인터 차단, 드래그, 퀵슬롯, 장비 교체, 패널 전환, 출격/귀환 후 상태, 지연 입력 취소를 검사하여 92개 PASS.
- Windows 개발 빌드 성공: `after_final_build.log`. 마지막 창고 표시 보완 빌드와 화면은 아래 최종 확인 항목에 기록한다.
- 원본 Unity 화면에서 2×2 헬멧 드래그 이동 성공, 원래 공간에 교환 대상이 들어가지 않는 드롭 실패 및 물품/내구도 보존을 직접 확인했다.
- R를 누른 채 드래그하는 전체 키·마우스 조합은 네이티브 자동화로 재현하지 않았다. 회전/미리보기/입력 분리와 ESC 취소는 코어 검사·UI 코드 독립 검토로 확인했고, 실제 마우스 드래그는 별도로 확인했다.

### 검증 중 발견하여 해결한 사항
배치 저장이 무기 객체를 복원하여 발사 대기시간을 초기화할 수 있는 문제, 의료품 물리 위치 변경 누락, 전리품 미리보기의 수색 시점 차이, 부분 합치기 수량 메시지, 오래된 전리품 드래그 ID, 퀵슬롯 이전 우선순위, 큰 창고의 반복 탐색 비용을 수정하고 재검증했다. 마지막 화면 비교에서 가방 배경이 창고 위를 덮는 문제와 제목 잘림도 수정했다.

첫 렌더링 검사는 그래픽 비활성 모드에서 URP의 `EndRenderPass` 오류가 발생했다. 그래픽을 활성화한 동일 Play Mode 검사는 통과했다. 기존 NavMesh 폐기 예정 API 경고는 남아 있으며, 이번 변경의 컴파일 오류는 없다.

검증 도구는 `validation_tooling/`에 보관했다. 원본 Unity 씬에는 추가하지 않았다.
