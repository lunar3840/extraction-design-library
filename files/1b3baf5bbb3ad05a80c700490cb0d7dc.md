# A맵 전체 환경의 노후화·파손·덩굴 적용

## 사용자 지시 원문

> 좋다. 이제 이 노후화 파손 시스템과 덩쿨 시스템을 전 맵 / 전 에셋에 적용해볼래?

## 의도와 범위

이전05~06의 개별 시안 검증을 이어 실제 현재 A맵의 건물·실내외 배경물·차량·산업 소품·담장 등 환경을 전수 조사하고 적용한다. 일부 시안만 만들고 전체 완료로 보고하지 않는다. 최신 `StageA_Relay_Blockout_v08.unity`와 Resources의 현행 맵 프리팹을 기준으로 하고, 과거 버전으로 맵이나 최신 AI/가림 작업을 되돌리지 않는다. 임시 B 보관 씬/비활성 과거 구조·미사용 원본 에셋 라이브러리를 현재 플레이 맵으로 취급하지 않는다.

모든 인공물의 상태를 적용·보호·기존 처리·지원 불가와 사유로 구분한다. 캐릭터·AI·진입/탈출 마커·기능 상호작용·물·지형·보행면·기존 식생을 무차별 파괴하지 않는다. 출입구·파밍 지점·이동로와 건물별 색/재료·실내외 콘셉트를 유지하며, 자연이 침식한 폐허의 강도와 군집을 위치·용도별로 다르게 준다. 원본 공유 모델·재질을 일괄 수정하지 않고 맵에 새 결과를 연결해 교체 가능하게 보존한다.

## 병렬 소유와 공유 Unity

메인이 통합·실행·전후 촬영·저장을 맡고 GPT-6 Sol high 서브가 배경 처리 제작(staging/builder), 구역별 전수 분류/강도(staging/profiles), 독립 검증(staging/validation)을 나눈다. 관련 AI/그래픽 채팅의 현재 미사용 확인과 명시 실행권 인계를 받았다. 제작 완료 보고만으로 통과하지 않으며 실제 출력·게임 화면을 읽어 통합한다.

## 사전 증빙

최신 A맵 씬/88MB 맵 프리팹의 새 백업, 모든 Renderer/충돌체/기능 참조·스폰/위험 진입 정책의 before inventory, 실제 URP 전후 사진을 확보한다. 처음 native capture는 활성 화면이 다른 앱으로 잘못 잡혀 `invalid_capture_other_window.raw.jpg`로 분리했으며 증빙·게시에는 사용하지 않는다. Unity 활성화 후 다시 확인한 실제 편집 화면만 `before_editor_handoff`로 보존한다. 이 오류를 모델 before 이미지로 위장하지 않는다.

## 검증 방향

가시 형상과 충돌의 불일치, 보행·문/창·탈출/파밍 접근, 기존 기능 컴포넌트/참조, 스폰 B1~B4/R 비활성 정책, B4/R8 접근 경험, V33의 플레이어 가림 및 새 덩굴의 가시성 연계, 새 메시·재질의 영속성, 지오메트리/Renderer/재질 증가와 실제 게임 프레임을 검사한다. 원래의 일부 경로 경고나 과거 빌더 전제를 새 실패와 구별하며, 측정하지 않은 FPS나 전맵 무결성을 단정하지 않는다. 게시 완료는 최종 원문·사진·검증 동결 후 실제 공개 재조회로 확정한다.
