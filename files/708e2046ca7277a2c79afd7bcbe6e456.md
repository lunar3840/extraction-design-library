# 에델 런타임 최적화 2차 계획

사용자 원문: “2차로 어떻게 작업 가능할까?” 이번 회차는 계획·코드 검토이며 게임 코드/에셋/설정/씬/저장 데이터 변경0, 새 Unity 실행·성능 실험0이다. 같은 런타임 개선 의도의 후속이므로 기존 주제 ID와 회차04를 유지한다. 구현 완료 횟수로 세지 않는다.

## 근거와 우선순위

1차 최종 기록 ../edel-runtime-optimization/CHANGE_RECORD.md, MATCHED_SUMMARY.json, fixed_results.json 및 staging/review/FINAL_REVIEW.md를 근거로 한다. 동일 입력 whole Step 평균58.6825→56.8811ms(3.07%)는 헤어 CPU 재생의 결과이며 전체 게임 FPS를 뜻하지 않는다.

최종 실제 Play fixed240표본의 내부 평균은 CurrentSource Apply17.29ms, BraidSurface17.32ms, BeginFrame CurrentSource Refresh11.37ms다. BodyQuery8.31ms는 위 구간에 중첩된다. 타이머를 합산하지 않으며 위 실 Play 값과 같은 입력56.88ms의 실험 범위를 섞지 않는다.

1. 정밀 거리 경로: CurrentSourceClearanceFieldBudget EvaluateParts→Distance→HeadSourceClearanceFieldBudget.TriangleDistanceSquared의 호출 수·커널 시간을 분리 계측한다. 기존 BVH/거리 캐시를 유지하고, part epoch가 같은 삼각형의 edge/bounds 등 불변 항목에서 실제 반복 비용을 확인한 항목만 재사용한다. 형상/표정/pose epoch 변경 시 무효화와 기존 질의 순서를 보존한다. 커널 비중이 작으면 구현을 확대하지 않는다.
2. 땋은 머리의 Adaptive/Score: 모든 후보 자세와 접촉 witness를 유지하며, 동일 Step에서 변하지 않는 입력을 묶어 중복 읽기·변환을 줄인다. 기존 collection/score cache와 중복인 설계는 제외한다. 1차에서 이득이 불분명해 반려한 score 정점/face 캐시는 재도입하지 않는다. 본 분류/방향 snapshot은 실제 하위 계측에서 비중이 확인될 때만 채택한다.
3. 실제 플레이 검증: 동일 입력 CPU A/B 뒤 일반 이동·조준·사격·재장전·방향 전환의 실제 프레임 평균/p95·GC와 근접 외형을 비교한다. 최종 Serin 조합 미검증을 해소하고 Liv/Yui도 회귀한다. 개발 빌드에서 CPU/GPU를 분리하여 헤어 외 AI·비·그림자 병목을 확인한 뒤에만 해당 범위의 후속안을 낸다. 이번 계획만으로 그래픽 품질을 낮추지 않는다.

## 구현·검증 원칙과 분담

메인이 공유 Unity 사용 순서를 재조율하고 같은 카메라/캐릭터/무기/해상도에서 실제 before를 먼저 보존한다. 기존 1차 이미지를 새 2차 before로 가장하지 않는다. GPT-6 Sol high 제작은 우선 CurrentSource 경로, 별도 독립 검토는 품질·캐시 무효화·계측 해석을 맡는다. 같은 SdHairCollisionMotion 파일의 동시 수정을 금지하고 별도 staging 파일로 순차 통합한다.

한 후보씩 원본/개선 독립 스위치로 같은 포즈 A/B를 반복한다. 메시/본/표정과 접촉 선택·깊이·valid·bound 등 핵심 결과를 대조하고 기존 허용치/검사 의도를 유지한다. 1차 digest에서 빠졌던 개별 접촉 결과도 필요한 범위를 보충한다. 평균뿐 아니라p95, GC/메모리, 초기 Bind/첫 프레임도 구분한다. 결과 불일치·관통 증가·미확인 접촉 증가 또는 반복 측정에서 오차를 넘는 이득이 없으면 반려/복원한다. 검사 횟수 변화가 최적화 결과일 경우 실제로 생략 가능한 동일 연산인지 별도 증명 없이는 수용하지 않는다.

후보 탐색은 Transform 상태를 순차 변경하고 거리 질의는 nearest seed/cache 상태를 사용하므로 곧바로 병렬화하지 않는다. 입력 snapshot과 결과 선택 순서의 동등성을 확보한 뒤 필요할 때 병렬 수치 계산을 검토한다. 후보 수/품질/갱신 주기를 줄이거나 헤어를 숨기는 변경은 이 계획에 포함하지 않는다. 예상 절감률·60FPS·2ms 달성을 약속할 근거는 아직 없다.

## 검토·증빙과 라이브러리

GPT-6 Sol high 코드 담당이 최종 소스/실측을 읽기 검토했고 메인이 검토 보고를 읽어 주력 후보를 Current Apply와 Braid Adaptive/Score로 좁혔다. REVIEW.md는 그 판단을 보존한다. 현재 소스 해시는 SOURCE_HASHES.json이며 게임 파일 수정 없음 확인용이다. 계획이므로 새 전후 이미지가 없고, 1차의 실제 증빙을 출처로만 연결한다. 구현 시 새 전후/CHANGE_RECORD를 같은 주제 다음 회차에 남긴다.

초기 게시 보류 당시 기록(아래 인증 복구로 해소): 기존 라이브러리 담당의 직전 회차03 PUBLICATION_VERIFICATION.json에서 유효한 업로드 인증 미확보를 확인했다. 이번 계획은 로컬 준비 상태이며 공개 색인/원문 게시를 완료한 것으로 표시하지 않는다. 같은 담당에게 회차04를 인계하고 추가 인증 복구나 키 교체를 수행하지 않는다. 이후 인증을 확보한 담당이 미게시02/03/04 연속성과 실제 공개 원문을 검증한다.
