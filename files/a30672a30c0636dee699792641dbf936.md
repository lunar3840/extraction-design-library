# W10 한 동 샘플 독립 검토

검토일: 2026-10-26 KST. 검토 범위는 제출된 실제 Unity Editor/Play 보고서와 원본·결과 이미지다. 이 문서는 W10 한 동의 기술 검증을 판정하며, 최종 저장 상태·전체 맵 밸런스 승인 자료로 대체하지 않는다.

## 판정

- **Editor 기술 검사: PASS.** [`W10_VALIDATION.txt`](W10_VALIDATION.txt)의 최종 재실행 결과는 223 PASS / 0 FAIL이다. 첫 실행의 221 PASS / 2 FAIL은 비볼록 `MeshCollider`에 지원되지 않는 `ClosestPoint`를 호출한 검증기 오탐으로 확인됐으며, [`W10_VALIDATION_attempt_01.txt`](W10_VALIDATION_attempt_01.txt)를 진단 기록으로 보존했다. 수정 후에는 중앙 통로 및 두 상자 보호 영역에 실제 Physics overlap hit가 각각 0이다.
- **격리 Play 경로·상호작용 검사: PASS.** [`play_attempt_01/W10_PLAY_VALIDATION.txt`](play_attempt_01/W10_PLAY_VALIDATION.txt)는 6개 W10 전용 경로 모두 PASS / 0 FAIL이다. 북→남과 남→북 각각 기존 두 문을 통과했고, 새 검사실 문을 양방향으로 출입했으며, 기존 W10 상자 두 곳에 도달해 실제 `LootInteractor.CanOpen` 및 `Open`에 성공했다. `PlayerMotor.Simulate`와 활성 `CharacterController`를 사용했다. 물리 키보드/마우스 조작은 하지 않았다.
- **출격 미리보기 캡처: PASS.** [`../integration/AFTER_PLAY_CAPTURE.txt`](../integration/AFTER_PLAY_CAPTURE.txt)는 실제 런타임 상자 50개 생성과 북·남·실내 3뷰 촬영을 기록한다. 이는 상자 50개 전부의 플레이 동선 검증을 뜻하지 않는다.

## 확인한 기술 범위

- 새 루트 세 개의 부모와 W10 범위가 맞고, 원본의 명시적 변경은 기존 D09 외벽·지붕 두 루트의 비활성화뿐이다. Editor 검사는 다른 건물과 원본 지점·위치·상태 보존을 전후 스냅샷으로 대조했다.
- Blender manifest의 시각 메시 **143개**(외벽 52, 지붕 39, 실내 52)가 Unity에 들어왔고, 선언한 물리 메시 **17개** 모두 보이는 메시와 동일한 MeshFilter/MeshCollider 및 bounds로 판정됐다. 장식용으로 선언한 나머지 메시는 시각 전용이다.
- 기존 문 두 곳의 폭 3.4m·높이 3.1m, 캡슐·머리 높이·턱·바닥 지지, 시야, 양방향 임시 NavMesh 경로가 통과했다. 새 검사실 문은 폭 1.6m, 물리·시각 개구, 지지 바닥, 양방향 NavMesh와 실제 Play 통행이 통과했다.
- 기존 W10 파밍 두 지점의 바닥·접근점·방향·지지 충돌체·선택 문과 시야가 전후 일치했고, 실제 출격 상자 ID `loot_w10_shipping`, `loot_w10_weapons`의 접근·상호작용이 통과했다.
- 새 지붕 렌더러 **39개**는 Play에서 외부 닫힘, 내부 컷어웨이, 외부 복귀 상태를 보였으며 옛 지붕 루트는 계속 비활성이다.

## 판정의 한계와 후속 확인

- Play 검사는 AI만 동결한 격리 월드의 결정적 경로 검사다. AI 위협·생존율·전체 69동·게임 밸런스는 판정하지 않았다. 루팅은 열기 동작까지 확인했으며 아이템 회수나 보스 처치는 범위 밖이다.
- `LootInteractor.CanOpen`은 거리/시야 등을 확인하지만 별도의 캐릭터 바라보기 조건을 검증했다고 해석하지 않는다. 테스트는 상자를 향해 캐릭터를 돌린 뒤 실제 `CanOpen`/`Open`을 호출했다.
- 이 검토는 보고서·제공 이미지에 대한 독립 읽기다. 최종 씬 저장/재열기, 잔여 콘솔 오류, 변경 기록·라이브러리 게시 상태는 통합 담당의 최종 확인 대상이다.
