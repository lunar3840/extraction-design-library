## 사용자 지시 요약

다른 컴퓨터에서 비밀번호를 입력해 게임 수치를 수정한 뒤 변경 CSV를 내려받고, 실제 Unity 프로젝트가 있는 PC에서 편집기를 실행해 그 CSV를 가져와 게임 수치에 반영할 수 있게 한다. 두 컴퓨터를 동시에 연결하거나 원격 반영 요청을 계속 대기시킬 필요가 없는 경로를 제공하는 요청이다.

이 작업은 기존의 공개 열람·비밀번호 편집 권한과 별도 반영 버튼을 유지하는 범위에서 진행했다. 기획 라이브러리 담당 채팅과는 공통 화면 배열을 맞추기로 조율했으며, 라이브러리 소스 수정은 해당 담당의 소유 범위다.

## 기획 의도와 해결하려는 문제

공개 웹은 실제 Unity 프로젝트가 없는 PC에서도 데이터를 보여 주지만, 원격 반영 경로만 사용하면 프로젝트 PC가 연결되지 않은 동안 실제 파일을 바꿀 수 없다. 수치 조정 작업과 Unity 반영 작업을 시간·컴퓨터 양쪽에서 분리할 수 있도록, 여러 분류의 변경과 그 변경의 기준값을 한 파일에 담아 이동하게 했다.

프로젝트 PC에서는 가져오자마자 원본을 수정하지 않는다. 현재 원본과 CSV의 기준을 검사하고 전후 값을 보여 준 뒤 사용자가 마지막 반영 버튼을 눌러야 기존 백업 절차를 거쳐 원본을 수정한다.

## 변경 전 상태 및 문제점

- 기존 편집기는 분류별 CSV 가져오기·내보내기와 웹의 Unity 반영 요청을 제공했다.
- 서로 다른 분류의 미저장 변경을 하나로 모아 다른 PC로 전달하는 전용 흐름이 없었다.
- 전달 당시의 원본값과 프로젝트 PC의 현재값을 비교하는 이동용 파일 형식이 없었다.
- 실제 로컬 편집기를 재시작하는 과정에서, 다른 작업으로 C# 줄 구성이 변한 뒤 기존 CSV의 줄 ID가 다른 필드에 재사용되는 초기화 문제도 발견했다. 이전 숫자를 새 불리언 필드로 해석하려고 하면서 시작이 실패했다.

실제 수정 전 공개 웹과 로컬 편집기의 화면을 각각 `before_web.png`, `before_local.png`로 저장했다. 로컬 CSV 초기화 보완을 적용하기 전의 실제 데이터 폴더도 `before_csv_store/`에 백업했다. 사후 이미지를 변경 전 이미지로 사용하지 않았다.

## 실제 변경한 부분

### 웹에서 변경값 내보내기

- 상단에 **CSV로 PC 이동** 진입점을 추가했다.
- 공개 열람 상태에서는 비밀번호 잠금 해제를 안내하며, 서버도 인증되지 않은 내보내기를 거부한다.
- 비밀번호 인증 후 **변경값 CSV 내려받기**를 누르면 플레이어·적·경제 등 모든 분류의 변경을 CSV 한 개로 받는다. 아직 웹에 저장하지 않은 편집값도 포함한다.
- 내보내기는 웹 저장, Unity 반영 작업 생성, 게임 원본 수정을 수행하지 않는다. 기존 반영 요청이 대기 중인 경우에도 인증된 소유자가 변경 CSV를 받을 수 있다.

### 프로젝트 PC에서 가져와 검토·반영

- 프로젝트 PC의 **데이터 편집기 열기.cmd**로 연 로컬 화면에서 **CSV로 PC 이동 → 웹 변경 CSV 가져오기**를 제공한다.
- 파일 안에 분류와 원본 식별 정보가 포함되므로 분류를 따로 고르지 않는다.
- 가져오기는 변경값을 임시 편집 상태에 올린 뒤 **게임에 반영할 변경 사항** 비교 화면을 연다. 이 단계에서는 저장 CSV와 Unity 원본을 수정하지 않는다.
- **검토한 변경을 게임에 반영**을 눌렀을 때만 기존 검증·원본 백업·파일 반영·재추출 경로를 사용한다.
- 같은 목표값이 이미 반영된 파일은 중복 변경으로 처리하지 않는다. 다른 임시 편집값이 남아 있다면 가져온 CSV의 목표값으로 검토 상태를 정리한다.

### CSV 기준 및 충돌 검사

- 전용 형식 `extraction-transfer-v1`에 프로젝트, ID, 대상, 필드, 값, 자료형, 원본 경로, 변경 전 값을 포함한다.
- UTF-8 BOM과 CSV 인용을 사용하고 쉼표·따옴표·여러 줄 문자열을 보존한다. 문자열은 JSON 문자열 표기로 담아 수식으로 시작하는 텍스트가 직접 실행될 형태로 출력되지 않게 한다.
- 다른 프로젝트·없는 ID·읽기 전용 항목·중복 ID·자료형 오류·필드나 원본 정보 변경·잘못된 헤더·CSV 형식 오류를 거부한다.
- 프로젝트의 현재 원본이 CSV의 변경 전 값과도 목표값과도 다르면 충돌로 처리한다. 한 항목이 잘못되어도 다른 항목만 부분적으로 가져오지 않는다.
- 편집기를 연 후 원본 파일이 바뀐 경우도 다시 확인하며, 기존의 수량·최소/최대 관계 등 게임 데이터 검증을 함께 수행한다.

### 로컬 초기화 보완

- 저장 CSV를 새 행 자료형으로 해석하기 전에 기존 원본·필드·자료형 메타데이터부터 비교한다.
- 줄 ID가 다른 필드에 재사용되었고 기존 CSV에 미반영 변경이 없으면 현재 원본을 다시 읽어 안전하게 갱신한다.
- 재사용된 ID에 미반영 변경이 있거나 기준을 확인할 수 없으면 시작을 명확히 거부한다. 기존 모든 CSV와 기준 파일의 바이트를 보존한다.
- 전체 확인이 끝나기 전에 누락 CSV를 먼저 쓰지 않도록 초기화 순서를 보완했다.

### 기획 라이브러리와 공통 셸 조율

기획 라이브러리 담당 채팅과 합의해 브랜드를 `EXTRACTION WORKSPACE / 익스트랙션 워크스페이스`, 심볼을 E로 맞췄다. 첫행76px·작업 버튼행44px·하단여백12px, 좌우14px, 좌메뉴236px, 열간격16px, 도구탭40px를 적용했다. `.shared-header`, `.shared-brand`, `.shared-tabs`, `.shared-actions`, `.shared-workspace` 클래스를 공유한다. 편집기 우측 상세 패널은 도구 기능에 맞춰 유지했다. 라이브러리 소스·배포는 해당 담당이 소유한다.

### 실제 브라우저 확인

1. 별도 웹 미리보기에서 비밀번호로 잠금을 해제했다.
2. 최대 체력 `100 → 110`을 웹에 저장하지 않은 상태로 **CSV로 PC 이동 → 변경값 CSV 내려받기**를 실행했다.
3. 실제 Unity 프로젝트 PC에서 실행한 로컬 편집기로 다운로드한 파일을 파일 선택 창을 통해 가져왔다.
4. 비교 화면에 최대 체력 `100 → 110`과 대상 원본 `Assets/Escape/Settings/PlayerDefaults.asset`이 표시되는 것을 확인했다.
