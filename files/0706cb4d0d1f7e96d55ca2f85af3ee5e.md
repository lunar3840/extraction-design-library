# 폐차 파손 내면 보강 독립 검증 계획

## 범위와 선행 증빙

- 이 문서는 **실행 전 검증 계약**이다. Unity 실행과 원본·후보 렌더 촬영은 메인 담당이다.
- 이번 회차의 원본 차량/건물 prefab, source mesh/material, A맵 scene, renderer/lighting 파일의 fresh SHA-256 또는 Unity dependency hash를 production 수정 전 별도로 확보한다. 이전 구조 파손 회차의 before 이미지를 이번 회차 fresh before로 바꾸어 부르지 않는다.
- 검증용 원본 95,314 triangle 차량은 `Assets/Escape/Art/FactoryV12/Prefabs/StageA_v12_RustyVehicle_Car.prefab`이다. 실제 아트 시안의 source는 이전04 `SAVED_PREFABS.txt`의 `combined_car=Assets/Escape/Art/SurfaceIvy/Generated/CombinedReclaimed_car_Ivy_f5316c07ca/CombinedReclaimed_car_WithIvy.prefab`이며 candidate04 `car_recipe.json`의 seed731/damage.68/debris.80/fullness.94/raw weather 수치를 재사용한다. 두 source의 역할을 섞지 않는다.
- 폐차는 같은 iso/top/detail과 **새로 드러나는 파손 내면 상세/낮은 각도**를 before/after/reloaded로 찍는다. 금속 내면이 차량의 찢긴 외피 뒤에 있고 창·문 개구부를 막지 않는지 그림자 포함 화면에서 본다.
- 사용자는 기존 건물 결과 유지를 명시했다. candidate04 건물의 저장 prefab 및 원본 S06 FBX의 해시와 동일 카메라 렌더를 전후 비교한다. 새 범용 엔진에서 동일 건물 fixture 고정 seed 재생성 시 geometry fingerprint와 report 수치도 이전 `VALIDATION_215002.txt`와 일치해야 한다.

## 자동 게이트: 실행 전 계약

1. **차량 원본 보존:** original car prefab과 mesh/material dependency hash가 전후 같다. Preview는 source renderer와 mesh/material reference를 바꾸지 않는다. Bake는 새 폴더에 별도 자산을 저장한다.
2. **실제 보강:** 생성 child `__RuinGenerated_VehicleBacking_<sourceRenderer>`와 재질 `RuinGenerated_ironBacking`에 실제 삼각형이 있다. 새 `GeometryReport` 계약 `vehicleBackingTriangles`는 뒤로 물린 **내면만**, `vehicleStitchTriangles`는 기존 절단 경계와 잇는 **연결면만** 센다. 두 값을 더한 수가 backing mesh 전체 삼각형 실측과 일치하고 `vehicleBackingMeshes`는 child 수와 같아야 한다. `vehicleBackingMinRecessWorld`/`Max`도 확인한다. cutTriangles>0, 본체 mesh fingerprint가 원본과 다르고, 단순 파편 수 증가만으로 통과하지 않는다.
3. **면 품질:** backing 정점/노멀/UV 및 모든 삼각형 좌표가 finite다. 삼각형 index는 범위 안이고 면적은 world space에서 의미 있는 양수이며, 노멀은 finite·길이 양수다. 차량 seed731 시안의 깊이 튜닝값은 절단 경계 약 `0.025~0.05m`에서 안쪽 약 `0.16~0.23m`까지 연속 변화하는 방향이다. 하네스는 이 시안에 한해 report 최소/최대가 `0.02~0.25m` 안에 있고 차이가 `0.02m`보다 큰지 확인한다. 이 숫자는 사용자 확정 사양이 아니며 다른 seed/차종에 일괄 강제하지 않는다. 외피와 같은 평면의 z-fighting, 수직 명암 줄무늬, 평면 보수 패치처럼 보이는 문제도 낮은 각도 렌더로 확인한다.
4. **원래 개구부:** 앞/뒤 유리, 옆창, 출입구의 열린 경계를 넓은 fan으로 덮지 않는다. 원본의 개구부 템플릿/마스크를 원본과 같은 카메라로 대조하고, backing mesh의 projection이 주요 빈 유리 영역을 메우지 않는지 확인한다. 이름만 `door`/`glass` 보호한 것으로 통과 처리하지 않는다.
5. **예산과 씨앗:** 같은 seed에서 생성 메시 vertex/index fingerprint와 backing 수·recess 수치가 같다. 다른 seed는 피해 위치 또는 메시 fingerprint가 변한다. 극소 triangleBudget은 모든 변경 renderer를 되돌리고 새 backing/rim/debris root와 자원을 남기지 않는다. 별도 저폴리 차량 fixture에서 원본 triangle 수 이상·정상 생성 resultTriangle 수 미만으로 예산을 설정하여, **원본 사전 통과 후 backing/stitch를 더한 최종 예산 초과**가 rollback되는지도 확인한다. 이 경우 `Generated triangles ... exceed budget` 경고, source renderer 재활성화, 생성 root/면/파편/카운터 제거를 요구한다. damage=0은 생성 root와 backing/stitch 수가 모두 0이어야 한다. 정상 resultTriangles는 backing까지 합산해 budget 이하이며 fragmentBudget도 지킨다.
6. **Bake/reload:** car 새 prefab을 Bake→강제 reimport→다시 load하고 생성 몸체/backing의 vertex/index fingerprint, recipe/seed, 새 material·mesh asset path, 참조가 유지된다. 기본 시안 신규 Collider=0이다.
7. **건물 불변:** 이전 `VALIDATION_215002.txt`의 S06 shell **검증 fixture seed81231/damage.72/debris.70** 값 `source=21332`, `result=21995`, `cut=781`, `cap=60`, `fragments=24`, 생성 shell mesh fingerprint `e0bb08d3c57b487d`를 **같은 설정**으로 대조한다. candidate04 건물 저장 prefab(`...S06_Ruin_Building_Original_RuinPreview_WeatheringPreview_Ruin_c89fb734cd67/...prefab`) 및 원본 S06 dependency hash는 fresh before/after가 같다. 렌더의 기존 지붕 개구부·덩굴·앞 모서리·잔해를 같은 카메라로 확인한다. 이 검증 fixture 숫자를 candidate04 실제 아트 recipe seed731/damage.74 숫자로 혼동하지 않는다.

## 판정 제한

- 이전 회차 `VALIDATION_215002.txt RESULT PASS`는 당시 범위에서 유효하다. 이 문서의 backing 게이트는 새 구현과 fresh baseline 뒤에만 판정한다.
