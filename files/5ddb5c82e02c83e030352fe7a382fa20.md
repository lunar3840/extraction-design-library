## 추가 bridge 동적 봉쇄 시험이 필요할 경우

현재30초B정지는 bridge시험이 아니다. 추가하려면 각교량별로 **동일한 로스터/seed의 live회차**에서 플레이어를 north접근30m밖에 한번 배치하고, 이후 매프레임Δt 그대로 normal PlayerMotor로 접근→교량→south이탈20m를 연속 걷는다. 시험도중워프·적freeze·AI수치변경은하지않는다. 반대방향도 같은기준으로한회측정하고 아래값을 남긴다.

- 실제경과초, HP, 사격대상/실제shots/피격, 교량구간XZ폴리곤내살아있는NPC수와agent정체시간
- 플레이어목표진행이1m미만인연속2초 이상은정체후보로 기록하되, 사망·수동정지·생존회피의도와벽충돌을분리
- 실패시 bridge도착전/교량위/이탈후 구간,충돌체path,localNavMesh와실제agent반경을함께보존
- 자연로스터에교량을막는적이없으면 `통과관찰/동적봉쇄미유발`로 보고. 적을임의로교량에줄세운스트레스시험은 별도 fixture로표시하며 자연발생난도와혼용하지않음

두교량자연통과한회도 모든조합봉쇄부재를증명하지않는다. 실제유발이필요하면 현재리쉬내유인이가능한인접적만 자연적으로유인하고, 담당시설병력을교량밖으로강제이동시키지않는다.

## 후속 소스 검토 — 국소 파밍 loop 추가본

첫 리뷰 이후 메인이 source에 실제 loot 검색/획득과 continuous lane을 추가한 것을 확인했다. 앞의 최초 소스 판정은 이 변경 이력으로 보존한다.

- 마지막 일반 `B4_X3_final`을 B4→최인접 loot 접근과 loot→최인접 exit의 두 lane으로 교체했다. **물리 lane은 이제14개**다. 마지막 두 lane 중 두 번째는 `continuous=true`이고 현재 실제 위치가 계획 시작점1m 이내인지 확인하며 Warp하지 않는다. 따라서 성공하면 **AI frozen 상태의 B4 국소 파밍→탈출 한 사례**로 인정할 수 있다. B1~B3까지 국소 파밍을 수행했다고 표현하지 않는다.
- `OpenLocalLoot`가 실제 CanOpen/Open을 호출하고, `SearchLocalLoot`가 완료된 슬롯의 실제 Take를 실행하며 live bag의 해당 item 수량+1을 확인한다. LootInteractor.Update는 UseLiveInput=false여도 Active.State.Advance(now)를 호출하므로 실제 검색시간 경과 구조가 유효하다.
- 중간 이동은 여전히 가속 스텝이고 world 생존/작전 timer는 꺼져 있다. 이 국소 loop는 상호작용·이동·저장 통합 근거이며 실제 전투 위험을 포함한 자연 출격 성공률 근거는 아니다.
- 모든 상자가 무조건 비어 있지 않거나 가방에 연속 공간이 있다고 보장하지 않는다. 35초 뒤 검색/Take 실패가 나면 empty box, inventory space, 실제 검색 상태, CanOpen 실패를 나눠 원인을 기록한다. 전리품 생성·분포 결함이나 경로 결함으로 즉시 귀속하지 않는다.
- direct query 상세에 sampledFrom/To를 기록하도록 보완됐다. fallback query의 sampled 좌표와 정확한 sample 오차는 추가 기록이 바람직하지만, helper 내부 endpoint 검증 계약은 앞서 확인했다.

기존 문·교량·위험시설의 과거 좌표를 current witness/지지바닥과 대조하는 필요, actor radius/leash 검증과 단순 NavMesh 연결성의 구분, 정지 관찰의 범위 제한은 그대로다.
