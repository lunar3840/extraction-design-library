# 컷씬 자동 연출과 실제 맵 촬영

## 사용자 지시 및 의도
스토리의 감정·상황을 잘 보여 주는 자연스러운 정면/대각선 구도를 자동으로 고른다. 뒷모습·위에서 내려다보는 화면을 피하고 부드러운 움직임을 넣는다. 별도 대화창과 실제 인게임 맵 촬영을 모두 지원하며 재생 중 게임과 시간은 정지한다. GPT-6.1 Sol / ultra 에이전트 3개에 구도 계획, 무대/인물, 독립 검증을 분리 배정했다.

## 변경 전
기존 퀘스트 시스템에는 메인/서브/인연과 예시 퀘스트가 있고, 컷씬은 별도 3D 대화 무대와 고정된 대사별 구도였다. 실제 맵에서의 촬영·공간을 평가하는 자동 구도 선택은 없었다.

## 구현 내용
- 감정과 주목 대상에 따라 정면·얕은 좌우 대각선 후보를 평가하는 로컬 촬영 계획기.
- 얼굴 위치/화면 영역/장애물/전체 이동 경로를 검사하고 후면·높은 내려다보기를 배제.
- 제한된 호 이동·접근·후퇴와 부드러운 정지. 자동 진행 최소 촬영 시간 보장.
- 실제 맵 인물 연결, 기존 장비/위치/재질 보존, 얼굴 썸네일, 기존 리그를 활용한 작은 고개/시선 연출.
- 실제 맵 및 별도 대화 무대 모드, 시간/입력/적 정지 및 종료·실패 복원.
- A맵 진입 예시와 거점 귀환 예시. 현장 완료는 출격 저장 경계를 지켜 미회수 전리품 저장을 방지.

## 방식과 제한
온라인 GPT 호출이 아니라 구조화한 감정·상황과 실제 공간을 점수화하는 결정적 런타임 시스템이다. directingNote는 제작용 메모이며 자유 텍스트 자동 이해 기능이 아니다. 세린의 실제 메시에서 표정 blend shape가 없음을 확인했으므로 카메라·고개·시선으로 표현하며 미소/눈깜박임/립싱크 제작 완료로 취급하지 않는다.

## 증빙 상태
- before_camp.png / before_dialogue.png / before_dialogue_late.png: 수정 전 별도 검증 실행의 실제 캡처.
- before_editor.png: 작업 시작 시 주 편집기 창 캡처. 다른 실행 창이 겹친 부분이 있어 구도 비교용으로 쓰지 않는다.
- before_editor_clear.png: 실제 Unity 편집기에서 가림 없이 다시 확보한 수정 전 화면.
- before_ingame.png: 동일한 시드 19371로 A맵에 진입한 수정 전 실제 게임 화면. before_complete.txt로 최종 실행 완료 확인.
- 첫 검증 복제본의 A맵 프리팹에 최신 배치 의존성이 없어 진입이 실패했다(before_errors_initial.txt). 두 번째는 동적으로 읽는 최신 전리품 배치 자료가 없어 실패했다(before_errors_missing_loot_manifest.txt). 실제 프로젝트의 의존 에셋·배치 자료를 전용 복제본에 동기화한 최종 빌드(before_map_build_final.log)와 실행은 성공했다. 실패 기록을 지우거나 실패 장면을 정상 전 이미지로 위장하지 않았다.
- 원본 캐릭터·맵 에셋 및 사용자 저장은 수정하지 않는다. 검증은 독립 저장 경로와 전용 복제 프로젝트에서 진행한다.

## 확인 결과
Unity 6000.1.0f1에서 독립 구도/저장/적 정지 검사 16개 그룹, 57,260 assertions 통과. 검사 작성 에이전트가 실제 로그 및 검사 소스 해시 일치를 직접 검토했다. 기존 QuestStoryChecks 60개, SessionChecks 43개도 통과했다.

별도 회귀 검사인 BasecampChecks는 상품 수를 63개로 고정한 이전 기대값에서 실패했다. 병행 총기/탄약 상품 개편 담당에게 전달했으며, 이를 컷씬 검사 통과로 숨기지 않는다. 실패 원문은 BasecampChecks_existing_failure.txt 및 after_build_2.log에 보존한다. 해당 담당이 최신 상품 목록을 검사하도록 기존 Editor 검사를 수정하고 11개 그룹 2,241 PASS를 보고했다(`../weapon-ammo-tiers/legacy_checks_final_summary.txt`). 우리 최종 컷씬 소스와 최신 거점 검사를 조합한 재검사를 별도로 수행한다.

1차 실제 플레이어 실행은 193개 상태 검사를 통과했다. 실제 게임 시간/남은 작전 시간/플레이어·적의 상태를 4초간 고정하면서 컷씬 카메라는 움직였고, 종료·중단·자동 진행·비활성화·배우 누락·전 구도 차단에서 원래 상태와 촬영 자원 해제를 확인했다. `attempt_01/`에 원본 결과를 보존했다.

1차 화면에서는 스킬 HUD 중첩, 작게 잡힌 정사각형 썸네일, 테스트 동료의 과노출을 발견했다. 스킬 표시만 컷씬 중 숨기고, 정사각형 얼굴 촬영 전용 구도를 추가하고, 대화 무대 주광 강도를 3에서 1.35로 낮췄다. 실제 맵 조명·재질·캐릭터 머리색은 바꾸지 않았다.

## 최종 검증 및 적용

- Unity 플레이어 빌드 성공: after_build_4.log.
- 최종 독립 검사: 17개 그룹, 57,407 assertions, 실패 0. 썸네일 전용 검사 147개 포함. CinematicDirectionChecks.txt.
- 최종 실제 실행: GUID cc457bc46ca64896bdd33b202a2d3acc, 79.70초, runtime_checks.txt의 199 PASS / FAIL 0 / ABORT 0. after_errors.txt에는 실행 식별 헤더만 있고 오류가 없다.
- 최신 거점 검사 339개, 세션/저장 검사 43개, 퀘스트/대화 검사 60개 통과. CinematicRegressionRecheck.txt 및 각 검사 로그. 앞서 실패한 오래된 상품 수 기대값은 최신 검사로 재검증하여 해소했다.
- 실제 Space·기록·Escape·건너뛰기 취소/확정과 게임 화면 복귀 확인. MANUAL_UI_CHECKS.md와 after_manual_*.png.
- 메인과 독립 검토자가 최종 사진에서 HUD 겹침 해소, 얼굴 썸네일 확대, 테스트 동료 노출 완화, 실제 맵 넓은 구도→감정 근접 구도를 확인했다. 독립 검토 결과는 INDEPENDENT_REVIEW.md.
- 실제 프로젝트 C:/UnityProject/escape/Assets/Escape에 검증한 소스 19개를 적용하고 SHA-256을 대조했다. deployed_hashes.json에 적용 시각과 전후 해시, source_before_apply/에 적용 직전 백업을 보관했다.
- 실제 Unity 편집기가 변경을 자동 감지해 컴파일/어셈블리 재적재/Refresh를 완료했다. 적용 이후 구간만 저장한 actual_editor_import.log에서 컴파일 오류 0, 최종 빌드 명령 ExitCode 0을 확인했다. 같은 Scene 시점의 after_editor.png를 저장했고 실제 19개 파일을 다시 대조한 결과 해시 불일치 0이었다. 기존 지도 검사 메뉴 중복 및 폐기 예정 API 경고는 남아 있으며 이번 컷씬 컴파일 오류가 아니다. 실제 편집기에서 Play나 Scene 저장은 하지 않았다.
- 공유 ProfileSession은 최신 총기/탄약 변경을 유지한 채 FinishRunStory 호출 두 곳만 통합했다. CompanionAbilityController는 컷씬 중 HUD 표시를 숨기는 조건 한 곳만 변경했다. 병행 작업 소유자와 충돌 없음을 확인했다.
- 검증 드라이버/격리 프로필/임시 검사 빌더는 실제 프로젝트에 배포하지 않았다. 실제 맵·프리팹·모델·재질·사용자 저장 및 진입점은 수정하지 않았다.
