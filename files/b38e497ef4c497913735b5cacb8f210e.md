## 반드시 구분할 현재 적용 상태

Blender 파일은 **애니메이션을 편집할 원본**이고, 최근 Unity 보정이 모두 구워진 최종 게임 모델은 아니다. FBX 단독으로 열었을 때 마지막 게임 화면과 파지·머리 모양·명암이 완전히 같다고 가정하면 안 된다.

- 현재 Unity에 설치된 `Edel.fbx`와 위 Blender 원본에서 내보내 둔 `Edel.fbx`의 SHA256은 동일하다: `779ED67BABB89920E190573C05E63FAF484111A1A46A16C5861CB4E536F4949B`.
- Blender의 `Rest_Original`은 27,647정점이고 Unity FBX의 동일 메시에는 UV/노멀 경계 분리로 27,958정점이 있다. 두 파일의 정점 번호를 그대로 일대일로 대응시키지 않는다.
- 본체·표정 작업 리그 이름은 `EDEL_V16_RIG`, 본 수52개다. 이름의 V16은 오래된 접미사이며 현재 사용하는 리그다.
- 기존 액션92개는 저장된 액션 수다. 92개의 모션이 모두 현재 게임에 연결되었거나 최종 승인됐다는 뜻이 아니다. `Vxx_*`, `.001`, `RM_*` 등에는 과거 시험·루트모션 변형이 포함된다.
- Unity가 실제로 가져온 에델 전용 FBX 클립은 `R_Idle`, `R_AimIdle`이며, 현재 컨트롤러/공통 클립 연결은 포함된 overrideController와 의존 자산을 확인한다. Blender의 모든 액션이 자동으로 Unity에서 재생되는 구조가 아니다.
- 현재 감정 반응 Joy/Surprise/Shy/Curious/Determined 및 NeckStretch/BackStretch/WeaponInspection은 주로 `SdIdlePresentation.cs`의 절차적 보정이다. 원본의 `CBG_*` 액션을 전부 직접 재생하고 있는 것이 아니다.
- 최근 검지 끝 보정은 `EdelIndexSkinBinding.cs`, 손·팔 파지는 `SdWeaponPose.cs`에서 실행 중 적용한다. 이 결과를 원본 FBX에 모두 베이크한 상태가 아니다.
- 현재 머리 상태 C15b는 위쪽 매듭의 원래 연결 위치를 유지하도록 바꾼 중간 상태다. `SdHairCollisionMotion.cs`와 `EdelProximalHairBinding.cs`를 함께 봐야 한다. **팔·몸·총과의 교차는 아직 미완료다.**
- 에델 팔의 얼룩 같은 명암은 `EdelSkinShadingMask.cs`, `ToonCharacterStyle.cs`, `HybridToon.shader`의 피부 영역 처리를 적용한 상태다. 그늘 표현을 피부 텍스처의 문신으로 오해해 임의로 덧칠하지 않는다.

## 이 프로젝트에서 유지할 사용자 요구

1. **HIGH READY는 폐기했다.** 기존 액션과 코드에 흔적이 남아 있어도 재활성화하거나 새 HIGH READY를 제작할 필요가 없다. 현재 게임은 LOW READY 고정이다.
2. LOW READY는 어깨의 자연스러운 부착 위치를 유지하고, 위팔이 내려온 뒤 팔꿈치에서 전방으로 이어지는 형태를 원한다. 팔을 몸 안으로 밀거나 과하게 옆으로 벌려 해결하지 않는다. 짧은 팔을 억지로 늘이거나 어깨를 앞으로 끌어내는 방식도 피한다.
3. 왼손은 총 앞쪽 하단을 받쳐 지지해야 한다. 총 위에 손이 떠 있거나 손바닥을 관통해서는 안 된다. 오른손은 권총 손잡이 사이로 실제 손잡이가 들어가며, 비사격 대기 중 검지는 방아쇠 밖 리시버 옆에 자연스럽게 편다. 두 마디뿐인 검지 끝이 위로 솟는 형태를 만들지 않는다.
4. 총이 가슴/머리를 관통하는 문제와 파지 문제를 함께 본다. 파지 한 곳의 수치만 맞추고 팔 전체가 비정상적으로 꺾인 상태를 통과시키지 않는다.
5. 대기는 제자리에서 수행한다. 발 위치·캐릭터 중심·인벤토리 카메라 크기가 몸짓 때문에 흘러가면 안 된다. 캐릭터 직접 조작이 없을 때 표정과 어울리는 몸짓을 주기적으로 자동 재생하며, 캐릭터 클릭으로도 반응한다. 인벤토리 아이템 정리·이동은 캐릭터 조작으로 취급하지 않는다.
6. 머리카락은 중력 방향으로 자연스럽게 내려와야 한다. 충돌을 피하려고 위쪽 매듭부터 위·옆으로 들어 올리는 이전 C10은 사용자가 반려했다. 원래 위쪽 형상을 유지하면서 아래쪽 충돌을 해결한다. 머리/팔/몸/총 관통은 모두 검토 대상이다.
7. 표정과 고개·상체·손발 몸짓이 어울리게 이어져야 한다. 현재 관통을 피하려고 고개 방향만 바꿔 놓는 방식은 해결 완료로 볼 수 없다.
8. 원래 체형·얼굴·머리색·이너웨어 외형을 유지한다. 현재 방어구 외형은 임시 비활성 상태이므로 새 의상 제작을 이번 작업으로 확대하지 않는다.

이 목록은 지금 익스트랙션 작업에서 확인한 사용자 요구다. `legacy_contracts/`와 Blender 내부의 오래된 README/스크립트는 원본 모델의 역사·참고 자료이며, 다른 프로젝트 또는 과거 단계의 지시를 현재 요구로 자동 승격하지 않는다.

`04_PREVIEWS/Edel_CurrentLowReady_STATIC_REFERENCE.glb`는 마지막 Unity 정지 자세의 실제 표면과 총기를 뽑아 만든 회전 열람용 참고 모델이다. 리그/모션/물리는 없으며 새 애니메이션의 편집 원본으로 쓰지 않는다. 함께 있는 `static_reference_blender_preview.png`는 이 GLB를 다시 열어 확인한 사진이다. Unity 툰 셰이더 대신 일반 재질을 사용하므로 명암과 노멀 표현은 게임 사진과 다르다. 좌우가 게임 정면과 일치하도록 Unity (x,y,z)를 Blender (-x,-z,y)로 변환했고 자세 스냅샷 JSON의 좌표 자체는 그대로 보존했다.

Unity 참고 자산의 재질은 URP 17.1.0의 Lit 셰이더/AssetVersion 자료를 참조한다. 이 두 패키지 GUID는 누락된 에델 파일이 아니라 설치된 URP 패키지 의존성으로 확인했다. Unity 환경 요약은 `05_TECHNICAL/Unity_environment.json`에 있다.

## 현재 남은 문제와 재현 참고

`05_TECHNICAL/HAIR_CURRENT_C15b_PARTIAL_VALIDATION.json`은 완료 보고서가 아니다. 정지/Curious/Joy/WeaponInspection에서 머리 위쪽335정점의 원래 형상과 경계는 유지되지만, 팔·총 주변 실제 표면 교차가 남는다. 표면 교차쌍은 삼각형 쌍의 개수이며 시각적인 독립 구멍 수가 아니다.

손 파지에도 이전 수치 PASS만으로 모든 피부 관통을 증명하지 못한 부분이 있다. 에델의 오른손 손바닥은 별도 내부 재구성 검사에서 그립 내부 관통 가능성이 기록됐으므로, 기존 자세를 그대로 정답으로 삼지 말고 실제 정면/좌우측면/후면에서 본다.

`05_TECHNICAL/current_unity_pose_snapshot/`에는 실제 C15b 정지 자세의 메시·본 행렬·가중치·활성 셰이프키와 총 정보가 있다. 모델을 편집할 기본 파일이나 새 애니메이션 클립은 아니고, 런타임 결과를 비교하는 JSON 참고 스냅샷이다. 좌표는 Unity model-facing world unit metres이며 Blender 좌표로 그대로 복사하지 않는다.

Blender의 원본 총기 `RIFLE | ...`와 Unity의 현재 총기 `LP_AR_A_1`은 서로 다른 자산이다. 게임 총기를 기준으로 손을 재검토할 때는 포함한 현재 M16 자산과 Unity 파지 좌표/참고 화면을 사용한다.

## 후속 결과를 다시 Unity로 받을 때

- 편집한 `.blend`와 수정한 새 액션 목록, 액션별 길이/FPS/루프 여부를 함께 반환한다.
- 기존 변형 본 이름·위계·Avatar 대응을 보존하고, 편집용 IK 컨트롤을 추가했다면 내보낼 변형 본과 구별한다. 이미 수정한 twist 본 부모 관계를 과거 원본으로 되돌리지 않는다.
- 몸 동작은 별도 FBX 애니메이션 클립으로 내보내고, 얼굴 셰이프키/드라이버가 Unity에서 어떻게 재생될지도 함께 적는다. Blender 드라이버가 FBX에 자동으로 모두 포함된다고 가정하지 않는다.
- 대기·LOW READY·조준 진입/복귀·각 표정 몸짓의 전환을 확인한다. 최종 게임 연결은 IK/절차적 보정과 중복되지 않게 다음 Unity 통합 단계에서 처리한다.
- 확인하지 않은 항목은 미검증으로 남긴다. 이번 전달본의 인계 완료와 기존 애니메이션·물리 완료를 구분한다.
