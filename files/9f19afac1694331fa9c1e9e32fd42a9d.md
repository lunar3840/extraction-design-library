# 무기 모델 썸네일 — 배치 회전·슬롯 확대·실제 모델 연동

## 사용자 지시 / 해결하려는 문제

무기의 격자 점유 영역을 세로로 돌려도 썸네일은 같은 가로 방향으로 작게 나오는 문제를 수정한다. 모델을 슬롯에 최대한 크게 맞추고, 향후 실제 총기 모델을 교체할 때 별도 PNG 재제작 없이 UI도 함께 갱신되도록 한다. 첨부 델타포스 이미지는 배치 참고이며 다른 게임의 기능/규칙을 새로 이식하는 지시는 아니다.

## 변경 전 상태

- `InventoryGridGeometry.Icon`이 무기를 항상 가로 2.8:1 영역으로 제한했다.
- 가방/보관함 공통 격자와 전리품 격자에서 아이템의 `Rotated`를 아이콘에 전달하지 않았다.
- 소총은 `Resources/WeaponThumbnails`의 저장된 PNG, 다른 총기 종류는 별도 도형/아틀라스 아이콘을 사용하여 현재 실제 총 모델과 달라질 수 있었다.

## 실제 변경 / 방식

- 무기 아이콘 영역을 슬롯 전체에서 테두리 3px와 하단 이름 한 줄만 제외한 영역으로 바꿨다. 원본 비율은 유지하며 늘이거나 총구/개머리판을 잘라내지 않는다.
- 가방·보관함의 공통 격자, 수색 완료된 전리품 격자, 드래그 배지에 동일한 회전 상태를 전달한다. 세로 배치에서는 총구가 위로 향하도록 -90도 회전하며 그리기용 가로/세로 영역도 맞바꾼다. GUI 변환은 그린 직후 복원한다.
- `WeaponModelThumbnails`가 캐릭터의 `SdWeaponPose`와 동일한 `SdGunLibrary.Resolve(RifleDefinition)` 결과를 사용한다. 현재 실제 prefab/임시 클래스 모델의 메시·원래 재질을 렌더한다.
- 별도 스튜디오 씬과 전용 카메라/레이어 29를 사용한다. 기존 컷신 30·인벤토리 인물 31과 분리했다. 메시/트랜스폼만 복사하고 게임플레이 컴포넌트·충돌체·Animator·총구 섬광은 복사하지 않는다. 실제 플레이어·적·총기 prefab을 수정하지 않는다.
- 모델의 투영 경계를 측정하여 여백을 약 3.5%만 두고 투명 RenderTexture로 렌더한다. 기존 PNG와 도형은 첫 프레임 또는 모델이 없는 종류의 대체 표시로만 남겼다. 실제 모델이 없는 근접 무기의 새 아트를 만들지는 않았다.
- 모델 참조 교체는 다음 렌더에서 감지하고, 같은 prefab 내부의 트랜스폼/메시/재질 참조 변화도 추적한다. 이미 보이는 모델은 약 0.5초 주기로 갱신한다. Editor에서 prefab/메시/재질/텍스처를 재임포트할 때도 캐시를 무효화한다.
- 캐시는 최대 48개이며 한 프레임 렌더 작업은 2개로 제한한다. 회전만 바꿀 때는 동일한 모델 텍스처를 재사용한다.
- 장착 상태·아이템 수량·무게·점유 칸·드롭/맞교환 규칙·개체별 부착물 시스템은 수정하지 않았다. 일부 종류가 단순한 모양인 것은 현재 게임이 선택하는 실제 임시 모델을 그대로 보여주기 때문이다.

## 전후 증빙

- `before_inventory_grid.png` ↔ `after_inventory_grid.png`: 1600×900, 동일 슬롯 좌표·정의·조명/프로젝트 설정·폰트·UI 배율의 독립 렌더 검증 화면이다.
- 이 화면은 실제 제품의 `GlassIcons`, `InventoryGridGeometry`, `ItemTierPresentation`, 아이템 카탈로그 및 무기 모델을 호출한 **검증 도구 화면**이다. 전체 플레이어 인벤토리/파밍 세션을 실행한 스크린샷으로 가장하지 않는다. 인벤토리/전리품 열의 격자는 같은 실제 표시 함수를 사용한다.
- before는 제품 3개 소스를 수정하기 전에 원본 소스와 같은 코드로 촬영했다. 마지막 배치에서 겹치지 않는 동일한 산탄총 두 방향으로 비교 시점을 맞춰 다시 촬영했다. 원본 제품은 이때까지 변경하지 않았다.
- 초기 백그라운드 실행에서는 Unity 화면 캡처가 실패하거나 검게 저장되어 최종 증빙으로 사용하지 않았다. 실제 창 렌더가 필요한 검증 실행을 짧게 수행한 후 자동 종료하여 올바른 전후 이미지를 확보했다.
- `after_model_*.png`: 11개 실제 모델의 투명 렌더 결과.
- `after_live_replacement.png`: 원본과 별개인 검증 프로젝트 메모리에서만 교체한 청록색 시험 모델. 실제 게임 총기의 교체 결과로 오해하지 않는다.

## 검증 결과

- `after_checks.txt`: **63 PASS, 0 FAIL, RESULT PASS**. 최종 전체 보고서를 직접 읽고 전후 화면도 확인했다.
- 11개 총기에 대해 실모델 RenderTexture 사용, 가시 픽셀 존재, 긴밀한 경계 맞춤, 배경 투명을 확인했다. 투명 텍스처의 모델 경계는 각 축 약 92.8~97.6%를 차지했다.
- UI가 열린 상태에서 `SdGunLibrary.modelReplacements` 참조를 바꾸자 명시적인 재베이크/재열기 없이 렌더 픽셀이 바뀌었다. 동일 모델 내부의 크기 변경도 감지했다.
- 모델 복사본에 충돌체/Animator가 없고, 수평 총구 방향·세로 회전·기존 비무기 아이콘 경로·슬롯 치수/영역을 확인했다.
- 최종 독립 Windows 빌드 성공 및 실행 종료 코드 0. 최종 실행 로그에 예외/C# 오류 없음. `after_final_build.log`, `after_final_player.log` 참조. 초기 후보의 타입명 오류는 staging에서 수정하고 재빌드한 뒤 검증했다.
- 통합 직전 원본 3개 파일의 SHA-256이 `source_before`와 동일함을 확인했다. 검증한 변경만 반영했으며, 통합 후 7개 소스/.meta가 `staging`과 일치한다.
- 원본 Unity의 자동 컴파일 완료는 확인되지 않았다. 22:24 KST 확인 시 DLL 시각이 소스 반영 전이었다. 독립 프로젝트의 최종 빌드/실행 검증과 구분하며, 원본 Unity에 포커스가 돌아가 변경 파일을 임포트·컴파일한 다음 재생해야 한다.
- 전체 게임의 인벤토리 거래/드래그 회귀 테스트는 새로 실행하지 않았다. 이번 검증 범위는 모델 표시·회전·갱신·실제 소비 지점의 코드 연결이다.
