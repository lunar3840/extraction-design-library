# A맵 v0.8 독립 검증

## 판정

**참조용 그래프·2D 기하·실행 가능한 spawn policy 기준으로 `pass_with_warnings`입니다.**

- 22 pass / 2 warn / 0 fail / 1 info
- 검증 입력: `layout.json` v0.8
- 입력 SHA-256: `79208b53883563b8f284624abe45a5a930a8af89d01394ab8eb0ab65d1fbd02a`
- Unity는 실행·수정하지 않았습니다. 본 결과는 Unity 구현, NavMesh, AI, 저장 서버를 통과했다는 증명이 아닙니다.

## 중계망과 후보 선택 규칙

- 기존 공구점 노드는 `TOOL`, 중계 노드는 `RT1/RT2/RT3`, 표시 ID는 `T1/T2/T3`로 분리돼 있습니다. 중복 노드나 남은 공구점 `T1` 참조는 검출되지 않았습니다.
- B 집합은 정확히 B1–B4, R 집합은 R1–R8입니다. spawn 객체에 `tier`, 무장/장비 가치 문턱 필드가 없고 `equipmentValueUsed=false`입니다.
- 해금 대응은 T1→R1,R2 / T2→R3,R4,R5 / T3→R6,R7,R8로 정확합니다.
- 3-bit relay mask 8개×위험 진입 OFF/ON 2개, 총 16개 조합을 전수검사했습니다. OFF는 해금 상태와 무관하게 B1–B4만, ON은 B1–B4+해금된 relay의 R만 반환했습니다. 미해금 R 유출과 B 소실은 0건입니다.
- `spawn-policy.cjs`의 참조 함수를 실제 호출하고 검증기에서 독립적으로 생성한 기대 집합과 비교했습니다.
- 완료 전 중단 시 미해금, 완료 후 사망 시 유지, 재완료 멱등, 이미 만든 출격 snapshot 불변, 모든 후보 차단 시 `hold-or-cancel`, snapshot 밖 R 자동 승격 금지가 모두 통과했습니다.
- 이는 Unity 스폰 시스템이 아닌 실행 가능한 **설계 참조모델**의 통과입니다.

## 해금 전 relay 접근과 위치

- B1–B4 각각에서 T1–T3까지, 총 12개 경로가 relay·G·S-A 해금 없이 모두 연결됩니다.
- 가장 긴 사전 접근은 B1→T3 466.43m이며, 4m/s 이동+12초 조작으로 128.61초입니다.
- 각 relay는 2개의 3m 접근 edge를 갖고, 연결된 `approaches` 목록과 일치합니다.
- 접근 edge의 중심선과 1.5m 반폭은 relay console 고체 사각을 관통하지 않았습니다. relay 노드는 2×2m interaction 영역 안에 있습니다.
- relay site는 모두 맵 안에 있고 water, 건물, G1–G4 core, M encounter 반경, H1/H2 boss-candidate 순찰 polygon과 중첩하지 않았습니다. `bossKillRequired=false`, `requires=[]`도 일치합니다.
- T3의 가장 가까운 기계 encounter는 M1이며 표시 반경 밖 clearance는 41.47m입니다. 이 수치는 시야·감지 안전을 보장하지 않습니다.
- INFO_T1/T2/T3 polygon은 각각 담당 relay와 R 진입 좌표를 모두 포함합니다. BASE polygon도 B1–B4를 모두 포함합니다.
- relay는 G1–G4, S-A, Q, X1–X7을 잠그거나 공개 물리 edge를 개방하는 조건으로 사용되지 않았습니다.

## 이동 그래프

- S-A를 닫은 기본 그래프는 1개 연결 성분입니다.
- 16개 상태에서 활성되는 spawn을 모두 펼쳐 1,248개의 spawn→공개 목적지 6곳/탈출 attach 7곳 조합을 검사했고 누락 경로는 0건입니다. 중복을 제거한 기본 행렬은 12×13=156개입니다.
- 중정비동 `HN/HW/HE/HS/H0/HU`와 `K0`를 동시 제거해도 relay를 포함한 외곽 그래프가 연결됩니다. 중앙 허브 강제가 없습니다.
- 서교와 동교를 하나씩 제거한 두 사례 모두에서 고립 노드가 생기지 않았습니다.

## 기하·폭 검사

### 중심선

- bridge가 아닌 공개 edge의 water polygon 관통: 0건
- outdoor edge의 건물 polygon 관통: 0건
- 공개 edge의 같은 층 G core 관통: 0건
- B/R/X→attach 직선의 water·건물·G core 관통: 0건
- 두 bridge는 water 내부를 지나고 양끝은 water polygon 밖입니다.
- 건물 문은 모두 계획 외벽 오차 2m 이내입니다.

### 계획 폭/clearance

- non-bridge edge 반폭과 water clearance 충돌: 0건
- 공개 edge 반폭과 같은 층 G core clearance 충돌: 0건
- 폭 3m로 명시된 B/R/X attach 반폭과 water·건물·G core clearance 충돌: 0건
- 회전된 V/C/RC polygon과 공개 edge 반폭 buffer 중첩: 0건
- V/C/RC polygon의 맵 밖·water·건물 중첩: 0건
- relay approach 반폭과 console 중첩: 0건

위 폭은 `layout.json`의 계획값입니다. 실제 collider를 빼 뒤의 NavMesh 유효폭, 인간과 AI의 교행, 회전반경, 기울기를 보장하지 않습니다. relay site의 `siteSlopeMaxPercent=2`도 실측 결과가 아니라 조성 목표입니다.

## 인간 순찰과 시간

- H1–H3는 모두 `behavior=bounded-farming-exploration`, `permanentGarrison=false`, `extracts=false`이며 맵 안의 폐곡선입니다. 자원 탐색 순환이지 탈출·상주 동선이 아닙니다.
- 실제 AI가 폐곡선 범위를 떠나 탈출구로 이동하지 않는지는 런타임 검증이 필요합니다.
- B→relay 12초 조작→가장 가까운 X 중 최악 참조 사례는 B3→T2→X4, 이동 707.62m입니다. 4m/s에서 188.90초, 3m/s에서 247.87초로 30분의 13.8%입니다.
- 30분 레이드와 4m/s·3m/s 속도는 사용자 확정 밸런스가 아니라 경로 길이 민감도를 비교하기 위한 검증 가정입니다.
- 시간 검사는 최단경로 이동+prototype 조작만 포함합니다. 감지·전투·은폐·수색·재탐색 시간을 반영하지 않았습니다.

## 잔여 위험

1. **시야·AI 감지**: C01–C12와 RC1–RC3의 좌표·치수는 있지만 실제 적 차폐를 입증하지 않습니다. 좌표상 R6은 M3 표시 반경 밖 42.73m, R5/R4는 H2 순찰 선형까지 27.00m/27.62m입니다. 우선 플레이테스트 후보입니다.
2. **실제 통행폭·경사**: 2D 중심선과 계획 반폭은 통과했지만 collider·NavMesh·교행·회전·실측 경사는 미검증입니다.
3. **영구 상태**: 완료·중단·사망·멱등·snapshot 참조모델은 통과했지만 실제 저장·재접속·동시성을 확인하지 않았습니다.
4. **인간 순찰 런타임**: 구조화된 비철수 의도는 있으나 AI가 실제로 이를 지키는지는 입증되지 않았습니다.
