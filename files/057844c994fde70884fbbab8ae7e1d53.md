## 설계 점검

- 기준은 원본 Head 좌표계의 clean Combined Current `4E589B1F...`, 후보는 model 좌표계 `A8DE938E...`이며 양쪽 Refit/Distance 병렬 옵션을 켠다. Hair의 독립 Head budget과 소유 판정은 변하지 않는다. mirror는 동일 소스/선택/무기/모션 인자와 입력 taper의 복제본을 사용하고, Head 우선·후보 우선 순서를 바꾼다.
- 후보와 기준의 로컬 budget은 그대로 비교하지 않는다. 각 좌표계 `localToWorldMatrix`의 `MinimumScale`로 세계 길이 하계를 만든다. `Apply`의 mobility도 같은 metric으로 세계 단위 cap을 계산한다. 허용 오차 0.0002 m는 기존 margin 0.00025 m보다 작게 시험 전에 고정됐다. fresh 18프레임은 Head 원본을 매 프레임 재Bind/Prepare하고 후보 world budget과 taper 기반 최대 이동이 원본보다 이 허용 오차 이상 커지면 실패한다. 후보가 더 보수적인 결과는 안전성 검사상 허용되지만 시각적 움직임 감소로 별도 평가가 필요하다.
- `AfterApply`는 양쪽 성공·available, invalid query 0, Body/Weapon 삼각형 일치, eligible source vertex ID/배열 길이, budget의 infinity/NaN 일부, world budget·taper 차이를 확인한다. `BeforeApply`의 taper 복제로 두 `Apply`가 같은 초깃값을 받는다. 성공/실패 마커는 CSV와 상태로 다시 대조해야 한다.
- 정적 한계: oracle은 양수 infinity와 NaN budget을 처리하지만 음수 infinity를 명시적으로 거부하지 않는다. 정상 Current 경로에서는 budget이 `+∞` 또는 비음수 거리에서 출발하지만, 비정상 입력에 대한 완전한 유한값 검사로 오해하지 않는다. metric의 NaN도 `<=0` 조건만으로는 검출되지 않으나 model 안전 프레임 guard가 비유한 모델 행렬을 별도로 차단한다. 실제 CSV의 빈값/NaN을 독립 집계한다.
- `ModelBlock()`의 완료 조건인 `totalJobs`/`totalDistance`는 후보와 기준의 **합계**다. 한쪽만 worker를 써도 완료 마커가 가능하므로 각 블록에서 후보/기준 각각의 Refit jobs와 Distance parts를 별도로 합산해야 한다. native CPU/GPU 유효성은 CSV에 기록하지만 자동 완료 조건은 아니므로 무효 행을 확인한다. 자체 Refresh/Apply 타이머의 같은 프레임 차이만 좌표계 비용을 추정하는 데 쓰고, mirror를 포함한 Hair Step/native CPU로 제품 FPS 개선을 주장하지 않는다.
