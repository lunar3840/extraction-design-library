# Independent read-only line-transform review

검토일: 2026-10-22 (Asia/Seoul)

## 범위

- 수정된 `InventoryHudVisuals.Line()`의 좌표 합성과 행렬 복구를 읽기 검토했다.
- Unity 조작, 원본 수정, 앱·씬·Play 상태 변경은 하지 않았다.
- 독립 수학 검사 스크립트만 이 폴더에 만들었다. 실제 렌더·라이브 입력 검증과 구별한다.

## 판정

**수정 방향 적합, 발견한 차단 이슈 없음. 93개 검사 통과.**

- 부모 행렬 × 로컬 TRS 순서이므로 로컬 선의 (0,0)은 부모 좌표의 A, (길이,0)은 부모 좌표의 B가 된다.
- `finally`가 이전 GUI.matrix를 복구하므로 그리기 예외가 다른 HUD로 좌표 변형을 누출하지 않는다.
- 변경 전 백업과 현재 InventoryHudView 전체 소스에서 Line 메서드만 제외한 문자열이 동일했다. 소모품·머리 위 바·원호 비율 및 다른 HUD 처리는 바꾸지 않았다. 전투·스킬 상태를 조작하는 코드가 새로 생기지 않았다.

## 수학 검사

- 배율: 0.5 / 1 / 1.2 / 1.5.
- 선: 수평·수직·대각·화면 우측하단 좌표·0길이.
- 원호: ratio 0 / .01 / .25 / .5 / .999 / 1. 각 조각의 시작/끝과 두께2의 모든 모서리를 확인했다.
- 모든 시작/끝 좌표가 배율 적용 기대값과 오차 1e-8 미만으로 일치했다.
- 76×76 논리 rect의 반경38 범위에서 실제 stroke의 최대 x/y 오프셋은 36.9990483 논리 이하다. 1.2배에서 최대44.3988579px < 반폭45.6px로 게이지 자기 영역을 벗어나지 않는다.

실행 결과는 `result.txt`, 재현 스크립트는 `Verify-LineTransform.ps1`이다. 첫 실행의 PowerShell 배열 연산 문법을 고친 뒤 최종 실행 exit0/93 PASS를 얻었다. 이 스크립트 수정은 게임 원본 변경이 아니다.

## 원인 근거

Unity6000.1의 RotateAroundPivot은 기존 GUI 행렬을 저장하고 identity 상태에서 pivot을 풀어 회전 행렬을 만든 뒤 `newMat * mat`으로 합친다. 배율 적용 전 논리 pivot을 넘기는 기존 코드에서는 선분별 회전 중심과 스케일된 선 위치가 맞지 않아 큰 원형 궤적이 발생한다.
