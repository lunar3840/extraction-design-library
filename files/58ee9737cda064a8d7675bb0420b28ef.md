# 가림 처리 통합 · 자연스러운 경계의 Cutout (건물·나무·소품)

## 사용자 지시 요약

- 원문은 [SOURCE_REQUEST.md](SOURCE_REQUEST.md). 2026-11-24 05:26 KST 구현 지시: "그럼 그냥 다 cutout을 쓰되 그 경계를 자연스럽게 깎아줘볼래? 건물 외에도 필요하다 싶은 부분 다 적용해줘"
- 앞선 대화에서 쇼츠 영상(Fade/Dither/Cutout/Silhouette 비교)을 분석했고, 현재 게임은 건물만 V33 국소 반투명(플레이어 모양 + 처마 영역, 테두리 반투명)이며 나무에는 처리가 없다고 답했다. 그에 대한 결정이 위 지시다.
- 05:56 "모든 작업 파일은 전후로 스크린샷 찍어서 기획 라이브러리에 업로드" — AGENTS.md의 기존 규칙 재확인. 별도 수정 회차가 아니다.

## 기획 의도와 해결하려는 문제

- 쿼터뷰에서 큰 오브젝트 뒤에 들어가면 SD 캐릭터가 완전히 사라진다(특히 나무 수관 아래, 바위·차량 뒤). 건물만 처리돼 있어 표현이 일관되지 않았다.
- 표현 방식을 **Cutout 하나로 통일**하되, 경계가 컴퓨터로 오린 원처럼 보이지 않도록 **표면에 고정된 노이즈로 깎인 듯한 가장자리 + 살짝 어두운 단면 테두리**를 준다.
- 슈터이므로 **조준 중에는 플레이어→조준점 방향도 좁게 연다.** 적에게 실루엣을 주는 방식은 쓰지 않는다(엄폐 정보 보호).
- 바닥·발목 아래 낮은 엄폐물·플레이어 뒤쪽 물체는 깎지 않는다. 그림자, 충돌, 총알 판정은 바꾸지 않는다.

## 변경 전 상태와 문제점 (코드·실제 화면 확인)

- 건물: `StageABuildingV33Reveal` + `BuildingV33LocalReveal.shader`(2026-10-30 after07, SHA 4AA5BA99…). 가림 벽·지붕의 플레이어 주변을 **반투명 veil**(중심 불투명도 1%, 테두리 부드러운 반투명)로 보여 줌. 실제 화면에서 지붕 위에 흐린 사각·사다리꼴 창이 생긴다(`before_04/before_building_behind_1·2.png`).
- 나무·덤불(D14 MutedFoliage / D11 VertexFoliage / D15 FoliageLit, 그리고 URP Lit을 쓰는 PT 과일나무·소나무): **처리 없음.** 수관 아래에서 플레이어가 완전히 가려진다(`before_tree_1`, `before_tree_2`, `before_prop_1`).
- 바위·차량·장비 등 URP Lit / Weathered Lit 소품: 처리 없음.
- 예전 청록 실루엣 2종(`StageAHallV24…`, `StageAWestD02…`)은 V33 도입 때 꺼져 있었고 이번에도 건드리지 않았다.

## 실제로 바꾼 부분과 방법

새 파일
- `Assets/Escape/Art/OccluderCut/EscapeOccluderCut.hlsl` — 공통 절개 함수. 화면 픽셀에서 월드 위치를 복원(깊이 전용 패스도 같은 픽셀을 깎기 위해)하고, 카메라 기준으로 **플레이어 가슴 둘레 반경 1.7m 원 + (조준 시) 조준점까지 반경 0.85m 캡슐** 안이면서 **플레이어보다 0.6m 이상 카메라 쪽**이고 **발 높이+0.2~0.55m 위**인 표면만 깎는다. 경계는 월드 고정 fBm 노이즈(±0.31)로 흔들고, 절단선 바로 안쪽을 최대 34% 어둡게 한다.
- `Assets/Escape/Art/OccluderCut/EscapeOccluderCutPasses.hlsl` — URP Lit 계열 패스(Forward/GBuffer/DepthOnly/DepthNormals) 프래그먼트 래퍼. 원래 URP 프래그먼트를 그대로 호출하고 앞에서 절개만 한다. ShadowCaster는 감싸지 않아 그림자는 그대로다.
- `Assets/Escape/Resources/EscapeVision/EscapeOccluderCutLit.shader` (`Escape/Occluder/CutLit`) — 프로젝트 URP 패키지(17.1, `com.unity.render-pipelines.universal@24527717fb47`)의 Lit.shader를 그대로 복사해 위 래퍼만 연결한 것. URP Lit 소품의 런타임 복제 재질이 쓴다.
- `Assets/Escape/Runtime/Visuals/OccluderCutout.cs` — 플레이 시작 시 자동 생성(씬·프리팹 수정 없음). 게임 카메라에만 전역값을 넣고(씬 뷰·프로브·UI 카메라는 0), 0.18초로 페이드. 조준 중(`PlayerMotor.IsAiming`)이면 마우스 광선과 가슴 높이 평면 교점(최대 7m)을 조준점으로 쓴다. 플레이어 9m 안의 키 1.2m 이상 URP Lit / Weathered Lit 소품에 **런타임 복제 재질**을 씌우고 멀어지면 원래 재질로 되돌린다. 건물(V33 건축 판정·V33 건물 컴포넌트·벽/지붕/파사드 이름)과 바닥·도로·물·경계는 제외하고, V33가 쥐고 있는 렌더러는 건드리지 않는다.
- `Assets/Escape/Editor/StageAOccluderCutoutPlay.cs` — 증빙 전용 촬영 도구(게임 동작 변경 없음). `Library/StageAOccluderCutout.request`에 `before`/`after`를 쓰면 Play에서 기록된 지점으로 플레이어를 옮기고 기본 TopDownCamera 구도(look-ahead 0)로 1600×1000을 저장한다.

수정한 파일 (원본은 `originals/`, 해시는 `originals/SHA256_BEFORE.txt` / `SHA256_AFTER.txt`)
- `BuildingV33LocalReveal.shader`: 반투명 veil 폐지. 불투명 셸이 V33의 기존 가중치(플레이어 모양·처마 영역)와 공통 원형 중 큰 값으로 **깎인 구멍**을 만들고 테두리를 어둡게 한다. V33의 표면 선택·층 규칙·C#은 그대로(`StageABuildingV33Reveal.cs` A5F9ADFC… 미변경). veil용 오버레이 렌더러는 여전히 생성되지만 아무것도 그리지 않는다.
- `D14MutedFoliage.shader`, `FoliageLit.shader`(깊이 패스 UsePass를 CutLit으로), `D11_VertexFoliage.shader`: 항상 절개(깊이·높이 조건으로 풀·바닥은 유지).
- `WeatheredLit.shader` + `WeatheredLitInput.hlsl`: 재질별 옵트인 `_EscapeOccluderCut`(기본 0) 추가. 런타임 복제본만 1이라 이 셰이더를 쓰는 건물·바닥 원본 재질은 변하지 않는다.
- 수정한 셰이더 패스에 `#pragma editor_sync_compilation` 추가(에디터 비동기 컴파일 자리표시자 방지; 빌드에는 영향 없음).

## 한계 / 아직 확인하지 않은 것

- **빌드 미검증**: CutLit 복제 재질은 런타임에 만들어지므로, 플레이어 빌드에서 URP Lit의 `shader_feature` 키워드 변형이 빠질 수 있다. 빌드 전 변형 수집(ShaderVariantCollection 등) 확인이 필요하다.
- 실제 마우스 조준(캡슐) 체감, 이동 중 연속 화면, 적이 있는 교전, 성능(FPS)은 측정하지 않았다. 조준 캡슐은 시험용 고정 조준점으로만 확인했다.
- 반경 1.7m·깊이 여유 0.6m·노이즈 세기·테두리 34%는 첫 시험값이다.
- 씬 뷰에 효과가 없는 것은 코드상(게임 카메라 외 0) 보장이며 화면으로 따로 찍지 않았다.
