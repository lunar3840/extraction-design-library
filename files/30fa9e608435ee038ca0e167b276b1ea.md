# 차량 파손부의 안쪽 면과 단면 두께 보강

## 사용자 원문

> 차량 파손 효과는 모델링을 깨트리기만하고 빈 공간 메꾸질 않으니 좀 아쉬워보이는데(건물은 괜찮음) 저 부순 부분 모델링을 메꾸는 식으로 해줄 수 있나?

## 의도와 범위

이전 D09 당일05회차의 범용 Surface Ruin Tool을 이어 수정한다. 차량 파손으로 삭제한 원래 외판 영역에만 후퇴한 내부 금속면을 만들고 절단 가장자리를 연결해, 외판이 종이처럼 잘려 내부가 통째로 비어 보이는 문제를 줄인다. 원래 모델에 없는 창·좌석 공간을 큰 평판 fan으로 덮지 않는다. 기존 건물 분기와 최종 건물 결과, 전체 A맵·AI·조명·가림·원본 모델·재질을 보존한다. 이번에도 격리된 차량 시안과 도구 Vehicle 처리의 개선이며 전체 맵 배치 작업은 아니다.

## 병렬 작업과 실행권

메인이 설계·Unity 통합·전후 촬영·정리를 맡고 GPT-6 Sol high 서브가 `staging/geometry/`의 차량 보강 코어, 다른 GPT-6 Sol high 서브가 `staging/review/`의 독립 검증을 소유한다. 제작 완료만으로 통과 처리하지 않는다. 관련 AI/그래픽 채팅의 명시 Unity 인계를 받았으며 현재 사용자 Play/dirty 상태를 확인하고 보존한다. MD 담당에 기존 D09의2026-10-29-06 충돌 없음·후속 회차를 확인했다.

## 검증 계획

수정 전 실제 차량을 같은 로컬 카메라·조명·해상도로 촬영하고, 보강 후 파손 구역의 내부면·단면·노멀·그림자와 기존 창/바퀴/좌석 공간을 확인한다. 건물 생성 메시 fingerprint를 수정 전후 대조한다. 원본 보호 해시, 출력 예산·0강도·시드 재현·저장 후 재열기·새 면 영속성을 검사한다. 네이티브 편집 화면 및 차량의 덩굴 있는 상태/없는 상세를 모두 남긴다.

## 실제 변경과 최종 결과

최종 채택은 **candidate_03**이다. 실제 기존 차량 외판과 파편 메시의 해시는 이전과 모두 같고, `__RuinGenerated_VehicleBacking_Model` 메시 하나를 추가했다. 기존 차체를 더 잘라 파손 위치를 바꾸지 않았다. `RuinGeometryEngine.cs`의 Vehicle 처리만 확장하고 `VehicleLiningBuilder.cs`를 새로 분리했다. UI·저장기·설정 클래스·Runtime marker·기존 셰이더는 수정하지 않았다. 기존 도구에서 차량으로 생성하면 보강이 함께 만들어진다.

삭제된 원래 삼각형을 역방향으로 클리핑해 후보로 삼되, 차체 외곽 위치·바깥을 향한 면·손상 모서리 근접 조건으로 좌석·대시보드의 재출력을 제한했다. 원래 삼각형이 없는 창문 공간에 큰 fan 면을 만들지 않는다. 공통 안쪽 방향으로 이동시키고 경계에서 얕고 안쪽에서 깊어지는 연속 후퇴와 약한 찌그러짐을 준다. 같은1mm 위치의 중복 face/edge를 제거하고, 연결 띠의 법선과 면 방향을 일관되게 정렬한다. 모든 새 면에 world cross²>1e-14의 물리 면적 검사를 적용한다.

최종 실제 수치는 원본95,314 / 결과94,709 triangle, 새 내부면3,390 + 연결 띠652 = 보강 메시4,042 triangle이다. 실제 후퇴는 약 **4.2~14.75cm**, 기존 파편14개다. 설계상 깊이 상한·공간 필터 숫자는 첫 시안 튜닝값이며 사용자 확정 영구 요구가 아니다. 새 안쪽 면은 어두운 철 재질을 사용하고 기존 노후화 도구에서 metal로 처리된다. 원래 차체 도장·실내 좌석 재질·유리 개구부를 일괄 치환하지 않았다.

첫 시안의 돌출 쐐기와 반복 줄무늬는 최종 상세·저각 이미지에서 사라졌고, 앞창·옆창이 열려 있으며 좌석·핸들이 식별된다. 채운 면이 파손부의 안쪽 철판으로 읽힌다는 메인·독립 검토를 받았다. 넓은 철판의 미술 취향상 추가 조정 여지는 있으나 차단 결함은 없다는 판정이다. 사용자 원문에 없는 ‘파손 중앙은 언제나 비워야 함’을 확정 요구로 추가하지 않는다.
