# 최신 에델 작업 이후 렉 — 성능 분석

## 요청·의도와 범위

사용자 원문은 `USER_REQUEST.md`에 보존했다. 캐릭터 외형·머리카락·파지를 유지하면서 최신 작업 후 렉의 원인 후보와 최적화 순서를 확인하는 **분석**이다. 코드/에셋/설정/씬/저장 데이터를 수정하지 않았다. 신규 Play, 빌드, FPS 전후 비교도 수행하지 않았다. 분석 완료와 최적화 구현 완료는 구분한다.

기존 네 캐릭터 표시·파지의 후속 검토이므로 `topic:outputs/change_records/2026-10-22/four-character-chips-idle`를 유지한다. 새 대표 주제를 만들거나 미완료 10월25일 헤어·파지 회차를 완료로 승격하지 않는다.

## 확인한 현행 상태와 측정의 출처

- 관련 「Edel 변신 캐릭터 적용」 및 「UI 배치 적용 분석」 채팅이 공유 Unity 사용권을 명시 반환한 것을 확인했다. 실제 화면 `current_editor_state.png`는 A맵의 **편집 모드**이며 재생 버튼은 꺼져 있다. 스크린샷을 읽고 저장했을 뿐 Unity 입력·재생·설정 변경은 없었다.
- 캐릭터 담당이 `r26_finalgrip_*_metrics.json`은 실제 2026-10-26 측정이며, 출력 도구의 고정 폴더만 `2026-10-24/edel-natural-arm-pose`였다고 확인했다. 원시 파일을 `evidence/`에 바이트 그대로 보존했다. 새 측정인 것처럼 표시하지 않는다.
- 메인이 현행 소스 해시를 다시 계산했다. `SOURCE_HASHES.json` 및 `evidence/CURRENT_STATE.json`의 마지막 적용값과 대조하여 헤어 `32183682…`, CurrentSourceClearanceFieldBudget `22D8E609…`, 파지 `5F61536E…`, 검지 `0FFA3743…`, InventoryPortrait `AEB7B8F4…`의 일치를 확인했다.
- 원시 계측은 격리된 Editor 실 모델/초상화 검증 중 각 `SdHairCollisionMotion.Step`의 CPU 경과 시간이다. 실행 시작 이후 누적 평균이며 동일 길이의 표준 벤치마크나 프레임 p95가 아니다. 본체/초상화의 평균을 단순 합산하여 실제 게임 프레임 시간이나 FPS라고 주장하지 않는다. 현행 소스와 일치하는 비용 증거이지, 사용자의 전체 렉을 단 하나의 원인으로 확정한 결과는 아니다.

## 실제 비용: 머리카락 CPU 계산이 우선 대상

단위 ms. 프레임 전체가 아니라 **머리카락 Step 한 인스턴스**의 비용이다.

| 캐릭터 | 본체 누적 평균 | 본체 마지막 표본 | 가방 미리보기 누적 평균 | 미리보기 마지막 표본 |
|---|---:|---:|---:|---:|
| 에델 | 35.964 | 33.651 | 20.477 | 14.875 |
| 세린 | 68.849 | 111.784 | 61.273 | 45.573 |
| 리브 | 17.697 | 18.088 | 16.846 | 18.457 |
| 유이 | 12.497 | 11.573 | 12.387 | 10.862 |

60FPS의 전체 프레임 예산은 약16.67ms다. 에델 본체의 머리카락 CPU 단계 하나만 이 예산을 넘는 표본·누적 평균이므로 최적화 필요성은 실제 자료로 확인된다. **에델만의 문제는 아니다.** 최신 공통 헤어/몸/총 충돌 처리의 영향도 함께 다뤄야 한다. 이 표의 역수를 현재 게임 FPS로 쓰지 않는다.

### 확인된 반복 경로

- `SdHairCollisionMotion.cs:471–487`: 매 Update에서 원본 정점 복원, LateUpdate에서 몸/총 충돌 Step. `:612–637`: 스키닝·접촉 탐색·역스키닝 후 메시 정점 재전달.
- 에델 본체 마지막 표본 Step33.651ms 중 CoherentSolve31.586ms, 그 내부 BraidSurface23.633ms다. BraidSurface 안에서는 Populate4.450ms, Adaptive9.406ms 등 접촉 후보·표면 증인 계산이 반복된다. **내부 타이머이므로 합산하지 않는다.**
- 세린 본체 마지막 표본에는 CurrentRootBudgetApply74.194ms 급증이 기록되어 있다. 평소 평균으로 일반화할 수는 없지만 최악 구간을 별도로 조사할 근거다.
- `InventoryPortrait.cs:374–376,506–511`: 가방을 열면 독립적인 미리보기 헤어 Step이 생긴다. 실제 캐릭터의 Step을 대체하지 않으므로, 같은 프레임에 양쪽 비용이 발생할 수 있다. 닫힌 가방에서 미리보기 경로는 early return하므로 항상 실행된다고 표시하지 않는다.

### 직접 원인으로 단정하면 안 되는 부분

- 검지12정점 보정은 캐릭터 모델 연결 시 한 번 실행된다(`SdCharacterVisual.cs:139–141`, `EdelIndexSkinBinding.cs:35–68`). 지속적인 매프레임 비용으로 보기는 어렵다. 교체 순간의 지연/복제 메모리 영향은 별도다.
- 에델 근위 머리카락 바인딩도 Bind 시 한 번 구성한다. 계속되는 렉과 초기 로딩 끊김을 구별한다.
- 배열/행렬을 재사용하는 경로가 많으므로 GC가 주원인이라고 단정하지 않는다. 현행 주요 경로가 BakeMesh를 매프레임 호출하는 것으로 잘못 진단하지 않는다.
- 에델 prefab의 SkinnedMeshRenderer13개, offscreen갱신13개 및 4096² 헤어 텍스처는 렌더/메모리 후보다. GPU 시간·VRAM·드로우콜 원시 측정 없이 병목이라고 확정하거나 텍스처부터 낮추지 않는다.

## 최적화 우선순위 — 제안이며 아직 미적용

사용자 추가 답변(2026-10-26, KST)은 **“일반 이동·전투 중”**이다. 따라서 다음 계측은 가방 미리보기보다 **live 헤어 Step과 일반 이동·전투 중 적 AI·비·그림자 비용을 분리해 프로파일하는 것**을 먼저 한다. 이는 다음 측정의 우선순위 보충이며 기존 분석·측정 수치를 바꾸거나 새 병목을 확정한 결과가 아니다. 추가 진단·신규 Play·수정은 실행하지 않았고, 같은 분석 회차를 유지한다. 질문·답변 원문은 `USER_REQUEST.md` 끝에 보존했다.

1. **동일 조건 계측을 짧게 표준화.** 같은 A맵 위치·해상도·무기에서 본체/가방 각각 대기·이동·조준·사격·재장전·Curious 복귀를 기록한다. Main Thread/Render/GPU/GC와 헤어의 독립 하위 시간을 분리하고 최소3회 반복하여 평균·p95·최악 표본을 비교한다. 신규 Profiler 계측은 다음 구현 단계의 전후 기준이며 이번에는 실행하지 않았다.
2. **품질 불변형 중복 접촉 계산부터 줄인다.** 동일 입력 본/표정/총/머리 다발의 동일 후보 재평가를 계수하여 실제 반복인 부분만 재사용한다. 변경된 본과 영향을 받는 다발/충돌체에만 갱신을 전파하는 방향을 검토한다. 과거 적응형 캐시는 재사용0회로 반려되었으므로 “캐시를 넣으면 해결”이라고 가정하지 않는다. 기존 정밀 판정·허용 오차와 동일 결과라는 검증이 전제다.
3. **메시/본의 불필요한 native 전달을 확인한다.** 현재 전체 정점 복원 업로드와 결과 업로드가 각각 있고, 이미 같은 본 목록도 다시 할당한다. Profiler에서 비용을 분리한 뒤 최종 결과가 바뀐 버퍼만 전달하고 중복 setter를 제거할 수 있는지 검토한다. 인벤토리 복제본의 원본 본 복원 순서는 유지해야 한다. 단순 제거는 제안하지 않는다.
4. **가방 이중 계산과 표시 갱신 주기를 분리한다.** 가방에 완전히 가려진 본체 또는 완전히 동일한 미리보기 상태에 한해 마지막 결과 재사용/갱신 생략을 검토한다. 일부 화면에서 본체가 보이거나 표정/머리/총이 움직이면 해당 상태를 무조건 얼리지 않는다. 단순 회전이나 화면 확대만으로 충돌 입력이 바뀌지 않는 경우를 먼저 구분한다.
5. **큰 비용이 남으면 런타임 해법을 재설계한다.** 이미 몸을 본별 프록시로 처리하고 있으므로 이를 새 기능처럼 다시 제안하지 않는다. 기존 검증용 정밀 증인·탐색과 매프레임 런타임 해법의 역할 분리, 데이터 지향 구조/Jobs·Burst 가능성을 다음 후보로 검토한다. 모두 정확성·스레드 안전성·실제 성능을 검증해야 하며, 작은 캐시 개선만으로 현재 수십ms 비용을 60FPS 수준까지 낮출 수 있다고 약속하지 않는다.

초기 제안 목표는 주인공 헤어 평균2ms 이하/p95 4ms 이하로 두되, 사용자 확정치나 달성 결과가 아니다. 판정은 같은 위치·외형·충돌 기준의 전후 비교와 실제 빌드 측정으로 한다. 검지/엄지·헬멧 아래 머리색·입/몸 보호·Curious 복귀·목/개머리판의 기존 미해결 접촉을 회귀 점검한다. 허용 관통을 늘리거나 머리카락을 숨기는 것은 이번 우선안이 아니다.

## 별도 발견: 에디터 파티클 오류 누적

현재 Editor.log에서 `Particle Velocity curves must all be in the same mode`를207,314회 확인했고 화면 하단에도 같은 마지막 오류가 보였다. 짧은 간격의 재확인에서도207,314회로 같았으며, 현재 편집 모드에서 계속 증가한다고 주장하지 않는다. 오류 원점의 콜스택이 없어 에델/비/연막 중 무엇이 만들었는지 확정하지 않았다. 변신 VFX는 자체 메시 빌보드를 쓰며 해당 velocity 모듈을 사용한다고 확인되지 않았다.

이 오류는 `2026-10-22/chip-raid-test-access/CHANGE_RECORD.md:52`와 같은날 item-doubleclick-loot-auto-reload, 10월23일 inventory-vitals-unity/chest-rig-backpack에도 기존 오류로 기록되어 있다. 최신 검지·헤어 작업 뒤 처음 생겼다는 근거는 없다. RainCourtyardAtmosphere와 StageARainV37의 velocityOverLifetime 코드는 점검 후보이지 발신 인스턴스 증명이 아니다.

대량 로그는 **에디터 체감 지연의 2차 후보**다. 다음 실행 때 시간당 증가와 최초 발신 스택을 확인하고 원인을 수정할 대상이지, 로그 파일/콘솔을 지워 원인이 해결됐다고 처리할 사안이 아니다. 이번에는 콘솔·로그를 지우지 않았다. 원시 전체 Editor.log는 인증/환경 정보 노출을 피하려고 게시하지 않고 해당 메시지·횟수만 기록했다.

## 라이브러리 반영

원문·원시 계측·현행 해시와 독립 코드 검토를 정리한 뒤 좁은 분석 회차만 현행 게시 담당에게 인계한다. `LIBRARY_EVIDENCE.json`의 허용목록만 대상으로 하고, 공개 원문/이미지/회차 및 PUBLISH_LEDGER 재조회 전에는 published로 표시하지 않는다. 같은 날 회차 순서는 게시 담당과 충돌 여부를 최종 확인한다. 종합 헤어 수정 미완료 기록의 ready 상태는 변경하지 않는다.

### 초기 게시 인계 결과 — pending (인증 복구 전 이력)

- 현재 게시 세션에 유효한 업로드 인증을 확보하지 못했다. 사이트 소유자/공개/활성 상태의 읽기 확인은 게시용 업로드 인증 확보와 구분한다. 인증 거절 응답을 받은 것처럼 기록하지 않는다.
- 수집 빌드·자료 업로드·사이트 배포를 시작하지 않았다. 담당 채팅의 후속 요청에 따라 이번 분석만을 위한 추가 인증 갱신·복구는 수행하지 않고 소유권을 반환한다. `library_ready: true`는 분석 자료 준비 상태이며 공개 완료가 아니다.
- `LIBRARY_EVIDENCE.json`의 문서12개·확인 이미지1장·전후 쌍0개를 유지했다. 이미지 descriptor만 현행 수집기 형식의 `file`/`role: verification`/설명으로 정규화했으며 원래 목록은 `PUBLICATION_SUBMITTED_EVIDENCE.json`에 보존했다. PNG·원시 계측·기존 검토 문서의 바이트는 변경하지 않았다.
- 추가 사용자 답변을 원문에 이어 붙이고 위 측정 우선순위만 보충했다. 기존 주제 ID·2026-10-26-02 순서·검토·검증 분류를 유지했고 새 구현 회차는 만들지 않았다. 보충 전 두 문서는 `publication-source-snapshots/`에 보존했다.
- 공개 게시 화면은 바뀌지 않았으므로 게시 전후 화면을 새로 만들지 않았다. `current_editor_state.png`는 기존 분석 당시 편집 모드 확인 자료이며 게시 결과나 최적화 전후 화면으로 재사용하지 않는다. 공개 회차·원문·이미지 열람은 이번 건에서 미검증이다.
- 게시 확인 결과와 다음 조치는 `PUBLICATION_VERIFICATION.json`에 `pending`으로 남긴다. 유효한 게시 인증을 확보한 담당이 동일 분석 회차의 선택 자료만 게시하고 공개 원문·확인 이미지·회차 및 `PUBLISH_LEDGER.json`을 재검증해야 한다. 그 전까지 실제 게시 완료로 보고하지 않는다.
