# A 구역 임시 잔해·엄폐물 배치 v04

## 사용자 지시와 역할

기존 A 블록아웃에 잔해와 엄폐물을 우선 임시 배치합니다. 사용자 요청대로 Astra 메인은 배치 기준·통합·검증을, Sol high 서브는 배치 도구 제작과 독립 시각 검토를 맡아 병렬로 작업했습니다.

## 변경 전 상태와 기획 의도

520×400 정비지구에는 중앙 중정비동과 외곽 건물·수로·교량이 있으나 야외 이동 구간 대부분이 비어 있었습니다. 인간이 상주하는 방어진지를 만드는 것이 아니라, 방치된 도시 정비시설의 작업차량·폐기계·콘크리트 잔해·폐자재를 이용한 임시 엄폐를 추가했습니다.

낮은 엄폐 약 0.9~1.2m, 높은 엄폐 약 2.0~2.6m, 낮은 잔해 약 0.35~0.7m를 섞었습니다. 도로 중심부의 6m 통로, 기존 건물 바깥 5m 여유 영역, 수로·교량 접근부를 배치 제외 구역으로 두었습니다. 진입/탈출 지점은 군집 전체 범위 외에 8m 여유를 목표로 보호했으며 검증에서도 실제 충돌 표면까지 최소 6m 이상의 여유를 확인했습니다. 실내·상부·정비 피트는 변경하지 않았습니다.

## 실제 변경

- 8개 야외 배치 구역에 총 80군집을 불규칙한 간격과 방향으로 추가했습니다.
- 종류: 방치 작업차량, 부서진 콘크리트, 폐기계, 폐자재 수거함, 적재 팔레트, 넓은 잔해 더미.
- 실제 충돌이 활성화된 BoxCollider 241개. 부수적인 장식은 비충돌입니다.
- 계층: `StageA_v03_HeavyMaintenance_Blockout/05_Temporary_Debris_And_Cover_v04`. 각 군집에 번호·구역·종류가 있어 개별 편집하거나 전체 계층을 비활성화할 수 있습니다.
- 같은 추가 계층을 A 편집 씬과 일반 출격용 A 프리팹에 모두 저장했습니다. 기존 건물/스폰/탈출/순찰 데이터를 재생성하지 않았습니다.
- 기존 B 씬·B 프리팹·게임 런타임 코드·캐릭터·재질 원본·세이브·빌드 설정은 변경하지 않았습니다.

## 작업 방법과 보존

1. 원본 Unity 편집 화면을 `before_editor.png`로 저장했습니다.
2. 현재 원본 A 씬·A 프리팹을 `work/stage-a-cover-v04/backup/`에 백업했습니다.
3. 원본 Assets/Packages/ProjectSettings의 최신 복사본으로 격리 검증 프로젝트를 갱신한 후, 수정 전 동일 카메라 렌더 3장을 먼저 저장했습니다.
4. 서브가 작성한 AddTo 도구로 새 계층만 추가하고 메인이 충돌·보호 영역·NavMesh·실제 Play 검증을 실행했습니다. 전후 이미지도 메인과 서브가 각각 확인했습니다.
5. 검증 후 원본 A 씬/프리팹이 백업 시점과 같은 해시인지 확인하고 필요한 두 에셋과 새 Editor 도구만 설치했습니다. 설치본과 검증본의 해시 일치를 확인했습니다.
6. 원본 Unity 편집 화면에서도 신규 배치를 확인했습니다. 후속 UI 조작 중 사용자 입력이 감지되어 더 조작하지 않았습니다. 관련 없는 전경 앱 화면은 작업 증빙으로 저장하지 않았습니다.

## 검증 결과

- 배치 검사 PASS: 80군집 / 241개 활성 충돌 면.
- Collider별 직접 Raycast로 실제 차단 면 존재를 확인했습니다.
- 12개 진입점 × (실내 6곳 + 탈출구 7곳) = 156개 경로 연결 유지.
- 실제 Unity Play 검사 PASS: 총 188개 경로, PlayerMotor 이동 10건.
- 새 높은 엄폐물 하나가 실제 HitscanService의 사격 경로를 막는지 확인했습니다.
- 실제 PlayerMotor가 그 엄폐물을 우회해 반대편에 도달했습니다.
- 기존 실내 진입·계단/피트 왕복, 인간 순찰 폐루프, 루팅, A/B 탈출 및 A→B→A 재진입 검사도 통과했습니다.
- A 씬·A 프리팹 설치본이 검증본과 일치하며 B 씬·B 프리팹은 변경 없이 검증 복사본과 일치합니다.
- 상세 결과: `COVER_VALIDATION.txt`, `PLAY_VALIDATION.json`.
