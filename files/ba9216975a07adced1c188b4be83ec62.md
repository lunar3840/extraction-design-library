# 총기 부품 모딩 시스템

작업일: 2026-10-20, 한국 시간. 대상: `C:/UnityProject/escape`.
상태: 구현, 통합 검사, 실제 플레이와 최종 게임 화면 검증 완료.

## 사용자 지시와 설계 의도

델타포스의 손잡이·플래시·레이저·조준경·개머리판·탄창·기타 부품 구성을 분석하고, 성능 선택은 덕코프를 많이 참고하여 현재 익스트랙션의 전투에 맞게 구현한다. 총기 모델이 아직 완성되지 않았으므로 총의 메시·프리팹 외형을 바꾸지 않으며, 나중에 장착 외형을 연결할 수 있게 한다.

추가 지시: 가방 안의 총과 장착 중인 총을 클릭하면 세부창을 표시하고 개조 진입 옵션을 제공한다. 출격 중에도 가방의 부품을 총으로 드래그해 즉시 장착할 수 있어야 한다. 분리할 때는 기존 아이템 위치 변경 방식을 사용해 가방 칸을 직접 지정하고 가능한 부품 교환을 지원한다.

메인은 설계·런타임 연결·Unity 실행·통합 검토를 담당했다. 요청한 GPT-6.1 Sol 서브 에이전트의 추론 수준은 지원되는 `xhigh`로 설정하여 참고 조사/독립 검증, 무기 규칙, 인벤토리/거래/UI를 분리했다. 이번 작업은 맵 변경이 아니다.

## 변경 전

무기 개체별 추가 옵션과 여러 탄종의 순서·개체 저장은 있었으나 물리 부품 아이템, 부품 슬롯, 개조 UI와 부품에 따른 전투 성능 연결은 없었다. 탄창 용량은 기본 정의만 사용했다. 조준 전환은 방어구의 지연을 제외하면 즉시 완료되어 취급 부품의 속도 차이를 표현할 기반이 없었다.

코드 수정 전에 실제 Unity 편집 화면을 `before_editor.png`로 저장하고 전체 Runtime 원본과 두 카탈로그 JSON을 `source_before/`에 보관했다. 첫 캡처가 다른 전경 창을 담아 Unity를 활성화한 뒤 실제 Unity 화면으로 교체했으며, 이 교체도 런타임 수정 전에 완료했다. 시작 시 Console에는 기존 `Particle velocity curves must all be in the same mode` 메시지가 보였다.

## 설계와 구현

- 총구, 총열, 전방 손잡이, 후방 손잡이, 개머리판, 탄창, 조준경, 전술장비, 핸드가드의 9개 슬롯과 29개 부품.
- 플래시/레이저/복합 장치는 전술 슬롯 하나를 공유한다. 장착 직후 꺼짐 상태이며 T로 전환한다. 켜진 레이저만 집탄/취급 보조를 제공한다. 플래시는 실제 전방 Spot Light를 켜며 총기 외형은 추가하지 않는다.
- 수직·수평 반동, 조준·비조준 산포, 조준 진입 시간, 이동·조준 이동, 사거리, 재장전, 탄창 용량, 총성 감지거리, 조준 시 카메라 전방 이동을 구분한다.
- 총기 조준의 기본 진입 시간은 0.2초로 두고 부품과 취급 옵션을 곱한 뒤 기존 방어구 지연을 더한다. 이는 두 게임의 복제값이 아닌 이번 프로젝트의 첫 튜닝값이다.
- 고배율 명칭의 조준경은 현재 탑다운 카메라에서 조준 중 전방 시야 이동량을 늘리고 산포·취급 비용을 적용한다. 화면을 실제 2배/4배 확대하는 조준경 렌더링은 아니다.
- 일반 부품으로 기본 피해, 탄약 관통력, 연사 간격을 높이지 않는다. 중복 보정으로 성능이 무한히 강해지지 않도록 각 축의 한계를 둔다.
- 소음기는 적의 발사음 청각 반경을 줄인다. 탄착 소리나 실제 피격·시야 인식은 삭제하지 않는다.
- 조준경으로 요청 시야가 커졌을 때 기존 카메라의 0.75배 계단 감축 때문에 실제 시야가 작아지는 문제를 수정했다. 기존 화면 내 플레이어 위치 한계는 유지하고 그 안에서 허용되는 최대 전방 이동량을 연속 계산한다.
- 일시 정지·사망·지도 입력 중에도 조명 표시를 갱신하여 켜진 손전등이 남지 않게 했다. 전술장비의 켜짐 상태와 정지된 무기 시간은 보존한다.
- 장착 부품은 실제 가방에서 소비되며 분리된 부품은 가방으로 반환된다. 가방의 부품 중량과 장착 부품 중량을 함께 계산하고 판매 가치에 부품을 포함한다. 보급소에서 부품을 구매할 수 있다.
- 개조는 동일한 살아 있는 RifleState를 수정하여 탄약 순서·발사 쿨다운·블룸을 보존한다. 재장전 중, 호환되지 않는 부품, 가방 공간 부족, 현재 탄수가 새 탄창 용량을 넘는 탄창 교환은 거부한다.
- 부품 상태와 전술장비 켜짐 상태를 무기 저장 schema3에 기록하고 schema1/2를 읽는다. 출격 중 변경은 기존 출격 저장 규칙을 따르고 추출 성공 시 저장한다. 거점 저장 실패에는 부품 이동과 개조를 함께 되돌린다.
- 향후 외형용으로 부품의 안정적인 ID, 장착 위치 키, 리소스 키를 준비한다. 현재 리소스 키는 비어 있고 모델 생성 기능은 사용하지 않는다.

부품의 이득·불이익, 호환성, 가격은 첫 구현의 조정값이다. 덕코프의 커뮤니티 자료는 버전·단위 불일치가 있어 숫자를 그대로 옮기지 않았다. 공식 확인 내용, 비공식 관찰값, 우리 게임 제안을 구별한 근거는 `REFERENCE_RESEARCH.md`에 있다.

## 화면 대응과 주요 파일

`before_editor.png`는 코드 수정 전 실제 원본 편집 화면이다. 원래 장면 외형은 변경 대상이 아니므로 해당 시작 화면 자체를 성능 변화의 증거로 삼지 않는다. 원본 Runtime 백업을 보존했으며, 수정 전 인벤토리 Play 화면은 별도로 확보하지 못했다. 사후 화면을 수정 전 이미지로 위장하거나 원본을 재구성했다고 표시하지 않았다.

최종 증빙 목록:

| 화면 | 확인 내용 |
| --- | --- |
| `before_editor.png` | 수정 전 실제 Unity 편집 장면 |
| `after_equipped_details.png` | 장착 중인 총의 세부창과 개조 진입 버튼 |
| `after_modding_empty.png` | 개조창의 9개 슬롯, 현재 성능과 호환 부품 미리보기 |
| `after_grip_installed.png` | 실제 마우스 드래그로 장착한 수직 손잡이, 감소한 반동, 열린 총 세부창 |
| `after_grip_detached_at_cell.png` | 같은 총의 손잡이를 사용자가 지정한 가방 칸으로 분리, 빈 장착 슬롯과 원복된 성능 |
| `after_bag_gun_details.png` | 가방 속 총 클릭 시 세부창 |
| `before_bag_selection_fix.png` / `after_bag_selection_fix.png` | 후속 수정 전 외부 획득 안내 오류 / 수정 후 가방 소유 안내와 장착 조준경 |

손잡이 장착/분리 화면은 동일한 시험 실행·화면·총으로 비교했다. 마지막 가방 선택 수정 전후는 별도 시험 실행이어서 무기의 무작위 추가 옵션과 해상도는 같지 않으며, UI 소유권·개조 상태 비교용이다. OS의 네트워크 권한 팝업이 반복되어 마지막 사진은 Unity ScreenCapture가 실제 게임을 렌더링한 2배 해상도 캡처다. 보안 창을 지우거나 합성한 이미지가 아니다. 네트워크 권한을 허용하거나 보안 설정을 변경하지 않았다.

실제 사용자 프로필은 시험에 사용하지 않았고 InventoryTest의 일회용 가방을 사용했다. 원본 ItemCatalog.json/WeaponCatalog.json은 백업과 해시가 동일하다. 시험 종료 후 원래 `StageA_Relay_Blockout_v08` 편집 장면으로 돌아온 것을 Unity 로그로 확인했고 맵과 총기 모델 에셋을 저장·변경하지 않았다. 완료 보고 전 전후 사진·기록·주요 결과 17개 파일이 실제로 존재하고 비어 있지 않은지도 점검했다.

주요 파일: `Runtime/Weapon/Core/RifleState.cs`, `WeaponAttachments.cs`, `RifleController.cs`, `RifleAttachmentPresentation.cs`, `Runtime/PlayerMotor.cs`, `Runtime/TopDownCamera.cs`, `Runtime/Core/PlayerRules.cs`, `Runtime/Combat/CombatSignals.cs`, `Runtime/Enemy/EnemyController.cs`, `Runtime/Inventory/Core/InventoryWeaponAttachments.cs`, `Runtime/Inventory/InventoryWeaponModding.cs`, `Runtime/Save/WeaponModdingTransactions.cs`, 인벤토리·거래·아이콘 표시 연결 파일과 Editor 검사 파일. Runtime 원본과 해시 비교로 작성한 전체 목록은 `MODIFIED_FILES.txt`에 있다. 새 스크립트에는 Unity meta가 포함된다.
