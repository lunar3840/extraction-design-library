# Blender → A맵 Unity 반입 계약

이 회차는 W10 검증 샘플을 유지하고 나머지 68동과 야외7그룹을 제작했다. 편집 원본은 blender/EXPORT_INDEX.json의 68 .blend와 outdoor/export/live_004/StageA_Outdoor_Authored.blend다. 실제 반입 FBX는 Unity Assets/Escape/Art/BlenderEnvironmentExpansion/Buildings 및 Outdoor/Models에 있다. 원본·실패 산출물·이전 기획은 별도 회차 기록으로 보존한다.

- 각 건물은 현재 D09 facade geometry frame을 기준으로 Shell/Roof/Interior를 분리했다. CLINIC/HALL/PARTS/POWER/TOOLS의 owner 원점과 geometry frame은 다르므로 owner 좌표로 옮기면 안 된다.
- Blender는 미터, Unity(x,y,z)→Blender(x,-z,y). FBX 복제본에 X 반사와 winding 보정을 적용하고 -Z forward/Y up을 사용한다. Unity ModelImporter는 useFileScale=true, globalScale=1, readable=true, preserveHierarchy=true, normals Import/tangent Mikk, compression Off, weldVertices=false, animation/autocollider Off다.
- **이 회차의 다중 재질 모델에는 ImportStandard/InPrefab과 SourceAssetIdentifier(typeof(Material), FBX source material name) → 정확한 원본 GUID/localFileID AddRemap을 사용한다.** materialImportMode=None 후 manifest materialSlots 배열 순서로 강제 대입하면 Unity의 FBX submesh 재정렬 때문에 벽·지붕에 잘못된 재질이 붙는다. 실제 remapped imported prefab의 슬롯 순서를 후보 instance에 그대로 사용한다. 새 outdoor DETAIL 재질4종도 원본과 같은 방식으로 이름 연결한다.
- 유리/금속 창틀/벽을 재료별로 유지한다. 원본 129개 건물 material과 야외 원본 material·shader·texture asset은 수정하지 않았다. 재질별 triangle 수·기하 영역·GUID 전수 비교와 stain UV/topology/winding 검증을 별도로 보존한다.
- colliderOnly는 MeshFilter+MeshCollider만 남기고 MeshRenderer를 제거한다. 지붕 가림 처리가 자식 Renderer를 일괄 켜도 물리용 벽이 드러나지 않게 하기 위함이다. collider manifest submeshCount=0은 의미상 material 없음이며 Unity imported mesh의 물리 삼각형은 하나 이상의 submesh에 들어갈 수 있다.
- opaque visual-only trim/roof가 반드시 collider를 가져야 하는 것은 아니다. Collider는 원본 활성 물리 메시와 새 방의 설계된 벽에만 존재한다. visual mesh 전체와 collider-only subset의 AABB를 같다고 요구하지 않는다. 읽을 수 있는 실제 정점으로 unit/axis/world AABB를 검사한다.
- HALL에 새 sibling을 반입한 편집 세션에서는 StageAHallV13LayerVisibility.RebuildCache()로 transient renderer cache를 재구성한다. 새 Play 세션은 fresh cache로 정상 가림을 처리한다. CLINIC/HALL의 문 라벨 inside는 기존 roof footprint inside와 동일하지 않으므로 roof 검증은 동일 고정 카메라의 실제 player 좌표로 한다.
- 지형·식생·수면·날씨·LOD와 외부 차량8개는 현재 에셋을 보존·참조한다. 비건물8,588 renderer/1,925 collider 전수 목록과 실제 교체563개+신규detail237개를 구별한다. 모든 자연물을 새로 모델링했다고 주장하지 않는다.
- 원본 A 프리팹 저장은 최종 Editor/실제 플레이/성능/시각 검증 후 한 번만 수행한다. 원본 씬 파일은 기존 프리팹 참조와 override를 유지한다. linked FBX InstantiatePrefab과 명시 override 복제 경로를 사용한다. Object.Instantiate(source prefab instance)는 nested FBX 연결을 끊으므로 사용하지 않는다.

현재 저장/최종 검증 여부는 CHANGE_RECORD.md와 main/PERSIST_REPORT.json 실제 결과로 판정한다. 이 문서는 제작 방식이며 자체 완료 표식은 아니다.
