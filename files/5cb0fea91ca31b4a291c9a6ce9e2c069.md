검사는 실제 Unity의 JsonUtility, 파일 저장·백업, 물리·NavMesh, 플레이 모드 시작, 출격·철수·사망·유품 복원까지 포함한다. 최신 대상 프로젝트와 검사 사본의 코드/데이터/씬/설정 **80개 파일 해시가 전부 일치**했다.

독립 검증에는 무작위 인벤토리·전리품 수량 보존, 무기 탄약 보존, 실패 주입 거래, 퀘스트 25개, 성장·특수 사용 563개, 감염 28개 항목과 저장 잠금·오래된 작성자 거부가 포함된다. 반복 조합 검사 횟수를 서로 다른 기능 수로 해석하면 안 된다. .NET 독립 검사에서 사용한 대체 JSON은 실제 Unity 직렬화 검사와 구분했다.

주요 수정 사항:

- 적 비활성화 후 재활성화 시 총성 구독 복원, 동적으로 생성한 적도 발소리 수신.
- 저장에서 퀵슬롯 허용 여부 재검증, 손상된 기존 파일의 재저장 차단.
- 화면 알림 예외가 이미 성공한 저장을 실패로 바꾸지 않도록 처리.
- 성장 선택 저장 중 살아 있는 무기 객체·탄창·발사 시간축 유지.
- 저장 작성 잠금과 버전 충돌 확인.
- 성장 산탄도 보정은 원작대로 최소 산탄도 제한 전에 적용.
- 저장 확정 중 루팅·장전·이동·생존 수치·피해 차단.

## 범위와 한계

- **스테이지 맵, 지형/오브젝트 배치, 몹 종류별 구성, 스폰 배치는 이식하지 않았다.** 같은 작은 시험장과 일반 적 placeholder를 사용한다.
- 실제 보스·맵 목표 대신 `QuestTargetId`/획득 이벤트 연결점을 제공한다. 통합 시험의 `TEST ONLY` 버튼은 명시적 목표·아이템 시험 도구이며 실제 콘텐츠가 아니다.
- UI는 기능 확인용 IMGUI다. 최종 디자인/아이콘/모델/애니메이션은 포함하지 않는다.
- 원작 `AmmoManagement`의 최대 예비탄 보정 함수에는 활성 호출부가 없었다. 계산 함수는 제공하되 새로운 보유 상한이나 무료 탄약을 만들지 않았다.
- 원작 감염 회복·치유 계수도 생성 외 활성 소비 코드가 없어 값만 노출했다. 추가 피해/치유 규칙을 임의로 적용하지 않았다.
- Unity의 실제 수집 이벤트는 퀘스트에 연결했다. 조사한 StageA 원작 획득 경로에서 수집 목표 호출부는 확인되지 않아, 이 연결을 원작과 구분한다.
- 저장은 Windows 로컬 시험 프로필이다. Roblox DataStore, 멀티플레이 동기화, 배포·게시에는 연결하지 않았다.
- 기존 Roblox는 읽기만 했고 원본을 수정·저장·게시하지 않았다. Unity의 기존 SampleScene/Packages/ProjectSettings도 직접 수정하지 않았다.
- 격리된 Unity 검사는 렌더링 없는 실행이다. **사용자 화면에서의 최종 URP 시각 품질 검증은 하지 않았다.**
