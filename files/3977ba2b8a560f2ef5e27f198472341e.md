# Basecamp 메인 화면·슬롯·로비·출격 이식

## 범위와 원본 확인

2026-09-04 연결된 Roblox Basecamp(Place 103063400021951)의 Edit 데이터만 읽었다. Studio Play 실행, 스크립트 편집, DataStore 변경을 하지 않았다.

원본 전체 읽기: `ReplicatedFirst.EXIT4_MainMenuController`(826줄), `ServerScriptService.EXIT4_MainMenuServer`(477줄), `StageTravelController`(251줄), `StageTravelService`(377줄), `TeleportTriggerService`(158줄), `GameplayMenuServer`(312줄). GUI의 실제 메뉴 텍스트도 조회했다.

원본의 핵심 규칙은 최초 접속 시 슬롯 미선택, 신규/불러오기 분리, 3개 슬롯, 프로필 준비 완료 후 로비 입장, 출격 전 저장, 저장 실패 시 이동 취소, 캠프에서 메뉴 복귀 전 저장, 철수·사망 복귀 시 동일 슬롯 유지다.

## 구현

- `FrontEndController`: Main → NewSlots/LoadSlots → 확인 → Loading → Lobby → Departing → Stage. 메인·슬롯·전환 화면에서는 HUD 숨김과 이동/사격/아이템/전리품 잠금.
- `SessionTestWorld`: 자동 슬롯 1 선택 제거. 신규 생성/기존 로드 분리, 최초 저장 성공 후 활성화. 로비 출격은 구역 선택 후 별도 출격 버튼. 메뉴 복귀는 저장 성공 후 세션 해제.
- `InventoryTestWorld.ShowUI`: 메뉴와 로딩 중 기존 가방·체력·퀵슬롯 UI 숨김.
- 페이지 revision과 세션 identity로 이전 화면의 지연 클릭 폐기. 중복 로딩/출격/메뉴 복귀 차단.
- 슬롯 메타데이터는 기존 검증된 프로필과 파일 시간에서 읽음. 기존 저장 스키마·경로·아이템 ID 유지.
- 손상된 저장 또는 primary 없이 `.bak`만 남은 슬롯을 빈 슬롯으로 취급하지 않음. 자동 복구/삭제/덮어쓰기 없음.

## 의도적 차이

- 사용자 요청에 따라 튜토리얼·인트로와 스테이지 맵/몹 배치는 제외.
- 원작 터치 게이트 대신 로비 UI에서 구역 선택. A~D는 기존 공통 placeholder 시험장 사용. 퀘스트 해금 조건 유지.
- 신규 게임에는 기존 Unity 시험용 장비/스크랩만 한 번 지급. Roblox 튜토리얼 키 지급을 흉내 내지 않음.
- 원작 설정·크레딧·게임 종료·슬롯 삭제·기존 슬롯 덮어쓰기는 이번 요청의 화면 흐름에 필요하지 않아 제외.
- 원작 서버 이동을 Unity 로컬 세션 전환으로 구현. 멀티플레이/클라우드 저장 기능을 추가하지 않음.

## 실행

Unity Play를 중지 후 `Assets/Escape/Scenes/SystemsTest.unity`에서 다시 Play. **새 게임/불러오기 → 슬롯 → 로비로 입장 → 출격 구역 선택 → 출격**.

기존 게임은 불러오기를 사용한다. 로비에서 **저장** 탭의 **저장하고 메인 화면 / 저장하고 슬롯 선택**으로 나간다. Play 강제 중지까지 자동 저장하는 기능은 아니다.

## 검증

별도 검증 프로젝트에서 실제 Unity 직렬화/파일/물리/Play 검사를 수행. 사용자 프로젝트의 SampleScene, Packages, ProjectSettings를 수정하지 않았다.

- 실제 Unity batch 7회 모두 exit 0. FrontEnd 44 + Systems 18 + Session 42 + Basecamp 50 + Inventory 50 + Equipment 63 + Loot 58 + Player 67 + Enemy 98 = **490 PASS**. 이번에 Combat/Weapon/Arsenal 전용 검사를 다시 돌렸다는 뜻은 아니다.
- 메뉴 44검사에는 미선택 부팅, 신규/로드 확인·취소, 중복 요청, 최초 저장 실패와 재시도, 확인 이후 파일 손상, 기존 슬롯 덮어쓰기 거부, 출격/메뉴 저장 실패 보존, 같은 슬롯 철수 복귀, 슬롯 분리, 손상/backup-only 보호, 지연 UI 무효화가 포함된다.
- 최초 검사에서 장착 무기를 가방 수량으로 센 테스트 기대값을 수정했다. 장착 슬롯과 가방 내부 수량을 각각 검사하며 이후 PASS다. 게임의 무기 보존 동작은 변경하지 않았다.
- 독립 검증 에이전트가 정상 입장 문구의 번역 fallback 오류를 발견해 수정했다. 추가 권장 오류 경계 2종을 5개 검사로 보강했다. 검증자는 코드와 실제 실행 결과를 독립 대조했으며, 새 실행 검사를 직접 수행했다고 주장하지 않는다. `work/review/FRONTEND_REVIEW_FINAL.md` 참조.
- 대상/검증 프로젝트의 C#/JSON/씬/에셋/문서 89파일 해시 일치 확인.
- 그래픽 검증 빌드는 Built-in 렌더러의 IMGUI 표시 검사이며 대상 URP 프로젝트의 최종 아트 품질 검증과는 구분한다.
- 최종 실행본 빌드/실행 exit 0. 메인·신규 슬롯 확인·로딩·로비·960×600 불러오기·출격 준비·출격 후 **7개 PNG** 생성, 런타임 오류 0. 실제 Update 기반 저장→메인/불러오기→로비/출격→Stage 자동 전환 PASS. 실제 마우스 입력을 자동 주입한 end-to-end 검사는 아니다.
- 밝은 시험장 배경 위 안내문에 어두운 배경을 추가했다. 화면 재검사에서 발견한 부분 글자 누락은 공통 문자/크기별 글꼴 사전 준비 후 재캡처에서 해소 확인했다. 동적 폰트 문자 유지 방식은 [Unity Font.RequestCharactersInTexture 문서](https://docs.unity3d.com/es/2021.1/ScriptReference/Font.RequestCharactersInTexture.html)를 참고했다. 기능 회귀 490검사 후 이 표시 수정을 적용했고, 최종 실행본 재빌드·자동전환·PNG 확인으로 검증했다.
- 마지막 복사에 별도 작업에서 추가된 `SdCharacterLibrary`/`SdCharacterVisual`이 포함되어, 검증 프로젝트에만 Unity 기본 Animation 모듈을 추가했다. 해당 캐릭터 코드는 이 작업에서 수정하지 않았다. 최종 아트/애니메이션 통합 검증 결과로 확대 해석하지 않는다.
- 마지막 해시 비교 93파일 중 별도 작업의 `SD_CHARACTERS_README.md`만 변경되어 달랐고, 실행에 사용되는 코드·데이터·씬은 대상과 검증 복사본이 모두 일치했다.
