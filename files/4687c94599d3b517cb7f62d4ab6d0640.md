# 인벤토리 카드 간격 / 무기 카드 폭 후속 조정

상태: 간격/tight-fit 적용은 메인이 실제 r04 인벤토리 화면에서 확인했다고 보고했다. 이 담당자의 직접 검토는 r03까지이고 r04 독립 시각 검토는 validation 담당이다. 이후 새 슬롯 단순화 지시는 별도 `SLOT_SIMPLIFICATION_RECORD.md`에 기록한다. 이 간격 단계의 사용자 요청은 **현재 익스트랙션 게임**의 슬롯 간 여백을 늘리고 캐릭터 크기·초상을 유지하며 무기 슬롯만 왼쪽으로 늘리는 것이다. Roblox 등 다른 게임의 공통 규칙으로 확대하지 않았다.

## 전 증빙과 원본

메인이 사용자 변경 지시 후 `before_inventory_spacing_native.png`와 이전 최종 `after_r02_inventory_1920x1080.png` 등을 확보한 다음 수정을 승인했다. 원본3파일과 .meta를 기존 before를 덮지 않고 `source_before_spacing/` 아래 경로를 보존하여 추가 백업했다. 정확한 before/after SHA는 `inventory_spacing_source_manifest.json`이다.

## 선택한 방식

기존60 pitch와6열 가방412폭을 유지한다. pitch70은 가방 폭을472로 늘리고 우측10열 보관함을500→440으로 줄여 보관함 셀을44.8→38.8 pitch로 더 좁히는 문제가 있어 채택하지 않았다.

- logical `Cell`, `Item`, `CellAt` 및 아이템 원점은 그대로다. 새 `Card`는 각 면을3 logical 안으로 넣어 단일 카드54×54, 인접 간격6 logical을 만든다. multi-cell 카드도 전체 `pitch*w−6` / `pitch*h−6` 한 장을 그린다.
- 점유 셀의 작은 empty backing을 생략하여 큰 아이템 안에 작은 셀 테두리가 겹쳐 보이지 않게 했다. empty cell만 같은6px 간격으로 그린다.
- 그림/hover/click은 보이는 card rect를 사용한다. drag-grab cell은 기존 logical rect 원점으로 계산하므로 넓은 아이템의 둘째 셀 첫3px에서도1칸을 잘못 잡지 않는다. destination grid와 drop preview의 논리 좌표·pitch는 유지했다.
- 사용자 승인에 따라1×1과 좁은 세로 카드의 이름은 항상 표시하지 않고 hover/상세에서 읽는다. 가로2칸 이상인 넓은 카드만 하단 이름을 유지한다.
- 메인 가방54px 카드에는 V22×16/왼쪽3, 수량22×16/오른쪽3, 전용11px 글자를 사용한다. 의료 잔량·탄약T는 다음 행으로 분리하고 아이콘도 옆/아래 공간에 놓았다. 주요 수량/잔량/이름은 불투명 흰색이다. 보호 표식도 유지하고 좁은 resource 카드의 표식과 잔량은 다른 위치를 사용한다.
-10열 보관함은 기존44.8 pitch와 새38.8px 시각 카드라는 제약이 있다. <50px 카드에는10px 메타 글자·숫자만인 수량을 쓰며, resource/Ammo 또는 긴 수량 때문에 공간이 부족하면 **V 글자 배지를 생략하고 pastel tier stripe와 hover의 V를 유지**한다. Ammo의 T는 따로 `T` 접두어로 표시한다. V와 T의 의미·가격/수량/관통 문턱은 바꾸지 않았다.
- 무기 rect는 full layout에만 x442/폭180/right622로 늘렸다. y/height108은 유지한다. character600/portrait460, 프레이밍·텍스처·카메라·모델·재질은 변경하지 않았다. `PortraitAcceptsPointer`는 기존에도 WeaponRect 안을 우선 제외하여 새로 늘어난 영역의 weapon click을 portrait 회전이 가져가지 않는다.

## 수정 파일과 범위

1. `Inventory/InventoryGridPresentation.cs`: 시각 card geometry, empty/card 표시와 metadata, 보이는 표면의 hover/click 경계.
2. `UI/ItemTierPresentation.cs`: adaptive V/T badge 표시·전용 글자 스타일.
3. `Inventory/InventoryGlassView.cs`: WeaponRect 한 표현식.

이 최초3파일 외 runtime 및 UiTheme는 수정하지 않았다. 특히 저장·가방 데이터·장착/거래·transfer·split·quantity·실제 슬롯 위치·카메라를 바꾸지 않았다. 이후 메인이 추가 승인한 전리품 grid 적용은 아래 후속 범위에 기록한다.

## 확인

- 전체 runtime 정적 컴파일 오류0/기존 warning21: `compile_inventory_hud/runtime_compile_inventory_spacing.txt`.
- 순수 geometry 확인34항목 PASS: `compile_inventory_hud/inventory_spacing_checks.txt`.60/44.8 pitch 유지,1~4×1~3 연속 카드 크기,6px 간격, cell/drag 원점, V/수량 칸 합계, weapon right622를 확인했다.
- Unity Roslyn AST 비교: `inventory_spacing_ast_audit.json`. 기존 메서드는 DrawInventoryGrid, DrawBadge 및 WeaponRect만 변경했다. 나머지 기존58메서드와34 lambda callback이 그대로다. Tier ColorForTier/Tint/DrawSlot/Summary와 portrait pointer guard 등도 그대로다. 새 코드는 presentation geometry/style/그리기 메서드다.
- source_after3파일과 manifest를 갱신했다. Unity/native 앱 조작·reload는 하지 않았다.

## 메인 실제 검증

같은 인벤토리 정면/측면에서 캐릭터 크기·모자/부츠·메인 패널 좌표 유지, 무기 카드 왼쪽 연장과 겹침 여부, 실제 새 영역 클릭·portrait drag 구분을 확인한다. 카드 간격/큰 아이템 내부 테두리/1×1 이름 숨김, V/qty/resource/T 가독성을6열 가방과10열 보관함에서 각각 확인한다. hover·두번째 셀을 잡은 drag·수량 보존과 카드 사이 빈 여백의 click/hover 동작도 실제 입력으로 확인한다.

## 전리품 grid 후속 승인 및 적용

메인이 UI 일관성을 위해 `Loot/LootInteractor.cs`의 OnGUI 시각 grid만 추가 승인했다. 변경 전 증빙은 spacing 적용 전 실제 `after_r02_loot_revealed_1920x1080.png` / `after_r02_loot_search_1920x1080.png`이며 해당 원본 파일/.meta도 `source_before_spacing/`에 새로 보관했다.

- 완료된 entry는 같은6px gap/Card geometry와 공개한 `DrawGridCardContents`를 재사용한다. 점유 셀 backing을 생략하고 multi-cell은 연속 카드다. 인벤토리 helper가 없는 fallback도 null guard와 간결한 아이콘/수량 표시를 제공한다.
- 미검색/수색 중 카드는 같은 rounded shape만 사용한다. 완료 조건·시간·`?`/수색 중/남은 초 문구는 그대로이며, hover 등록과 click/drag 처리는 계속 Completed 분기 안에만 있다.
- logical cell 원점과 grab-cell 계산은 유지했다. 보이는 card만 hover/click 경계로 사용한다. Take/TakeAt/Deposit/Close 등 모든 lambda14개와 다른 기존19메서드가 동일한 것을 Roslyn AST로 확인했다. 변경 기존 메서드는 OnGUI 하나뿐이다: `loot_spacing_ast_audit.json`.
- 최종 전체 runtime 정적 컴파일 오류0/기존 warning21: `compile_inventory_hud/runtime_compile_loot_spacing.txt`. 이전 geometry34항목 검증의 Card 함수를 그대로 사용하며 새 mutation 로직은 없다.
- source_after와4파일 SHA manifest를 갱신했다. 앱/native 조작·reload는 하지 않았다. 실제 전리품 search/revealed/hover/획득·drag 화면 검증은 메인이 이어서 진행한다.

## r03 확인 후 의료 아이콘 tight-fit 보완

실제 `after_r03_inventory_1920x1080.png`를 독립 검토해6px 간격·큰 카드의 중복 테두리 제거·weapon180폭·캐릭터 영역 유지가 개선된 것을 확인했다. 다만 의료 그림을24×29 rect에 넣을 때96px 원본의 투명 여백까지 포함되어 실제 kit 폭은약17.5 logical, 진통제는약10 logical에 불과해 숫자보다 식별성이 약해진 문제가 있었다.

메인의 추가 승인으로 `UI/MedicalIcons.cs`만 새로 source_before_spacing에 백업하고 `TryDrawItemTight`를 추가했다. 기존 의료 ID 판단/종류 생성/texture cache 조회를 재사용한다. 알파8보다 큰 픽셀의 bounds를 texture별 최초1회 구해2px padding을 더하고 UV/aspect fit으로 현재 rect를 채운다. 텍스처가 CPU unreadable이거나 pixel 읽기가 실패하거나 빈 이미지면 false를 반환해 기존 `GlassIcons.Draw` 경로를 사용한다. 현재 생성 texture는 기존 `Texture().Apply()`가 CPU readable을 유지하므로 적용 가능하다. UV cache는 기존 생성 texture들과 함께 Reset 때 비운다.

이 새 경로는 `DrawGridCardContents`에서만 호출되어 가방/보관함/전리품 grid에 공유된다. HUD·퀵슬롯·의료 휠·상세의 기존 DrawItem은 private texture 조회 추출 외에 원래 rect/ScaleToFit/색 복원을 그대로 유지한다. 아이콘 원본/카탈로그/수량/잔량/metadata/패널/character/portrait/camera를 바꾸지 않았다. 의료품의 기존 rotated 표시가 무회전인 것도 유지한다.

최종 runtime 정적 compile 오류0/기존 warning21: `compile_inventory_hud/runtime_compile_medical_tightfit.txt`. source_after와5파일 manifest를 갱신했고 runtime 파일은 freeze했다. 실제 확대 효과와 다른 화면 경로 보존은 후속 after/입력 검증을 맡은 메인이 확인한다. 이 담당자가 앱/native 조작·reload를 하지 않았다.

메인은 실제 r04 inventory를 열어 의료 tight-fit 확대, metadata 분리 및 gap을 확인했다고 보고했다. r04 독립 validation은 별도 담당이 수행한다. 이후 사용자가 metadata 자체 제거를 새로 지시했으므로, 위 단계의 결과와 새 단순화 적용을 구분한다. 새 작업의 before 원본·변경 및 확인 범위는 `SLOT_SIMPLIFICATION_RECORD.md`를 참조한다.
