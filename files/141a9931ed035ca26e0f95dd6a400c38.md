# 변경 기록 — Figma 인벤토리 Hover 검토 시안 먼저 구성

## 사용자 지시 요약

사용자는 Unity 구현보다 Figma 시안의 검토가 먼저여야 한다고 정정했다. 이에 기존 인벤토리 전체 화면 안에서 Hover 카드와 선택 대상·커서의 관계를 함께 볼 수 있는 **Figma 디자인 검토 시안**을 별도 페이지에 구성했다.

이번 작업에서는 Unity·코드 조작이나 수정이 없었다. 앞서 진행된 런타임 작업을 자동으로 되돌리지도 않았다.

## 기획 의도와 변경 전 상태

기존에는 UI 키트의 단독 Tooltip 컴포넌트와 별도의 인벤토리 화면이 있어 실제 화면 속 크기·배치·계층을 한 번에 검토하기 어려웠다. 기존03 Inventory + Loot 화면을 복제한1920×1080 보드의 편집 전 상태를 먼저 저장하고, 그 복제본에만 Hover 예시를 구성했다.

## 실제 변경 부분

- Figma 파일: KUD4t84BL1S77c3cnb8co0.
- 새 페이지: **검토 시안 · Inventory Hover**. page ID는 확인되지 않았다.
- 보드: **01 · Inventory Hover · 디자인 검토 시안**, frame105:2987,1920×1080, x0/y0.
- 기존 인벤토리·전리품 화면의 편집 가능한 계층을 그대로 복제했다.
- 기존 마스터105:2984의 Tooltip 인스턴스를 x810/y530,304×260으로 추가했다. 세로 Auto Layout gap8/padding16/radius21, 기존 dense 배경과 Tier2 상단3px 강조를 유지했다.
- 한 의료품 슬롯만 Tier2/StateSelected/표기V2로 맞추고 Medical field-kit 아이콘을 확인했다.
- 해당 하단 슬롯 위에26×32 네이티브 SVG 커서를 x750/y790으로 배치했다.
- source 화면의 고정 Item detail은 **복제본에서만** 숨겼다.
- 편집자 보고상 다른 원본 페이지·컴포넌트는 바꾸지 않았고 Screenshot을 UI로 가져와 덮는 방식도 쓰지 않았다.

## 변경 방식

Figma 네이티브 레이어·인스턴스·벡터를 사용해 화면을 구성했다. 새 Tooltip 전체를 이미지로 대체하지 않았다. 현재는 단일 의료품 Hover를 보여 주는 정적 검토 시안이고 Prototype Hover 이벤트는 연결하지 않았다.

## 변경 후 기대 효과와 확인 결과

전체 화면에서 선택된 V2 의료품, 커서, Hover 카드의 관계를 확인할 수 있다. 독립 검토자가 실제1×export와133%카드를 열어 제목·수량·용량·무게·판매가·설명·안내의 가독성 및 카드 전체 표시를 확인했으며, 새 잘림이나 비의도적 겹침을 발견하지 못했다. 자세한 범위와 한계는 visual-audit.md에 기록했다.

## 주요 에셋·파일과 범위

- 새 페이지와 frame105:2987, 기존 마스터105:2984를 참조한 인스턴스 및 네이티브 커서.
- 이 폴더의 원본 JPG7개, 변환 PNG7개, 기존 실제 export PNG1개, visual-audit.md, CHANGE_RECORD.md, design-review-state.json.
- 마스터 latestRevision 포인터는 유지했다. 메인 작업자는 별도로 latestInventoryDesignReview를 이 폴더 상태 기록에 연결하고 uiWorkSequence와 currentUiStage만 디자인 검토 순서에 맞춰 갱신했다고 보고했다. 기록 작성자는 이 폴더 밖의 파일을 수정하지 않았다.
- 현재 Figma는 새 검토 프레임을24%로 선택해 둔 상태라고 메인 작업자가 보고했다. 프레임 직접 URL을 브라우저에서 열기 위한 요청은 queued 상태이므로 실제로 새 브라우저 화면이 열렸다고 주장하지 않는다.
- 정적 Figma 디자인 검토 단계이며 Unity 구현·입력 동작·전체 상태·인벤토리 전면 리뉴얼 완료로 취급하지 않는다.
