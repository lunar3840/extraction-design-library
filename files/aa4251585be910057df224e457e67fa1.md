# A맵 건물 정체성 D08 — 작업 기록

## 지시와 의도

사용자: “그럼 유니티에 적용해봐. 아까 말했듯 건물들 컨셉에 맞게 다른 외형으로 구현해야 하는거 잊지 말고.”

기준은 `outputs/concept_art/2026-10-12/a-map-building-identities-v01/BUILDING_DESIGN.md`의 69동·10계열이다. 동일 공장 창문과 평평한 벽이 반복되는 상태에서 벗어나 지붕 단면, 재료, 창·출입부 깊이, 처마와 부속 매스로 역할을 구별한다. 맵 풋프린트·동선·스폰 정책을 재설계하는 작업은 아니다.

메인이 기획·Unity 적용·통합 검토를 맡고 GPT-6 Sol high 서브 에이전트가 건축 제작, 독립 검증, Tripo 내려받기를 분리 수행했다. 제작 코드와 검증 코드는 서로 다른 소유 파일로 분리했다.

## 변경 전 증빙

- 저장된 A 씬을 Edit mode에서 확인했고 unsaved scene 변경이 없었다.
- `before_editor.png`: 실제 Unity 편집기 화면.
- `before_overview.png` 및 69개의 `before_<ID>.png`: 실제 Unity 카메라 렌더. `BEFORE_CAPTURE_INDEX.csv`에 동일 시점 재현 좌표를 기록했다.
- `backup/A.unity`, `backup/A.prefab`: 수정 전 저장본. `BEFORE_HASHES.txt`에 해시, `BEFORE_PROTECTED.txt`와 `BEFORE_COLLISION_TRANSFORMS.txt`에 보호 대상 상태를 기록했다.
- 변경 전 이미지는 사후 재구성이 아니다. `BASELINE.txt`와 `COMMAND_before.txt`에 캡처 완료를 남겼다.

## Tripo 모델 전달 상태 — 사용자 직접 다운로드로 해결

아래 첫 두 문단은 **사용자 직접 다운로드 이전의 실패 이력**이다. 현재 수령·반입 상태는 뒤의 32개 완료 기록을 기준으로 한다.

새 T01–T14 및 선택 Z 소품 18개, 총 32개는 클라우드 생성 기록만 있고 이번 자동 내려받기에서 검증된 로컬 GLB는 0개다. T01 GLB/2K 및 1K 내보내기 시 사이트 완료 메시지는 나왔으나 다운로드 이벤트와 파일은 없었다. 다른 브라우저 UI 접근도 도구의 안전 확인 단계에서 중단되어 우회하지 않았다.

`DOWNLOAD_BLOCKER.md`, `DOWNLOAD_MANIFEST.json`, `before_tripo_export_T01.png`, `after_tripo_export_T01.png`, `after_tripo_export_T01_1k.png`를 참조한다. 사용자에게 직접 다운로드·첨부를 요청했고, 사용자가 첫 미다운로드 에셋을 물어 T01 진료소 둥근 타일 코너 링크를 안내했다. 추가 생성·유료 후처리·추가 크레딧 소비는 없다. Tripo 신규 모델의 Unity 반입·배치를 완료했다고 간주하지 않는다.

이후 사용자가 직접 내려받은 파일을 확인했다. 최초 25개는 T01·T10 및 Z 원안/수정 23개였고, 부족한 T02–T09/T11–T14 12개는 사용자에게 식별 원화 모음으로 안내해 추가 수령했다. 최종적으로 요청한 건축 14종+선택 소품 18종, 총 32개가 모두 있다. 보류 5개는 별도 감사용 보관이며 새 배치 대상이 아니다. 추가로 받은 기존 D05 벽·기둥 2개는 BIN 내용이 기존 파일과 같아 중복으로 제외했다. `RECEIVED_MANIFEST.json`이 최종 수령 상태이며 초기 DOWNLOAD_MANIFEST의 0개는 실패했던 브라우저 시도의 역사적 기록이다. GLB 헤더·길이·내장 2K 텍스처·삼각형 수·해시를 확인했다. T06/T13처럼 면 수가 같은 경우 생성 화면과 실제 색상 아틀라스를 대조했다. Unity 반입은 별도 IMPORT 기록으로 판단한다.

다운로드 식별 안내 이미지: `download_architecture_T01_T14.png`, `download_zone_props_selected18.png`, `download_missing_architecture_12.png`. 실제 모델을 새로 생성하거나 변형한 것이 아니라 기존 생성 원화를 번호·이름과 함께 배열한 안내판이다.

## 실제 수정과 검증 상태

**콘셉트 재현 미달 — 완료 처리하지 않음.** 3차 후보 적용 중 사용자가 “외형적으로 너가 준 컨셉아트를 구현하길 바랐는데.. 좀 많이 다른 것 같지 않니?”라고 지적했다. 추가 적용과 Play 테스트를 중지하고 원본 콘셉트 3장과 실제 Unity after 화면을 대조했다. 이미 시작된 동기 적용 명령의 저장·재열기 결과는 별도로 확인하며, 임의로 원복하거나 다음 개조를 진행하지 않는다.

핵심 미달: 기존 직사각형 건물 틀에 지붕과 얇은 외피·소형 부품을 덧붙이는 방식이라 콘셉트의 큰 형태·비례·높이차·증축량·깊은 현관/차양을 충분히 옮기지 못했다. CLINIC의 ㄴ자 인상·둥근 포치, POWER의 큰 환기탑/부벽, TOOLS의 서로 어긋난 3개 증축량, N17의 다각 관찰실이 대표적인 차이다. 이는 텍스처 해상도가 아니라 구조적 외형 재현 문제다. 기존 충돌/문 보존을 지나치게 좁게 해석한 구현 접근을 재검토해야 한다.

3차 편집 상태 검사는 `attempt_03/VALIDATION.txt`에서 1410 PASS / 0 FAIL이나, 이것은 지정된 원본 보존·문 통행·배치 검사의 통과일 뿐 콘셉트 재현이나 그래픽 완성의 증거가 아니다. 실제 캐릭터 Play 검증은 시작하지 않았다. 또한 `after_F01.png`에서 경사지붕과 외벽 사이 큰 틈으로 실내가 노출되는 외관 문제를 발견했다. 이 문제를 포함해 최종 외형 합격으로 간주하지 않는다.

진행 중이던 `apply` 명령은 이후 COMPLETE로 종료했다. 3차 후보는 기존 A 씬과 프리팹에 저장되어 있으며 `RELOAD_VALIDATION.txt`도 1410 PASS / 0 FAIL이다. `FINAL_HASHES.txt`로 저장 상태를 식별한다. 69동+전체+진입점 3장(73장)의 before/after 동일 시점 증빙이 있다. 저장된 버전은 **외형 미달 검토 후보**이며, 원본 백업은 보존했다. 사용자의 지적 이후 새 맵 수정·추가 Play 실행·임의 원복은 하지 않았다.

### 반입 완료

`IMPORT.txt`와 `IMPORT_AUDIT.md`에서 32개 Unity 프리팹 반입을 확인했다. 원본 내장 2K 이미지는 보존하고 Unity 사용 텍스처는 최대 1024로 제한했다. 32개 모델의 양쪽 2분할 미리보기 64장을 저장했다. 배치 후보는 건축 부품 13종 78개 및 구역 소품 18종이다. T10 붕괴 벽은 기존 폐허 통로를 메울 우려가 있어 반입만 하고 배치에서 제외한다.

### 1차 후보 — 불합격, 저장하지 않음

`attempt_01/VALIDATION.txt`: 1378 PASS / 32 FAIL. `failed_01_<ID>.png`와 실패 후보 씬을 보존하고 원래 저장 씬을 다시 열었다. 원본 씬·프리팹 해시가 BASELINE과 동일함을 별도로 확인했다.

- 새 파사드의 일부가 실제 출입 경로와 겹침: 실제 열린 문을 추가 탐지하여 제작 코드를 보정한다. 충돌체가 없어 이동 가능하더라도 시각적 관통은 통과로 보지 않는다.
- W01/E08 외형 메시 중복: 건물별 차이를 보완한다.
- 소품 12개 감사 값은 회전된 모델의 로컬 크기를 세계축 AABB와 비교한 좌표계 불일치. 배치 위치를 임의 변경하거나 허용 오차를 넓히지 않고 감사 값의 좌표계를 맞춘다.
- 스폰 검사 1개는 검사식 오류: 기존 맵 배열에 B+R 12개를 보존하고 실제 출격 후보를 B 4개로 제한하는 구조인데, 배열 자체가 B만 포함해야 한다고 잘못 검사했다. 원본 스폰 서명은 이미 일치했다. R 비활성 정책을 유지한 채 배열 순서 및 실제 선택 스폰을 검사하도록 수정한다.
- 메인이 CLINIC/POWER/TOOLS/N17/S07/HALL 후보 이미지를 직접 확인했다. 서로 다른 지붕 실루엣은 생겼으나 넓은 외벽·지붕의 단색 재질이 지나치게 단순해 기존 낡은 표면 텍스처를 활용하도록 제작 담당에 보완 요청했다.

### 2차 후보 — 측정 준비 오류로 중단

`attempt_02/ERROR.txt`: 실제 문 목록을 재측정하는 코드에 임시 NavMesh 생성이 누락되어 N01 문을 찾지 못했다. 실제 문 삭제나 막힘의 증거가 아니라 측정 준비 오류이며, 건축 생성 전에 중단했다. 기존 씬은 그대로 유지했다. 임시 탐색 데이터 생성·정리를 추가하고, 폐허 지붕의 겹친 상부 조각 높이도 보정한 뒤 3차 후보를 실행한다.

실패 후보의 PNG와 검증 로그는 당시 상태의 증빙이다. 후보 씬이 참조하는 D08 생성 메시·재질은 재시도 때 갱신될 수 있으므로 실패 후보 `.unity` 자체를 불변의 완전한 버전 스냅샷으로 간주하지 않는다.
