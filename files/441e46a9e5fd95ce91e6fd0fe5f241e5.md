# 개별 화면 스타일 패치 계획

상태: **메인의 before_r02 34개 캡처 확인 후 9개 담당 Runtime 파일에 표시 코드 패치 적용.** 독립 문법·수정 범위 검사 PASS. 전체 컴파일과 실제 after 화면 검증은 통합 담당 메인 진행 후 기록한다.

실제 적용 내역은 `PRESENTATION_PATCH_RECORD.md`, 원본/결과 SHA 및 메서드별 검사는 `presentation-patch-manifest.json`을 기준으로 확인한다. 아래 표와 실행 순서는 최초 계획이며 실제 적용 완료 주장으로 사용하지 않는다.

## 주의할 실제 코드 위치

- TacticalMapView의 Panel/FlatButton/마커 라벨/목적지·북쪽 배지에는 사각 Fill과 Outline이 있다. 이 UI 배경이 우선 대상이다.
- 같은 파일의 viewport Ink, grid선, 축 좌표·지도 이미지·화살표 회전·마커 좌표 및 Outline이 지도 영역을 표시하는 경우는 유지한다.
- CutsceneDirector의 dialogue/portrait/speaker background는 바꾸되 전면 dim/전체 폭 letterbox는 둥글릴 대상이 아니다.
- SessionGrowthView의 재료 목록은 기존 unpadded28px ResearchRecipeStyle을 보존한다. 과거 표시 누락을 다시 만들지 않는다.
- SessionGlassView 로비에는 portrait 회전 drag와 pointer capture가 있으므로 표시 영역을 옮길 경우 같은 hit rect를 사용해야 한다. 기본 계획은 배치 보존이다.
- 실제 DrawShop/DrawDeparture/DrawSave는 SessionTestWorld.cs에 존재한다. 해당 본문 외의 gameplay/save 메서드는 수정하지 않는다.

## 실행 순서

1. 메인의 before 캡처 완료 신호와 UiTheme helper 구현 확인.
2. 최신 UiTheme를 다시 읽어 실제 색 토큰과 helper 이름·단위를 확인.
3. 각 파일별 표시 코드만 작은 단위로 패치. 다른 담당자 파일은 수정하지 않음.
4. diff에서 표시 코드 밖 변화, save/gameplay callback 변화와 신규상수/기능 변경이 없는지 점검.
5. 기존 환경의 컴파일/진단 실행은 메인과 조율. 플레이 모드·앱을 독자적으로 끄거나 재시작하지 않음.
6. 메인이 동일 화면의 after를 확보하면 독립 시각 QA: 큰 패널/카드/캡슐 일관성, 글자·긴 오류/재료 목록 잘림, 버튼 disabled/selected, 지도/대사 동작의 기존 표현 보존.
7. 화면을 확인하지 못한 상태·조명·해상도는 미검증으로 기록한다. before 확보가 안 된 대상은 재구성 전 이미지로 위장하지 않는다.

## 완료 기준

코너·명암·폰트·배치·실제 문구의 일관성을 맞추고 기존 기능 동작을 유지한다. 컴파일/적절한 실제 화면 증빙/파일별 diff 검토 후 메인이 통합 완료를 판단한다. 이번 계획 문서를 실제 구현 완료 증빙으로 쓰지 않는다.
