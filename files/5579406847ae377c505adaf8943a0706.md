# Surface Ivy tool integration contract

Unity 6000.1.0f1 / URP17. The source lives in staging first. No Assets import or Unity operation until the current editor owner explicitly returns control. Main owns integration and real captures. All source edits use apply_patch.

## Ownership

- core agent: staging/core/SurfaceIvyGenerator.cs only. Editor-only deterministic mesh-surface sampling/growth/branch/mesh generation, no scene mutations or material creation. Namespace Escape.EditorTools.Ivy.
- authoring agent: staging/authoring/SurfaceIvyInstance.cs (runtime data + bounded visibility follower), SurfaceIvyWindow.cs (Editor UI/persistence/Undo), optional SurfaceIvyLeaf.shader only. No existing project files.
- validation agent: staging/validation/SurfaceIvyValidation.cs and independent review notes only. No production mutation. Main runs the harness.
- main: contract, validation orchestration/capture helper, records, imports/integration, target selection and final art judgement.

## Shared API

Runtime namespace Escape.SurfaceIvy, file SurfaceIvyInstance.cs (the original proposal Escape.Environment.Ivy was renamed during integration to avoid shadowing System.Environment in existing project code):

- [Serializable] public sealed class SurfaceIvySettings with public fields: int seed=731, roots=12, steps=65, maxBranches=24, maxLeaves=1800; float stepLength=.14f, maxProjectionDistance=.35f, surfaceOffset=.025f, stemRadius=.012f, leafSize=.13f, leafSpacing=.10f, upwardBias=.65f, branching=.06f, spread=.55f; bool includeRoof=true. Clone() returns independent data. Settings are in world metres; seed points and exclusions are local to target. Public static preset methods Vehicle(), Wall(), Roof() return different finite settings. Clamp()/Sanitize() may be added but notify other agents.
- [Serializable] public sealed class IvyExclusionBox: public Vector3 center,size; public Vector3 rotation; values local to target; pure bool Contains(Vector3 targetLocalPoint,float margin=0) with margin in local units; no live colliders required.
- [DisallowMultipleComponent] SurfaceIvyInstance : MonoBehaviour with public Transform sourceTarget; public SurfaceIvySettings settings; public List<Vector3> seedPointsLocal; public List<IvyExclusionBox> exclusions; public Material stemMaterial,leafMaterial; public Mesh customLeafMesh (optional); public Renderer[] sourceRenderers. It belongs to generated root only. No automatic growth in Awake/Update. Visibility follower may mirror known source-renderer enabled/cutaway state only; no map-wide renderer scans per frame and no gameplay colliders/scripts injected into target. Never treat mixed transparent glass as an opaque grow surface by default.

Editor generator namespace Escape.EditorTools.Ivy, file SurfaceIvyGenerator.cs:

- public sealed class SurfaceIvyBuildResult : IDisposable: public Mesh stems,leaves; public List<Vector3> attachmentPointsLocal; public int sourceTriangles,paths,segments,leafCount,excludedSamples; public string summary; public Bounds targetWorldBounds. Dispose destroys owned unsaved meshes only. Add diagnostic path list as needed without breaking API.
- public static class SurfaceIvyGenerator, public static SurfaceIvyBuildResult Build(GameObject target, SurfaceIvySettings settings, IList<Vector3> seedPointsLocal=null, IList<IvyExclusionBox> exclusions=null, Mesh customLeafMesh=null).
- Pure editor build: return meshes in target-local coordinates; do not attach/modify/create objects on target. Read only visible MeshFilter/MeshRenderer geometry (support non-readable imported static meshes using MeshUtility.AcquireReadOnlyMeshData; do not change importer flags). Ignore own generated ivy and transparent glass/particles. Report unsupported/skipped renderers. No scene Physics/global query dependence; accelerated triangle nearest/raycast surface analysis preferred, all temporary data disposed. Growth must follow surface with finite gap/corner rules; no bbox-only wrap or branches across doors/empty holes. Deterministic seed. No changes to UnityEngine.Random state. Finite triangle/step/leaf/branch limits, cancellation. Nonuniform scale geometry works in world space and returns target local. Optional custom leaf mesh keeps its UV; default leaves should have pointed/heart-lobed silhouette and folded centre ridge rather than rectangles.

## Authoring workflow

Menu Escape/Environment/Surface Ivy Tool (Korean labels welcome). Select scene object or prefab asset; presets car/wall/roof; density/length/seed/spread and surface clearance; optional local seed and exclusion boxes; explicit Preview/Regenerate, Bake, Clear-owned-preview. Never delete unrelated children or overwrite source prefab/material/importer. Prefab input makes a separate editable working copy; no recursive regeneration over earlier generated geometry. Result is a child root, stems/leaves combined mesh with shared materials, no colliders. Persistent Bake creates unique new assets under Assets/Escape/Art/SurfaceIvy/Generated and reconnects meshes, supports save/reload. Source geometry/material references/transform/colliders remain exact. Undo/Redo and clear only tool-owned objects/assets. A preview does not save the current user's scene or source prefab.

Use actual geometry for stems/leaf clusters, material tint is not a substitute for growth. Reuse compatible existing texture/material assets without editing originals; full alpha-clip/PBR compatibility to be inspected. Custom leaf mesh/material can be supplied later. Plan a strong recognisable vine silhouette in top-view, not uniform green blanket.

## Validation and demo

Independent meaningful checks: deterministic output, target hash/transform/material/collider unchanged, non-readable real wreck asset, rotated/nonuniform scale, convex corner/body following, exclusion box window/door clear, no attachment in empty hole, differing seed/density produce changed output within budgets, repeated generation doesn't accumulate, cancellation cleanup, baked save/reload references and persisted prefab copies. Renderer/collider/shadow/cutaway state observed separately. No FPS claim from triangle count. Actual before/after same-camera render of real vehicle and representative structure/building; new source tool UI before/after evidence. Avoid giant map mutation or paid asset generation. Initial production-map pilot only after explicit main integration and current shared editor handoff; otherwise saved isolated demos are the first reviewable result.
