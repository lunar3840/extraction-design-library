## 사용자 지시 및 의도

- 반투명 편집기 배경의 검은 줄을 제거한다.
- 파일이 없는 다른 PC에서도 웹으로 열람하도록 배포하고, ‘MD 파일 (지침 파일)’ 채팅과 조율하여 상단 ‘기획 라이브러리 / 데이터 편집기’ 탭으로 오간다.
- 포트폴리오 방문자는 열람만 가능하고 특정 비밀번호를 확인한 소유자만 수정하도록 한다.
- 웹에서 명시적인 반영 버튼을 누르면 Unity 프로젝트의 실제 수치에 적용되도록 연결한다.
- 공개 범위를 질문했으며 사용자가 **‘기획 라이브러리 원문·스크린샷도 함께 공개’**를 직접 선택했다. 담당 채팅에 이 선택을 전달하여 공개 전환과 배포를 조율했다.

## 변경 전 상태와 문제

`before_editor.png`는 실제 수정 전의 1280×720 로컬 편집기 화면이다. 배경에 수직의 어두운 줄이 있고, `127.0.0.1:8890`과 원본 프로젝트가 있는 PC에서만 작동했다. 공개 열람/편집 권한과 웹에서 원본 프로젝트로 변경을 전달하는 기능이 없었다.

## 실제 변경 및 방법

1. 기존 반투명 패널·민트색과 글꼴은 유지하고 배경의 90도 줄무늬 그라디언트를 제거했다.
2. 별도 Sites Worker와 D1 저장소를 배포했다. 게임 자료는 실제 프로젝트에서 재수집하며, 파일이 없는 방문자에게 게시 카탈로그를 제공한다. 서버 저장본은 다른 PC에서도 열람할 수 있다.
3. 화면은 기본 공개 열람 모드다. 비밀번호 검증, 세션과 CSRF 확인을 서버에서 수행한다. 로그인 시도 제한, 로그아웃·비밀번호 변경 시 이전 세션 무효화, 수정 가능한 항목과 값 형식 검사를 추가했다. 초기 비밀번호와 연결 토큰은 게시 소스에 넣지 않았다.
4. 반영 버튼은 인증된 요청을 서버 대기열에 넣는다. 프로젝트 PC의 사용자 계정 전용 연결 도구가 외부 HTTPS 통신으로 요청을 가져와 정확한 원본 지문·개별 값·프로젝트를 검사하고 백업 후 적용한다. 다시 수집한 값이 요청과 일치할 때만 웹 기준을 갱신하고 완료로 표시한다.
5. PC가 꺼져 있으면 대기한다. 처리 중 추가 저장은 막고, 원본 충돌·실패·통신 중단·중복 요청·재시작을 구분한다. 완료는 프로젝트 파일 반영이며 Unity 에셋 재로딩·코드 컴파일과 실행 상태 갱신은 별도임을 화면에 표시한다.
6. 연결 설정은 `%LOCALAPPDATA%/ExtractionDataEditor/connection.dpapi`에 현재 Windows 계정 전용으로 암호화했다. 설정 폴더는 현재 사용자만 접근하도록 제한했다. 연결 토큰은 웹 편집 비밀번호와 분리했다. 현재 프로젝트 PC의 숨김 실행 및 heartbeat를 확인했다.
7. 기획 라이브러리 담당 채팅이 기존 Site·자료 저장소·배포를 소유하고, 이 채팅은 편집기·연결 도구를 소유하여 병렬 수정 충돌을 피했다. 두 실제 웹 사이트의 상단 탭 왕복을 확인했다. 라이브러리 이미지의 순차 업로드는 담당 채팅에서 계속 진행한다.
