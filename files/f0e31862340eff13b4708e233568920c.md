# 인벤토리 영역 교환 및 전리품 교환

## 사용자 지시와 기획 의도

- 큰 아이템을 같은 크기의 영역에 드롭했을 때, 그 영역에 완전히 들어온 작은 아이템들을 한 묶음으로 원래 자리와 교환한다.
- 예: 3×3 방탄복 ↔ 1×2 + 2×3 아이템. 작은 아이템들의 상대 위치와 회전은 그대로 유지한다.
- 대상 아이템 중 하나라도 드롭 영역의 경계를 넘으면 전체 교환을 거부한다. 주변 아이템을 자동으로 밀어내거나 재정렬하지 않는다.
- 작업 도중 추가 지시: 플레이어 가방 내부뿐 아니라 전리품 파밍에도 적용한다. 전리품 창 ↔ 가방 양방향 드래그에 같은 교환 규칙을 연결했다.

목적은 사용자가 작은 물품을 하나씩 비워 놓지 않아도 명확한 직사각형 영역을 맞바꾸어 정리할 수 있도록 하는 것이다. 대상 영역에 빈 칸이 있더라도 허용한다. 사용자 예시인 1×2 + 2×3은 8칸으로, 3×3 영역의 1칸은 비어 있기 때문이다.

## 변경 전 상태와 증빙

- `InventoryGrid.PlanMove`는 충돌 대상이 하나일 때만 교환하고, 여러 아이템과 겹치면 무조건 거부했다.
- 전리품의 지정 위치 가져오기/넣기는 합치기 또는 빈 공간 이동만 가능했다.
- 수정 전 원본 4개 파일을 `before_source/`에 복사했다. 변경 전 게임 화면 `before_field.png`도 저장했다.
- 실제 변경 전 코어를 보존한 별도 Unity 검증 프로젝트에서 같은 3×3 / 1×2 / 2×3 사례를 실행해 변경 전 화면을 촬영했다. 이후 전리품 요구가 추가되었을 때에는 아직 수정하지 않은 전리품 코드를 사용해 추가 전 화면을 촬영했다. 초기 격자 화면은 전후 비교 배율을 맞추기 위해 보존된 변경 전 코드로 다시 촬영했다.
- 별도 검증 환경의 변경 전 `InventoryGrid.cs`, `LootState.cs`는 원본과 SHA256이 같음을 확인했다. 사후 상태를 전 이미지로 사용하지 않았다.

## 실제 변경과 구현 방식

### 동일 인벤토리 내부

- 드롭 사각형과 충돌하는 모든 아이템을 수집하고, 각 아이템의 전체 직사각형이 안에 들어오는지 검사한다.
- 원래 공간과 드롭 영역의 가로·세로 크기가 같아야 한다. 비정사각형 물품을 회전하여 가로·세로가 바뀌는 경우에는 먼저 빈 공간으로 옮겨야 한다. 빈 공간 이동 시 회전은 기존대로 가능하다.
- 각 작은 물품을 `원래 영역 시작점 + 대상 영역 안에서의 상대 위치`로 이동한다. 페이지, 회전, 빈 칸, 개별 물품 ID와 수량을 보존한다.
- 모든 최종 위치를 별도로 검사한 뒤 한 번에 적용한다. 원래 영역과 드롭 영역이 일부 겹치더라도 최종 물품끼리 겹치지 않을 때만 허용한다.
- 기존 수량 합치기·분할·장비 교체·자동 정리 경로는 유지했다. 드래그 미리보기에는 ‘영역 교환’으로 표시한다.

### 전리품 ↔ 가방

- `PreviewTakeAt` / `TakeAt`과 `PreviewDepositAt` / `DepositAt`에 양방향 영역 교환을 연결했다. 기존 UI 드래그에서 이 함수들을 이미 사용하므로 파밍 창에서도 동작한다.
- 작은 물품 그룹을 원래 큰 물품이 있던 반대쪽 영역으로 돌려보내며 상대 배치를 유지한다.
- 동일한 전체 교환 절차를 분리된 복사본으로 먼저 실행하여 물리 공간, 항목 수, 수량, 회전과 양쪽 반환 위치를 검증한다.
- 실제 교환은 개별 무기·방어구·의료품 객체를 그대로 이동하며, 중간 단계의 변경 알림을 억제한다. 양쪽 소유권과 위치가 모두 완성된 뒤 가방과 전리품에 한 번씩 알린다.
- 경계에 걸친 물품, 수색이 끝나지 않은 물품, 양쪽 수납 불가 조건은 교환을 막는다. 수색 진행 시간 자체는 기존 `Advance` 동작을 그대로 사용한다.
- Shift 빠른 이동에는 교환을 적용하지 않았다. 빠른 이동은 기존처럼 합치기·빈 공간 이동만 하며, 의도하지 않은 역방향 교환이 일어나지 않는다.

### 안전상 유지한 제한

- 부분 수량 드래그는 전체 영역 교환을 하지 않는다. 기존 합치기·분할 이동을 사용한다.
- 하나의 전리품 표시가 실제로 여러 스택을 합쳐 보여 주는 경우에는 그대로 그룹 교환하지 않는다. 예: 최대 50발인 탄약이 한 전리품 항목에 95발로 표시되는 경우. 같은 칸에 두 실제 스택을 겹쳐 반환하거나 임의로 재배치하지 않도록 분리 이동/빈 공간 이동을 요구한다. 일반 95발 파밍은 기존대로 지원한다.
- 기존 전리품/가방의 논리 항목 보유 한도를 늘리지는 않았다. 반환할 작은 물품 수를 담을 항목 공간이 부족하면 전체를 보존하고 거부한다.
- 창고 ↔ 가방의 교차 컨테이너 교환이나 전리품 내부 재배치까지 새로 확장하지 않았다. 가방 내부, 동일 창고 내부/페이지 간, 전리품 ↔ 가방이 이번 적용 범위다.

## 검증 결과

최종 Unity 컴파일, 규칙 검사와 Windows 개발 빌드 성공. 최종 검사/빌드 프로세스 종료 코드는 0이다.

- `EscapeInventoryRegionSwapChecks.txt`: 신규 검사 52개 PASS.
- 3×3 ↔ 1×2 + 2×3, 빈 칸 보존, 꽉 찬 격자, 9개 소형 물품 그룹, 상대 위치, 회전, 페이지 간 교환 통과.
- 네 방향 경계 초과, 일부만 포함된 큰 아이템, 최종 겹침, 격자 초과를 검사했다. 거부 시 JSON이 동일하고 변경 알림이 없는 것을 확인했다.
- 가방과 창고의 저장 실패 시 그룹 전체 원상태 유지, 성공 저장·재로드 시 동일 배치 확인.
- 전리품 ↔ 가방 양방향, 수색 잠금, 항목 수 부족, 부분 수량, 다중 스택 안전 거부 및 기존 대량 파밍을 확인했다.
- 실제 등록된 무기·방어구·의료품으로 개별 객체, 탄창, 발사 대기시간, 내구도, 의료 횟수, 보호 표시를 확인했다. 교환 중간 소유권을 관찰자에게 노출하지 않는 검사도 통과했다.
- 2,000회 결정적 조작을 독립 직사각형 계산과 대조했다. 허용 541회, 영역 교환 36회. 모든 결과·거부·경계·겹침 검사 일치.
- 기존 인벤토리, 장비, 전리품, 저장/사망, 기지, 테트리스 격자/이전, 무기, 신체/의료 회귀 검사 통과: `after_final_rules_results.txt`의 9개 검사 묶음 PASS.
- 실제 Play Mode UI 검사 101개 PASS: `EscapeGlassLayoutChecks.txt`, `after_ui_rules.log`. UI 검사 프로세스 종료 코드 0.
- 총 10개 `Escape*Checks.txt` 보고서에 563개 PASS가 있다. 2,000회 조작은 요약 검사 1개로 집계한 수치다.
- 네이티브 실행 결과 `after_fixture_result.txt`에서 `contained=True`, `crossingRejected=True`, `after_loot_fixture_result.txt`에서 `deposited=1` 확인. 전후 PNG를 직접 열어 정상 교환과 경계 거부를 확인했다.

주 Unity는 다른 대화의 맵 작업과 사용 순서를 조율하여 Play를 종료했다. 이후 주 Unity의 씬·카메라·Play 모드는 제어하지 않았다. 이번 완료 후 화면 검증은 독립 환경에서 수행했다. 기존 씬/모델/맵/밸런스/저장 파일은 이 작업에서 수정하지 않았다. 실제 사용자 저장 데이터 대신 분리된 검사 데이터 및 기존 백업의 복사본만 사용했다.

## 검증 도중 환경 처리

- 재사용한 격리 검증 프로젝트의 패키지 캐시에 메타 파일이 빠져 최초 빌드가 실패했다. 원본의 패키지 캐시를 격리 환경에 복사하여 복구한 뒤 컴파일·검사·빌드가 통과했다. 원본 패키지 설정은 변경하지 않았다.
- 숨김 실행의 최초 화면 캡처는 검게 나와 증빙으로 채택하지 않았다. 별도 검증 실행 창을 표시하여 다시 촬영한 정상 PNG로 교체하고 직접 확인했다.
- 기존 Unity/NavMesh 폐기 예정 API 및 패키지/환경 경고는 별개로 남아 있다. 최종 변경 코드의 컴파일 오류 및 검증 실행의 예외는 없다.
