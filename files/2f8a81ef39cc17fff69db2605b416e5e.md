# DMZ 참고 인벤토리 아이템 hover 정보 카드

## 사용자 지시와 적용 범위

- 첨부된 DMZ 인벤토리 화면처럼 마우스를 아이템에 올리면 티어와 짧은 정보를 읽을 수 있는 반투명 카드를 제작한다.
- 참조 범위는 정보 우선순위, 반투명 바탕과 명암, 간결한 조작 안내다. DMZ의 티어명·가격·판매·핑 규칙을 이 게임에 가져오지 않았다.
- 실제 게임의 판매가 기준 가치 V1~V6와 탄약 관통 T1~T6를 구분한다. 기존 클릭 상세/무기 비교 기능은 유지한다.
- 실제 Unity 프로젝트: `C:/UnityProject/escape`. UI는 현재 IMGUI이며 uGUI/UI Toolkit 전환은 이번 작업 범위가 아니다.

## 변경 전 상태와 증빙

- 인벤토리 슬롯을 클릭해야 상세창이 열리며, 마우스를 올렸을 때의 간결한 정보 카드는 없었다.
- 수정 전 원본 슬롯/장비/전리품 연결 파일 5개를 `source_before/`에 복사하고 `manifest.json`에 SHA256을 저장했다.
- 실제 InventoryTest 씬에서 변경 전 화면을 저장했다. 재구성 이미지가 아니다.
- 자동 키 입력으로 I키 토글이 재현되지 않아, Editor 전용 `Show Test Inventory` 메뉴로 기존 `Controller.Player.State.InventoryOpen` 상태만 열었다. 런타임 입력 코드, 씬 에셋, 아이템 데이터, 저장 프로필은 바꾸지 않았다.
- 원본 캡처는 `before_inventory_hover.jpg`, `before_test_hud.jpg`다. 같은 픽셀을 PNG 형식으로 다시 저장한 `before_inventory_hover.png`, `before_test_hud.png`도 보관했다. 화면 내용이나 가독성을 후처리하지 않았다.
- 실제 비교 화면은 InventoryTest, Game뷰 16:9, 표시영역 x120~1466 / y132~885, 첫 가방 아이템 중심 마우스 위치 약 x189 / y591이다. helper의 렌더 해상도 좌표는 Editor 게임뷰 표시 배율과 다르므로 실제 관측 좌표를 사용한다.

## 기획 의도와 실제 변경

- 304 논리 픽셀 폭, 18px 라운드, 짙은 흑연색 80% 불투명 바탕과 약한 외곽선/그림자로 읽기 쉬운 정보 카드를 구성했다.
- 기존 티어색을 부드럽게 섞어 상단 3px 선과 작은 가치 V 배지에만 사용한다. 본문은 흰색과 약한 그림자로 표시한다.
- 이름 최대 2줄, 실제 아이콘 76px, 종류, 수량, 개당 무게, 판매가, 관련 상태 1행, 설명 최대 2줄과 실제 가능한 조작 안내 1행을 표시한다.
- 무기에는 장착 부품 가치가 별도로 더해질 수 있으므로 금액을 `기본 판매가`로 명시했다. 가치 V 산정은 기존 개당 기본 판매가 기준을 유지한다.
- 가방의 실제 인스턴스에는 탄약 관통 T, 의료품 남은 용량/횟수, 유효 탄창 용량, 방어구 내구도 등 관련 정보만 표시한다.
- 퀵슬롯은 아이템 ID에 연결된 묶음이며 실제 의료품 사용 시 다른 인스턴스를 선택할 수 있다. 따라서 총 보유 수량만 보여주고 특정 부분 사용품의 잔량은 생략한다.
- 가방/보관함 공용 그리드, 장착 무기·방어구, 인벤토리 퀵슬롯과 수색 완료한 전리품에 hover를 연결했다.
- 전리품은 수색 완료 분기에서만 등록하고 표시 시 현재 컨테이너·페이지·검색 상태·인스턴스를 재확인한다.
- 원본 상태를 매 표시 시 재조회한다. 드래그가 시작되기 전 누름 캡처부터 숨기고, 인벤토리 닫힘·숨김·상세창 열림·동료 선택창·사망·메뉴 잠금·맵 입력 점유 상태에서도 숨긴다. 상세창이 열려 있으면 포인터 위치와 관계없이 hover 카드 전체를 숨겨 중복 정보를 방지한다.
- 커서 옆 18px 간격으로 배치하고, 우측/하단에서 좌측/상단으로 반전하며 16px 안전 여백 안에 고정한다. 스크롤 내부 아이템은 보이는 교집합만 hover 대상으로 등록한다.
- 별도 Repaint 전용 오버레이이며 버튼, 컨트롤 ID, 이벤트 소비 없이 그린다. 실제 클릭·드래그·빠른 이동 처리 코드는 유지한다.

## 검증

- Unity가 사용하는 C# 컴파일 응답을 기록 폴더로 복사하고 출력 경로만 분리해 런타임 및 Editor 전체 소스를 컴파일했다. 실제 Unity 빌드 산출물을 덮어쓰거나 Unity를 재시작하지 않았다.
- 최종 외부 컴파일: runtime exit 0 / Editor exit 0. 기존 다른 코드의 warning 21 / 35개, 이번 변경 관련 컴파일 오류 없음. 로그는 `compile/runtime_compile.txt`, `compile/editor_compile.txt`다.
- 실제 컴파일된 런타임 DLL을 별도 .NET 검사 프로세스에서 호출해 화면 모서리/작은 화면/포인터 간격/스크롤 교집합/기존 가치 V 경계 계약 검사 25개가 모두 PASS했다. Unity를 실행하거나 종료하지 않았다. 결과는 `compile/contract_checks.txt`다.
- 앱을 종료하지 않는 `Escape > Inventory > Hover Tooltip > Run Hover Tooltip Checks` 메뉴를 제공한다. 모서리/작은 화면 배치, 스크롤 잘림, 기존 V 경계, 실제 카탈로그의 탄약 T·의료 용량/횟수·무기 유효 탄창을 확인한다.
- 실제 Unity Editor에서 해당 메뉴를 실행했고 **33개 PASS**를 확인했다. 결과 파일은 `editor_hover_checks.txt`다. 이는 앞의 별도 DLL 계약 검사 25개와 구별되는 실제 카탈로그 검사다.
- 독립 정적 리뷰에서 입력 이벤트 소비·미수색 전리품 노출·반복문 클로저 오류는 발견되지 않았다. 발견된 무기 판매가 문구 및 퀵슬롯 개별 잔량 혼동을 수정했다.
- 첫 실제 hover 확인에서 카드 상단이 가방 패널 뒤로 가려지는 그리기 순서 문제가 발견되었다. 증빙은 `observed_tooltip_layering.jpg`다. 부분적으로 카드가 보였다는 이유로 시각 검증을 통과 처리하지 않았다.
- Repaint에서만 지정하던 GUI depth를 오버레이의 모든 GUI 이벤트 시작에서 지정하도록 수정했다. 기존 동료 칩 오버레이와 같은 순서이며, 오버레이의 기본 스크립트 실행 순서도 10000으로 지정했다. 카드는 여전히 Repaint에서만 그리며 입력 이벤트는 소비하지 않는다.
- 그리기 순서 수정 후 실제 Unity Play 화면에서 카드 전체가 가방 위에 표시되는 것을 확인했다. `after_inventory_hover.png`, `after_medical_hover.png`에 상단 배지·이름·이미지·가격·설명이 가려지지 않는 정상 카드를 저장했다.
- 야전 응급키트는 실제 데이터대로 가치 V2, 300 블랭크, 0.8kg, 남은 용량 120/120으로 표시되는 것을 확인했다.
- 실제 클릭 상세창 열림과 드래그 이동을 검증했고 기존 기능이 유지되는 것을 확인했다. `after_drag_move.png`는 야전 응급키트가 1행 6열에서 3행 6열로 이동하고 `1개 이동` 결과가 표시된 **최종 상세창 숨김 가드 적용 전** 중간 검증이다. 이 시점에는 상세창과 hover가 중복되는 문제가 있었다. `after_click_details.png`는 포인터가 상세창 안에 있을 때 hover가 숨는 기존 동작을 확인한 중간 검증이며, 해당 이미지에 중복 카드가 보이는 것은 아니다.
- 중복 표시를 없애기 위해 최종 `CanShowItemHover`에 `!DetailsVisible` 가드를 추가했다. 기존 클릭·드래그 처리에는 손대지 않았다. 최종 가드 적용 후 runtime/Editor 전체 재컴파일 오류 0을 확인했다.
- 최종 실제 Unity Play 검증 **PASS**: `after_final_inventory_hover.png`, `after_final_medical_hover.png`에서 전체 카드와 V 배지·이름·이미지·가격·잔량·설명을 읽을 수 있다. `after_final_details_suppressed.png`는 포인터가 야전 응급키트 슬롯에 남아 있고 상세창이 열린 상태에서 hover가 전역으로 숨는 것을 확인한 화면이다. `after_final_drag_move.png`는 같은 실제 드래그 이동 성공(1행 6열→3행 6열, 1개 이동) 뒤 상세창만 열리고 hover가 겹치지 않는 화면이다.
- 코드에는 V1~V6 표시와 기존 경계값을 모두 유지했고 계약 검사로 경계값을 확인했다. 실제 화면의 색/배지 확인은 V1 탄약과 V2 의료키트까지이며 V3~V6의 개별 실제 화면, 보관함/장착품/퀵슬롯/미수색 전리품 조합의 별도 실기 화면은 이번 캡처에 포함되지 않는다. 해당 연결·노출 가드는 컴파일 및 독립 정적 검토로 확인했다.
- before/after의 첫 소총탄 수량과 가방 무게는 동일하지 않다. 실제 테스트 중 자동 장전이 발생해 첫 탄약 묶음이 50개에서 20개로, 가방 표시 중량이 24.4kg에서 23.8kg으로 변했다. 아이템 데이터를 수정하거나 캡처를 조작한 결과가 아니며 실제 캡처 차이를 보존했다.
- 모든 JPG 캡처 원본을 유지하며 같은 크기(1587×910) PNG 사본으로 재저장했다. 리사이즈·화면 편집·보정은 하지 않았다.
- 최종 Play 정지 후 원래 작업 씬 `StageA_Relay_Blockout_v08`을 복원했다. 메인이 실제 창 제목·Hierarchy, 별표 없음, Play 비활성, 정상 Editor 레이아웃을 확인했고 `after_restored_work_scene.png`에 기록했다. 앱을 닫거나 재시작하지 않았다.
- `CODE_STATE.json`에 최종 소스 SHA256, 구현 V1~V6와 화면 확인 V1/V2의 구별, 검사 33+25, 최종 실제 증빙, 남은 검증 범위와 씬 복원 상태를 저장했다. 기록된 소스 8개와 실제 파일의 해시가 모두 일치한다.
- 독립 시각 QA의 `runtime_visual_audit.md`를 전문 확인했다. 제공된 최종 4개 이미지 범위에서 가독성·가림 해결·상세창 중복 억제·드래그 후 상태가 PASS이며 필수 추가 수정 권고는 없다. QA 담당자는 이미지만 검토했고 실제 클릭/드래그는 메인이 수행했다.
