# 방어구 실제 모델 썸네일 — 팔꿈치·무릎 범위와 끈 제외

## 사용자 지시와 의도

[SOURCE_REQUEST.md](SOURCE_REQUEST.md)에 최초 요청과 같은 작업 중의 범위 축소·끈 제거 지시를 보존했다. 실제 방어구를 알아보기 쉽게 보여 주면서 지속적인 모델 렌더 비용을 추가하지 않는다. 기존 무기 모델 썸네일 주제의 후속 회차다. S4 지급·착용 외형 변경 회차와는 별도이며, 같은 작업 중의 조정을 독립 구현 완료 횟수로 부풀리지 않는다.

## 변경 전

공통 GlassIcons는 아이템별 PNG가 없으면 노란 헬멧/조끼 도형을 표시했다. 현재 플레이어 방어구 중 아이템별 실물 모델 연결이 존재하는 것은 TEST_EDEL_S4_MAINTENANCE다. 아직 모델을 지정하지 않은 다른 방어구에 S4나 NPC 공통 외형을 임의 배정하지 않았다.

before_inventory.png와 before_samples.png는 변경 전 실제 공통 인벤토리/아이콘 경로를 실행해 확보했다. 검증은 별도 프로필·빈 임시 장면에서 수행했으며 일반 플레이 세이브를 바꾸지 않았다. 표시 도구 화면에는 전체 게임 화면이 아닌 공통 아이콘 검증임을 명시했다.

## 실제 변경

- Editor의 ArmorItemThumbnailBaker가 원래 S4 의상 메시·재질만 읽어 render-only 사본을 촬영한다. 플레이어, Animator, 머리 물리, 게임플레이 컴포넌트는 생성하지 않는다.
- 원래 캐릭터의 팔꿈치/무릎 위치를 기준으로 촬영용 메시를 자른다. 새 경계의 UV·법선·접선은 보간하며 원본 의상 메시와 착용 모델은 수정하지 않는다. 장갑·신발은 썸네일에 포함하지 않는다.
- 소매 tripo_part_17에 연결된 긴 대각선 끈의 44개 삼각형만 촬영용 사본에서 제외했다. 검사한 소매 본체는 로컬 z .475 이상이고 끈 끝점은 .421~.433이다. 전체 소매를 숨기는 방식은 사용하지 않았다.
- 촬영 결과는 Resources/UI/ItemIcons/TEST_EDEL_S4_MAINTENANCE.png에 저장한다. 기존 GlassIcons의 1회 로드/캐시를 그대로 사용한다. 방어구 슬롯 회전을 허용하도록 런타임 코드 한 줄만 바꿨다.
- 모델을 교체하면 Escape > UI > Rebuild S4 armor item thumbnail 메뉴로 이미지를 다시 생성한다. 자동 실시간 모델 렌더나 자동 에셋 재생성 루프는 추가하지 않았다.

## 전신 시도와 후속 조정

최초 전신 결과 after_inventory.png / after_samples.png / S4_MODEL_THUMBNAIL.png는 폐기된 구도를 설명하기 위해 보존한다. before_crop_inventory.png / before_crop_samples.png는 그 시점 실제 캡처의 바이트 동일 사본이다. 변경 전으로 위장한 재구성본이 아니다.

팔꿈치·무릎 범위 결과 S4_MODEL_THUMBNAIL_CROPPED.png와 after_crop_inventory.png에는 아직 끈이 있다. 이들은 중간 결과이며 최종 대표 이미지로 쓰지 않는다. before_strap_thumbnail.png와 before_strap_samples.png는 끈 제거 직전의 실제 출력/공통 UI다. 최종 출력은 after_strap_thumbnail.png다.

## 검증 결과와 범위

- Unity 컴파일 후 실제 인벤토리 장착칸에서 도형 대신 S4 PNG가 표시됨을 확인했다. 전신 및 팔꿈치·무릎 범위 양쪽을 실제 화면에서 확인했다. 기본 조끼는 계속 기존 도형으로 표시한다.
- 공통 GlassIcons 표시 도구에서 정방향/90도 회전과 GUI 행렬 복원을 확인했다. 아이콘 표시 전후 Camera 5→5, Light 24→24였다. 이 수치는 해당 임시 검증 장면의 전체 개수이며 실제 게임 전체의 성능 측정은 아니다.
- Resources 로드가 동일 Texture를 재사용하며, 임포트 512×512, mip 1, readable false, 측정 메모리 525,120 bytes를 확인했다. 전신 이미지에 대한 런타임 측정이며, 같은 경로/임포트 설정의 최종 PNG 교체는 별도 프레임 시간 측정으로 포장하지 않는다.
- 최종 끈 제거는 Editor 실제 PNG 촬영·알파 경계·소매 보존으로 검증했다. 제거 후 별도 Play를 재실행하지 않았다. 렌더/캐시/회전 경로는 직전 실제 UI 검증과 동일하다.
- 최종 BAKE_REPORT.json: 43개 표시 메시, 출력 685×768 원본 PNG, 투명 픽셀 존재, 사방 알파 여백 확보. 고해상도 화면 배율을 고려해 실제 RenderTexture 전체를 읽으며, 게임용 임포트는 최대512로 제한한다.
- sourceUnchanged / sceneUnchanged / transientObjectsReleased 모두 true. PROTECTED_AFTER.json에서 GlassIcons의 의도한 한 줄 변경 외 무기 썸네일 코드·착용 외형 코드·Edel/Outfit 프리팹 보존을 대조했다.
- 초기 촬영의 일부 잘림은 Editor 화면 배율과 읽기 크기의 불일치였다. 실제 RenderTexture 전체 읽기로 해결했고, 메시 범위도 실제 꼭짓점으로 계산한다. 실패 출력과 진단 로그는 최종 결과와 구별해 보존했다.

## 공유 작업 복원·게시

성능 담당에게 받은 clean Edit 구간에서만 Unity를 사용했다. GamePerf53 도구/요청은 조작하지 않았다. 전용 ArmorIconReviewTemporary 코드·메타·요청은 기록 폴더에 회수했다. 원래 Relay 씬과 맵 프리팹 SHA는 제공된 체크포인트와 같다. 최종 컴파일/idle 확인 및 명시 반환 후 ready를 올리고 기존 주제에 게시한다. 현재 게시 대기이며 로컬 저장을 게시 완료라고 간주하지 않는다.


최종 정리 확인: checkpoint_return_native.jpg 및 UNITY_RETURN_CHECKPOINT.json에 native Play OFF / clean Relay / compile·import idle / 전용 요청·helper 회수와 scene·prefab SHA 보존을 기록했다. 성능 담당에 명시 반환했다. 기획 라이브러리는 기존 주제·11-03-01 예약 회차로 게시 요청하며 아직 pending이다.


## 실제 라이브러리 게시 확인

기존 10/20 실제모델 썸네일 주제에 2026-11-03-01 후속을 연결했다. 새 대표 주제는 만들지 않았고 이전 무기 기록의 제목·분류·원문·이미지는 유지했다. 이번 회차는 UI·UX / 인벤토리·툴팁 / 변경 결과이며, 문서13개·고유이미지9장·명시비교3쌍·최종대표1장을 실제 공개 브라우저에서 확인했다. 별도 S4 지급·착용 구현 회차와 합치지 않는다.

전신 폐기중간안과 팔꿈치·무릎 범위의 끈있는 중간안,사용자 확대 참조는 최종과 구별해 캡션/원문으로 보존한다. 메인 대표는 after_strap_thumbnail.png 한 장뿐이다. 비교는 최초 인벤토리/공통표시 UI의 전후(전신중간안)와 같은 Editor 촬영의 끈 제거 전후다. 문자열 허용목록은 publication_baseline에 원형을 보관하고 동일9파일에 역할/캡션만 부여했다. 추가이미지·게임파일을 임의 공개하지 않았다.

최종 PNG685×768/349484bytes의 SHA가 반환체크포인트와 일치하고,43표시메시·끈44삼각형제외·투명 픽셀/사방여백을 확인했다. 보호보고서의 비대상5개 불변/GlassIcons 변경1개,직전 실제UI의Texture재사용·회전행렬복원·카메라5→5/광원24→24·메모리525120bytes 및 clean Edit 반환보고를 대조했다. 원본 착용 모델과 무기 썸네일 경로는 보존했다는 당시 보고이며 게시담당은 Unity를 재실행하거나 현재 성능담당의 live 파일을 수정하지 않았다.

최종 끈 제거 후 Play 미재실행을 그대로 남겼다. 해당 최종 단계는 Editor PNG 검증이고,직전 범위축소/회전/캐시의 실제UI 검증과 구별한다. 지속 렌더가 아닌 수동 재촬영 PNG이며 전체 게임 성능 검증 완료로 확대하지 않는다. 실제 모델 미지정 방어구는 기존 대체표시를 유지한다.
