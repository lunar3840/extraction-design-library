# D08 독립 검증 기록

상태: **외형 콘셉트 재현 미달·요청 미완료**. 3차 후보는 편집 검증과 저장 후 재검증에서 각각 1,410 PASS / 0 FAIL이었지만, 사용자가 요청한 콘셉트 이미지의 핵심 건축 요소와 실제 화면 사이에 큰 차이가 있다. 따라서 구조 검증 PASS를 제작 완료나 콘셉트 재현 PASS로 해석하지 않는다. 사용자 이의 제기 뒤 추가 수정 및 실제 플레이 검증은 중단했다.

## 근거와 범위

- 변경 전 A맵 69동과 전체 화면이 `before_<ID>.png`, `before_overview.png`로 저장됐으며, `BASELINE.txt`와 원본 씬·프리팹 백업이 존재한다.
- 출처는 익스트랙션 A맵 V33의 69개 활성 건물, `BUILDING_DESIGN.md`의 10개 건축군, D07 `ASSET_PLAN.md`, 기존 D04/D06 실제 통행 기록이다. S11은 차고(06), S01–S10/S12는 생활 폐허(08)로 분리한다.
- 기존 D04 검증은 D04 외관 루트의 활성 상태를 전제한다. D08에서는 정확한 D04 외관·지붕 루트를 비활성화하므로 과거 검증을 그대로 재실행해 통과 조건으로 삼지 않는다. D08 전용 검증은 원본 물리 상태와 새 외관을 별도로 확인한다.
- HALL은 활성 V13 건물이며 남쪽 중앙 주출입과 남동쪽 하역문 두 곳만 실제 열린 문이다. 옛 V08 `DOOR_HE/HW` 앵커는 현재 열린 문으로 세지 않는다.
- D07 원화의 T01–T14와 B1–B6은 실제 3D 모델/정확 치수의 증거가 아니다. 사용자가 내려받은 자료 중 GLB 원본 37개를 확인했고, 적용 후보 32개(T 14종·Z 18종)를 Unity로 반입했다. 보류 Z 5종과 중복 파일 2개는 배치 대상이 아니다. `IMPORT.txt`와 `IMPORT_AUDIT.md`를 근거로 삼되, 반입만으로 건물 접합·소품 배치·통행은 검증되지 않는다. 추가 생성 크레딧은 사용하지 않았다.

## 1차 후보 실제 실행 기록

- `attempt_01/VALIDATION.txt`: 1,378 PASS / 32 FAIL, `RESULT FAIL`. `attempt_01/ERROR.txt`에 따르면 검증 탈락으로 씬 저장 전 중지했고 원본을 복원했다. 이 후보를 완료로 보지 않는다.
- 실패 구성: 건축 메시 중복 2개, prop 감사 크기 12개, 시각 외벽의 실제 출입 경로 교차 17개, 스폰 검사식 오판 1개. 원본 물리 서명과 배열 참조는 통과했다.
- 스폰 오판 원인은 `map.SpawnPoints`에 B1–B4뿐 아니라 위험지점 R1–R8을 원본 메타데이터로 보존한다는 설계를 검사식이 반영하지 못한 것이다. 실제 `StageMapRouter.Enter`는 B1–B4만 선택 풀에 넣는다. 검사식을 12개 정확 순서와 R8의 비기본 구분으로 수정하고, D08 플레이 검사에 실제 선택 스폰 확인을 추가했다. 스폰 로직/맵은 수정하지 않았다.
- prop 감사 크기 12건은 제작 코드가 holder 로컬 방향의 bounds를 썼으나 독립 검사식은 렌더러 세계축 AABB를 쓰기 때문에 90°/270° 회전과 건물 회전에서 불일치한다. 감사 기록 산출을 세계축으로 고치는 중이다. 위치·통로 간격 검사를 완화하지 않았다.
- `before_*.png`와 `failed_01_*.png` 동일 시점을 직접 비교했다. CLINIC의 경사 지붕, POWER의 설비형 평지붕, Y01의 곡면 차고, S07의 개방 폐허 등 큰 실루엣 차이는 보인다. 그러나 다수 건물의 새 외벽/지붕이 단색으로 기존의 노후 텍스처를 덮고 원본 출입구의 밝은 벽과 경계가 이질적이다. 텍스처·실측 UV 수정본으로 다시 평가해야 한다.

## 3차 후보 편집 결과와 독립 시각 판정

`attempt_03/VALIDATION.txt`와 `RELOAD_VALIDATION.txt`는 모두 **1,410 PASS / 0 FAIL**이다. `COMMAND_apply.txt`는 COMPLETE이고 69동 대응 `after_<ID>.png` 및 개요·B4/R8 비교 화면이 저장됐다. 이 수치는 ID, 원본 보존, 새 메시의 기계적 중복, 검사한 통로와 NavMesh에 관한 것이다. 아래의 콘셉트 아트 재현 평가나 실제 PlayerMotor 검사를 포함하지 않는다.

`BUILDING_DESIGN.md`와 최종 비교 시트 `01_landmarks_v02.png`, `02_workshops_and_civilian_v02.png`, `03_control_and_waterworks_v02.png`를 `before_*.png`/`after_*.png` 동일 시점과 직접 대조했다. 대표 10군의 핵심 불일치는 다음과 같다.

콘셉트 시트는 기존 풋프린트에 그대로 꽂히는 제작 도면이 아니다. 그러나 사용자 요청은 그 외형을 실제 게임에 구현하는 것이었고, 현재 후보는 주로 지붕 유형과 넓은 새 표면·색/텍스처 변화에 머문다. 따라서 **요청한 외형 재현 품질은 불합격**이다. CLINIC 지붕의 작은 흰 점들은 일정한 열로 보이나 정지 화면만으로 볼트/텍스처와 깊이 충돌을 판별할 수 없다. 결함이 없다고 단정하지 않는다.

B4/R8 전후 3쌍에서는 두 마커·주 동선·폐허군 배치가 유지된다. R8이 실제 위험 스폰으로 활성화됐다는 증거는 없고 편집 검사는 비활성 정책을 확인했다. 두 진입점이 약 62m로 가까우며 W5 길목을 공유한다는 기획 문제는 새 외관으로 해결되지 않았다.

사용자 이의 이후 **추가 적용·실제 플레이 검사는 시행하지 않는다**. 최종 판정은 미완료이며, 편집검사 PASS로 완성 보고를 해서는 안 된다.

## 검증 코드 및 예정 산출물

- `StageABuildingD08Validation.Run(map)`은 편집 상태의 맵과 신규 건축 메시를 검사하고 `VALIDATION.txt`, 저장 후 재열기 `RELOAD_VALIDATION.txt`로 판정한다.
- `StageABuildingD08Play.Run()`은 확인된 모든 실제 문을 PlayerMotor와 활성 CharacterController로 왕복하고 10군 대표의 안/밖 스크린샷, `D08_PLAY_VALIDATION.txt`를 생성한다.
- 최종 독립 판정은 위 결과 파일을 읽고 실패 줄, 누락 사례, 이미지 품질을 직접 점검한 뒤 갱신한다. 현재 합격 판정은 없다.
