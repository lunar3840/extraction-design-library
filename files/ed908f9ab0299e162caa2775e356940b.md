# A맵 공장 창 깊이감·반사 및 나머지 외벽 재질 V21

## 사용자 지시와 기획 의도

V20 후 남은 창의 깊이·반사 부족, 상부 채광창·다른 외벽의 반복을 안내한 뒤 사용자가 “한번 해볼래?”라고 요청했다. 같은 공장 건물 안에서 창 표현과 외벽 재질을 개선하되 구조·이동·충돌·캐릭터·조명 설정은 유지한다.

## 변경 전 상태와 증빙

2026-09-23 07:04부터 실제 변경 전 장면을 촬영했다. 기존 남측 벽은 V20 재질이나 다른 면과 상부 채광창에 밝은 파손 무늬가 남았고, 창은 불투명 평면이라 시선 이동에 따른 깊이·주변 반사 변화가 부족했다. `backup/`에 장면과 Resources 프리팹을 보관했고, `before_*.png` 고정 21장과 실제 플레이 20장을 저장했다. 이전 단계 이미지를 변경 전으로 재사용하지 않았다.

## 실제 구현 범위와 방법

- 같은 `V13_HallRoot/Exterior/Facade` 및 `Roof` 그룹의 유리 슬롯 38개(외벽 24, 상부 14)만 새 V21 유리 재질을 사용한다. 남측 V20의 창별 색·패턴 변주는 유지한다.
- 파손 영역에 시선 방향에 따라 제한된 범위로 이동하는 어두운 내부 층을 표현한다. 이는 셰이더의 가상 깊이감이며, 실제 실내 구조나 투명 개구부를 추가하는 것이 아니다. UV 이동은 축마다 ±0.022 이내로 제한한다.
- 공장 외부의 한 지점에서 주변 장면을 여섯 방향으로 촬영한 256×256 HDR 큐브맵을 새 유리 재질에서만 참조한다. 온전한 유리에 약한 각도 의존 반사를 더하며 파손 영역·창틀에는 적용하지 않는다. 실시간 반사나 각 창 위치에 정확히 맞는 반사는 아니다. 전역 반사 설정이나 ReflectionProbe를 추가하지 않는다.
- 남측을 제외한 외벽 34개 및 상부 측면 채광창 벽 6개의 콘크리트 57개 슬롯을 V20과 같은 낮은 대비의 별도 V21 재질로 교체한다. 표면 방향에 맞춰 완만한 무늬 좌표를 선택해 동·서측 벽에서 무늬가 한 방향으로 늘어지지 않게 한다.
- 기존 V20 남측 콘크리트·V17 하부 보수판·V19 부분 금속 보수/물때, 벽돌·금속·지붕판, 터널 상부 지면, 내부와 다른 건물은 보존한다.

원본 재질·텍스처·메시·UV·변환·충돌은 수정하지 않고 렌더러의 허용된 재질 슬롯만 교체한다. 반사 촬영용 임시 카메라는 촬영 후 제거하고 일시적 숨김 상태를 모두 복원한다. 큐브맵 방식은 [Unity의 장면 큐브맵 생성 설명](https://docs.unity.com/en-us/engine/6000.6/manual/materials-and-shaders/textures/class-cubemap/create)을 참고했다.

### 시각 판정과 남은 한계

메인과 별도 검토 담당자가 전후 원본을 비교했다. 다른 외벽·상부 채광창의 과도한 흰 파손 무늬와 벽 얼룩 반복은 명확히 줄었다. 동·서측 무늬의 축 늘어짐, 새 UV 경계나 프레임 손상은 발견하지 않았다. 기존 남측 콘크리트·보수판과 나머지 건물은 유지된다.

**창의 깊이·반사는 부분 달성이다.** 구현과 재질 연결은 정상이나 남측 정면/좌우 사선의 전후 차이는 거의 식별되지 않았다. 정면 반사 기여도는 약 2.16%이며, 어두운 가상 내부 층도 뚜렷한 깊이 단서를 주지 못한다. 따라서 ‘현실적인 입체 창을 완성했다’거나 ‘반사가 눈에 띄게 개선됐다’고 판정하지 않는다. 이번 결과는 반복 완화와 재질 일관성 개선이 중심이다. 북·서측 그늘에서는 외벽이 짙게 뭉쳐 세부가 약한 점도 남았다. 창틀의 실제 두께·안쪽 면과 실내 깊이 단서를 추가하는 후속 구조 표현은 이번 범위에 포함하지 않았다.

### 검사 중 보정·재현 조건

기준 검사에서 Unity의 구형 `RenderSettings.customReflection` 접근자가 큐브맵이 아닌 값을 읽으며 예외를 발생시켜, `customReflectionTexture`로 수정한 후 기준을 정상 확보했다. 실제 재질 변경은 정상 기준 확보 이후 수행했다.

반사 촬영/고정 비교/저장은 바깥 시점·cutaway=false 상태를 전제로 한다. 임시 카메라 및 렌더러 표시 상태를 복원하고 실제 플레이에서 잘라보기·지붕 표시 복원을 별도로 확인했다. 범용 임의 cutaway 상태의 캡처 복원까지 보증하는 도구는 아니다.
