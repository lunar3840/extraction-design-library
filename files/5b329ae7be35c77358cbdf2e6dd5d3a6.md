# A맵 구역별 Tripo 추가 생성 최종 독립 감사 — 2026-10-13

## 판정

**수량·비용 산술·후보/보류 구분은 일치한다.** 다만 저장된 캡처는 가로 702px의 잘린 Tripo 화면이므로, 작업 URL과 해당 모델의 연결, 실제 잔액·차감, 결과별 삼각형 수·`내보내기` 상태, 2K 세부 설정은 이 파일만으로 독립 재확인할 수 없다. 따라서 판정은 **기록 간 정합성 통과 / 서비스 작업 상태와 게임 사용 품질은 미검증**이다. 이 검토에서 Tripo·Unity를 조작하거나 크레딧을 사용하지 않았다.

`CHANGE_RECORD.md`, `TRIPO_JOBS.md`, `ART_BRIEFS.md`, `ASSET_PLAN.md`, 두 차례 독립 QA와 위험 검토를 읽고, 저장된 **Z 원화 24장과 `after_Z*_tripo.png` 23장 전부**, 전후 Tripo 캡처 2장을 직접 열었다. 원화는 Z01–Z20의 20개 용도 중 Z10의 중복 원화와 대체 입력 Z10b를 함께 보존해 **21장**, 수정 Z07r·Z09r·Z19r **3장**으로 총 24장이다. 결과 캡처는 Z10을 제외한 첫 20회와 수정 3회로 총 23장이다. 파일명 기준 누락·중복 ID는 발견하지 못했다.

## 수량·비용·링크 대조

| 항목 | 감사 결과 |
| --- | --- |
| 생성 장부 | `TRIPO_JOBS.md` 표 23행, 서로 다른 ID 23개. Z10 원화에는 결과 행/캡처가 없고, Z10b에는 있다. Z07·Z09·Z19 원안과 각 `r` 수정본은 각각 별도 유료 작업으로 세었다. |
| 링크 형식 | 23개 작업 URL은 모두 `studio.tripo3d.ai/ko/workspace/generate/<UUID>` 형식이며 UUID **23개가 서로 다르다**. 브라우저에 접속하지 않았으므로 링크가 해당 ID의 실제 결과를 여는지, 화면의 삼각형 수와 일치하는지는 확인하지 않았다. |
| 비용 산술 | 23×30 = **690**; 2,330−690 = **1,640**. 중간 20×30 = 600 → 1,730, 이후 3×30 = 90 → 1,640. 이전 450+420 = 870을 합하면 누적 **1,560/2,500**, 잔여 상한 **940**. 세 문서의 숫자는 일치한다. 단, 잔액은 캡처에 보이지 않아 실제 결제 원장 확인은 UI 접근성 상태를 읽었다는 메인의 기록에 의존한다. |
| 설정/공개 범위 | 전후 및 각 결과 캡처의 왼쪽 패널에 H3.1, `비공개`, 8K 토글 OFF, 생성 버튼 **30**이 보인다. `지오메트리 및 텍스처` 세부 메뉴는 접혀 있어 **2K 선택과 추가 강화 OFF는 캡처로 직접 확인 불가**. `비공개`는 이 작업 UI의 표시 상태이지 외부 접근 권한의 독립 검사 결과가 아니다. |
| 3D 품질 | 23개 결과 캡처에서 원화 주제와 대응하는 모델의 **왼쪽/정면 일부**는 보인다. 오른쪽이 모두 잘리고 작업 정보 패널도 보이지 않는다. 후면·윗면·바닥, 단일 메시/열린 구멍, UV·피벗·실측 치수·LOD·Unity 충돌·탑뷰 가독성의 합격 증거는 없다. 이 한계를 `CHANGE_RECORD.md`와 `TRIPO_JOBS.md`는 대체로 정확히 밝힌다. |

## 수정·보류 모델의 실제 화면 확인

- `Z07_workshop_welding_bay.png`의 높은 ㄴ자 판은 `Z07r_open_welding_station.png`에서 뒤쪽 한 면으로 줄었다. `after_Z07_tripo.png`와 `after_Z07r_tripo.png`의 보이는 부분도 원안의 측면 벽과 수정본의 열린 전면을 구별할 수 있다. 수정본의 오른쪽, 후드 아래 충돌과 실제 WC 통행은 미확인이다. 원안 **배치 후보 제외** 표시는 타당하다.
- `Z09_central_weigh_station.png`의 넓은 램프 판은 `Z09r_compact_cargo_scale.png`에서 다리 달린 저울로 바뀌었다. 두 Tripo 캡처에서도 보이는 왼쪽 실루엣 차이가 있다. 오른쪽 전체가 잘려 램프 부재·설치 폭을 3D 기준으로 확정할 수는 없다. 원안 **배치 후보 제외** 표시는 타당하다.
- `Z19_control_patch_cabinet.png`의 앞면 잭은 `Z19r_top_patch_island.png`에서 기울어진 상부 소켓/케이블 코일로 옮겨졌다. `after_Z19r_tripo.png`의 왼쪽에는 상부 소켓이 실제 보인다. 전체 윗면·코일 토폴로지/실내 카메라는 미확인이다. 원안 **배치 후보 제외** 표시는 타당하다.
- `Z12_residential_ruined_stair.png`와 `after_Z12_tripo.png`는 건물 접합·오르내림 가능 여부를 결정하지 못한다. `Z17_water_inspection_chamber.png`와 `after_Z17_tripo.png`는 높은 콘크리트 기초를 지형에 어떻게 묻을지 결정하지 못한다. 두 모델의 **배치 보류**는 유지해야 한다. Z02·Z05·Z13·Z14·Z16·Z18의 조건부 설치/탑뷰 검사는 장부에 명시되어 있다.

## 기록 문구 수정 제안

1. `CHANGE_RECORD.md`의 전후 화면 표에서 신규 결과 캡처의 확인 범위를 **“각 링크/완료·삼각형 수”**라고 적었다. 캡처에는 URL·완료 상태·삼각형 수가 보이지 않는다. “각 생성 결과의 잘린 정면 일부와 왼쪽 설정 표시; 링크·완료·삼각형 수는 당시 UI 확인을 `TRIPO_JOBS.md`에 전사”로 고치면 증빙 범위가 정확하다.
2. `TRIPO_JOBS.md`의 비용 절: `before_tripo_balance.png`/`after_tripo_balance.png`를 **“최초 20종 전후의 동일 뷰 비교”**라 부르지만, `after_tripo_balance.png`에는 마지막 수정본 **Z19r**이 표시된다(`CHANGE_RECORD.md`의 설명도 동일). “전체 23회 생성 전후”로 고치고, **두 캡처 모두 잔액 수치가 없는 설정·모델 비교 화면**임을 유지해야 한다.
3. `ASSET_PLAN.md` 첫 문단의 **“Z01–Z20은 Tripo에서 1회씩 생성”**은 Z10 원화가 미생성인 최종 기록과 문자 그대로 충돌한다. “Z10 대신 Z10b를 포함한 선정 20종을 각 1회 생성”으로 고치면 된다.
4. `INDEPENDENT_VISUAL_QA.md`의 **“과금 전 결론”** 소제목과 “주문 전” 표현은 최종 `CHANGE_RECORD.md`가 밝힌 **첫 20회 과금 후 독립 검토** 순서와 혼동된다. 과금 전에 확정된 것은 Z10→Z10b 교체뿐임을 분리하고, 20종 검토는 “생성 후 원화 독립 검토”로 바꾸는 편이 정확하다. `REVISION_QA.md`의 세 수정 원화 검토는 수정본 유료 생성 전에 이뤄졌다는 기록과 일치한다.
5. `ART_BRIEFS.md`의 공통 방향 중 **“글자 … 제외”**는 실제 원화 Z03 계기 단위(`kV`, `MΩ`, `A`)와 Z09·Z09r 계기의 숫자/단위와 맞지 않는다. 의도가 읽을 수 있는 상표·문장 제외였다면 그렇게 좁혀 쓰고, 계기 눈금·단위가 원화에 남아 있음을 명시한다. 이것은 핵심 형상 오류가 아니라 재생산 브리프의 정확성 문제다.

이 다섯 문구 외에, 확인한 자료만으로 23종을 Unity 배치 합격으로 승격하거나 위험 모델 보류를 해제할 근거는 없다. 특히 B4와 비활성 R8의 약 62m·W5 합류는 기존 계획 그대로이며, 새 중형 구조물 설치 시 두 출발점의 초기 노출·엄폐·이동·파밍·탈출 접근을 다시 비교해야 한다.

## 메인 통합 후 반영

위 1–5번 문구는 메인이 각각 `CHANGE_RECORD.md`, `TRIPO_JOBS.md`, `ASSET_PLAN.md`, `INDEPENDENT_VISUAL_QA.md`, `ART_BRIEFS.md`에 반영했다. 원본 3개가 이미 유료 생성된 사실과 향후 배치 후보 제외를 `REVISION_QA.md`에도 분명히 했다. 감사의 핵심 한계인 **잘린 캡처만으로 서비스 작업·게임 사용 품질을 독립 입증할 수 없다는 점**은 그대로 유지한다.
