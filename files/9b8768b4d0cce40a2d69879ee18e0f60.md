## 임시 Keyboard 정리 확인

helper는 기존 Keyboard를 보관한 뒤 자신이 추가한 `UiKitEvidenceSimulatedKeyboard`에만 QueueStateEvent를 전송했다. 실제 PlayerLoop의 Dynamic update에서 down/up을 관찰했으며 수동 InputSystem.Update 호출은 없다. 종료 시 자신의 장치에 all-up을 예약하고 이벤트 구독 해제 → 자신의 장치 RemoveDevice → 기존 attached Keyboard.MakeCurrent 순서로 정리한다. OS 장치 상태에는 이벤트를 큐하지 않는다.

세 텍스트 마지막의 `Temporary virtual device removed; previous attached keyboard restored. No OS device state was changed.`를 확인했다. 텍스트 안의 `AFTER` state는 finally 정리 **직전**의 관찰값이므로 `keyboardCurrent=UiKitEvidenceSimulatedKeyboard`와 `simulatedInputActive=True`가 남아 있는 것이 정리 실패를 뜻하지 않는다.

추가 근거로 E 이후 V의 BEFORE 및 V 이후 I의 BEFORE가 `keyboardCurrent=Keyboard`, simulatedInputActive=False임을 확인했다. 마지막 I 처리 후 실제 status(UTC `2026-10-21T22:01:16.7663268Z`) 역시 다음과 같았다.

- `SIMULATED_INPUT_FINISHED`
- keyboardPresent=True, keyboardCurrent=Keyboard
- simulatedInputActive=False, simulatedInputKey=none
- medicalWheelOpen=False
- interactiveOwned=True, interactiveSaveOwned=True: 입력 테스트용 임시 fixture는 당시 main의 후속 마우스 검증을 위해 유지 중이며, 가상 Keyboard 장치 수명과 별개다.

## OS 입력과 구분

이 증빙은 Unity Input System에 추가한 **가상 Keyboard**의 이벤트가 기존 게임 Update 및 UI 상태에 도달한 결과다. 물리 키보드, Windows 입력 주입, Sky의 press_key 전달, IME/텍스트 입력 성공을 의미하지 않는다.

E/I/V가 이 경로에서 작동하므로 기본 게임 입력 처리와 UI 경로가 동작한다는 근거는 된다. 이전 Sky 키 입력이 반응하지 않은 원인이 OS 주입 경로인지 장치 수신/초점 타이밍인지 현재 증빙만으로 확정할 수는 없다. 따라서 OS 키 입력 PASS로 표기하지 않았다.
