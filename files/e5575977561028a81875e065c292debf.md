## 실제 화면과 API fixture의 구분

- 임시 세션 생성, 상점 열기, StageA 진입, 6종 탄약/의료/배낭의 테스트 컨테이너 생성, 수색 완료 전진, 화면 저장은 기존 Editor 전용 격리 fixture의 공개 게임 경로를 사용했다. 일반 출격의 자연 파밍이나 물리 키보드 입력 검증으로 확대하지 않는다.
- hover 대상은 실제 OS 마우스로 지정했고, 실제 공용 production hover UI가 Repaint 경로에서 그려졌다. `ScreenCapture` PNG는 해당 실제 GameView의1920×1080 원본이다. native JPEG도 함께 보존했다.
- 단순히 `hoverCandidate` 값이 있다는 이유로 표시 성공으로 간주하지 않았다. PNG와 native 사진에서 실제 카드가 보이는지 함께 확인했다. 헤더·버튼에 커서가 있을 때는 오래된 후보 값이 남을 수 있지만 카드가 뜨지 않는 것을 화면으로 확인했다.
- 이번에는 실제 정상 구매/판매 거래를 실행하지 않았다. 거래 안전성은 기존 조건·콜백 원문 보존과 잔액 부족 버튼 클릭 후 실제 상태 유지 범위로만 확인했다.
- 미수색 상태는 이번 요청의 전후 자동 route에 동일한 중립색 `?`/수색중 슬롯으로 촬영했다. 6종 컨테이너의 실물 표시 검증은 공개 완료 이후이며 미공개 슬롯에 색을 강제로 드러내지 않았다.
- 기존 `Particle Velocity curves must all be in the same mode` 오류 문구는 과거에도 있던 VFX 문제다. 이번 변경의 C# 컴파일 오류와 구별하며 이 범위에서 VFX를 수정하지 않는다.

## 추가 발견: 증빙 도구의 수색 시계 보완

독립 검토가 마지막64KiB Editor 로그에서 `LootState.Advance`의 `ArgumentOutOfRangeException(now)`를 발견했다. 최초 자동 route와 대화형 수색 완료 도구가 `Time.timeAsDouble+120`으로 테스트 컨테이너 시계를 앞당겼고, 이후 실제 `LootInteractor.Update`가 현재 시각으로 호출하면서 단조 시간 조건과 충돌했다. 실제4개 런타임 표시 파일의 회귀로 판단하지 않는다. 이전 사진은 실제로 그려진 화면의 증빙으로 보관하지만 해당 테스트 도구 예외 발생 사실을 숨기지 않는다.

Editor 증빙 도구에서만 미래 시각 전진을 없앴다. 자동 route는 세 항목의 정상 수색9.2초를 기다리고, 대화형8항목 테스트는 실제1초씩 순서대로 수색한다. 공개 완료 명령도 현재 시각만 사용한다. 게임의 LootState 시간 검증·수색 규칙·LootInteractor.Update는 바꾸지 않는다. 이후 정상 시간 흐름의 최종 재검증을 별도 기록한다.
