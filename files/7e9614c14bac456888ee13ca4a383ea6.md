# 실제 접촉·W5 가림 진단 독립 검토

2026-10-29. 메인이 Unity에 임시 설치·실행한 결과를 읽었다. 이 감사자는 설치/실행/에셋 변경을 하지 않았다. 실제 설치본과 마지막 staging의 차이는 setup 실패 검사 및 오류 시 상태 복구 try/finally뿐이며 정상 성공 경로의 이동·접촉·캡처 조건은 같다. 실행본은 메인의 `main/executed_helpers/` 보존본을 기준으로 삼는다. 마지막 staging을 이미 실행한 원본으로 소급하지 않는다.

## 1. B4→PARTS 경로 정체는 실제 맵 충돌 접촉으로 재현됨

결과 폴더:

- `diagnostic_blocked_direct_639288508548642403/`
- `diagnostic_blocked_replan_639288508646040531/`

두 회차는 원래 정체 발 위치(-39.38,1.35,-51.29)에서 플레이어/카메라를10개 실제프레임 동안 안정시킨 뒤, 프레임당1회1/60초로180step을 진행했다. 적71개체는 frozen/automatic off,world timer off인 통제 검사다.

두 회차 모두 현재점→다음goal(19.32,1.86,-40.08)의 새 NavMesh가 **2코너 직선 Complete**였다. Direct와 더 엄격한 .06m 코너 추종 Replan의 결과도 동일하다. 실제 변위는 **수평0.071598m**,60step 이후 위치는 계속(-39.376630,1.35,-51.218480)이었다. 따라서 첫 probe의 가속 스텝 또는 .34m 조기 코너 전환만으로 생긴 현상이라는 가설은 이 재현을 설명하지 못한다.

실제 `OnControllerColliderHit`는 아래 맵 Collider를 반복 보고한다.

`StageA_Relay_Blockout_v08/LookV16_SouthYardDressing/ConcreteApron_And_Drainage/Curb_WestEdge_Tile_01`

- owner=`MAP`; NPC collider 접촉이 아니다.
- CC radius0.4,height2,stepOffset0.25,skinWidth0.02,slopeLimit45도.
- curb BoxCollider 월드 중심(-38.8,1.528796,-50.25),크기(약.34,.24,3.5),월드 상단Y1.648796.
- 시작 발밑 실제 terrain ray Y1.344358,normalY.998435. curb 상단과 이 지지바닥의 높이차는 **약0.30444m**이며 CC stepOffset0.25m보다 크다. 명목 curb 부품 높이0.24m만 보고 통과 가능한 턱이라고 판단하면 실제 지형과의 높이차를 놓친다.
- CC의 반복 접촉 normal은 대체로 X 음수 방향이며 `collisionFlags=5`(Sides|Below),grounded=True. 주변 지지바닥은 실제 terrain MeshCollider `V13_Cut_LandSurface_09`다.

**판정:** 특정 B4→PARTS 경로가 밟는 낮은 연석에서 **NavMesh의 통과 경로와 실제 CharacterController의 턱/측면 충돌이 불일치하는 재현**이다. curb 끝으로 돌아가는 수동/대체 경로나 PARTS 전체 접근 가능성까지 부정하지 않는다. 차후 수정 시 지형 지지 높이, curb collider 상단,PlayerMotor stepOffset,NavMesh voxel/climb의 조합을 함께 대조하고 같은점/같은방향에서 전후 재검증해야 한다. 이번 감사 자체로 collider나 전역 stepOffset을 변경하지 않는다.

## 2. W5에서 플레이어 몸체 가림은 즉시 캡처 문제만이 아님

결과 폴더 `diagnostic_W5_visibility_639288508738697040/`의 `after_W5_actual_game.png`를 직접 이미지로 열어 확인했다. HUD·플레이어 체력바는 보이지만 플레이어 몸체는 큰 건물 표면 뒤에 가려져 식별되지 않는다. camera-only 이미지와 별도인 **실제 Game ScreenCapture**다.

- semanticW5 발 위치(-92,0.022240,-93),grounded=True.
- 기존 runtime camera/roof 갱신을10개 실제프레임 기다린 후 캡처했고,다음3프레임 뒤 Game 파일 존재까지 확인했다.
- 카메라(-87.253,13.68937,-84.52049),회전약(50,210,0),FOV60도.
- 활성 `StageABuildingV33Reveal`의 `IsRevealing=False`.
- camera→player 물리 ray에는 `EnclosuresV33_ConnectedFacilities/Buildings/S11/BlenderExpansion_S11_Shell/S11_Shell/S11_Shell_colliderOnly`가 검출됐다.

**판정:** 원래 이동 후 사진만의 즉시 캡처 타이밍 문제로 처리할 수 없다. 현재 카메라와 위치에서10프레임을 지난 실제 Game 화면에도 몸체 가림이 남는다. 통과 가능한 길이더라도 조작 캐릭터가 안 보이는 상태이므로 W5의 실제 플레이 가독성은 미통과다. 다른 모든 건물이나 맵 전체 가림에 자동 확장하지 않는다.

가능한 통합 원인으로 `StageABuildingV33Reveal.cs:189`–195는 parent building을 찾으면 `AddBuildingRenderers` 후 continue하고,`:411`–419의 `AddBuildingRenderers`는 `VisualRoot`와 `RoofCutawayRoot`만 순회한다. 새 BlenderExpansion shell이 이 두 참조 밖의 sibling이면 탐색에서 빠질 수 있다. `:461` 이후 IsBuildingSurface도 `Shell`만인 이름을 포함하지 않는다. 이 코드 경로는 원인 가설이며 실제 renderer/등록 root를 대조한 뒤 수정 범위를 결정해야 한다. roof를 강제로 숨기거나 카메라를 임의로 옮긴 사진으로 원래 위치의 실패를 덮지 않는다.

## 후속: 원래 B4→PARTS 전체 경로의 엄격 코너 재시험

`main/runtime_parts_639288509560221558/AUDIT.txt` 원문을 추가로 읽었다. 2026-10-29T06:09:25Z 시작한 별도 통제 회차로 원래 B4→PARTS 전체316.5387m/16코너 경로를 재사용했고,코너 도달 허용을 .06m로 줄이고 step overshoot를 제한했다. 그래도12001step 뒤(-39.38,1.34,-51.48)에서 다음goal(-39.12,1.38,-51.48)을 향해 정체했다. 플레이어는 생존했다.

이는 정체점만에서 시작한 Direct/Replan과 일치하며, **원래 전체 경로의 빠른 코너 생략만으로 생긴 시험기 실패가 아님**을 추가로 확인한다. 실제 연석 접촉과 현재 NavMesh/CharacterController 통행 불일치 판정을 유지한다. 이 테스트도 대체 경로를 조사한 것은 아니므로 PARTS 전체 접근 불가라고 말하지 않는다.

## 후속: 209개 후보의 body/leash 예측 전수

`main/runtime_census_639288511214355325/ALL_VARIANTS_PATROL_PREFLIGHT.json` 원문을 읽었다. Scope 자체가 `Read-only preflight predictions, not actual execution of all variants`라고 명시한다. 73actor/209variant/627leg에서 **208후보 예측 적합,1후보 예측 부적합**이다. LeashFailure0,BodyFailure2는 같은 후보의 왕복 두 leg이며 두 개체 실패가 아니다.

부적합 후보는 `G12_02/B`다. 출발(-4.440292,2.04,19.075562),원래 다음목표(-1.440308,2.04,19.075562)의 직접 경로는 PathInvalid다. .599701m 떨어진(-2.040009,2.04,19.075562)로 sample하면 PathComplete가 되지만 반경.9m bodyclear가 실패한다. blocker는 `V13_HallRoot/Exterior/Facade/BlenderExpansion_HALL_Interior/HALL_Interior/HALL_Interior_colliderOnly`다. 돌아오는 leg도 bodyclear가 실패한다.

따라서 기존 공통.4m NavMesh627쿼리PASS를 모든 크기 NPC 실제순찰 성공으로 확대하지 않아야 한다는 리뷰가 실제 구체 사례로 뒷받침됐다. 208적합은 물리/행동 **예측**이며208실제 이동 완료가 아니다. 실제 G12 정체 관찰과의 통합 판단 및 분류는 메인/전투 감사 보고서를 따른다.

프리팹 추가 대조: `StageA_Relay_Blockout_v08.prefab:112603`의 S11 VisualRoot는 `S11/Visual`,`:112605` RoofCutawayRoot는 `S11/Visual/Generated/Override_ENV11_BUILDING_SWR_06/RoofCutaway`다. 새 `S11/BlenderExpansion_S11_Shell`은 두 참조 밖의 **직속 sibling**임을 현재 YAML Transform 계층에서 확인했다. 새 `BlenderExpansion_S11_Roof`만 RoofCutawayRoot 아래다. 따라서 새 Shell을 AddBuildingRenderers가 순회하지 않는 구조적 누락은 확인됐다. 가리는 실제 renderer와 정확한 mesh ray를 대조하면 직접 인과를 더 확정할 수 있다.
