상태: W10 한 동의 `.blend`, Shell/Roof/Interior FBX, 외부·지붕 제거 실내·검수실 근접 렌더가 생성되었다. 새 Blender 5.2.3 배경 세션의 독립 FBX 재반입 검사가 PASS다. Unity 적용·실제 게임 화면·출입 동작 검증은 메인/Unity 담당 범위다.

## 메인에게 필요한 실측 계약

1. 선택 건물 ID와 현행 건물 역할·외관 콘셉트, Unity의 parent/frame 기준점·회전·스케일.

3. **실제** 출입구 각각의 방향, 중심, 폭, 하단/상단 높이, 문턱·접근 통로와 충돌 보호 폭. 창문과 환기구의 실측 위치·범위.
4. 유지할 실내 바닥·벽·가구·설비·전리품/상호작용·경로와 교체 가능한 벽/지붕/칸막이 범위.
5. 전후 이미지의 같은 시점 및 cutaway/가림 규칙. 중형창고가 어느 D09 재질 키/FactoryV12 고유 재질을 현재 사용하는지.

## 제작·검사 원칙

- 벽 두께·개구부 리빌, 모서리 베벨, 실제 창틀과 문틀, 지붕 두께·지지 구조, 용도에 맞는 실내 구획·통로·걸레받이·설비를 각각 실제 메시로 만든다.
- 통행이 필요한 문은 문짝/문턱으로 막지 않는다. 유리는 `GlassMuted`, 금속은 `IronDark` 또는 현행 고유 금속 재질로 분리하고 벽색으로 일괄 칠하지 않는다.
- 출입구·창문·지붕 이음과 실내 동선은 실측 계약과 제작 후 숫자/이미지 양쪽으로 확인한다. FBX 재반입에서 좌표·스케일·면 방향·재질 슬롯이 안정적인지 확인한다.
- Blender 실행 명령은 메인에게 전달한다. 공유 Blender 장면과 Unity는 메인이 실행·조율한다.
- FBX 후보 축 설정은 `axis_forward='-Z'`, `axis_up='Y'`, `global_scale=1.0`, `apply_unit_scale=True`, 선택 객체만 내보내기다. 최종 계약은 메인의 Unity 재반입에서 기준점과 각 문 중심의 오차를 검사한 뒤 확정한다.

## 메인 실행 명령

아래 경로의 Blender 실행은 **메인**이 다른 작업과 순서를 맞춰 수행한다. `blender/`와 `main/`은 이번 기록 폴더 아래를 뜻한다.

```powershell
& 'C:/Program Files (x86)/Steam/steamapps/common/Blender/blender.exe' --background --python 'outputs/change_records/2026-10-26/a-map-blender-warehouse-sample/blender/build_warehouse_sample.py' -- --contract 'outputs/change_records/2026-10-26/a-map-blender-warehouse-sample/main/W10_MODEL_CONTRACT.json' --source-json 'outputs/change_records/2026-10-13/a-map-concept-rebuild-d09/blender/all_r04/D09_ARCHITECTURE.json' --materials 'outputs/change_records/2026-10-13/a-map-concept-rebuild-d09/blender/D09_MaterialLibrary.blend' --textures 'C:/UnityProject/escape/Assets/Escape/Art/BuildingD09/Textures' --out 'outputs/change_records/2026-10-26/a-map-blender-warehouse-sample/blender/export'
```

성공 시 `export/W10_WarehouseSample.blend`, `W10_{Shell,Roof,Interior}.fbx`, `W10_exterior_threequarter.png`, `W10_interior_cutaway.png`, `W10_inspection_room_close.png`, `EXPORT_MANIFEST.json`이 생성된다. `EXPORT_MANIFEST.json`의 `files[].objects[]`가 객체 이름·`materialSlots`·`collisionSuggested`·`localBoundsUnity`·`vertexCount`·`triangleCount`를 제공한다. 기존 물리 바닥과 가구 충돌은 보존해야 하며 새 검수실 벽의 `collisionSuggested`만 신규 충돌 후보로 다룬다.

첫 생성 후보의 외부/실내 렌더와 manifest는 `blender/diagnostic_r01/`에 보존했다. 첫 실내 렌더는 카메라가 우측을 잘라 넓은 빈 바닥만 강조했고, 기존 Unity 바닥/4개 작업대가 Blender 원본 파일에 없어 제작품 자체의 판단 자료로 부족했다. 두 번째 실행은 기존 WalkableFloor를 **렌더 전용** 시각 참조로 놓고 전체 실내/검수실 근접 화면을 만든다. `W10_PreviewOnly_ExistingWalkableFloor`는 `W10_PreviewOnly_NotForUnity` 컬렉션에만 있으며 FBX에는 포함하지 않는다. 원래 Unity 바닥·작업대·소품은 메인이 보존해 함께 실제 화면을 확인해야 한다. 긴 어두운 줄은 소스의 구멍이 아니라 신규 하역 유도/줄눈 메시였으며 폭을 9–18mm, 높이를 1mm로 줄이고 StoneBase 톤으로 조정했다. 모서리 기둥의 첫 덮개는 너무 높이 떠 보여 원본 기둥 상단에 겹치도록 낮췄다.

## 생성·독립 재반입 결과

- `blender/export/`의 최종 모델과 이미지 3장을 직접 열어 확인했다. 분리된 벽돌·석재·금속·유리, 비대칭 지붕과 검수실 구획이 보인다. `diagnostic_r01/`, `diagnostic_r02/`에는 이전 후보 이미지만 보관했다.
- `blender/validate_roundtrip.py`가 Blender 5.2.3의 새 배경 장면에서 FBX 3개를 하나씩 재반입하고 원점, scale 1, 객체 수, 재질 슬롯, 실제 Unity 변환 바운드(허용오차 5cm), 면 수를 비교했다. 이어 `.blend`를 읽어 외부 이미지 39개의 접근 가능 여부를 확인했다. 결과는 `blender/ROUNDTRIP_VALIDATION.json`과 `.log`에 있다.
- **PASS, 오류 0**: Shell 52개 / 실제 8,848삼각형, Roof 39개 / 4,604삼각형, Interior 52개 / 3,792삼각형. 누락 이미지 0개. 새 베벨 상세 91개는 FBX로 내보낼 때 실제 형상이 적용되어 각 12→108삼각형이다. `EXPORT_MANIFEST.json`의 `triangleCount`는 편집 가능한 원본 메시의 수치이며, 실제 FBX 삼각형 수는 `ROUNDTRIP_VALIDATION.json`의 `fbxTriangles`를 사용한다.
- Unity 기본 바닥·기존 작업대 4개와 소품은 Blender FBX에 포함하지 않았다. 실제 게임 화면의 실내 완성도, 충돌/시야, 두 문 통행은 Unity 통합 후 별도로 판단해야 한다.

## Unity 실제 재반입 X축 보정

첫 Unity 재반입에서 Unity의 왼손 좌표 변환이 FBX 메시 X축만 반사하는 것을 실측했다. 예를 들어 `W10_Back_PortalQuoin_-1`은 목표 X=-2.01..-1.75m 대신 +1.75..+2.01m로 들어왔다. 이에 FBX 내보내기용 메시 복제본의 정점 X만 반사하고 면 winding 및 UV loop를 역전시켰다. 객체 transform은 원점·scale 1을 유지하고 음수 scale을 사용하지 않는다. 편집용 `.blend`와 렌더는 기존 형태로 유지한다. `EXPORT_MANIFEST.json`은 Unity 목표 `localBoundsUnity`와 `fbxGeometryMirroredXForUnity: true`를 명시하고, Blender 재반입 검사는 FBX raw X를 Unity 수입 변환에 맞춰 다시 반사해 예측 바운드를 검사한다. 첫 Unity 시도 이전 모델·이미지는 `diagnostic_r03_pre_unity_axis_fix/`에 보존했다.

보정 FBX 3종의 Blender 새 장면 재반입 결과는 `ROUNDTRIP_VALIDATION.json`/`.log`의 **PASS / 오류 0**이다. 143개 객체(Shell 52, Roof 39, Interior 52)의 재질·원점·scale1·실제 바운드가 일치했고 외부 이미지 39개가 모두 열렸다. 위 PortalQuoin의 FBX raw X는 +1.75..+2.01m이고 Unity 반사 예측 X는 정확히 -2.01..-1.75m다. 실제 Unity 143개 바운드 검사는 메인이 별도로 실행한다.

보정 전체 모델은 SHA256 `7234B7035AB7487CB5D5158F77029A14E807AF080F3376EFC180267445E30D96`인 생성기 실행으로 만들어졌다. 현재 생성기의 SHA256 `2036065A3BA4A466D060A9999DF4249BD9A2B99DEA0EE31FC04B8BB92478880E`는 이후 `--export-only` 옵션만 추가된 판본이다. 내보내기 X반사 및 메시 생성 코드는 동일하며, 현재 `export/`는 7234 실행 결과로 동결한다. 실제 생성기 버전과 `.blend`/FBX 해시는 `EXPORT_MANIFEST.json` 및 이 기록을 함께 참조한다.
