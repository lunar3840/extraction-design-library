# SCAR 장전 속도 미리보기 — 검증 완료, Unity 미적용

사용자는 기존 검토 영상을 실제 게임의 장전 시간에 맞춰 보여 달라고 요청했다. 원문은 `USER_REQUEST.md`에 보존했다. 동일한 SCAR 파지·재장전의 속도만 바꾼 후속이므로 기존 무기 모딩 주제를 유지한다. 게시 담당과 당일 후속 순서를 `2026-11-21-01`로 예약했다. 예약 근거는 `../library-coordination/WEAPON_RELOAD_GAME_SPEED_RESERVATION.json`이다.

기존 검토 영상은 9.033초여서 실제 장전 속도를 판단하기 어려웠다. 승인20의 저장 모델과 실제 렌더 PNG를 그대로 사용해 게임 시간에 맞춘 미리보기 두 개를 만들었다. 수정 전에 원본 영상과 같은 카메라의 주요 프레임 8장을 `before_`로 복사했다. 사후 이미지를 전 이미지로 사용하지 않았다.

## 시간 근거와 변경 방법

현행 Unity `WeaponCatalog.json`의 SCAR(AR_013) 기본 `reloadTime`은 3초다. 런타임 `RifleState`와 `EdelOriginalMotion`은 부품·성장·상태·개체 옵션을 반영한 실제 장전 시간에 애니메이션을 맞춘다. 이 파일들은 읽기만 했다.

현재 모델 A의 9개 부품 ID를 현행 게임 정의와 대조했다. 전술 개머리판은 1.05배, 확장 탄창은 1.12배이며 나머지 7개 부품은 장전 시간에 영향을 주지 않는다. 성장·상태 배수 1, 재장전 개체 보너스 0을 가정하면 `3 × 1.05 × 1.12 = 3.528초`다. 현재 플레이어 인벤토리나 실게임에서 측정한 수치로 주장하지 않는다.

| 조건 | 게임 시간 근거 | 실제 미리보기 | 원 영상 대비 |
| --- | ---: | ---: | ---: |
| 기본 SCAR | 3.000초 | 180프레임 / 60fps = 3.000초 | 약 3.01배속 |
| 모델 A의 부품 구성 가정 | 3.528초 | 212프레임 / 60fps = 3.533초 | 약 2.56배속 |

명목 시간과 출력의 차이 5.33ms는 60fps 출력으로 생기는 한 프레임 미만의 차이다. 원본 프레임을 시간에 맞춰 순서대로 선택해 인코딩했다. 새 포즈나 보간 형상을 만들지 않았다. 팔 동작과 기존 대기·빈 탄창 낙하도 함께 빨라지는 속도 비교 영상이다.

## 검증 결과

메인과 독립 서브에이전트가 두 MP4 전체를 각각 디코딩해 60fps, 180/212프레임, 3.000/3.533초를 확인했다. 선택 PNG 총 392개는 대응 원본 PNG와 SHA가 같으며 원본 첫 프레임부터 마지막 프레임까지 순서가 엄격히 증가한다. 392개는 두 영상의 출력 수 합계이며 새 공간 검증 표본 수가 아니다.

메인과 독립 서브에이전트 모두 `GAME_SPEED_COMPARISON.png`와 `GAME_SPEED_CADENCE.png`를 실제로 열람했다. 빈 탄창 접근·분리·놓기 → 파우치 접근·새 탄창 인출 → 운반·삽입 → 복귀 순서가 유지된다. 독립 판정은 `PASS_TIMING_ONLY_TWO_PREVIEWS`다. 실제 시간으로 동영상을 연속 재생해 관찰했다거나 새로운 공간 충돌 검증을 수행했다고 주장하지 않는다. 원본20의 공간 검증과 이번 시간·영상 검증은 범위를 구별한다.

`TIMING_PLAN.json`의 보호 입력 7개(모델·기존 영상·게임 코드/데이터·부품 명세)는 메인과 독립 검사 모두 이전 SHA와 동일했다. 검증 상세는 `VIDEO_VERIFICATION.json`, `MAIN_REVIEW.json`, `qa-speed/QA_REPORT.md`, `qa-speed/CORE_VERIFICATION.json`에 보존했다.

최초 정지사진 추출은 FFmpeg 9에서 제거된 `-vsync` 옵션으로 중단됐다. 정상 생성된 기본 영상은 보존하고 추출 옵션만 고쳐 재개했으며 `VIDEO_TOOL_ATTEMPT_01_FAILURE.json`에 남겼다. 독립 검사의 최초 이미지 라이브러리 import 중단도 파일 작성 전에 발생했으며, 표준 라이브러리와 FFmpeg로 검사를 마쳤다. 두 건은 모델·게임 결함으로 집계하지 않는다.

## 전후 증빙과 변경 파일

`before_<시점>.png` 8장과 `after_<시점>.png` 8장이 대응한다. `after_`는 실제 3.53초 MP4에서 추출했고 `base_<시점>.png`는 3초 MP4의 대응 프레임이다. 카메라·포즈·조명·1080×960 해상도는 같고 미세한 정지사진 차이는 영상 압축으로 생긴다. 속도 변화는 MP4와 비교 보드의 경과 시간으로 확인한다.

변경은 이 폴더의 두 미리보기 MP4, 대응 PNG, 비교 보드, 검증 기록과 작업 폴더의 미리보기 생성기에 한정된다. 기존 모델·뼈·키·경로·Unity 설정과 원본 영상·기존 ZIP은 수정하지 않았다. 게임 적용 완료 횟수는 0이다. 전달 영상은 `Edel_SCAR_Reload_Base_3p00s.mp4`와 `Edel_SCAR_Reload_ModA_3p53s.mp4`다.

## 라이브러리 인계

공개 수집은 `LIBRARY_EVIDENCE.json`과 `PUBLICATION_ALLOWLIST.json`에 명시한 문서와 정지 이미지에만 허용한다. 모델·리그·형상 데이터·ZIP·MP4·작업 코드는 공개 목록에 포함하지 않는다. 기존 주제 후속 회차의 실제 게시 검증을 기다리는 상태이며 파일 저장만으로 게시 완료를 주장하지 않는다. 브라우저 화면 검증이 불가능하면 HTTP 검증과 구별해 보류 상태로 남긴다.

## 라이브러리 공개 반영 및 검증 수준 — 2026-11-21

기존 모딩 주제의2026-11-21-01 검토·검증 회차로 허용문서7개·정지PNG18개의 웹열람본, 같은포즈8비교쌍 및 대표보드2장을 연결했다. MP4·native·ZIP·rig·형상·작업코드는 업로드하지 않았다. 기본3초와 부품조건가정3.528초/60fps출력3.533초의 시간 미리보기만을 다루며 실게임실측·새공간검증·Unity적용이 아니다.

공개원문·이미지의 비인증HTTP/SHA 및 최신대표선택을 확인했다. 실제브라우저화면·새사이트전후스크린샷은 기존주소확인정책중단이 해소됐다고 확인되지 않아 pending이다. 우회하지 않았으며 HTTP검증을 실제화면열람으로 보고하지 않는다. 상세검증/소스대응은 PUBLICATION_VERIFICATION.json과 outputs/change_records/2026-11-21/weapon-reload-speed-publication/에 보존한다.
