# 에델 런타임 2차 최종 독립 검토

2026-10-26 KST. **조건부 채택 판정:** 보관된 최종 세 소스의 동일 입력 CPU 경로는 기존 계산보다 빨랐고, 검증 도구가 관찰한 거리·예산·정점·본·접촉 결과는 같았다. 실제 게임 전체 FPS 개선, 모든 trial 방문 순서의 완전 동일성, 전체 장비 외형과 무할당까지 통과시킨 판정은 아니다. 공유 Unity가 다른 작업에 반환된 뒤에는 live source를 읽거나 변경하지 않았다. 이 검토는 `adopted/` 사본, `FINAL_SOURCE_HASHES.json`, 결과 파일 및 빌드별 provenance만 사용했다.

## 같은 입력에서 확인된 결과와 CPU

- 80 source pose를 한 Play에서 reference/optimized/optimized/reference/reference/optimized/oracle 7회 fresh Bind한 `paired_results.json`을 다시 집계했다. 기준 대비 **480쌍**에서 기존 fingerprint, body queries/triangles/witnesses/unverified와 Current distance queries/triangle tests/seed/BVH node 작업 카운터의 불일치가 0이다. oracle Current distance calls=checks **375,078**, mismatch0; braid 누적 checks **110,503**, mismatch0이다. Braid oracle은 mismatch 시 원식으로 fallback하므로 누적 mismatch0 확인이 필수이며 이번 관찰은 이를 만족한다.
- 처음10자세를 각 비-oracle 회차에서 제외한 210표본/모드의 외부 전체 Step Stopwatch 평균은 reference **55.04252ms**, optimized **53.10372ms**로 **1.93880ms, 3.52237% 감소**했다. 이는 같은 입력의 연속 Step CPU 결과다. `CurrentRootBudgetApply` 17.18593→16.10008ms는 하위 타이머이며 전체 Step에 더하지 않는다. 초기 Bind/첫 Step·prepared 배열을 포함한 원본 대비 비용과 다른 장면·긴 실행에서의 편차를 별도 경계로 둔다.
- 새 `paired_quality` 및 세린/리브/유이 품질 replay는 각각 6 source pose×reference/optimized/oracle이다. 각 기준 대비 12쌍의 **확장 fingerprint와 관찰 작업 카운터 불일치0**이다. 원래 unreadable이던 에델 조끼는 `BakeMesh`로 **6,041정점**을 포함했다. oracle 거리 calls=checks는 에델 **28,578**, 세린 **168,844**, 리브 **967**, 유이 **2,388**이며 mismatch0; 에델 braid checks **9,073**, mismatch0이다. 이 짧은 품질 replay는 각 캐릭터의 대표 속도 수치가 아니다. 앞선 긴 회귀에서 유이는 작은 악화가 관찰됐으므로 모든 캐릭터가 빨라졌다고 일반화하지 않는다.

Render/GPU recorder는 유효하지 않았다.

## Player 빌드와 메모리

- 서로 다른 고유 timestamp 빌드의 `SOURCE_HASHES.txt`를 직접 읽었다. reference는 Current `3B945...`, Head `BAD7...`, Hair `321836...`; candidate는 위 채택 세 해시 `6DD7.../E402.../EC7...`이며 probe 소스 해시는 양쪽 동일 `670DAE...`다. `PLAYER_reference_RESULT.json`/`PLAYER_candidate_RESULT.json`은 각 360행, 12발, 재장전3회, exit code0, 서로 다른 전용 temporary save root를 기록한다. Main/GC recorder는 valid, Render/GPU는 invalid다.
- 두 hidden-window Development Player는 AI·날씨·애니메이션 시간이 서로 달라 같은 source pose를 재생한 A/B가 아니다. warm 240행의 frame 평균 **96.53→83.78ms**, Step **68.30→57.89ms**는 관찰값일 뿐 후보의 인과 FPS 개선율로 쓰지 않는다. `ReadPixels` drawing-frame 경고가 난 Player PNG는 시각 증빙에서 제외한다.
- 새 64KiB 시험 할당도 thread allocation API delta **0**이므로 `threadAllocationCounterValid=false`가 맞다. 이전 `allocatedBytes=0`은 무할당 근거가 아니다. native `GC Alloc In Frame` recorder 값은 유효했지만 서로 다른 실제 실행의 할당량을 cache 효과로 단정하지 않는다. 품질 probe가 계산한 에델 prepared Part **3,729,000B**, epoch 배열 **149,160B**, source prepared **128,900B**, braid invariant **224B**의 payload 합은 **4,007,284B**로 배열 헤더·기타 참조를 빼고도 약 3.82MiB다. 메모리 비용과 fresh Bind 지연은 최적화의 실제 tradeoff다.

## 전후 화면과 남은 위험

- 원본 세 소스를 복원한 동일 frozen input의 세부 정면/측면/후면 PNG와 최종 세 PNG의 SHA-256이 각각 **완전히 같다**. 세부 base avatar의 해당 layer 화면에는 시각적 변화가 없다. 이 촬영은 isolated layer31이라 외부 장비·일부 렌더 feature가 제외될 수 있다. 전체 착용 모델과 모든 전투 자세의 외형 동일성으로 확대하지 않는다. 정상 before/final 20기하 digest와 별개의 증거다.
- 세 후보는 프레임 스킵·검사 생략·헤어 숨김·텍스처 하향을 도입하지 않는 좁은 수식 재사용으로 보이며, oracle 및 관찰 카운터는 안전성을 뒷받침한다. 그러나 집계 카운터와 fingerprint가 **모든 후보/trial의 ordered trace를 완전 수집한 것은 아니다**. 개별 contact depth·valid/budget의 전 범위, 드문 morph·장비·본 계층 변경, 장기 epoch 수명과 외부 장비 렌더는 남은 회귀 범위다.
- 기존 braid 비틀림과 팔 음영은 이 최적화로 해결되었다고 승격하지 않는다. 사용자 후속의 별도 캐릭터 담당 수정·검증 대상이다. CPU 절감 뒤에도 Hair Step이 53ms 안팎으로 무거운 solver이며, 실제 플레이 지연을 단일 원인 해결로 보고할 수 없다.

**결론:** 동일 입력에서 소폭 순 CPU 감소와 관찰 범위의 결과 동일성은 채택을 지지한다. 무할당·전체 장비 외형·빌드 FPS 개선까지 확정한 판정은 보류한다.
