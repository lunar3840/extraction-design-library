# 대형 건물 덩굴 증량 제안

상태: 읽기 전용 정책. Unity/장면/소스 수정 없음. 기존 V2 정책을 덮어쓰지 않는다.

근거: BUILDING_SURVEY 69동, V2 전체 23,659행, 최종 ROLLOUT_RESULT 실제 157,099잎. S06 after_S06.png는 23×19m 지붕에 가는 덩굴 흔적이 남는 문제를 보여 준다.

선정: HALL/PARTS/POWER/CLINIC 4개 랜드마크와 조사 면적 400m² 이상 건물을 합쳐 31동. S06(약 437m²) 포함. 나머지 건물 38동, 차량, 소품, 경계의 밀도 정책 유지.

예비 잎 예산: 218,300 → 358,500 (+140,200); 실제 생성 잎 증가량 아님. 각 건물 외벽/지붕 그룹은 계속 유지.

## 제작 해석

- 외벽과 지붕에 여러 불규칙 군집을 분산하고, 실제 불투명 메시 삼각면에 투영한다. 지붕 구멍/없는 메시에는 씨앗을 심지 않는다. 패치는 건물 조사 footprint를 기준으로 한 정규화 좌표이며 실제 메시 표면으로 탐색한 뒤 유효한 것만 쓴다.
- 모든 기존 문·창·시설 게이트 제외 박스를 값 변경 없이 보존한다. 지붕 컷어웨이와 게임 카메라 외피 표시를 재검토하여 가려지는 원본에만 잎이 몰리지 않도록 한다. 추가 덩굴은 비충돌 시각 요소로 유지하고 출입/파밍/동선을 막지 않는다.
- 현행 builder는 정책의 ivyRoots/ivySteps/ivyMaxBranches/ivyClusterPlan을 읽지 않으며 Building roots=32, steps=130으로 다시 제한한다. RuinIvyRecipes.ForTarget의 maxLeaves=6000 제한도 랜드마크 예산보다 낮다. 이 정책은 해당 제한을 직접 고치지 않으므로 Unity 담당자가 범위 제한과 군집 패치 샘플링을 구현해야 실효가 있다.
- 현재 facade 실제 잎 수가 예산보다 낮은 곳이 많다. 예산만 늘린다고 외벽 잎이 자동으로 늘지 않는다. 재생성 뒤 각 그룹의 paths/stems/leaves와 같은 카메라 시점 사진 및 프레임 성능을 확인한다.

- 재생성 검증에서는 실제 잎/줄기 삼각형, renderer 및 draw call, 게임 카메라 프레임 시간을 이전 ledger와 비교한다. 큰 건물의 반복 잎은 기존 공유 재질과 거리별 LOD/배치 정책을 재사용한다.
