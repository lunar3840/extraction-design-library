# 체스트리그·배낭 참조 조사

조사일: 2026-10-23 (Asia/Seoul). 범위: 외부 게임의 수납·접근 구분과 현재 익스트랙션 프로젝트에의 적용 제안. 코드, Unity, Figma, 기존 저장 데이터는 이 조사에서 수정하지 않았다.

## 1. 이번 프로젝트에서 사용자가 확정한 요구

- 기존 여러 칸 퀵슬롯 시스템을 삭제한다.
- V 입력으로 **현재 상태에 맞는 회복품을 자동 선택해 하나만 사용**한다(조사 중 도착한 사용자 추가 답변). **배낭 안 물건은 빠른 사용 후보가 아니다.** 배낭 소모품은 인벤토리에서 직접 사용한다.
- V 자동 선택은 치료가 필요할 때만 한다. 진통제의 예방적 사용처럼 부상이 없어도 가능한 직접 사용은 인벤토리에서 허용한다(사용자 추가 답변).
- 체스트리그는 별도 장착·구매·분실하는 리그 아이템이 아니라 항상 있는 기본 수납 공간이다. 배낭이 없어도 이 공간으로 파밍할 수 있다.
- 체스트리그는 소모품을 미리 준비하는 공간이기도 하다. 이는 ‘소모품만 넣을 수 있다’는 제한을 뜻하지 않는다.
- 배낭은 실제 장착 아이템으로 추가한다.
- 중앙 패널은 체스트리그가 위, 배낭이 아래다. 다른 게임의 복잡한 파우치 모양을 복제할 필요는 없다.
- 최대 배낭 크기까지 고려하여 칸 크기와 화면 배치를 정한다.

위 사항은 외부 게임 분석의 결론이 아니라 이번 사용자 지시다. 아래 외부 게임 규칙이 이 요구를 덮어쓰지 않는다.

## 3. 가져올 수 있는 설계 원리

다음은 자료에서 확인한 ‘리그에 준비한 보급’과 ‘배낭에 담는 전리품’ 구분을 우리 요구에 맞춰 해석한 **기획 제안**이다.

1. **준비한 위치 자체가 접근 권한이다.** 같은 의료품이라도 리그에 있으면 V 사용 후보, 배낭에 있으면 인벤토리 직접 사용이다. 아이템 정의의 치료 효능을 복제하지 않고 현재 소속 컨테이너로 접근 권한을 판단한다.
2. **빠른 사용과 실제 소유 공간을 분리하지 않는다.** 삭제할 퀵슬롯처럼 아이템의 별도 복사본·추가 수납 칸을 만들지 않는다. 리그 안 실제 아이템을 가리키는 단일 선택만 보관한다.
3. **공간 경쟁을 게임 판단으로 만든다.** 리그에 의료품을 준비하면 전리품을 담을 기본 공간이 줄고, 그 공간을 파밍으로 채우면 회복 준비가 줄어든다. 이는 무료 기본 공간이라는 사용자 요구와도 맞는다.
4. **배낭 크기는 전리품 운반 능력으로 표현한다.** 슬롯 수 외에 가격·무게·이동 페널티까지 외부 사례와 같은 값으로 자동 도입하지 않는다. 이번 요청은 배낭 아이템과 용량에 대한 승인이고 구체 경제 수치는 튜닝 제안이다.
5. **외부 리그의 파우치 퍼즐은 복제하지 않는다.** 규칙적인 직사각형 격자로 충분하다. 복잡한 실루엣보다 ‘여기 있는 것은 빠르게 사용 가능’이라는 구분이 먼저다.

## 4. V 자동 회복의 확정 방향과 구현 제안

사용자 추가 답변으로 **상태에 맞는 회복품 자동 선택 후 한 개 사용**이 확정됐다. 별도 수동 고정 슬롯을 만들지 않는다. HUD에는 현재 상태에서 사용될 후보 아이콘 하나와 V를 보여 줄 수 있다. 여러 칸 바·휠·숫자 단축키를 새로 만들지 않는다. 진행 중인 사용 작업에 V를 연타해도 다음 사용을 예약하지 않는다.

- 후보는 리그 안의 실제 아이템만 대상으로 삼고 실제 아이템 식별자로 추적한다.
- 리그 → 배낭 이동, 버리기, 판매, 사망·출격 전환, 소진 때 후보를 다시 구한다.
- 화면에 예고한 후보와 실제 실행 시점의 컨테이너를 둘 다 검사한다. 드래그 중이나 사용 시작 직전 이동으로 배낭 물건을 빠르게 쓰는 우회를 막는다.
- 리그에 상태와 맞는 회복품이 없다면 배낭을 자동 탐색해 사용하지 않는다.
- V 입력은 누르기 시작한 프레임 한 번으로 처리한다. 누르고 있는 동안 연속 소비하지 않는다.
- 사용 시간, 피격 취소, 치료 효과, 사용 중 이동 등은 현재 게임의 기존 소비 작업을 재사용한다. ‘빠른 사용’을 즉시 효과나 무위험 회복으로 바꾸지 않는다.
- 자동 회복은 현재 치료할 상태가 없으면 소모하지 않는다. 직접 사용 경로는 예방 진통제를 허용하므로 이 조건을 공통 사용 함수에 잘못 넣지 않는다.
- 출혈·골절·HP 결손·통증 등이 겹칠 때의 구체 우선순위와 같은 효능의 여러 약품 중 선택 기준은 외부 자료의 확인 사실이 아닌 우리 구현의 제안값이다. 결정적 순서로 두고, 임의로 더 비싼 약품을 우선 소모하지 않으며 HUD 예고와 실제 실행 후보가 같도록 검증한다.

## 5. 용량과 UI를 함께 정하는 방법

최대 크기는 외부 게임 숫자를 옮겨 오기보다 현재 게임의 가장 큰 아이템 크기, 한 판 획득량, 화면에서 유지할 최소 아이콘 크기로 정해야 한다.

첫 비교안(모두 **제안값**, 사용자 확정치 아님): 기본 리그 6×2=12칸, 배낭 4×4=16 / 5×4=20 / 6×5=30 / 최대 6×6=36칸. 리그와 최대 배낭이 합계 8행이므로 두 영역 제목·간격을 포함한 실제 높이를 먼저 계산한다. 6×8 이상으로 상한을 늘려야 한다면 아이콘을 계속 작게 만드는 대신 배낭 영역만 스크롤하는 쪽을 비교한다.

- 배낭 등급마다 그리드 칸의 물리적 크기를 바꾸지 않는다. 작은 배낭은 같은 크기의 칸이 적게 있고 최대 배낭도 같은 크기의 칸을 사용해야 아이템 실루엣과 드래그 감각이 유지된다.
- 리그와 배낭은 같은 칸 크기, 같은 티어 외곽선·배경색, 같은 우측 하단 수량 규칙을 사용한다.
- 제목과 간격으로 두 컨테이너를 구분한다. 모든 칸에 V를 써서 잡음을 늘리지 않고 단일 선택된 아이템에만 작은 선택 표시를 둔다.
- 배낭 미장착 상태는 비활성 격자를 가득 보여 주기보다 ‘배낭 미장착’과 장착 위치를 표시한다. 위의 기본 리그는 항상 사용할 수 있다.
- 배낭을 바꾸거나 벗을 때 넘친 물건을 버리거나 삭제하는 방식은 금지한다. 새 용량에 들어가지 않으면 교환을 거부하거나 기존 보관함으로 명시적인 이동을 완료한 후 교환한다.
- 배낭 자체의 창고 점유 크기와 장착 시 제공 용량은 별도 데이터다. 중첩 가방·접기 기능은 이번 요청만으로 자동 추가하지 않는다.

## 6. 통합 검증에 필요한 사례

| 상황 | 확인할 결과 |
|---|---|
| 배낭 없이 출격·파밍 | 리그 기본 용량 유지, 물건 습득·추출·저장 가능 |
| 동일 약품이 리그와 배낭에 있음 | V는 리그 실제 아이템만 사용; 배낭 수량·내구도 불변 |
| 예고된 약품이 배낭으로 이동 | 후보 재평가, 리그에 맞는 약품이 없으면 V 사용 불가 |
| 치료할 상태 없음 | V로 예방 약품을 자동 소모하지 않음; 인벤토리 진통제 직접 사용은 가능 |
| V 길게 누르기·연타·사용 중 재입력 | 사용 작업 하나만 시작; 여러 개 연속 소비·예약 없음 |
| 배낭 소모품의 직접 사용 | 인벤토리에서 기존 효과·사용 시간으로 정상 사용 |
| 작은 배낭으로 교체·해제 | 넘침을 감지하며 아이템·수량·식별자 유실 없음 |
| 리그/배낭/루팅창/창고 간 드래그 | 서로 다른 컨테이너 목적지를 정확히 구분; 중복·소실 없음 |
| 기존 저장 데이터 로드 | 퀵슬롯 해제와 새 공간 배분 과정에서 기존 물건 보존 |
| 최대 배낭·다중 칸 장비·긴 이름 | 아이콘 최소 크기·간격·툴팁 가독성 유지, 리그 위/배낭 아래 유지 |

## 조사 결론과 남은 불확실성

Delta Force 자료에서 적용할 핵심은 **미리 준비하여 빨리 접근하는 공간과 전리품 운반 공간의 역할 구분**이다. 두 게임의 장착형 리그·주머니 수·파우치 레이아웃·구체 배낭 상한을 우리 게임의 확정 요구로 옮기지 않는다. 아레나 브레이크아웃 최신 모바일/Infinite의 리그·배낭별 빠른 사용 예외는 이번 공식 자료 읽기로 확정되지 않았다. 따라서 우리 게임의 ‘기본 리그 / 리그만 V / 배낭 직접 사용’은 사용자 지시를 근거로 구현하고, ‘다른 두 게임과 동작이 완전히 동일하다’고 보고하지 않는다.
