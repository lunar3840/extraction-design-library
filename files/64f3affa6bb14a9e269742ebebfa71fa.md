# 수색병 T포즈 4면도와 Tripo 스마트 메시 작업 기록

- 사용자 지시: 기존 수색병을 세린 제작 때처럼 별도 4면도 이미지로 준비하고 Tripo에 업로드해 HD 모델 대신 깔끔한 토폴로지의 스마트 메시로 1개 생성한다. 캐릭터 기본 자세는 T자 형태다.
- 대상: 이전 3종 중 기본 수색병(SCAVENGER). 무기 없이 의상과 방독면을 착용한 신규 3D 제작용 참조. 기존 프로젝트 모델이나 Unity 장면을 변경하지 않는다.
- 기획 의도: 네 방향에 동일한 신체 비율과 의상, 수평으로 편 팔을 적용하여 다중 이미지 기반 3D 생성의 형태 모호성을 줄인다.
- 변경 전 자료: before_reference_sheet.png는 기존 수색병 콘셉트 원본 복사본이다. 스크린샷이 아니라 원본 자료 증빙이다. 기존 콘셉트는 전면/후면의 팔이 내려가 있고 별도 좌우 측면이 없어 바로 4면도 입력으로 쓰기 어렵다.
- 변경 전 Tripo 스크린샷 미확보 사유: 2026-10-14 두 차례 컴퓨터 제어 도구가 현재 브라우저 URL을 충분한 신뢰도로 확인하지 못했다며 화면 접근을 차단했다. Chrome 창 목록에서는 Tripo 제목을 확인했다. 정확한 실패 원인을 확인하지 않았으며 Chrome 미실행이나 사용자 오류로 판단하지 않는다.
- 위 차단 시점까지 Tripo 업로드·생성·크레딧 소비는 없었다. 기존 자산 수정도 없었다. 사후 화면을 전 화면으로 재구성하지 않는다.
- 제작 방식: 내장 이미지 생성 도구로 정면, 후면, 인물 기준 왼쪽 측면, 인물 기준 오른쪽 측면을 각각 별도 PNG로 만든다. 원본 콘셉트와 새 정면을 일관성 참조로 사용한다.
- 실제 추가: scavenger_tpose_front.png, scavenger_tpose_back.png, scavenger_tpose_left.png, scavenger_tpose_right.png의 네 방향 단독 이미지와 이를 묶은 scavenger_tpose_4views.zip. 원본 콘셉트는 유지했다.
- 실제 변경 내용: 무기를 제외하고 양팔을 어깨 높이로 벌린 T포즈로 변경했다. 원화의 후드, 방독면, 호박색 렌즈, 청회색 의상, 주황 목천, 회수 배낭과 좌우 비대칭 어깨 보호구를 유지했다.
- 검토: 생성 결과 네 장을 각각 직접 열람했다. 정면/후면은 손끝과 발끝이 모두 보인다. 측면은 인물의 좌우로 정확히 구분하고 팔을 내리지 않고 카메라 방향으로 향하게 해 T포즈의 측면 투영을 표현했다. 큰 회백색 어깨판은 인물 왼쪽, 작은 청회색 어깨 보호구는 인물 오른쪽에 있다. 후면에는 얼굴과 방독면 전면을 그리지 않았다.
- 이미지 한계: 생성형 참조로서 주름·파우치 세부 위치와 손가락 표현에 작은 시점 간 차이가 있다. 물리적으로 일치하는 CAD/3D 정투상 렌더가 아니다. 참조만으로 토폴로지·리깅 적합성이나 최종 3D 품질을 확인했다고 주장하지 않는다.
- 변경 후 증빙: after_tpose_front.png / after_tpose_back.png / after_tpose_left.png / after_tpose_right.png는 각 생성 원본의 복사본이다. 게임 또는 Tripo 화면 스크린샷이 아니다. 기존 before_reference_sheet.png와 비교하면 원화에서 T포즈 4면도로 바꾼 범위를 확인할 수 있으나 같은 카메라의 게임 전후 화면은 아니다.
- 최종 프롬프트 전문: outputs/character_models/2026-10-14/scavenger-tripo-v01/PROMPTS.md.
- 브라우저 연결 추가 진단: 브라우저 전용 도구의 getState가 apps: [], browsers: []를 반환했다. 지원되는 Chrome 브라우저 연결을 요청했으나 'Browser is not available: chrome'으로 실패했다. Windows 창 목록에는 Chrome/Tripo가 존재하므로 '크롬이 꺼져 있다'는 진단은 잘못이다. 연결 부재와 기존 URL 검증 실패의 정확한 인과관계는 미확인이다.
- 현재 Tripo 상태: 업로드 전. 스마트 메시/HD 옵션 화면을 읽지 못했으며 생성 작업 ID, 모델, 3D 다운로드는 없다. 크레딧 사용 없음. 사용자에게 크롬 재실행을 반복 요청하지 않는다.
- 대체 연결 확인: 앱 내 지원 브라우저(iab)도 'Browser is not available: iab'를 반환했다. Chrome 및 앱 내 브라우저 모두 현재 도구에 연결되지 않는다. 브라우저 안전검사를 우회하는 직접 입력/숨은 API 호출은 하지 않았다.
- 파일 확인: PNG 네 장 모두 1254×1254이며 최종 폴더에 복사했다. ZIP에는 방향별 PNG 네 장을 묶었다. 전 자료 1장, 후 자료 4장, CHANGE_RECORD.md의 존재를 확인했다.

## 공식 Tripo 직접 생성 경로 준비

- 사용자 추가 지시: 브라우저를 대신 조작하는 방식에 한정하지 말고 Tripo에서 직접 생성할 수 있는지 확인한다.
- 공식 개발자 문서에서 Tripo CLI와 계정 인증 절차, P Series 다중 이미지 생성 API를 확인했다. 웹 화면 제어 실패와 별개로 공식적으로 제공되는 경로다.
- 도구 준비: 프로젝트의 `work/tripo-cli/`에 공식 npm 패키지 `tripo-cli@0.6.1`을 로컬 설치했다. 설치 스크립트는 실행하지 않았으며 전역 프로그램이나 실행 정책은 변경하지 않았다.
- 인증: 기존 Tripo CLI 인증은 없었다. 공식 기기 인증 절차를 시작하고 사용자에게 Tripo 공식 인증 페이지에서 직접 로그인·Authorize를 요청했다. 비밀번호·API 키를 대화에 입력하도록 요청하지 않았다. 이 기록 시점은 승인 대기 중이다.
- 생성 계획 검증: 네 PNG의 파일명으로 front / left / back / right가 올바르게 매핑됨을 `--dry-run` 결과에서 확인했다. 모델은 `P1-20260311`, 최대 20,000면, 텍스처 및 PBR 켬, standard 텍스처, 생성 후보 1개다. 자동 추가 처리 단계는 없고 경고·오류 없이 valid=true였다.
- 모델 선택 근거: 공식 문서는 P Series를 low-poly, clean topology 용도로 안내한다. 이 선택은 사용자 요청의 저폴리 방향을 따른 것으로, Studio의 Smart Mesh 메뉴를 직접 확인했다는 뜻은 아니다. 실제 모델의 품질과 리깅 적합성은 다운로드 후 확인해야 한다.
- 이 준비 단계에서는 이미지 업로드·3D 생성·크레딧 사용이 아직 없었다. 인증 뒤 계정 상태와 잔액을 확인하고 실제 생성을 진행한다.
- 관련 공식 문서: https://developers.tripo3d.ai/en/docs/cli 및 https://developers.tripo3d.ai/en/docs/generation-multiview-to-model/p .

## 계정 인증 완료 및 잔액 확인

- 사용자가 인증 완료를 알린 뒤 CLI 기기 인증 프로세스의 정상 종료와 `doctor` 결과를 확인했다. API 인증과 국제 리전 서버 연결은 정상이다. 인증 정보는 CLI 기본 사용자 설정에 저장되며 프로젝트 기록에는 비밀키를 저장하지 않는다.
- 별도 잔액 조회 결과도 `balance: 0`, `frozen: 0`이었다. 따라서 검증된 생성 계획을 아직 제출하지 않았다. 이미지 업로드·모델 생성·크레딧 소비·추가 결제는 없으며 작업 ID나 다운로드 모델도 없다.
- 공식 P1 모델 요금표에서 multiview + standard texture = 50크레딧을 확인했다. 공식 API 가격 페이지의 환산은 1크레딧=$0.01, 최소 충전액은 $1이다. 예정된 생성 1회의 기본 비용은 $0.50이며 구매를 실행하지 않았다.
- 공식 FAQ는 Studio와 API가 독립된 결제 체계이며 크레딧을 공유하지 않는다고 안내한다. 사용자의 Studio 잔액은 조회하지 않았고, API 잔액 0을 Studio 잔액 0으로 해석하지 않는다.
- CLI는 신규 계정의 무료 크레딧 수령 또는 충전을 안내하지만, 이 계정의 무료 크레딧 수령 자격·제공 여부는 확인하지 못했다.
- 진행에 필요한 다음 상태: API 잔액 50크레딧 이상. 인증을 다시 요청할 필요는 없다.
- 증빙 한계: 이번 확인은 공식 CLI의 텍스트 응답이다. 브라우저 스크린샷으로 위장하거나 새로운 전후 스크린샷을 확보했다고 기록하지 않는다. 기존 참조 전 자료 1장, 생성 후 자료 4장과 본 기록은 유지했다.
- 근거: https://developers.tripo3d.ai/en/models/p1 , https://developers.tripo3d.ai/en/pricing , https://docs.tripo3d.ai/other/support-faq.html .
