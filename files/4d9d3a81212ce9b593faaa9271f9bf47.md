## 사용자 지시와 기획 의도

사용자는 기존 Figma 시안에서 사용한 반투명 UI를 참고해 데이터 편집기 웹을 같은 스타일로 깔끔하게 제작하도록 요청했다. 익스트랙션의 기존 Modern Glass Kit와 시각적 일관성을 만들고, 불투명한 어두운 패널·작고 흐린 보조 글자·황색 중심 강조를 정리한다. 데이터 편집·저장 기능이나 게임 밸런스 변경은 이번 요청에 포함하지 않는다.

## 변경 전 상태와 증빙

기존 화면은 불투명한 남색 패널, 각진 경계, 황색 선택/주 버튼, Segoe UI/Malgun Gothic 계열이었다. 보조 정보가 작고 대비가 낮았다. 스타일 수정 전에 실제 브라우저의 플레이어 실제 설정 화면을 `before_editor.png`로 촬영했고 CSS·HTML·JavaScript·서버 원본을 `source_before/`에 보관했다. 이후 비교도 같은 기본 viewport 1280×720과 동일한 선택 항목·값100에서 촬영했다. 재구성본을 사용하지 않았다.

로컬 서비스가 종료된 상태여서 기존 실행기로 다시 시작했다. 이때 다른 캐릭터 작업에서 이미 추가된 BackSurfaceRuntime 원본이 자동 색인되어 이전103개에서104개 테이블이 됐다. 이번 디자인 작업이 게임 원본이나 해당 수치를 추가·변경한 것은 아니다. 시작 전후 데이터 폴더 해시는 `DATA_HASHES_BEFORE.json`, `DATA_HASHES_AFTER_STARTUP.json`에 구별해 보관했다. 이후 스타일 작업 중 기존 CSV들의 바이트와104개 테이블의12,956개 값은 모두 유지됐다.

## 참조 확인

공식 Figma 도구로 [기존 Modern Glass 시안](https://www.figma.com/design/KUD4t84BL1S77c3cnb8co0?node-id=105-2987)의 현재 코드와 스크린샷을 함께 읽었다. 기존 프로젝트의 동일 시안 연결 기록과 대조했다. Figma 파일은 읽기만 했으며 Unity 편집기·씬·게임 에셋은 수정하지 않았다.

회청색 패널 rgba(100,112,128,.44), 흰색6% 내부 표면, 흰색16% 경계, 민트 #72ebd1, 주 글자 #f5f7fb, 보조 글자 #c5cdd7, 배경 블러32px와 기존 인셋/그림자·둥근 모서리를 CSS로 번역했다. 세부 대응은 `DESIGN_REFERENCE.md`에 있다. Figma 스크린샷·캐릭터·아이템 그림을 웹 배경 자산으로 사용하지 않았다.

## 실제 변경과 방식

- `style.css`를 기존 DOM·클래스·ID에 맞춰 재작성했다. 분류·표·상세의3단 구조를 분리된 둥근 유리 패널로 정리하고 CSS 색광·수직 면으로 배경 깊이를 구성했다.
- 선택 항목과 주요 동작은 민트색, 미저장·주의는 황색으로 구분했다. 입력·선택·조회 전용·오류·대화상자·이력·토스트도 같은 표면과 경계로 통일했다.
- 본문12~13px, 보조10~11px의 읽기 쉬운 글자와 Noto Sans KR을 적용했다. 기존 프로젝트 글꼴 Regular/Bold를 그대로 복사하고 FONT-LICENSE.txt/OFL.txt를 함께 보관했다. `FONT_ASSETS.json`의 해시는 기존 글꼴과 일치한다.
- 1280×720에서 제목·요약 영역을 압축해 표 영역을242px로 확보했다. 본문4행과 상태 열을 기본 노출한다. 이 폭에서 중복되는 적용 범위·원본 열은 상세 패널과 필터에서 확인하도록 표현을 줄였다. 넓은 화면에서는 전체 열을 표시한다.
- 1100px 이하에서는 상세 패널을 표 아래로 배치한다. 필터·CSV 버튼을 숨기지 않으며 작업 버튼을 하단에 유지한다. 실제960px 화면에서 페이지 가로 넘침 없이 상세 입력과 하단 작업 버튼에 접근했다.
- 블러 미지원 시 불투명 대체 표면, 모션 감소 설정, 키보드 포커스와 `[hidden]` 상태를 유지했다.
- 서버는 정확히 두 글꼴 경로와 font/ttf 형식을 추가했고 기본 안내 문구를 간결하게 다듬었다. 없는 정적 파일의404/스트림 오류도 처리한다. CSV·검증·저장·게임 반영 로직과 app.js 이벤트 코드는 바꾸지 않았다. HTML에는 theme-color만 추가했다.

## 확인 결과

1. 기본1280×720 실제 렌더: 세 패널·선택·표4행·상태 열·CSV 버튼·필터·하단 버튼이 겹치지 않고 보인다. 글꼴 로딩 완료와 실제 적용 family를 확인했다.
2. 960×720 반응형: CSV 가져오기·내보내기와 원본 필터가 표시된다. 상세 패널이 아래에 존재하며 스크롤 후 실제 입력을 클릭해 값100이 정상 표시되고 하단 버튼에 가리지 않음을 확인했다. 검증 후 viewport를 원래 기본 크기로 복구했다.
3. 검색 MaxHealth로1행을 찾았다. 값100→110을 임시 입력해 미저장 상태·변경 비교창·정확한 대상 파일을 확인했다. 게임 반영은 누르지 않고 돌아가기와 실행 취소로100/대기0을 복구했다. CSV 저장도 수행하지 않았다.
4. CSV 가져오기 창의 입력칸·파일 선택·취소·버튼 배치를 확인하고 취소했다.
5. 브라우저 오류 로그는 빈 배열이었다. 서버·app.js 구문 검사 통과. 두 글꼴 요청은 HTTP200, font/ttf, 원본과 같은 바이트 수였다.
6. 디자인 전후12,956개 항목의 편집값·원본값 변화0, 기존 CSV 파일 변화0, 반영 대기0, 원본 외부 변화0, app.js 바이트 동일을 확인했다. 상세는 `VALIDATION.json`에 있다.
7. 독립 검토자가 첫 결과의 표 표시량 감소를 지적했고 제목/요약 압축으로 수정했다. 갱신된 PNG를 다시 읽어 Figma 스타일 일치·표4행/상태 표시·겹침 없음·입력 대비를 확인하고 시각적 차단 문제 없음으로 판정했다. 960px 동작은 메인의 실제 브라우저 확인이다.

Unity 재컴파일·실게임 밸런스 검증은 요청 범위가 아니며 수행했다고 주장하지 않는다. 변경 효과는 웹 UI의 전후 화면과 기능 유지로 확인했다.
