# COMBAT-01 코드·호환성 독립 검토

검토 대상: `staging/COMBAT01_DRAFT.diff`, `staging/EnemyController.cs`, `staging/AMapCombat01Regression.cs`와 현재 `EnemyController.cs`, `HitscanService.cs`, `DamageReceiver.cs`, 진영·체력 추정 코드. 생산 통합과 Unity 실행의 소유자는 메인이다.

## 정적 판단

현재 수정 범위에서 추가 P1/P2 문제는 찾지 못했다. 기존 `IsHostile` 정책을 재사용해 실제 최초 피격자만 처리하므로 별도 진영 관계나 사격 선택 규칙을 만들지 않는다.

- **동진영·자기 자신:** `IsHostile`가 자기 Receiver, 사망자, 같은 진영을 제외한다. 광선은 기존 `HitscanService.Nearest`에 shooter transform을 전달해 자기 자식 collider를 무시한다.
- **벽·무관통:** 가장 가까운 collider 하나만 평가한다. 벽·동진영·사망자에 피해를 주지 않는 경우에도 뒤 collider를 다시 탐색하지 않는다.
- **중복·부위:** 펠릿마다 광선의 최초1개만 `Receive`하고 기존 GUID·실제 hitbox.region을 유지한다. 산탄6펠릿의6개 피해와 겹친 hitbox로 인한 동일 펠릿 중복은 구분한다.
- **이벤트·귀속:** 기존 Receiver.Receive와 공격자 Receiver를 그대로 사용한다. 실제 피해 이벤트·최근 공격자·사망 통지는 실제 피격자에게 전달되고, NPC 최종타를 플레이어 킬로 바꾸지 않는다.
- **플레이어 피해 추정:** chosen 신분 대신 실제 receiver.player를 검사한다. 실제 플레이어 피해만 개인 관측치에 반영하며 NPC 피격량을 플레이어 피해로 오인하지 않는다. 플레이어의 실제 총체력·장비 수치는 읽지 않는다.
- **legacy:** 비encounter 배우는 기존 chosen 자식 명중 제한을 유지한다. A맵 encounter의 Human/Machine/Player 적대 판단과 기존 테스트 배우의 플레이어 전용 범위를 구분한다.
- **변경하지 않은 범위:** 피해량·탄종·부위 배율·발사 빈도·탄약·표적 전환·기계 역할 사격·전조·소리·탄흔은 유지한다.

## 검사 도구 확인

Unity 컴파일에서 드러난 `PlayerSettings` 이름 충돌은 `using PlayerSettings = Escape.Player.PlayerSettings;`로 명시했다. 수정 후 Unity6000.1.0f1 내장 Roslyn과 현재 Bee Editor 참조 DLL로 외부 컴파일하여 exit0, 오류·경고 출력0을 확인했다. `staging/EXTERNAL_COMPILE_RESULT.json`에 소스/출력 지문과 한계를 남겼다.

외부 컴파일은 실제 Unity refresh·Play 단언의 성공을 대신하지 않는다. 실제 플레이어 대신 독립 PlayerMotor/PlayerRules를 만들고, 생성한 시험 객체는 finally/Dispose에서 제거한다. 과거 원문 결과를 덮어쓰지 않는다.

## 최종 판단과 한계

**COMBAT-01 수정 수용 PASS.** 실제 피격 대상의 적대 판정·피해·공격자·사망·개인 플레이어 관측이 복구됐고, 같은 진영/벽/자기/legacy·기존 전투 회귀가 유지됐다. 추가 생산 수정은 필요하지 않다.

이는 격리된 실제 물리/무기 경로의 통제 검사다. 자연 출격의 교전 빈도·전체 난도·모든 지형·성능을 검증한 것으로 확대하지 않는다. 시각 전후 증빙과 다른3건의 통합 검토·공유 Unity 복구·라이브러리 게시 상태는 메인의 상위 변경 기록에서 관리한다. 이 담당은 생산 파일이나 Unity 실행 상태를 직접 변경하지 않았다.
