## 사용자 지시와 기획 의도

적·플레이어 스탯을 CSV로 모으고, 예시처럼 카테고리 목록·표·상세 패널이 있는 시각 편집기를 만든다. 경제 등 다른 변동 수치도 종류별로 편입한다. 첨부 백팩 크롤러 화면은 UI 구성의 참고로만 사용했으며 그 게임의 아이템·규칙·수치를 익스트랙션에 옮기지 않았다.

값이 JSON·Unity 설정 에셋·코드에 흩어져 있어 가격이나 적 스탯을 한 곳에서 찾기 어렵고, 기본값과 실제 설정·후속 튜닝을 혼동하기 쉬운 문제를 해결한다. CSV 보관과 실제 게임 반영을 구분하면서 출처를 추적할 수 있게 한다.

## 변경 전 상태

실제 프로젝트는 `C:/UnityProject/escape`다. Resources 카탈로그, Settings와 Runtime 코드가 수치의 원본이었다. 전용 수치 웹 편집기는 없었으며 기획 라이브러리는 문서 조회용이었다. 첫 수정 전에 WeaponCatalog 원본을 읽기 전용 로컬 화면으로 표시해 `before_editor.png`를 촬영했다. 이 화면은 실제 작업 전 JSON이며 사후 복원본이 아니다. 신규 편집기와 비교할 이전 동일 UI가 없으므로 전후 화면의 구조는 다르다.

## 실제 변경과 방법

- 작업 폴더의 `data-editor/`와 실행 바로가기를 신규 제작했다. 기존 기획 라이브러리나 Unity 원본의 게임 수치는 수정하지 않았다.
- 11개 상위 분류 아래 103개 실제 원본, 12,926개 스칼라 항목을 수집했다. 편집 가능 8,134개이며 나머지는 식별자·참조·현재 DTO에서 쓰지 않는 이전 필드·배치 참조 등의 조회용 항목이다. 행 수는 적/아이템 수나 실행 중 최종 스탯 수가 아니다.
- JSON 9개, Settings 에셋 2개와 게임플레이 C# 리터럴을 원본 위치·필드·자료형·문맥과 함께 연결했다. JSON 중첩·알 수 없는 필드·문자열 이스케이프·숫자 형식과 C# 접미사 등은 값의 정확한 위치만 교체해 보존한다.
- 왼쪽 종류별 목록, 가운데 검색·필터·페이지 표, 오른쪽 상세 편집과 적용 범위를 제공한다. 주요 플레이어 항목의 한국어 라벨, 자료형별 입력, 실행 취소/다시 실행, 미저장 복원, CSV 가져오기/내보내기와 이력을 추가했다.
- CSV는 `data/*.csv`, 분류·이름·원본·파일 대응표는 `data/TABLE_INDEX.json`에 저장한다. 원본과 CSV 비교 기준은 `source-baseline.json`에 보관한다.
- CSV 저장은 원본을 바꾸지 않는다. 변경 검토 화면에서 전후 값과 대상 파일을 확인한 뒤 최종 반영해야 원본이 바뀐다. 해시 충돌·오래된 화면·자료형·정수 범위·알려진 카탈로그 제약을 검사하고 반영 전 백업·반영 후 재추출 검증을 수행한다.
- 인터넷 업로드 없이 127.0.0.1에만 연결한다. 실행기는 이 PC의 Node.js/Codex 번들 Node.js를 찾는다. 공유 Unity 편집기·검증 요청 파일·실행 상태는 사용하거나 바꾸지 않았다. 관련 UI/캐릭터 채팅에는 파일 소유 범위와 미사용 상태를 직접 전달했다.

## 확인 결과

독립 자동 검증 **25/25 통과, 실패 0개**. CSV 한글/BOM/여러 줄/인용 왕복, 자료형·정수·카탈로그 교차 제약, CSV만 저장, 원본 반영·백업·복구, 외부 원본 충돌, 새로고침·재실행 대기 편집 보존, 누락 편집 보존, HTTP 경계를 확인했다. 실제 소스 복사본에도 적용/재추출 검사를 했다. 실제 Unity 원본 222개 파일의 바이트 불변 확인을 완료했다. 상세는 `INDEPENDENT_REVIEW.md`, 재현 결과는 `VERIFICATION.json`, 재실행은 `data-editor/verify.mjs`다.

브라우저 실제 화면에서 플레이어 실제 설정의 MaxHealth를 100→110으로 편집하고 CSV 저장했다. catalog의 CSV 값 110 / 게임 원본 값 100을 동시에 확인했고 `PlayerDefaults.asset`의 `MaxHealth: 100`도 직접 확인했다. 변경 비교창의 100→110과 대상 파일 표시를 촬영했다. **실제 게임 반영은 누르지 않았다.** 검증 후 CSV를 100으로 다시 저장해 게임 반영 대기와 미저장 항목을 모두 0으로 복구했다. 이력의 두 번 CSV 저장은 이 UI 검증 기록이며 게임 반영 이력은 없다.

검색으로 플레이어 MaxHealth 1행·무기 피해량 37행·거점 거래 유전자 가격 15000의 코드 원본을 찾았다. 실행 취소는 110→100, 다시 실행은 100→110을 표시하고 다시 100으로 복원했다. 주요 화면을 실제 PNG로 검토했다. 입력 상태가 즉시 갱신되지 않던 문제를 입력 이벤트로 수정했고, 입력 칸에서 다른 목록으로 이동할 때 클릭이 사라지던 부분도 후속 검수했다. 최종 화면과 오류 로그 확인 결과는 `BROWSER_VERIFICATION.json`에 보관한다.

## 적용 범위와 남는 구분

수집한 C# 행은 기본값·수식 계수 후보다. 런타임 계산의 최종값이나 씬/프리팹·세이브의 개별 재정의 전체를 수집한 것은 아니다. 설정 우선순위·실내/역할별 후속 튜닝·현재 비활성 문턱은 원본 문맥과 함께 확인해야 한다. Unity 원본 수치를 바꾸지 않았으므로 이번 도구 검증을 Unity 컴파일·실게임 밸런스 변화 검증으로 표시하지 않는다. 개별 값을 실제 반영한 뒤에는 Unity 재로딩·컴파일·초기화와 실게임 효과를 확인해야 한다.
