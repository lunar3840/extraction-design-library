## 제작·개선·재사용 구분

1. **건물 68동:** W10과 같은 순서로 ID별 콘셉트·실제 프레임·문·실내·지붕·재질 계약을 확정한 다음 외벽/지붕/실내를 함께 개선한다. 10개 군의 재료 언어를 쓰되 건물별 기능과 손상도를 달리한다. 회색 공통 공장 칸막이로 덮지 않는다. HALL은 크레인·다층/지하·중앙 채광 지붕을 가진 별도 랜드마크로 취급한다.
2. **도로·지형·수변·경계:** 기존 높이·충돌·교량·진입점 물리 계약을 재사용한다. 실제 시각 품질이 부족한 구간만 타일/모듈 단위로 재제작하고 물·날씨 효과는 전후 화면에서 판단한다. 일괄 FBX 변환만으로 개선 완료라고 처리하지 않는다.
3. **엄폐·잔해·가구·설비·자연물:** 이미 배치된 소품/Tripo/Factory/Look/D14 메시를 우선 재사용하거나 재질·접합·LOD를 개선한다. 새 모델은 중복 표현을 줄이고 기존 엄폐/시야·전리품 접근·NPC 이동을 깨지 않는 범위에서 추가한다.

## 다음 실측과 통합 계약

[StageAEnvironmentSurvey.cs](StageAEnvironmentSurvey.cs)는 **staging 소스**다. `Escape.EditorTools.StageAEnvironmentSurvey.Inspect()` 또는 `Export()`를 메인이 공유 Unity 사용권을 확보했을 때 `Assets/Escape/Editor`로 복사·실행하면, 로드된 현재 씬에서 69개 실제 외벽/지붕 프레임과 RoofCutaway 부모, 문 관련 renderer bounds, 원래 개구를 가로지르는 9개 높이/가로오프셋 물리 ray 결과, 보존 바닥, 실내 collider keepout, 50개 loot 배치점의 raycast hit, 환경 루트별 고유 mesh/material 수를 새 `survey/LIVE_INSPECTION_###.json`에 쓴다. 기존 파일을 덮어쓰지 않는다. 오프라인 Roslyn 컴파일은 오류 0으로 통과했다. Unity 런타임/Editor 실행 결과는 아직 없다. 물리 ray만으로 시각 메시의 실제 구멍 폭을 확정할 수 없으므로 `doorMeasuredCurrent`와 `geometryVerifiedCurrent`는 의도적으로 false로 출력한다.

같은 staging 소스의 `ExportGeometry()`는 W10을 제외한 **현재 활성 68동**의 `D09_Facade_ID` 및 `D09_Roof_ID` 아래 실제 MeshRenderer/MeshFilter 메시를 현재 D09 프레임의 vertex/normal/UV/submesh 삼각형, material slot, 메시 GUID와 local file ID, 재질 색·금속성·매끈함·기본/법선/금속 texture 경로로 별도 `LIVE_GEOMETRY_###.json`에 출력한다. D10 교체/추가 메시가 D09 루트 안에 들어 있으므로 **오래된 D09 Blender JSON만 재제작하면 현 파손·표면 디테일이 퇴행**한다. 읽을 수 없는 현재 메시나 slot 불일치는 오류 파일을 남기고 중단하며 importer 설정은 수정하지 않는다. 이 메서드도 오프라인 컴파일만 통과했고 Unity 실행은 아직 하지 않았다.

별도 [StageARendererMetadata.cs](StageARendererMetadata.cs)의 `ExportRendererMetadata()`는 기존 메서드 계약을 변경하지 않고, renderer path+mesh GUID/local file ID를 키로 Collider 유무/원본 메시, shadow casting/receive shadows, material render queue를 `RENDERER_METADATA_###.json`에 기록한다. D10 얼룩처럼 collider가 없고 그림자를 끄는 시각 요소를 구조물과 구별할 수 있게 한다. 오프라인 컴파일 오류 0이며 Unity 실행은 메인 담당이다.

제작 확정에는 각 건물의 실제 문 개구부 폭·높이·턱과 양측 발 위치, 원래 지붕 컷어웨이/가림 상태, 보존할 floor visual·collider, 가구·설비·전리품 keepout, 현재 메시 기준 통로/NPC 동선의 확인이 필요하다. Unity에서 외부·실내 동일 카메라 전후 화면, renderer/Collider/메시 bounds, 50개 파밍 접근, NavMesh·실제 플레이어 경로와 시야를 검증해야 한다. B4와 R8은 약 62m 떨어진 비교 지점이고 **R8은 현재 스폰 후보에서 비활성**이다. 프리팹에 R8 앵커 GameObject가 활성이라는 사실을 스폰 활성으로 해석하지 않는다. B4/R8→W5 초기 동선·위험 구별은 환경 배치 때 재검토한다.

이 조사는 제작 전 inventory다. 변경 전후 스크린샷과 `CHANGE_RECORD.md`는 실제 후보 적용·검증 단계에서 동일 시점으로 남겨야 하며, 현재 산출물을 전체 맵 교체 완료 또는 게시 완료로 취급하지 않는다.
