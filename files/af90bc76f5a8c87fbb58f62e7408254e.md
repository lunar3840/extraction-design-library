# A맵 파밍 용기·금고·동료 회수 칩

2026-10-21. Unity 적용·실제 플레이 검증·독립 게임플레이/시각 검토 완료. 최종 승인 범위와 증빙 한계는 아래에 기록한다.

## 지시와 기획 의도

사용자는 델타포스 비콘 에어리어의 수색 용기 종류를 참고해 무기상자·의료상자·책상서랍 등 여러 형태의 파밍 포인트를 A맵에 배치하고, 핵심 시설의 금고는 고가품 가능성이 다른 상자보다 높되 확정은 아니게 하도록 지시했다. 구역별 Edel/Liv/Uui 완전 데이터 칩, 특정 보스의 해당 파편 확정과 완전 칩 확률 획득도 요청했다. 서브 에이전트는 사용자 지정 GPT-6.1 Sol extra high로 배정했다.

메인은 기획·소스 통합·Unity 실행·화면 검토를 맡고, 분리된 staging에서 게임플레이·용기 외형·배치 및 독립 검토를 병렬 수행했다. 서브 에이전트는 production Assets나 Unity를 직접 수정하지 않았다.

## 변경 전 실제 상태

조사 결과 기존 구현에는 33개 건물에 출격별 42개 유한 상자를 생성하는 코드와 7종의 상자 스타일이 있었다. 실제 격리 A맵 출격에서도 42개 생성됨을 `before_actual_spawn.txt`로 확인했다. 따라서 ‘기존에는 몹만 파밍 가능했다’고 기록하지 않는다. 기존 잠금 valuables 케이스는 금고와 다른 휴대함이며, 무기상자·서랍·금고·컴퓨터 본체의 고유 외형과 탐사 칩/파편/복원은 없었다.

`before_editor.png`는 진단 도구 설치 전 실제 원본 편집 화면이다. 수정 전 실제 Play에서 일곱 장소를 촬영했고, 초기 촬영의 상부 바닥/지붕 가림은 `diagnostic_initial_occluded/`에 분리했다. 실제 용기 모델/내용물 변경 전에 가림을 정리한 진단 카메라로 일곱 장을 다시 촬영했다. 사진용으로 카메라와 물체 사이의 건물 Renderer만 일시 숨겼고, 원본 씬/프리팹/콜라이더는 바꾸지 않았다. 전후 동일 촬영 처리를 사용한다. `camera_*.json`에 카메라 위치·회전·화각을 고정했다. 무작위 진입에 따른 미니맵·실행 시간과 적 자세는 달라질 수 있다.

`before_catalog_*.png`는 동일 조명·배율 진열이다. 새 스타일 이름을 구버전 시각 생성기에 넣으면 예전 보급상자 기본형으로 표시되므로, 해당 진열이 과거에 금고/서랍 등이 이미 존재했다는 증거는 아니다. 실제 전 상태의 배치는 Play 사진과 42개 생성 기록을 따른다.

## 적용 내용

- 기존 42개 ID/건물/좌표/검색 반경/난도/내용물 풀을 보존하고 8개 포인트를 추가하여 출격당 50개, 실제 건물 33곳을 사용한다.
- 금고 5개: 중정비동 HALL, 전력 POWER, 정밀부품 PARTS, 기술자료 N11, 진료소 CLINIC. HALL은 기존 핵심 작업장 귀중품함 자리를 교체한다. 경비 무기 케이스는 W10/E05/Y02에 추가하며 PARTS 예비 탄약함도 추가한다.
- 시각 용기 13종: 무기 케이스·의료함·서랍·금고·공구함·컴퓨터 본체·사물함·가방·전자장비함·보급함·귀중품 케이스·잔해·탄약함. 기존 메시 제작 API와 군용 상자, 복제한 기존 목재/금속/에나멜 텍스처를 활용하고 원본 건물 재질은 보존한다. 모든 모형은 기존 1.2×0.8×0.9m 예약 외피 안에 맞추며 새 고체 엄폐를 추가하지 않는다.
- 칩 구역: Edel=HALL/PARTS/N11/E06, Liv=POWER/N08/N12/N14/E01/E03, Uui=CLINIC/N03/N05. 다른 지역 및 Serin은 신규 칩 풀에서 제외한다. 이 연결은 시험 배정이며 캐릭터의 공식 속성이나 영구 요구로 취급하지 않는다.
- 초기 확률: 해당 일반 상자 완전 칩 1%, 해당 금고 3%. 금고는 기존 귀중품 풀에 별도 35% 고가품 추가 추첨을 적용한다. 금고의 고가품은 확정이 아니며 35%가 최종 고가품 발견률을 뜻하지 않는다. 기존 풀에서도 고가품이 나올 수 있다.
- 지정 보스 롤백 N2→Edel, 차단기 N3→Liv, 봉인자 N4→Uui. 실제 출격에 선택되어 등장한 해당 보스의 사망 전리품에 같은 칩 조각 1개 확정, 완전 칩 8%를 별도로 적용한다. 보스 출현 확률·홈·전투는 유지한다. N1/N5에 신규 칩 보너스를 확대하지 않는다.
- 같은 동료의 보호되지 않은 파편 5개를 거점에서 완전 회수 칩 1개로 복원한다. 보관함 우선 소비, 결과 공간 확인, 단일 저장 성공 후 반영으로 저장 실패/공간 부족 시 파편이 사라지지 않도록 한다. 연구 화면의 ‘데이터 칩 복원’ 탭에서 수집량·획득처와 복원 버튼을 제공한다.
- 신규 완전 칩은 ‘미정화 회수 칩’ 화물이며 기존 장착용 정화 동료 칩과 구별한다. Liv/Uui의 모델·정화/동료 해금 기능을 새로 완성했다고 표현하지 않는다. 현재 진행 중인 Edel 변신과 저장 키 prototype, 기존 동료 선택 기능은 유지한다.

B1~B4와 R 비활성, 기존 73개 적 슬롯/동선·네임드 홈·건물·NavMesh·진입/탈출 정책·V38 날씨·V39 카메라를 유지한다. B4/R8 약62m 및 W5 공유 기준을 다시 검토하고 새 금고를 초입/W5에 배치하지 않았다. 낮은 난도 생활권 보급과 외곽 전력/부품 고난도 목적지를 구별한다. 실제 새 위치의 바닥·문 간격·벽/가구 겹침·접근 경로는 별도 Unity 검증으로 판정한다.

## 검증

현재까지 실제 규칙을 사용하는 독립 20,000시드 계산에서 동료별 완전 칩은 일반 약1%/금고 약3%/보스 약8%였다. 같은 등급 귀중품함의 A/S 고가품 발생은 54.745%→금고70.665%였고 금고 29.335%는 해당 고가품이 없었다. 이 수치는 맵 전체 수익이나 장기 캐릭터 획득 속도가 아니다. 자세한 표와 한계는 `staging/gameplay/tests/PROBABILITY_TEST_RESULTS.txt`를 따른다.

최신 원본 Unity에서 다음 검증을 완료했다.

- `PLACEMENT_CHECKS.txt`: 실제 50개 상자의 바닥·전체 외피·문·벽/가구 겹침·접근 내비게이션·시야와 209개 적 전리품 후보를 포함하여 **2,010 PASS / 0 FAIL**. 추가 8개 위치가 같은 건물/같은 층 안에서 해결됐다. `RESOLVED_PLACEMENTS.csv`에 실제 좌표·접근점·문·지지 바닥·보정량을 저장했다.
- B4에서 가장 가까운 기본 보급 경로는 33.91m로 동일하고, 1단계 이상 파밍점은 새 W10 무기 케이스까지 88.26m(기존89.64m)다. 비활성 R8의 비교는 97.28m/51.04m다. 기존 W5 공유와 적 노출·엄폐·탈출 정책은 유지한다.
- `CHIP_CARGO_CHECKS.txt`: 칩/파편 정의, 결정적 확률, 보호 파편 제외, 단일 저장, 저장 실패/공간 부족 원상 보존, 탈출/사망 및 JSON 저장 검사 **60 PASS / 0 FAIL**.
- 기존 회귀: `EscapeLootChecks.txt` 48, `EscapeLootEquipmentChecks.txt` 81, `EscapeLootEconomyChecks.txt` 1,221, 합계 **1,350 PASS / 0 FAIL**. 검색·실물 개체/무기·장비 이전·기존 연구와 물품 경제의 호환성을 확인했다. 전체 게임의 모든 기능을 재검증한 것은 아니다.
- `container_art_build_validation.txt`: 13종 모두 예약 외피/바닥 기준과 비충돌 시각 모형 검사 PASS. 각 모형의 Renderer/삼각형 수를 기록했다. 기존 군용 탄약 상자만 실제 수입 메시를 재사용하고, 나머지는 베벨·다이얼·손잡이 등을 조합했다.
- `ACTUAL_CHIP_LIFECYCLE.txt`: 실제 격리 A맵 출격 50개 생성 → 금고의 실제 시간 수색/Interactor 회수 → 선택된 보스 DamageReceiver 처치 → 중복 사망/드롭 방지 → 실제 보스 전리품 UI 수색·회수 → 4초 탈출 흐름 → 거점 복원 → 실제 LocalProfileStore 디스크 재로드를 **37 PASS / 0 FAIL**로 완료했다. 이 최종 본문은 N3/차단기·시드491이다. HALL 에델 칩과 보스 리브 칩을 보여 주려고 조건에 맞는 시드를 명시적으로 선택했으며 무작위 첫 시도 행운으로 표현하지 않는다. 복원 검사에는 실제 수집한 파편1개에 시험용4개를 더했다. 이4개는 실제 파밍 수익이 아니다. 사용자 정상 저장 대신 StageMapPreview의 고유 임시 저장 폴더만 사용했다.
- 복원 뒤 Session.Bag만 바뀌고 UI의 가방이 옛 객체를 참조할 수 있는 결함을 독립 검토에서 발견했다. 기존 CampMutation/BindPlayer 경로로 고쳤고 실제 UI 경로에서 객체 동일성·소비된 파편·새 칩·디스크 재로드가 일치함을 검증했다.
- 최초 복원 성공 문구가 공통 상태 번역기의 기본 실패 문구로 표시되던 문제와 새 칩이 일반 물품 가방 아이콘으로 표시되던 문제를 실제 화면에서 발견했다. 전용 성공 키와 칩/파편 도형 아이콘으로 수정했다. `ui_readability/`에 수정 전/후 화면을 저장했다. 화면의 제어 시드·보스 종류/수량은 서로 다를 수 있어 동일 재고의 픽셀 비교로 주장하지 않는다.

공유 원본 편집기에서 별도 Edel 검증이 같은 시점에 Play를 전환한 중간 호출은 완료 검증으로 세지 않았다. 이쪽 캡처 감시만 취소하고 원래 씬/저장을 보존했다(`CAPTURE_EXTERNAL_INTERRUPTION.txt`). 작업 순서를 조율한 뒤 실제 촬영과 위 순환 검증을 새로 완료했다. Edel 쪽은 별도 검증 환경을 사용하며 이쪽 반환까지 원본 사용을 보류했다. 기존 동료 선택 관련3파일은 `PRESERVED_COMPANION_FILES.json`의 전후 해시가 동일하다.

첫 N4 시험은 모든 NPC를 동결하고 자동 틱을 끈 상태로 사망시켜 본래의2초 충돌체 해제/3.6초 정리까지 멈추는 시험 조건 문제가 있었다. 실제 데이터 회수는 통과했지만 UI를 직접 열지 못하고 public LootState 경로를 썼으므로 `diagnostic_initial_lifecycle/`에 한계를 명시해 보존했다. 최종 N3 순환에서는 두 전리품 모두 실제 UI를 열도록 필수 조건을 강화하고 직접 상태 우회를 제거했다.

추가 정상 사망 정리 검증은 `strict_n4_lifecycle/`에 저장했다. 폴더명은 N4 우선 재시도 의도이지만 해당 출격에 N4가 없어 실제 선정된 **N2/롤백·시드1849**로 실행했다. 실제 사망 후 자동 틱을 재개하고 게임 시간2.2초를 기다려 원래 충돌체 정리가 동작함을 검사했다. 그 뒤 금고와 보스 모두 실제 LootInteractor 수색 UI로 열고 조각/완전 칩 회수·탈출·복원·UI 가방 연결·디스크 재로드까지 통과했다. N4 전용 실제 UI 재검증을 완료했다고 주장하지 않는다. 게임의 시체·벽 시야 규칙을 완화하는 예외는 구현하지 않았다.

## 관련 증빙과 주요 파일

실제 전후 일곱 장소: hall_overhaul / clinic_records / power_cells / n11_data / parts_security / w10_shipping / s01_dorm. 파일은 `before_loot_<장소>.png` ↔ `after_loot_<장소>.png`. 진열은 `before_catalog*.png` ↔ `after_catalog*.png`. 신규 획득/복원 동작의 후 상태 사진은 별도로 구별한다.

육안 검토에서 직접 비교에 유효한 실제 맵 구도는 HALL/POWER/PARTS 3쌍이다. CLINIC/N11/W10/S01 4쌍에는 기존 지붕·상부 구조가 가려지는 한계가 있어 유효한 모델 전체 비교로 주장하지 않는다. 이들은 제한된 진단 증빙으로 분류했다. 이후 `after_detail_loot_*.png` 11장에 시각 가림을 조정한 후 상태 전용 사진을 추가하여 나머지 시설·금고4곳·무기상자3곳을 확인했다. 이 추가 사진을 수정 전 이미지로 위장하지 않는다. 해당 촬영 동안에만 MapRouter의 LateUpdate 가림 덮어쓰기를 멈추며, Play 종료 후 원래 상태로 돌아간다. 실내 후 사진이 밝게 노출돼 배치/윤곽 확인용으로 쓰고 색의 정확한 비교는 같은 조명 진열을 따른다.
