# A맵 실내 다양화 V36 — 진행 기록

## 사용자 지시와 작업 분담

건물 외관에 비해 반복적인 내부를 벽·바닥 마감, 구조와 에셋 용도로 구별한다. 사용자가 「A맵 적 배치와 동선 계획」 및 「UI 배치 적용 분석」과 직접 조율하도록 승인했다.

- 방·복도, 구조 충돌체, 실내 적 배치: 「A맵 적 배치와 동선 계획」 담당.
- 이 작업: 실내 전용 재질과 기존 가구 받침 안의 시각 소품. 구조·NavMesh·적·스폰 정책·UI·전체 조명은 변경하지 않는다.
- GPT-6 Sol high 제작 담당 2명과 독립 검토 담당 1명이 파일 소유권을 나누어 작업했다.

## 시작 상태와 문제

기존 D04 실내는 건물 용도별 가구가 있지만 두 벽을 따른 유사한 포켓 배치와 소수의 공용 마감이 반복된다. 외벽은 D09/D10/D15에서 이미 다르게 처리되므로 공유 재질을 일괄 교체하지 않는다. 중정비동 V35 2층 조명을 유지한다.

2026-10-15 구조 담당이 공유 Unity를 사용하는 동안 이 작업은 Unity 밖 `staging/`에만 코드를 준비했다. 최초 네이티브 창 캡처가 Unity 대신 다른 앱을 반환했으므로 이미지를 저장하거나 변경 전 증빙으로 사용하지 않았다. 최신 CQB 최종 저장·인계 이후 실제 게임 전후 화면을 확보한다.

## 실제 1차 적용

1. 중정비동을 제외한 68동을 명시적 ID로 의료·사무·생활·급식·정비·보관·전기·수처리·차고·폐시설의 10종 마감으로 구분한다.
2. 기존 전용 바닥이 있는 46동과 POWER/PARTS 내부 코어 2곳의 48개 바닥 재질 슬롯, 실내 구획벽 59개 슬롯에 전용 복제 재질을 적용했다. 외벽·지붕·기초·창문·출입구는 보존했다.
3. 전용 바닥이 없던 22동은 원본 Foundation/WalkableFloor를 그대로 두고 윗면 +0.015m, 두께 0.01m의 시각 전용 마감층을 추가했다. 새 충돌체 0, 그림자 생성 꺼짐/수신 켜짐이다. 최초 1m inset은 전후 화면에서 테두리가 과도해 후속 국소 보정 대상으로 삼았다.
4. 58동에 총 106개 렌더러의 작은 용도별 장식물을 추가했다. 기존 가구의 상단·회전·실측 받침 범위 안에서만 배치하며 원래 가구는 이동하거나 삭제하지 않았다. POWER/PARTS 등 6동은 제외했고, F03/N07/N14/N17의 소품은 실물 크기가 지나치게 작아지는 후보라 건너뛰었다. 전체 가구 교체가 아닌 작은 생활·업무 디테일 추가다.

마감 계열: 의료·급식은 녹색 계열 타일, 주거는 목재, 사무는 옅은 콘크리트, 정비·차고는 마모 콘크리트, 창고·수처리·폐시설은 거친 콘크리트, 전기는 청회 금속 바닥. 내벽은 기능에 맞는 미장·벽돌·도장 금속 계열이다.

일반 건물 외곽 벽은 양면이 같은 렌더러를 공유하므로 전체 벽지 교체 대상이 아니다. 이 1차 작업의 벽 마감은 별도 내부 구획벽에 한정된다. 이를 전 건물 실내벽 전면 교체로 보고하지 않는다.

## 검토 및 검증 계획

- 정적 검사: 68 ID의 계획 일치, 텍스처·프리팹 존재, Unity 참조 DLL을 사용한 외부 컴파일(오류 0, JSON 역직렬화 필드 경고만) 확인.
- 독립 리뷰 후 소품 배치의 회전·받침 경계·접지, 실패 시 원복, 신규 렌더러 슬롯의 보존 검사 오류를 보완했다.
- 적용 전: CQB 최종 프리팹 해시 확인, 씬/프리팹 복사 백업, 원본 계층·재질·충돌·적·스폰·조명 스냅샷, 실제 게임 동일 시점 촬영.
- 적용 후: 68동 실내 조사 화면, 대표 12동 게임 카메라, 중정비동 1/2층 비교. 기존 출입 166경로와 새 CQB 6경로를 실제 PlayerMotor로 통과 검사한다.
- 저장 후: 재로드 보존 검사 및 실제 화면 재확인. 실행 후보 ID와 검증 결과를 연결해 오래된 결과로 저장을 승인하지 않는다.

## 독립 시각 검토와 한계

별도 GPT-6 Sol high 검토자가 대표 실내/게임 전후 화면을 열어 용도별 차이, 그림자·가구 접지·출입구를 확인했다. N03의 큰 암석·식생 실내 침범은 변경 전에도 있었고 이번에는 원본 배치를 보존했다. 기존 벽을 따른 유사한 가구 배치, 큰 빈 공간은 남아 있으며 이번 마감·소품 작업만으로 구조적 반복까지 해결했다고 하지 않는다.

POWER/PARTS의 방·복도는 먼저 인계받은 구조 담당의 최신 변경을 유지했다. 이전 검증에 남은 기존 CORE 모서리의 0.9m 기계 장거리 경로 여유 문제도 이번에 해결한 것으로 취급하지 않는다.

## 현재 상태

1차 화면의 넓은 쇄석 테두리를 그대로 최종 승인하지 않고 추가 보정했다. 원본 D09 네 면 벽 메시의 실제 두께·면 위치와 Foundation 지지를 조사해 `max(0.35m, 벽두께/2+0.08m)`의 안쪽 여유를 적용했다. 22/22동 보정, skip 0. N07은 0.43m, 두꺼운 석조부 일부는 약 0.355m, 일반 건물은 0.35m다. 원본 외벽/기초는 그대로 두고 자체 바닥층 크기만 넓혔다. V36 주거용 목재 재질 하나의 대비 .76→.90, lift .02→0, tint RGB 90%로 조정해 지나치게 밝고 균일한 인상을 줄였다.

최초 후보의 after 82장과 촬영 로그는 `trial_1/`에 보존했다. 루트의 `after_` 화면은 보정 완료 후보를 새로 촬영한 것이다. `FINISH_SURFACES.txt`에 모든 건물의 전후 크기·실제 벽 두께·inset 수치가 있다.

최종 candidate `0b75190b3331488eb6897d15abc388e4`: after 82/82 PASS, 구조 전용 PlayerMotor 172/172 PASS(원본 166+CQB 6), 저장 직전 독립 보존검사 14항목 PASS. TOOLS 중심 D_TOOLS_01 Body/Core 충돌체의 목표 중첩도 로그로 확인했다. 씬/프리팹 저장 후 다시 열어 실제 Play `reload_` 82/82 화면을 촬영했고, after/reload 82개 카메라 로그 차이 0이다. S07 저장 후 바닥 상태도 육안 확인했다. 전체 원본 바이트·계층 검사는 저장 직전 결과이며, 재로드 뒤에는 실제 게임 화면 재촬영으로 확인했다(재로드 후 전체 직렬화 비교를 재실행했다고 주장하지 않는다).

최종 저장 씬 SHA256 `C9E3D324A6DA7849188D1D92F9D79843B8E4820DCBE8325C3A0B227CD13D1874`, 프리팹 SHA256 `527EFAAF5CA130BAC0FA888AEDE33F1C9B8DB80E1153D2F15158E1E416AAA416`. 씬은 프리팹 참조를 유지하여 파일 바이트는 동일하고 프리팹에 변경이 저장됐다.

사용자의 추가 지시(중앙 회색 공장 창문벽도 건물별 컨셉에 맞추기)는 `a-map-interior-consistency-v36b` 후속 기록으로 이어간다. 이 V36 마감·소품 저장을 깨끗한 인계점으로 삼아 UI 코드 통합 → 인간형 패스 → V36b 순서로 직접 조율했다. 두 작업 이후 최신 상태를 V36b의 별도 baseline으로 확보하며 이 기록/스냅샷을 덮어쓰지 않는다.
