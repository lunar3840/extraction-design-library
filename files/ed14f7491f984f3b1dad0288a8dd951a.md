## 검사 도구 보완 내역
- 최초 보존 검사에서 컴포넌트 비교 1건이 실패했다. Unity 오브젝트 참조를 경로로 정규화한 뒤에도 그 내부의 `.m_FileID` 자식 값을 중복 비교하여, 프리팹 연결 해제와 백업 씬 로딩에 따른 임시 번호 변경을 실제 변경으로 오인한 것이었다.
- 백업 대조에서 임시 참조 번호 차이 55,543건 외의 차이는 0건이었다. 오브젝트 참조는 부모의 정규화된 경로만 비교하도록 수정했으며, 원본 기준 JSON은 덮어쓰지 않았다.
- 원본 백업과 SHA-256까지 동일한 임시 검증 씬에서 계층·컴포넌트 수·모든 원래 재질 슬롯·207개 기존 재질 파일을 재검증한 후 별도의 정규화 컴포넌트 기준을 저장했다. 이 복구 검사는 8개 통과했다.
- 같은 임시 번호 비교 문제가 조명 컴포넌트가 포함된 전역 서명에도 영향을 줘, 동일한 원본 백업을 활성 씬으로 읽은 별도 전역 기준을 만들었다. 원본 계층·컴포넌트·슬롯 및 백업 해시를 다시 확인한 6개 검사를 모두 통과했다. 원본 기준 파일은 유지했다.
- 보완 후 컴포넌트 대조는 차이 0건이며, 실제 최종 상태의 V23 검사는 20개 통과 / 0 실패다. 형상과 조명을 바꿔 검사에 맞춘 것이 아니라 참조 번호를 일관된 경로로 비교하도록 검사 도구를 고쳤다.
- 프리팹 연결 해제 후 미리보기 지붕 가림 캐시가 남는 현상도 발견해, 캡처와 검사 전에 가시성 캐시를 다시 구성하고 외부 상태를 명시적으로 적용하도록 작업 도구를 보완했다. 게임의 가시성 코드는 수정하지 않았다.

## 회귀 검사 해석
- V14: 123 통과 / 0 실패 / 0 경고. 기본 진입점 4 × 탈출구 7 = 28/28 연결.
- V15: 67 통과 / 0 실패 / 0 발견.
- 원래 V16 검사는 390 통과 / 2 실패다. 두 실패는 '홀 전체 시각 상태 불변' 및 '기존 비슬롯 시각 상태 불변'으로, 내부 해시에 재질 경로가 포함되어 이번 의도된 재질 교체를 거부한다. 원래 결과를 삭제하거나 무조건 통과로 표시하지 않았다.
- 호환성 보조 검사에서는 이번에 허용한 169개 재질 참조만 메모리에서 잠시 원래 참조로 바꿔 V16을 실행한 결과 392/392 통과했다. 검사가 끝나면 `finally`에서 V23 참조를 복원하고 실제 최종 상태를 별도의 엄격한 V23 검사로 다시 검증한다. 이 결과는 원래 V16 검사가 수정 후 상태에서 그대로 통과했다는 뜻이 아니다.
- 길찾기 V17 및 적 제어 코드, V14 검사 코드, V16 배치 코드와 원본 에셋 목록은 전후 SHA-256이 동일하다 (`PROTECTED_CODE_BEFORE.json` / `PROTECTED_CODE_AFTER.json`).
