# 이미지 기반 전술 지도 독립 시각 검토

검토 범위: 저장된 실제 Unity 화면 PNG와 동반 상태 기록, A 이미지 좌표 검사 및 GPU 등록 결과. 이 검토에서는 Unity를 실행하거나 본 프로젝트의 파일을 수정하지 않았다. `iterations/`의 첫 실패 화면은 최종 결과로 사용하지 않았다.

## A맵 전후 및 표식

- `before_gameplay.png`의 원형 지도는 암색 바탕에 일부 충돌체/계획선만 보이며 실제 도로, 지붕, 강, 식생과 구별된다. `after_gameplay.png`는 같은 월드 좌표 (-119, -129), 맵 좌표 (141,329)의 실제 탑다운 이미지로 교체되어 지형과 건물 지붕을 읽을 수 있다. `after_full_map.png`에서도 같은 A 이미지가 표시된다.
- 같은 1920×1080 프레임의 청록 화살표 픽셀 외접상자는 수정 전 x122–149/y174–198, 수정 후 x157–183/y162–188이다. 두 화면의 45° 방향 실루엣 차이를 감안해도 수정 전에는 중심에서 크게 벗어났고, 수정 후에는 계산상 중심을 둘러싼다.
- 실제 1920×1080 화면에서 미니맵의 계산상 중심은 `MiniViewport(30,26,232,232)`와 UI 배율 1.2로 (175.2,170.4)px이다. 0° 북쪽과 90° 동쪽 캡처의 청록 화살표는 이 점을 중심으로 각각 위와 오른쪽을 향한다. 180° 서쪽 건물 화면은 아래를 향한다. 45° 최초 화면에서 화살표의 외접상자 중심이 이 점보다 약 5px 왼쪽/아래인 것은 비대칭 화살표 실루엣이 회전하며 생기는 외접상자 변화다. 지도상 위치를 나타내는 회전 중심이 이동한 증거는 아니다.
- `after_move_north.txt`와 `after_move_east.txt`는 시작 (141,329)에서 각각 (141,319), (151,329)으로 정확히 10m 변한다. 그 PNG에서는 미니맵 배경이 반대 방향으로 이동하고 화살표는 같은 중심에 남으며, 도로·건물 위치가 연속적으로 이어진다.
- 1920×1080 기본 화면과 다른 해상도 `after_scale_800x450.png`, `after_scale_1600x900.png`, `after_scale_2560x1440.png` 모두 같은 위치의 화살표를 보인다. 게임 UI의 `ScaleFor`는 추가 세 화면에 각각 0.5, 1.0, 상한 1.5를 적용하므로 2560 화면을 1.6배로 예상하면 안 된다. 화살표 외접상자는 배율에 비례하여 이동하며 독립적인 회전/그룹 원점 이탈이 보이지 않는다.

## 지형과 실좌표의 대응

- `after_west_crossing.png`에서 캐릭터는 벽 옆 도로에 있다. `after_west_full.png`의 X112/Y149 표식 역시 서쪽 건물 가장자리와 도로에 놓인다. 진료소·공구점의 화면 표시 거리 72m·50m도 이 위치 관계와 모순되지 않는다.
- `after_east_road.png`의 동쪽 시설 울타리·컨테이너 구간은 `after_east_full.png`의 X448/Y132, 전력 제어소와 부품 창고 사이 구간과 대응한다. 게임 화면에서는 지붕/컨테이너가 캐릭터를 가리므로 스크린샷만으로 세부 위치를 픽셀 단위로 직접 판독할 수는 없다.
- `after_bridge.png`는 수로 위 난간 교량을 보여 준다. `after_bridge_full.png`의 X362/Y325 표식은 이미지의 동일한 수로 교량 중앙에 있다. 이 사례는 독립적으로 알아보기 쉬운 지형 랜드마크다.
- `after_full_map.png`의 A 전체 지도에는 이전 암색 도형식 배경이나 파란 계획 슬롯 윤곽/라벨이 보이지 않는다. 회색·청록색 사각형은 실제 이미지에 굽힌 건물 지붕 및 시설물로 판독되며, 그 위에 탈출/시설 UI 표식만 별도로 보인다.

## 기록 기반 검증과 한계

- `validation/image_checks_StageA.txt`는 A 이미지/보정값, 520×400m 범위, 주요 앵커, WorldToMap/MapToWorld, 중심·방향, 10m 이동 픽셀 차, 원형 이미지, 전체 지도 줌·이동·목적지 검사를 모두 통과한다. `validation/render_registration.txt`의 비공선 GPU 3점은 기대 픽셀과 실제 중심 차이가 모두 0px이다. 이는 화면상 랜드마크 판단과 독립적인 이미지 굽기 좌표 근거다.
- `after_b_gameplay.png`와 `after_b_full.png`에는 B맵의 별도 49×49m 탑다운 이미지가 보인다. 현재 위치 (24.5,24.5)의 동쪽 방향 화살표와 보관함·귀환 표식이 B 지형 위에 있고, `validation/image_checks_StageB.txt`의 20:33 KST 재실행은 전체 통과했다. 최초 `GetPixelBilinear` 비교 실패는 CPU 텍셀 중심 보간과 Unity native sampler의 규약 차이 가능성으로 판단되며, 최종 검사는 비최적화 `SampleImage`와 최적화 원형 crop을 비교한다. 두 경로가 일부 좌표식을 공유하므로 이 통과만으로 절대 영상 좌표를 증명하지는 않는다. B 보정 모서리/현재 플레이어 검증 및 A의 독립 GPU 3점 결과와 구별해 해석한다.
- B 미니맵의 실제 이미지가 약 98px 정사각형으로, 지름 약 278px 원형 영역 가운데 작게 나타난다. B가 49m이고 미니맵이 A와 같은 140m 범위를 표시하기 때문이다. 이는 좌표 오차가 아니라 기존 `70m` 표시 범위를 유지한 결과다. 향후 B 표시 크기를 바꾸려면 맵별 축척 정책과 거리 안내를 별도로 정해야 한다.
- 본 검토는 저장된 프레임을 확인한 것이다. 연속 플레이의 프레임별 흔들림이나 모든 맵 위치의 텍스처 정합까지 증명하지 않는다.
