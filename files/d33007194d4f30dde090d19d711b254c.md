## 사용자 지시

> 샘플로 한번 해봐

직전 제안은 중형 창고 한 동을 기존 문 위치·층 높이에 맞춰 외부/실내 제작하고 벽·지붕을 분리해 Unity에서 확인하는 것이었다. 이 범위의 샘플 구현 승인으로 해석한다. 전체 맵 재제작·다른 건물/적/스폰/경제/캐릭터 변경으로 확대하지 않는다.

## 의도와 대상

W10 Logistics/ExportInspection 검수창고를 선정했다. 약23×14m, 양면 출입구2곳으로 한 동의 외부·실내·통과 동선을 함께 비교하기 적합하다. 기존 벽돌/석재 기단/박공지붕/강철 하역 캐노피 콘셉트를 유지하고, 창고 한쪽에 실제 출입 가능한 검수실을 추가했다. 최신 직렬화 프리팹과 Unity baseline을 대조하여 제작 계약을 확정했다.

기존 라이브러리의 D09 주제와10/26-01 제작 방식 검토를 이어가는 구현 회차다. 날짜/폴더가 바뀌었다는 이유로 새 대표 주제를 만들지 않는다. 이 원문과 이전 검토는 별도로 보존한다.

## 전후 증빙과 검증

## 실제 변경과 가져오기 방식

- 기존 D09의 W10 33개 메시를 기준으로 문·창·비대칭 지붕 형태를 유지하고, 벽돌/석재 띠·기둥 덮개·문틀/창틀·캐노피 받침·처마/트러스·얇은 바닥 줄눈과 검수실을 보강했다.
- 최종 FBX는 Shell52개/8,848삼각형, Roof39개/4,604삼각형, Interior52개/3,792삼각형이다. 합계143개 시각 메시/17,244삼각형, 새 MeshCollider17개다. 편집 메시와 실제 베벨 적용 FBX의 삼각형 수는 구별한다.
- 첫 Unity import는 FBX 파일 단위 메타데이터를 사용하지 않아100배 오류가 났다. `useFileScale=true`와 globalScale1로 실제 미터 단위를 적용했다. 두 번째는 오른손/왼손 좌표 차이로 X가 반전되어, 내보내기용 복제 메시만 X 반사와 면 winding/UV loop 역전을 적용했다. authoring `.blend`와 미리보기 좌표는 유지하고 manifest에 `fbxGeometryMirroredXForUnity:true`를 명시했다. 음수 scale로 씬을 임시 보정하지 않았다. 앞으로도 동봉 builder로 재출력해야 같은 계약을 유지한다.
- Unity 실제 143개 메시의 W10 로컬 바운드를 manifest와 대조하여0.12m 이내 일치를 확인했다. 이 검사에서 앞선 두 오류를 걸렀고 원본 씬/프리팹을 저장하지 않은 채 각각 정리·재로드했다. `main/COMMAND_apply_candidate_01.txt`, `_02.txt`, `_03.txt`와 `integration/IMPORT_BOUNDS_FAILURE_*.txt`, `IMPORTED_BOUNDS.txt`가 근거다.
- 새 지붕은 기존 RoofCutaway 아래에 두고 부모 scale을 보상했다. 기존 D09 외벽/지붕 두 루트만 비활성화했으며, 지붕 footprint와 기존 기단·물리 바닥·밝은 V36 시각 바닥·작업대·소품을 보존했다. 기존 floor를 끈 첫 후보는 암석 바닥이 드러나 반려하고 `integration/diagnostic_floor_r01/`에 보존한 뒤 복구했다.
