# Ivy variants and weathering: independent validation notes

Status: **independent functional and selected-pass checks passed; Study 04 accepted as an isolated tool art study with the limits below**. The validation agent did not run Unity or edit Assets. These notes distinguish contract/static checks, executed results and visual judgment.

## Test design

- `EnvironmentToolsValidation.ValidateIvyVariants()` uses a real non-readable rusty car prefab in an isolated PreviewScene. It checks successive explicit variant seeds, differing generated meshes, exact replay from the captured seed through the fixed `Preview` API, caller settings and `UnityEngine.Random.state` invariance, one owned ivy root, source mesh/material/collider/transform invariance, Clear and unchanged original asset dependency hash. The existing `SurfaceIvyValidation.ValidateCore()` remains the corner/window/budget regression gate and is run by the main agent.
- `EnvironmentToolsValidation.ValidateWeathering()` uses a synthetic opaque URP Lit metal and exact D09 plaster/brick alongside glass, tire rubber, D09 wood/glass and unsupported custom fixtures. It checks isolated preview copies, cloned supported slots, unchanged original material references, strength-zero control, PBR texture slots and texture transforms, cutoff/normal/metallic/AO/emission, `_WeatherPreserveD09` and all original D09 weathering parameters, D09/URP distinction and material class, unsupported skips, repeat preview cleanup and Clear. It then uses the real car and S06 shell to check eligible slots, Bake to separate prefab/material asset sets, reload values and renderer references, and unchanged original asset dependencies and geometry/collider references. The baked test specimens are retained for main review.
- Structural shader pass checks require ForwardLit, DepthOnly, DepthNormals and ShadowCaster passes. They do not prove variant compilation or pixel equivalence. The main agent must compile actual variants and compare real strength-zero D09 render against the baseline.
- `WeatheringShaderProbe.ValidatePassRendering(outputDir)` adds a focused actual draw test for those four passes. It uses the same alpha-checker quad with URP Lit and the tool-converted material, saves paired `before_*.png`/`after_*.png` files and compares cutout masks against an uncut reference. The first depth-texture sampling attempt produced uniform gray even for original URP Lit, so that readback path was inconclusive. The hidden helper then drew a far black cover with a depth test after each DepthOnly/ShadowCaster pass. Its first mask incorrectly counted clear magenta background. The final version saves a cover-only `empty_*.png` baseline, uses a 1:1 camera aspect and counts only pixels changed from that baseline. Thus it tests actual depth writes and alpha holes, not numeric depth values. It does not replace real asset strength-zero D09 image comparison or exhaustive keyword compilation.

## Source review so far

- Ivy staging adds `NewVariantSeed(int previous)` with cryptographic random bytes and explicit avoidance of the previous seed. `PreviewVariant` clones settings, changes only the clone's seed and calls fixed `Preview`. The leaf-run change is limited to a maximum of five consecutive leaves; growth RNG remains separate from leaf style RNG. The executed variant gate below covers generation and replay; the source review establishes the intended API path.
- The prior S06 material inventory shows most opaque wall/roof materials use `Escape/BuildingD09/WeatheredLit`; the car has one opaque URP Lit material. That makes D09 preservation an essential gate. The exact D09 shader and PBR properties were read locally. D09 wood and glass are deliberate skips, while eligible plaster/brick/metal must preserve existing D09 effects beneath the new layer. Existing vendor/D09/V33 shader source is outside this agent's ownership.
- The staged weathering authoring creates an independent PreviewScene copy and records original/generated material arrays on its marker. Repeated Preview by the same source ID clears the previous copy. Its classification admits opaque URP Lit, Standard and exact D09, while excluding transparent materials, named glass/rubber/wood/foliage and other custom shaders. Its Forward pass calls copied `D09ApplyWeathering` before the new overlay when `_WeatherPreserveD09` is set. The selected pass probe and harness below now add executed evidence, while actual D09 baseline pixels remain a separate visual gate.
- The first staged GBuffer pass included the package's unmodified `LitGBufferPass.hlsl`, which would omit D09/new weathering in Deferred shading. The owner added a local `WeatheredLitGBufferPass.hlsl` before freeze; its fragment now calls `D09ApplyWeathering` and then `ApplyWeathering`, matching the Forward order. This resolves the source-level omission. The selected pass probe does not render GBuffer, so its actual lighting behavior remains untested here. The main was notified of the first state and the later correction.

## Study 01: independent visual and classification review (superseded candidate)

`study_01/STUDY_REPORT.txt` and `CAMERAS.txt` record same-camera isolated renders for fixed fuller ivy, two random variants, zero-strength, weathering only and combined car/shell/roof, plus before/after assembled S06 showcase and roof-hidden inspection. The zero-strength car has 0 changed pixels in both views; shell differs in 578/1,600,000 and 325/1,600,000 pixels with low mean byte error; roof differs in 1 and 4 pixels. Those are strong image-level equivalence observations for these cameras, not proof for every shader variant or lighting condition. The report records different variant seeds/shapes and exact replay, zero new colliders in combined cases, and stable source hashes.

I opened the six baseline object views and the main `study_01` iso comparisons, plus the assembled and roof-hidden showcase images. The fixed seed adds a modest visible leaf increment while retaining the car's exposed bonnet and shell openings. Variant A and B produce visibly different distributions; on the car both put considerably more foliage over the front than the fixed seed, with A especially close to the earlier front-heavy look. The S06 A variant returns a fairly continuous upper-wall green ribbon, while B leaves more gaps. On the roof, both variants keep the large opening visible but vines still read as thin green routes from the normal camera distance. Weathering-only views show a restrained dusty/patched change on car and roof and a subtler change on shell. The assembled example retains open doors/windows and legible original forms, but it remains an isolated composition, not map placement or gameplay proof.

**Blocking finding in Study 01:** The generation report classifies D09 plaster, brick, concrete, stone and terracotta S06 materials as `metal`, not merely its iron/sheet slots. This routes masonry and painted wall materials through the metal rust/metallic-loss behavior and breaks the intended material distinction. The previous synthetic test checked PBR/D09 property preservation but not `_WeatherMaterial` class, so `WEATHERING_193207 PASS` did not catch it. The weathering owner has changed classification priority in staging; the validation harness now includes intentionally high-metallic D09 plaster and brick fixtures that must classify as 0/1 while a real metal fixture remains 2. Study 01 must remain as first-candidate evidence, not final art approval. Reimport, rerun `ValidateWeathering`, and rerender S06/roof before judging final weathering art.

**Second blocking finding in Study 01:** The main agent compared its saved material file with the live preview and found that the baked car material's new `_Weather*` controls had reverted to shader defaults (including strength 0, material kind 0 and scale 1.5), even though the live recipe requested strength .65, kind 2 and scale 1.8. The first harness checked that assets and references survived reload but did not compare their weathering parameter values. This explains why `after_car_iso.png` matched `variant_a_car_iso.png` despite a visible weather-only preview. The weathering owner revised Bake to create and persist separate copies of live materials, reapply the recipe and verify values. The validation harness now snapshots every eligible material's PBR, all new weathering controls and retained D09 controls before Bake, compares live/Bake/reimported `.mat`/saved prefab renderer slots, and includes a real S06 D09 model Bake/reload case. The corrected source passed this stronger gate in `WEATHERING_195852.txt`, below.

`PROBES_194123.txt` reports the first pass probe FAIL at original URP Lit DepthOnly alpha coverage. Its ForwardLit original/new draws each showed 11,832 pixels and identical cutout masks. I opened the saved pass images: both depth images were uniform mid-gray, including the original control. ## Corrected material and shader pass results

The stronger first run `WEATHERING_195001.txt` failed because the generated material appeared to lack `_D09WeatherAmount`, even though shader-source `Properties` declared it. The main agent's `SHADER_DIAGNOSTIC_195229.txt` confirmed the loaded shader had all 70 properties, including D09 fields. A copy-stage diagnostic identified the cause: assigning the weather shader before `CopyPropertiesFromMaterial(source)` led Unity to drop the new shader's property metadata; `CreateAsset` then reset weather controls to defaults. The owner changed the copy order to copy under `source.shader`, switch to the weather shader and set the new controls, then restored source keywords and GI flags. The harness retained the strict property and persistence gates. An intermediate `WEATHERING_195637.txt` proved real car and S06 Bake values persisted but caught an `_EMISSION` keyword regression; the owner corrected it before the final run. These intermediate failures remain useful regression evidence and are not final PASS claims.
