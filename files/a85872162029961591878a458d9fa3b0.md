# 아이템 더블클릭·근접 파밍 목록·자동 재장전

## 사용자 지시

- 파밍 물품 더블클릭으로 가방 획득, 공간 부족 시 보존.
- 파밍창이 열려 있을 때 내 가방 더블클릭은 상자로 보내기. 사용자가 우선순위를 직접 확정했다. 닫혀 있을 때 장비는 장착, 소모품은 사용한다.
- 장착 장비 더블클릭은 해제 후 가방 반환이며 공간 부족 시 보존한다. 기존 드래그/Shift클릭은 유지한다.
- 파밍 상자는 F 한번으로 상호작용하고, 주변 상자들을 한 세로 목록으로 묶는다. 로블록스에서 결정한 UX는 사용자 후속 지시에 따라 대화 내역으로 확인한다.
- 탄창이 비고 호환탄이 가방에 있으면 자동 재장전한다. 호환 탄종 중 높은 티어를 우선하며 R 재장전도 유지한다.

## 작업 범위와 협업

- `Edel 변신 캐릭터 적용` 탭이 현재 공유 Unity 및 캐릭터·실물칩·일부 인벤토리/core 파일을 소유한다. 이 탭은 인계 전 production/Unity를 수정하지 않고 이 폴더 staging에서 준비한다.
- 더블클릭, 자동 재장전, 로블록스 대화 근거 조사를 분리해 병렬 진행한다. 원본 수정은 명시적 인계와 변경 전 증빙 확보 이후에만 진행한다.
- 상자 목록 외 다른 로블록스 게임의 수치·규칙은 임의로 적용하지 않는다.

## 변경 전 증빙

10:49~10:50 UTC 실제 production 변경 전 SystemsTest의 격리 프로필에서 before_inventory.png, before_group.png, before_f_single.png, before_empty_ammo.png와 대응 상태 txt를 확보했다. 일반 저장 프로필은 사용하지 않았다. 빈 탄창0/호환탄100인데 장전되지 않는 상태와 F 단발 미작동을 확인했다.

## 현재 상태

- 명시적 중간 인계 후 production 최소 hook 및 새 partial 병합 완료. 실제 Unity 컴파일과 세 API suite PASS. 동시 미니맵 검증을 중지하도록 캐릭터 탭이 조율한 뒤 native 더블클릭 장착/해제/획득/상자전송까지 확인했다. F native 키 입력 전달은 아직 미확인으로 남긴다.

## 확인한 로블록스 대화 기준

- `UI (BASECAMP)` 스레드(01a00953-7e1c-7231-82d0-8139f8d61aba)의 사용자 정정과 당시 실제 코드 수정 내역을 확인했다. 근거는 `reference/ROBLOX_DIALOGUE_REFERENCE.md`에 최소 발췌로 보관했다. 메인이 해당 보고서 전체를 읽었다.
- 최종 기준은 별도 패널이 아닌 기존 이름표의 동일 X 세로 묶음, 첫 대상 앵커 중심 정렬, 휠 선택, 선택 원 이동 및 진한/큰 행, 생존 순서/선택 유지와 신규 뒤 추가다.
- 이번 F 단발 입력은 과거 홀드 시간을 그대로 복사하지 않고 현재 사용자 지시를 우선한다. 내부 아이템의 수색 소요 시간은 별개이므로 보존한다.
- 전방 좁은 각도 제한을 제거한다. 현재 Unity의 기존10×worldScale 거리/4.5×worldScale 높이 제한과 벽 차단은 유지한다. 겹친 근접 전리품끼리만 서로 LOS를 차단하지 않도록 하는 것은 이번 편의성 보완이며 원본 Roblox와 완전히 같은 LOS라고 주장하지 않는다.
- 행 간격42, 높이34/선택40 및 선택 너비+14, 좌측 원24와 선택 보간은 Unity 공통 논리 UI 단위에 맞춘다. 실제 픽셀은 UiTheme 배율을 따른다. Roblox의 물리 stud를 Unity미터로 그대로 복사하지 않는다.

## 준비본 검증 (production 적용 전)

- 더블클릭 순수 입력 sequence24항목 PASS. 두 독립 클릭, 다른 UID/출처, 두 번째 클릭 중 드래그, Shift, 세 번째 클릭, 취소 이후 클릭을 구별한다.
- 자동 재장전 core38항목 PASS. 실제 보유 최고 호환티어 한 탄종으로 기존 시간 경과 장전을 시작한다. 여러 티어를 한 탄창에 자동 혼합하는 새 규칙은 추가하지 않는다. 부분 탄창의 수동 R은 기존 선택 탄종을 유지한다.
- 메인이 준비본을 공유 파일의 별도 사본에만 합쳐 전체 runtime·Editor 정적 컴파일 exit0을 확인했다. 검증 코드를 포함해 네임스페이스 모호함과 public 취소 API 연결을 수정했다. 이 결과는 Unity 실게임 검증이 아니다.
- 준비된 실제 API 검사: InventoryDoubleClickChecks, AutomaticReloadControllerChecks, InteractionGroupChecks. 인계 후 별도 테스트 프로필에서 실행한다.
- 자동 장전은 기존 전투·치료 제한 외에 로비의 MovementInputBlocked와 텍스트 입력 포커스를 막는다. 수동 R의 기존 입력 제한은 바꾸지 않는다.
- 10:53 UTC production Unity 통합 검사: InventoryDoubleClickChecks PASS, AutomaticReloadControllerChecks50 assertions PASS, InteractionGroupChecks272 assertions PASS. validation/integration_suites.txt 및 각 보고서 참조.
- 자동 장전은 실제 Stage에서도 공격 입력 없이0/100→30/70 완료했다. before_empty_ammo.png ↔ after_stage_auto_reload.png로 관찰하되, 후자는 근접그룹 준비 전이므로 완전히 동일한 오버레이 비교는 아니다.
