## 3. 키워드 꺼짐 = 무변경 [확인]

- Sampling.hlsl은 키워드가 꺼지면 `#include Core.hlsl`만 남음. Lighting.hlsl은 `#include Lighting.hlsl`만 남음. 위 표대로 두 include가 원래 include 위치보다 앞당겨지는 곳에서 그 사이에 있던 코드가 Core/Lighting 결과를 바꾸지 않으므로, 생성되는 HLSL은 기능적으로 같음.
- 차이 1: `#pragma editor_sync_compilation`을 9개 셰이더에 추가(WeatheredLit, D14, FoliageLit, CutLit, V33은 원래 있었음). 에디터에서만 쓰이고 런타임 출력과는 무관함(P2 참고).
- 차이 2: ForwardLit 프래그먼트 변형 수가 2배. 꺼짐 변형의 코드는 동일함.

## 4. EscapeStylizedLit.shader, OccluderCutout.cs [확인]

- `diff Lit.shader EscapeStylizedLit.shader`에서 나온 차이는 다음뿐: 1행 이름(`Escape/Look/StylizedLit`)과 주석 4줄, ForwardLit에 pragma 2줄(키워드, sync), `#include EscapeStylizedSampling` 1줄(LitInput 앞), 주석과 `#include EscapeStylizedLighting` 2줄(LitForwardPass 앞). 나머지(GBuffer/Shadow/Depth/Meta/2D/MotionVectors, CustomEditor, FallBack)는 바이트 단위로 같음.
- OccluderCutout.cs diff: (1) 상수 `StylizedLit` 추가, (2) `Eligible`의 shader 이름 조건에 `|| s == StylizedLit`, (3) `CloneFor`의 `if (s == UrpLit)`을 `|| s == StylizedLit`로 확장, (4) `ReleaseForExternalSwap()` 추가(기존 `ReleaseAllProps()` 호출만 함). UrpLit/WeatheredLit 경로와 Restore/Apply/ReleaseAllProps 본문은 바뀌지 않음. 이름이 `StylizedLit`인 재질이 없으면 동작이 이전과 같음.
- 상호작용 [확인]: StylizedLook.cs의 TurnOn(126-128)과 TurnOff(138-140) 모두 `ReleaseForExternalSwap()` 다음에 재질을 교체/복원함. 순서가 맞음. StylizedLit 클론에 컷이 걸리면 `cutLit`(EscapeOccluderCutLit, 훅 있음)으로 바뀌므로 툰이 유지됨. 사소: `clones` 사전에 스타일 클론을 키로 하는 항목이 남음(DontSave, OnDestroy에서 정리). 누수 수준은 아님.
- StylizedLook은 `renderQueue >= Transparent`인 URP Lit을 교체하지 않음(StylizedLook.cs 272, 284줄 부근). 그래서 F6은 StylizedLit에는 해당하지 않음.

## 5. 발견 사항

### F1 [화면 오류] 메인 라이트 그림자 강도가 0/1로 굳음 — 확인
- 위치: `Art/Look/EscapeStylizedLighting.hlsl:45` `half cast = smoothstep(0.5h - edge, 0.5h + edge, shadowAttenuation);`
- 근거: Shadows.hlsl:335 `attenuation = LerpWhiteTo(attenuation, shadowStrength);` 때문에 완전한 그림자 안의 값이 `1 - strength`가 됨. StylizedLook.cs:39 `sunShadowStrength = .8f` → 그림자 안 0.2 → edge .14에서 cast는 smoothstep(0.36, 0.64, 0.2) = 0. 즉 환경은 강도 1.0 그림자, 캐릭터(CharacterHybridD15)는 0.8 그림자로 서로 다름. 강도가 0.36 이하이면 반대로 툰 그림자가 완전히 사라짐.
- 고칠 방법: 강도로 정규화한 뒤 임계값을 적용하고 강도를 되돌려 곱하기. 예: `half k = GetMainLightShadowParams().x; half s = saturate((shadowAttenuation - (1-k)) / max(k, 1e-3h)); cast = lerp(1-k, 1, smoothstep(.5-edge,.5+edge,s));`(Shadows.hlsl:186 `GetMainLightShadowParams()`).

### F2 [화면 오류, 잠재] mip bias가 URP 내부 텍스처까지 번짐 — 확인(영향 범위는 추정)
- 위치: `EscapeStylizedSampling.hlsl:20-22`의 전역 `#undef/#define SAMPLE_TEXTURE2D`. Lit 계열 5개와 HLSLINCLUDE 5개에서는 Sampling이 `Lighting.hlsl`보다 **앞**이라, 그 뒤에 펼쳐지는 URP 함수 본문도 새 매크로로 컴파일됨.
- 근거: GlobalIllumination.hlsl:5가 EntityLighting.hlsl을 include하고, EntityLighting.hlsl:220 `#define SAMPLE_TEXTURE2D_LIGHTMAP SAMPLE_TEXTURE2D`, :275 라이트맵 샘플링 → 라이트맵에 +1.75 mip이 걸림(차트 경계 번짐). LightCookieInput.hlsl:91 `SAMPLE_TEXTURE2D(_MainLightCookieTexture, …)` → 쿠키 흐려짐. SSAO(AmbientOcclusion.hlsl:22 `SAMPLE_TEXTURE2D_X` → TextureXR.hlsl:44 별칭)와 스크린 스페이스 그림자(Shadows.hlsl:228)에도 bias가 걸리지만, 이 RT들은 mip이 없어서 실제 효과는 없음 [추정]. `Assets/Scenes`(깊이 3)에서 라이트맵/LightingData는 찾지 못했음. 그래서 현재 화면에는 안 보일 가능성이 큼 [추정].
- 고칠 방법: Sampling.hlsl의 `#if defined(ESCAPE_STYLIZED_LOOK)` 안, 재정의 직전에 `#include ".../Lighting.hlsl"`을 넣어 URP 본문이 원래 매크로로 먼저 펼쳐지게 하기(키워드 꺼짐 경로는 그대로 유지됨). 또는 bias를 재질 입력 함수 쪽에만 적용하기.

### F3 [화면 오류] 알파 테스트 식생의 컷아웃 모양 불일치 — 확인(체감 크기는 추정)
- 위치: D14MutedFoliage, FoliageLit(`ESCAPE_STYLIZE_FOLIAGE`, `_EscapeStylizeTex.y = .5`). 알파도 `SampleAlbedoAlpha`(SurfaceInput.hlsl, Sampling 뒤에 include됨)로 읽으므로 컬러 패스에서만 bias가 걸림.
- 근거: FoliageLit:170-171 `UsePass "Escape/Occluder/CutLit/DepthOnly|DepthNormals"`, :115 `UsePass ".../Lit/ShadowCaster"`에는 키워드가 없어 bias도 없음. PC_Renderer.asset: `m_DepthPrimingMode: 0`이라 구멍은 생기지 않음. 하지만 SSAO가 켜져 있고(Source: 1 = DepthNormals), Toon Outline feature(ToonOutline.shader는 DeclareDepthTexture/DeclareNormalsTexture 사용)가 bias 없는 알파 기준 실루엣을 씀 → 컬러에서 잘려 나간 잎 위치에 AO와 외곽선이 남고, 그림자 모양도 다름. 먼 거리에서는 mip 평균 알파 때문에 잎이 더 얇아짐.
- 고칠 방법: 식생은 `_EscapeStylizeTex.y = 0`으로 두거나 알파만 bias 없이 따로 읽기. 또는 같은 Sampling과 키워드를 식생의 Depth/DepthNormals 패스에도 넣기(ShadowCaster는 URP UsePass라 불가).

### F4 [사소] 식생 노멀 블렌드에서 NaN 가능 — 확인
- `EscapeStylizedLighting.hlsl:63` `normalize(lerp(normalWS, up, x))`: x = 0.5이고 노멀이 정확히 (0,-1,0)(수평 카드 뒷면)이면 0벡터가 되어 NaN이 생김. 현재 기본값 .3에서는 안전함.
- 고칠 방법: `SafeNormalize`로 바꾸기.

### F5 [사소, 잠재] Subtractive 혼합 조명에서 메인 라이트가 두 번 들어감 — 확인(현재 라이트맵 없음 추정)
