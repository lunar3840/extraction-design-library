# 에델 피부와 얼굴 명암 첫 조정

## 사용자 지시와 의도

사용자가 커뮤니티 피드백 검토 후 첫 조정을 승인했다. 피부색과 표정이 조명 속에서도 안정적으로 읽히고 몸통과 다리의 명암이 이어지도록 한다. 사용자 원문은 USER_REQUEST.md, 선행 검토는 ../character-shading-community-review/에 있다. 기존 D15 주제의 후속 실제 조정으로 연결하며 10/29-01 분석은 보존한다.

## 진행 범위

에델 1종의 기본/A맵 피부 보정과 피부·얼굴 음영만 첫 시험한다. 원본 모델·텍스처·UV0·헤어색·머리 C15b·포즈·파지·충돌·장비·다른 캐릭터·맵·전역 조명·기존 외곽선은 보존한다. 후보 제작, 증빙 도구 제작, 독립 검토를 GPT-6 Sol high에 각각 분담한다. Unity 조작과 실제 적용·화면 판단은 메인이 수행한다.

## 변경 전 상태

기본 HybridToon에는 에델 혼합 atlas의 UV4 피부 마스크가 있고 A맵 D15에는 대응 입력이 없었다. 실제 변경 전 Play에서 D15 active=True, 에델 모델 Player_Edel, Original_Rest_Iris 슬롯의 limbMask=ABSENT를 확인했다. 몸통 재질은 기존 .25/.18 완화를 받지만 혼합 atlas의 팔·다리에는 해당 표식이 전달되지 않았다. 정면 게임 화면에서 얼굴·가슴·팔의 밝고 어두운 조각과 몸통/다리의 대비가 보였다.

시작 시 Unity가 닫혀 있었다. 에델·맵·UI 담당 세 채팅에서 사용/예약 없음과 명시 반환을 확인한 뒤 메인이 프로젝트를 열었다. 실제 변경 전 Unity 창 before_editor.png, 같은 실제 플레이어·카메라의 게임/인벤토리 9개 시점을 먼저 저장했고, 그 전에는 후보를 라이브에 적용하지 않았다. 기존 프로덕션 13파일 해시가 기준과 같은지도 적용 직전 확인했다.

## 실제 변경

- **A맵 피부 보정 연결:** CharacterHybridD15에 기존 기본 셰이더와 같은 UV4 표식 입력·보간·피부 조명 평가를 연결했다. Rest_Original의 혼합 atlas 피부만 읽고 머리와 눈은 해당 표식에서 제외한다.
- **에델 전용 피부·얼굴 명암:** 두 셰이더에 기본값0인 _EdelSkinReadability와 피부 영역 표식을 추가했다. 확인된 Player_Edel 모델과 기존 EdelSkinShadingMask가 함께 있을 때만 얼굴 Face_Skin, 몸통 Body_Skin_Clean, Rest_Original의 첫 atlas 슬롯에 0.65를 전달한다. 이 값은 새 에델 actor에서 자동 적용되며 수동 시험 호출에 의존하지 않는다. 다른 캐릭터와 눈·머리·의상·장비의 재질 값은0이다.
- **얕고 넓은 음영:** 에델 피부의 조명 방향 변화는 넓은 부드러운 영역으로 섞고, 주광 그림자의 대비를 제한하는 후보 항을 사용한다. 해당 후보 항은 그림자 감쇠를 .72~1로 제한하지만 최종 색은 기존 조명과0.65로 혼합한다. 보조광에는 밝기 바닥을 추가하지 않는다. 피부의 좁은 광택·환경 반사는 줄이고 원래 알베도·UV0·알파와 바닥 투영 그림자는 유지한다.
- **공유 atlas 보호:** 피부 표식을 쓰는 atlas 슬롯에 별도 런타임 재질 복사본을 만들어 Iris_L/R의 공용 원본 재질에 설정이 전파되지 않도록 했다. 실제 Iris 재질의 새 값0을 확인했다. actor 모델이 교체되면 이전 복사본을 정리하고 새 대상을 다시 판정한다.
- **범위 보존:** 모델·텍스처·UV0·헤어색·C15b 헤어/포즈/파지/충돌, 맵 prefab/scene·전역조명·PC 렌더러와 기존 외곽선을 바꾸지 않았다. 얼굴 SDF나 새 외곽선 렌더링 패스를 추가하지 않았다.

## 적용 방법과 비교 조건

GPT-6 Sol high 제작 담당이 staging/appearance에 세 파일과 diff를 제작했고 메인이 원본 SHA를 대조한 후 적용했다. 촬영 담당은 별도 Editor 도구를 staging/probe에 제작했고, 독립 검토자는 소스와 실제 전후 화면을 검토한다. 임시 도구는 메인이 단독으로 설치·실행한다.

기존 StageScenePreview의 격리된 임시 저장 프로필만 사용했다. 에델의 실제 companion ID는 CompanionChipCatalog.EdelId(prototype)다. 실제 플레이어와 InventoryPortrait를 선택하고 게임 월드 틱·입력·적 틱·애니메이션 시간은 촬영 중 정지했다. 변경 전 POSE_PLAN.json을 재사용해 위치·카메라·FOV·1600×1000 해상도를 고정했다. 인벤토리는 실제 portrait RenderTexture의768×1152 화면이다. 카메라 근접3뷰는 비교용 구도이며 실제 기본 전투 거리의 화면과 구별한다. UI 없는 렌더 캡처를 게임 HUD 전체 검증으로 취급하지 않는다.

- 주요 프로덕션13파일 중 의도한 셰이더2개/스타일1개만 바뀌었다. 맵 prefab/scene·PC 렌더러·기존 피부 마스크·캐릭터 설치·헤어/파지/검지 소스는 동일했다. 상세는 VALIDATION_SUMMARY.json과 FINAL_SOURCE_HASHES.json이다.

메인의 시각 판단은 얼굴과 상체의 얼룩진 경계가 줄고 팔·다리 피부의 밝기 연결이 개선됐다는 것이다. 독립 검토자가9쌍을 직접 열어 같은 경향, 머리색·눈/총/의상 보존, 1층/2층의 접지와 백색 포화 없음 및 보호 소스 동일을 확인했다. 메인이 staging/review/FINAL_REVIEW.md를 직접 읽었고, 판정은 **좁은 1차 시험 결과로 잔류 가능**이다. 완전한 두 단계 카툰 음영이나 모든 실내외 조건의 아트 완성으로 평가하지 않는다.

## 전후 화면

실제 Play의 before_ ↔ after_ 접두사가 대응하는9쌍:

- outdoor_sun, outdoor_shade: 기본 게임 거리 야외

카메라·정지 포즈·광원 위치는 같은 조건으로 비교했다. 모든 시간 의존 환경 효과의 픽셀 일치까지 보장하지 않는다. 게임 창의 native 캡처와 별도 카메라 렌더 캡처를 혼용해 동일 해상도로 주장하지 않는다.

## 실패 이력과 남은 한계

임시 촬영 도구의 첫 컴파일은 PlayerSettings 이름 충돌(CS0104)로 실패했다. Escape.Player.PlayerSettings로 명시한 뒤 정상 컴파일했고 그 이전에는 후보를 적용하거나 Play를 시작하지 않았다. 최초 staged 도구의 ID 문자열도 실제 catalog 상수로 적용 전에 고쳤다. 실패 로그는 로컬 UNITY_SESSION.log에 보존하며 이 로그는 게시하지 않는다.

실제 Play는 촬영용으로 시간·입력을 정지한 제한된 Editor 시험이다. 일반 이동·전투의 지속 성능, 장비 착탈 전체, 모든 광원/날씨 조합, Player 빌드와 GPU 시간은 검증하지 않았다. 새 텍스처 샘플/렌더 패스는 없지만 추가 연산·재질 복사본 비용을0으로 단정하거나 FPS 개선으로 보고하지 않는다. 비대상 재질은 기본값0의 균일 분기로 새 형태 계산을 건너뛴다. 헤어 충돌과 기존 미완료 동작은 이번 피부 개선으로 해결되지 않는다.
