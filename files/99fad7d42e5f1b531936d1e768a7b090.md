# 게임 성능 점검과 1차 최적화 (에디터 Play 기준)

같은 주제(네 동료 대기 동작·헤어 성능)의 후속이다. 2026-11-03 회차가 에델에만 넣은 "게임 거리 헤어 단계"를 나머지 몸으로 넓힌 것이 이번 변경의 중심이라 같은 주제에 붙였다.

## 사용자 지시 요약
- 원문은 [SOURCE_REQUEST.md](SOURCE_REQUEST.md). "노트북이 4050인데 렉이 느껴지는 정도니 게임 내에서 리소스 많이 먹는 분야들 파악 후 좀 많은 최적화 방안들을 찾고, 적용."
- 지시 1회(재개 요청 1회는 같은 지시의 진행). 구현 1회.

## 기획 의도와 해결하려는 문제
- 어디가 느린지 짐작이 아니라 실제 출격 상태(A맵, 적 71~72기, AI 진행 중)에서 재서 순위를 정한다.
- 화면과 조작감이 달라지지 않는 것부터 적용한다. 화질이나 적 행동이 달라지는 항목은 수치만 재 두고 사용자가 고르게 남긴다.

## 변경 전 상태와 문제점
- 에디터 Game 1920×1080, 세린(새 슬롯의 기본 동료): 살아 있는 상태에서 프레임 중앙값 348ms(2.9fps). 그중 `SdHairCollisionMotion.LateUpdate`가 332ms.
- 11/03에 넣은 가벼운 헤어 경로는 에델 전용이었다. 세린·리브·유이는 항상 정밀 경로였다(리브 19.5ms, 유이 11.8ms, 세린 332ms. 세린·에델 몸은 충돌 대상 삼각형이 18만~19만 개).
- 에델도 진입 조건이 "화면 크기 180px 미만"인데 게임 카메라에서 에델 크기가 126~180px로 재져, 경계에 걸리면 가벼운 경로에 못 들어갈 수 있었다. 정밀 경로로 돌 때 에델은 프레임 2.9초까지 재졌다(runs/hairlook_01).
- 적 71~72기가 0.2초마다 같은 프레임에 한꺼번에 판단했고, 시야·명중 판정을 한 번 할 때마다 모든 캐릭터의 히트박스를 다시 맞췄다.

## 실제로 바꾼 부분
1. `Assets/Escape/Runtime/SdHairCollisionMotion.cs`
   - 가벼운 헤어 경로의 대상: 에델만 → 모든 플레이어 몸. 에델은 기존 토폴로지 확인 조건을 그대로 둔다.
   - 진입 기준 180px → 228px(1080p 환산). 이탈 기준 240px는 그대로.
   - 인벤토리 초상화·컷신 카메라처럼 게임 카메라가 아닌 화면은 전과 같이 정밀 경로다.
2. `Assets/Escape/Runtime/Enemy/EnemyController.cs`
   - 적마다 0.2초 판단의 시작 시점을 0.02초씩 10단계로 어긋나게 했다. 판단 주기 자체는 그대로다.
   - 체력바 `OnGUI`의 레이아웃 호출을 끔(`useGUILayout=false`). 그리는 내용은 같다.
3. `Assets/Escape/Runtime/Combat/BodyHitboxRig.cs`
   - `SyncPhysics()`가 부를 때마다 전원 히트박스를 다시 맞추던 것을, 포즈가 바뀌는 시점(LateUpdate)에 한 번 맞춘 값을 다음 프레임 Update 동안 재사용하게 했다. LateUpdate 구간에서 포즈 스크립트보다 먼저 들어온 판정은 전처럼 먼저 맞춘다.
   - 달라질 수 있는 점: 같은 프레임 Update 안에서 몸 안쪽 부품(포탑 등)만 따로 돌린 경우 그 회전은 다음 맞춤(같은 프레임 LateUpdate)부터 반영된다. 최대 한 프레임.
4. 측정 도구 `Assets/Escape/Editor/EscapePerfProbe.cs`(에디터 전용, 새 파일). `Library/EscapePerfProbe.request`에 `run <이름> [noablate] [char=<id>] [spots=a,b] [hairlook]`.

바꾸지 않은 것: 프로젝트·품질·URP 설정, 씬, 프리팹, 재질, 셰이더, 메시. 변경 전 파일은 `source/before_edit/`, 차이는 `source/DIFF_*.txt`, 지문은 `SHA256_AFTER.txt`.

## 확인 결과
수치 전체는 [MEASUREMENTS.txt](MEASUREMENTS.txt). 모두 Unity 에디터 Play 값이며 빌드 값이 아니다.

| 몸 (grove 지점, 살아 있음) | 변경 전 중앙값 | 변경 후 중앙값 |
|---|---|---|
| 세린 | 348.5ms (2.9fps) | 22.7ms (44.0fps) |
| 에델 | 25.4ms (39.4fps) | 27.3ms (36.7fps) |
| 리브 | 42.1ms (23.7fps) | 19.8ms (50.5fps) |
| 유이 | 35.1ms (28.5fps) | 19.9ms (50.4fps) |

- 세린 네 지점 최종: 중앙값 21.6~26.2ms(38~46fps). 기준은 76~209ms.
- 적 판단 분산: p95와 중앙값의 간격이 5.0~7.8ms → 2.1~4.5ms(세 번 실행 모두). 중앙값은 실행마다 ±2ms쯤 흔들려 이 변경의 효과를 가려낼 수 없었다.
- 에델은 이전에도 가벼운 경로여서 수치 차이는 흔들림 범위다.
- 헤어 모양: 같은 실행에서 정밀/가벼운 경로를 번갈아 켜고 앞·뒤·좌·우 근접 화면을 찍었다(`pairs/HAIR_PRECISE_vs_LIGHT_closeup.jpg`). 다섯 몸 모두 머리색·형태가 같고, 에델 땋은 머리 끝 위치가 조금 다르다. 정지 화면이라 움직일 때의 흔들림·겹침은 확인하지 못했다.
- 에디터 로그에 새 오류 없음(기존 "Stage A map has no validated encounter layout" 한 가지는 전부터 있던 미리보기 문제).

## 확인하지 못한 것
- 직접 플레이(이동·사격·구르기 중 헤어와 명중 판정 체감), 전투가 많은 상황, 빌드 실행.
- 적 판단 시점이 어긋난 뒤의 교전 양상(주기는 같지만 동시에 쏘던 타이밍이 흩어진다).
- 측정 지점 화면(`pairs/GAME_PAIRS_four_spots.jpg`)은 조건이 다르다: 기준 실행은 cluster 이후 플레이어가 죽은 상태였고, 카메라 앞보기가 마우스를 따라가 구도가 다르다. 화면 비교용이 아니라 측정 위치 기록이다.

## 남은 후보 (재 두기만 함)
- IMGUI 화면 5.2ms/프레임(`InventoryTestWorld.OnGUI` 3.0, 글꼴 캐시 1.8), 가벼운 헤어 경로의 몸 캡슐 맞추기 3.0, 비 0.7~2.1, 건물 가림 1.6, `StageMapRouter.LateUpdate` 0.8(+GC 11.9KB), 담쟁이 연동 0.7.
- 그림자: 끄면 GPU 11.1 → 6.7ms, 드로콜 1573 → 837. 지금은 CPU가 한계라 프레임 시간은 안 변했다. 화질이 달라지므로 사용자 선택.
- 에델로 몸을 바꾸는 순간 5.7~6.4초 멈춤(runs/hair_edel_01, hairlod_edel_01의 최대 프레임).
- 프레임 제한(수직동기)은 빌드 성능을 모르는 상태라 넣지 않았다.
