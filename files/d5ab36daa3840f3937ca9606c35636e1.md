# A맵 건물 외부의 실내 노출 방지

## 사용자 지시 요약

실내에 들어가지 않았는데 건물 내부 구조가 외부에서 보이는 현상을 확인하고 수정한다.

## 기획 의도와 해결하려는 문제

폐허나 개방형 쉼터가 아닌 닫힌 건물은 외부에서 지붕이 실내를 가려야 한다. 기존 지붕 숨김 구역은 실제 건물보다 넓어 플레이어가 벽 밖에 있어도 실내로 판정될 수 있었고, 일부 온전한 평지붕은 중앙이 항상 비어 있었다.

## 변경 전 상태 및 문제점

- `before_user_game_view.png`는 사용자가 제공한 실제 Play 화면의 수정 전 원본 사본이다. 벽 바깥에 선 캐릭터 옆으로 건물 내부처럼 보이는 넓은 면이 노출되어 있다. 화면만으로 해당 건물의 계층명은 특정할 수 없다.
- v0.8 주요 건물은 실제 벽보다 10% 넓은 지붕 숨김 구역을 사용했고, v0.9·v1.1 회전 건물은 대각선 반경의 축 정렬 정사각형 구역을 사용했다.
- v0.9 일부 온전한 평지붕은 양쪽 띠 사이에 시각적 개구부가 남아 있었다.

## 실제로 바꾼 부분과 방법

- `StageABlockoutMap.cs`에서 기존 프리팹에 기록된 건물 바닥 크기와 회전 방향을 읽어, 벽 안쪽 0.2m에 플레이어가 있을 때만 해당 지붕의 렌더러를 숨기도록 했다. 기존 직렬화 프리팹을 재생성하지 않는다.
- v0.9의 온전한 평지붕에만 기존 지붕과 공면으로 겹치지 않는 렌더러 전용 중앙 캡을 런타임에 한 번 추가한다. 원래 파손된 지붕과 개방형 건물, 교체 비주얼 에셋은 제외한다.
- 맵 배치·충돌체·스폰·씬·프리팹·기존 에셋은 수정하지 않았다.

## 변경 후 기대 효과와 확인 결과

- 닫힌 건물 밖에서는 지붕이 유지되고, 건물 안으로 실제 진입하면 지붕만 숨겨져 내부를 읽을 수 있어야 한다.
- 2026-09-21에 열린 Unity 편집기에서 실제 유지 중인 A맵 프리팹을 임시 PreviewScene에 인스턴스화하고 `W_PARTS_LOCKER`를 대상으로 외부→실내→외부 판정을 순서대로 실행했다.
- 대상 건물은 18×12m, 회전 -7도였으며, 지붕 렌더러는 외부 3/3 표시, 실내 0/3 표시, 외부 복귀 3/3 표시로 확인됐다. 런타임 중앙 캡도 존재했다. 결과 원문은 `ROOF_VISIBILITY_VALIDATION.txt`에 남겼다.
- `after_outside_roof_visible.png`에서 유지 중인 실제 프리팹의 외부 상태를 렌더링해, 중앙 캡을 포함한 지붕이 실내를 가리는 것을 확인했다.
- 자동 PreviewScene 렌더러는 상태 변경 뒤에도 직전 영상을 다시 반환해 실내 캡처가 외부 캡처와 동일한 해시로 저장되는 문제가 있었다. 이 이미지는 증빙에서 제외했으며, 실제 캐릭터를 같은 지점에서 왕복시킨 Game View 캡처라고 주장하지 않는다.
- Sol high 보조 검증에서도 v0.8·v0.9·v1.1 회전 바닥 판정, 벽 모서리 외부 유지, 벽 안쪽 0.21m 진입 시 숨김, 중앙 캡의 간극 및 공면 겹침 없음이 독립적으로 통과했다.
- `dotnet build Assembly-CSharp.csproj --no-restore` 결과 경고 0개, 오류 0개다. 임시 검증 도구 제거 후 열린 Unity 편집기의 재컴파일도 오류 없이 끝났다.
- 남은 확인 범위는 실제 캐릭터로 동일 건물의 외부·문턱·실내를 왕복하는 Game View 체감 확인과 교체 에셋 사례다. 해당 화면에서 계속 노출된다면 카메라의 벽·지붕 관통 또는 특정 오버라이드 에셋 형상을 추가로 확인해야 한다.

## 관련 스크린샷

- `before_user_game_view.png`: 사용자 제공 수정 전 Game 화면.
- `after_outside_roof_visible.png`: 실제 유지 중인 A맵 프리팹의 `W_PARTS_LOCKER` 외부 상태를 Unity PreviewScene에서 렌더링한 수정 후 확인 화면. 수정 전과 동일 카메라가 아니며 실제 Play 캐릭터 화면으로 위장하지 않는다.
