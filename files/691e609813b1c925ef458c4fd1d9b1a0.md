# S4 승인 일러스트 Unity 썸네일 적용

## 사용자 승인·기존 주제 연결

[SOURCE_REQUEST.md](SOURCE_REQUEST.md)의 ‘이거 이제 유니티 썸네일에 적용해봐’로04 시안의 적용이 승인됐다. 피부색 없이 장비 사이를 빈 공간으로 표현한 APPROVED_ILLUSTRATION.png가 정확한 적용 대상이다. 같은 아이템 식별/표시 목적의 후속이므로 기존 장비 썸네일 주제의05 변경 결과 회차로 연결한다. 이전01 실제모델 적용·02~04 시안·당시 검토 전 이력·QA·게시 원문은 소급 변경하지 않는다.

## 변경 전과 공유 작업 순서

성능 담당에게07:57 KST clean Edit 구간을 명시 반환받은 뒤 작업했다. InventoryPortrait/무기·헤어·GamePerf 소스는 소유 범위에서 제외했다. 실제 생산 변경 전에 기존 PNG·meta·베이커를 source_before에 보존하고, 현재 보호 파일 SHA를 PROTECTED_BEFORE.json에 기록했다.

Unity Refresh 때 C여유241192960bytes로 Low disk space 경고가 발생했다. 생산파일을 수정하기 전에 작업을 멈췄고, 성능 담당이 workspace의 동일SHA 보존본이 있는 자신의 과거 측정 PNG/데이터 중복만 정리했다. 이쪽은 공용 캐시·공유로그·원본증빙을 삭제하지 않았다. C여유가약1.3GB로 회복된 뒤 재개했다.

전용 임시 장면·격리 프로필에서 실제 에델/S4 장착 인벤토리를 실행해 before_inventory.png를 촬영했다. before_samples.png는 공통 GlassIcons를 같은 실제 경로로 그리는 명시된 검증 표시 도구다. 전체게임 화면인 것처럼 보고하지 않는다. 두 화면 모두1920×1080이며 후속도 같은 준비 절차·장비·조명·레이아웃이다.

## 실제 변경

1. 승인된 PNG를 Assets/Escape/Resources/UI/ItemIcons/TEST_EDEL_S4_MAINTENANCE.png에 바이트 그대로 복사했다. 원본SHA2515e99e7dd061889abda81a86729f90ca9db2f4d6834826d0e85f6a26377b9a와 일치한다. 기존 meta/GUID·압축/알파 설정은 유지했다.
2. 기존 공통 Resources 로더·캐시와 Equipment 회전을 그대로 사용한다. 새 런타임 카메라·모델·갱신 루프나 레이아웃 변경은 없다. 이번 적용은 S4 한 종이다. 미모델링 다른 방어구에는 이 그림을 임의로 배정하지 않는다.
3. ArmorItemThumbnailBaker의 모델 재촬영 출력만 Assets/Escape/Art/ItemThumbnailSources/TEST_EDEL_S4_MAINTENANCE_model.png로 옮기고 메뉴를 Escape > UI > Export S4 armor model reference로 명확히 했다. 승인된 일러스트를 모델 캡처로 덮어쓰지 않게 하기 위한 Editor 변경이다. 실제 내보내기를 한 번 실행해 새 참고 경로로 저장되고 runtime PNG의 SHA가 그대로임을 확인했다. 참고 PNG는 Resources 밖이며 런타임에서 로드하지 않는다.

## 실제 검증

- PNG/Editor 변경의 컴파일·임포트 후 Play를 새로 시작해 after_inventory.png를 촬영했다. 실제 방어구 장착칸에서 새 그림이 표시된다. 허리·팔·다리의 빈 공간과 두 줄 밴드는 슬롯 배경을 통해 구분된다.
- after_samples.png에서 공통 정방향·90도 회전·96px 작은 표시와 기존 미모델링 조끼 fallback을 직접 대조했다. GUI 행렬 복원 true, 표시 전후 Camera5→5/Light24→24다. 숫자는 임시 검증 장면의 전체 개수이며 일반 게임의 FPS 측정은 아니다.
- 전후 모두 Resources Texture 재사용 true,512×512,mipmapCount1,readable false,Profiler 측정525120bytes다. 두 세션의 인벤토리 상태는 각자 snapshot 대비 변경 없음이며, 저장 경로는 이 기록 아래의 격리 프로필이다. 일반 사용자 세이브를 수정하지 않았다.
- BAKE_REPORT.json의 sourceUnchanged/sceneUnchanged/transientObjectsReleased 모두true다. 실제 export 후 승인된 runtime PNG SHA가 유지됨도 확인했다.
- PROTECTED_AFTER.json에서 공통 GlassIcons,InventoryPortrait,WeaponModelThumbnails,S4 착용 코드·Edel/Outfit·원래Relay씬/맵프리팹/meta는 변경 없음이다. 의도한 베이커 코드와 runtime PNG 두 파일만 보호목록에서 바뀌었다.
- source PNG의 극미량 알파1 잔류와 엄격 알파0 QA false 이력은04 시안 기록에 보존하며 이번 적용으로 소급 통과 처리하지 않는다. 실제 Unity 임포트/작은 표시에서 피부색 면 없이 투명 개구부로 보이는 것을 확인했다. 실제 프레임시간이나 전체 게임 성능 개선은 이번 작업에서 측정하지 않았다.

## 증빙과 수정 파일
