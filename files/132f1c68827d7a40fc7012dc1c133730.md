# 겹치는 인벤토리 영역 교환 보완

## 사용자 지시와 기획 의도

- 사용자 지시: 같은 가방 안에서 3×3 방탄복을 겹치는 3×3 대상 영역으로 옮길 때, 대상 영역의 물품들이 방탄복의 원래 자리로 모두 이동할 수 있으면 교환되게 수정한다. 전리품 파밍 중 가방을 정리할 때에도 적용한다.
- 의도: 원래 위치로 단순 평행 이동했을 때 새 방탄복과 충돌한다는 이유만으로 가능한 교환을 거부하는 문제를 해소한다.

## 변경 전 상태

- `PlanMove`는 대상 영역에 완전히 들어 있는 물품들의 상대 위치를 유지하여 옛 방탄복 영역으로 평행 이동했다.
- 원본 영역과 대상 영역이 겹치면 반환 물품이 새 방탄복과 겹쳐 `교환할 물품이 원래 공간에 들어가지 않습니다.`로 거부되는 사례가 있었다.
- 사용자가 보낸 실제 게임 화면은 `before_user_report.png`로 보관했다. 동일한 기하 조건을 별도 검증 실행 화면에 재현한 `before_preview.png`, `before_result.png`에서도 해당 거부를 확인했다.

## 실제 변경과 방식

- 원래의 평행 이동 배치가 가능한 경우에는 그 배치를 유지한다.
- 반환 배치가 충돌할 때에는 대상 3×3 영역에 완전히 들어 있던 물품들을 두 영역의 중심을 기준으로 반 바퀴 대응시켜, 방탄복의 원래 영역 중 비어 있는 칸에 배치한다. 각 물품의 크기와 회전 상태는 유지한다.
- 반환 위치가 원래 영역 밖이거나 다른 물품과 겹치면 교환을 거부한다. 대상 영역의 경계에 걸친 물품을 거부하는 기존 조건도 유지한다.
- 교환 가능 여부는 실제 이동 전에 전체 최종 배치를 검사한다. 실패 시 인벤토리 변경과 알림이 발생하지 않는다.
- 인벤토리 검증에 겹치는 영역의 한 물품·여러 물품 교환, 미리보기의 무변경성, 물품 식별자 보존, 주변 물품 고정 조건을 추가했다. 기존 독립 기하 검증도 새 허용 조건을 검사하도록 갱신했다.

## 변경 후 기대 효과와 확인 결과

- `after_preview.png`에서 겹치는 3×3 대상 영역이 교환 가능으로 표시되고, `after_result.png`에서 방탄복과 작은 물품 3개의 교환이 완료됐다.
- 같은 화면의 오른쪽 경계 위반 사례는 전후 모두 거부됐다.
- 전리품 넣기 검증은 변경 전후 모두 성공했다(`before_loot_deposit_result.png` ↔ `after_loot_deposit_result.png`). 가방 내부 드래그는 실제 UI 코드에서 변경한 `PreviewPlacement`/`TryPlace`를 호출하는 것을 확인했다.
- 별도 Unity 프로젝트에서 수정한 원본 파일 두 개와 동일한 해시의 사본으로 검증했다. 빌드 성공, 교환 규칙 54개, 기존 규칙을 포함한 총 464개, UI 회귀 검사 101개가 통과했다. 독립 기하 검사 2,000회가 포함됐다. 실제 플레이 세이브와 맵은 변경하지 않았다.
- 별도 검증 실행 화면에서 실제 런타임 로직을 촬영했다. 실제 게임 화면에서 수동 마우스 드래그를 다시 수행한 증빙은 없으며, UI 연결 검사와 UI 회귀 검사로 보완했다.
